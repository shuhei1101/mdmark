## 原因の切り分け

Issue の見立て（リソースのタイミングの記録が上限の 250 件に達する）は当たらなかった。

| 実行 | 変更 | 結果 |
| --- | --- | --- |
| 修正前（08:30、ほかの worktree の結合テストの全件と重なる） | なし | 落ちる（0 件） |
| 準備で `performance.clearResourceTimings()` を呼ぶ（10:45、ほかの結合テストと重なる） | 記録の削除 | 落ちる（0 件） |
| 待ちの前に 3 秒止める | 記録の削除あり・なし | 合格 |
| 待ちの上限を 60 秒・5 秒・1 秒に明示し、かかった時間を測る | 記録の削除なし | 合格（168ms・148ms・177ms）。このテストの前の記録は 0 件で、上限に達していない |
| 修正前と同じコード（11:16・11:19・Vite のキャッシュを外した 11:23） | 記録の削除あり | 3 回とも合格 |

落ちたのはほかの重いテストと重なった実行だけで、負荷が高いと、約 2.3MB の変換のライブラリの読み込みと評価が既定の上限の 1 秒を超える。
