見出し行を画面の上端に留める方式（PoC 検証で案 C に決定）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 横スクロールの枠の外に見出し行の複製を置き、ページのスクロールで画面の上端に留め、枠の横スクロールと列の幅・ピン止めに合わせて動かす | 横にはみ出す表でも、はみ出さない表でも同じ仕組みで留まる | 列の幅と横の位置を合わせ続ける処理が要る。並べ替え・絞り込み・ピン止めのボタンと状態・フォーカス・読み上げを複製と元で揃え続ける処理が要る |
| B | 横にはみ出さない表は枠の `overflow` を外して `position: sticky` で留め、はみ出す表だけ A にする | はみ出さない表は CSS だけで済む | 2 つの仕組みを持ち、幅が変わるたびに切り替える。はみ出す表は A と同じ処理が要る |
| C | 複製を作らず、元の見出し行のセルを `transform: translateY` でページのスクロールに合わせて画面の上端まで下げる。集計の行のセルも同じく画面の下端まで上げる | ボタン・状態・フォーカス・読み上げが元の 1 組のまま。セルは元の表の中にあるため、横の位置・幅・ピン止めが今のまま揃う | 縦の位置をスクロールのたびに JS で合わせ続ける。下げたセルが本文の行に重なるため、背景と重なりの順を持たせる |

推奨: C

`overflow` を持つ枠の中の `position: sticky` は画面ではなく枠に対して効くため、横スクロールを保ったまま画面に留めるには、枠の外の要素（A）か、スクロールに合わせて JS で動かすセル（C）が要る。
C は見出し行のボタンの操作と状態を今の `src/interact/tables.ts` のまま使え、A が要る複製との同期が要らない。
PoC では A と C を同じ成功条件で測り、両方が満たせば C、片方だけならその案にする。
両方とも満たさなければ、横にはみ出す表では見出し行を留めないか、表の高さの上限を残すかの要件の見直しへ進む。

PoC 検証の成功条件: 横にはみ出し、ピン止めした列・並べ替え・絞り込みと集計の行を持つ表で、次が全て成り立つ。

- 縦に留まる: ページの縦のスクロール中、見出し行が画面の上端（ずれ 48px を渡したときはその下）から ±1px に、集計の行が画面の下端から ±1px に留まる
- 表から外れる: 表が画面から外れると、見出し行と集計の行も画面から外れる
- 横に揃う: 枠の横スクロールの左端・中ほど・右端と、ピン止めした列に、見出し行と集計の行のセルの位置と幅が ±1px で揃う
- 追従の遅れ: 30 回のスクロールのそれぞれで、次のフレームまでに位置が合う
- ボタンと状態: 留めた見出し行から並べ替え・絞り込み・ピン止めを操作でき、`aria-sort`・`aria-expanded`・`aria-pressed` が 1 組のまま正しく変わる。絞り込みのパネルが押したボタンの下に出る
- フォーカスと読み上げ: Tab で見出し行のボタンへ 1 回ずつだけ移り、アクセシビリティツリーに見出し行が 1 組だけある
- 幅の変化: 並べ替え・絞り込み・列の表示の切り替え・ピン止めの後と、画面の幅を 1280→390→1280px と変えた後も、横に揃う
- 印刷: 印刷では留めず、見出し行が 1 組だけ出る
- 動く環境: 上の全ての条件を Chromium と Firefox（Playwright）で、縦に留まる・横に揃う・ボタンと状態を VS Code 拡張機能のプレビュー（`@vscode/test-electron`）で確かめる

本番との違い: PoC は留める処理を PoC のページのスクリプトに置き、`src/interact/tables.ts` には入れない。
表の HTML とボタンの操作は今の `mount` が描いたものをそのまま使う。
VS Code 拡張機能のプレビューにはページのスクリプトを置けないため、留める処理を入れた PoC の配布物を作り、`MDMARK_VSCODE_DIST_BASE` で読ませる。
違いは留める処理の置き場所だけで、表の DOM・スクロールの追従・ボタンの操作は本番と同じため、結論に影響しない。

```js
const update = () => {
  const box = naturalBox(table);
  const top = stickyTop(root);
  // 見出し行: 画面の上端より上に出た分だけ下げ、本文の最後の行より下へは下げない
  const headMax = Math.max(0, box.bodyBottom - box.headTop - box.headHeight);
  const headShift = Math.min(Math.max(0, top - box.headTop), headMax);
  table.style.setProperty("--poc-head-shift", `${headShift}px`);
  // 集計の行: 画面の下端より下に出た分だけ上げ、本文の最初の行より上へは上げない
  const footMin = Math.min(0, box.bodyTop - box.footTop);
  const footShift = Math.max(Math.min(0, innerHeight - box.footTop - box.footHeight), footMin);
  table.style.setProperty("--poc-foot-shift", `${footShift}px`);
};
// CSS: thead th { transform: translateY(var(--poc-head-shift)) } / tfoot td { transform: translateY(var(--poc-foot-shift)) }
// 呼ぶ契機: window の scroll・表の中の scroll（capture）・resize・表の ResizeObserver
```
