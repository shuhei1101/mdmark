# 要件

## 要望

[Issue #150](https://github.com/shuhei1101/mdmark/issues/150) の子 Issue の終わりの条件を全て満たす。

<!-- table: data -->

| Issue | 終わりの条件 |
| --- | --- |
| [#119](https://github.com/shuhei1101/mdmark/issues/119) | 画面の幅を広げると本文もその幅を使う。表の縦の高さに上限が無く、縦はページのスクロールだけで読める。見出し行がページのスクロールで画面の上端（使う側の固定ヘッダーの高さを CSS カスタムプロパティで渡したときはその下）に留まる。狭い画面では長い最終列を畳み、行を押すと開ける |
| [#123](https://github.com/shuhei1101/mdmark/issues/123) | 言語の指定があるコードブロックに言語のラベルが表示される。Dockerfile・diff が色分けされる。コピーボタンが、行のマーカーとマーカーだけを持つ行コメントの頭を除き `[!code --]` の行を含めない変更後のコードをコピーし、結果をボタンの文言で知らせる |
| [#130](https://github.com/shuhei1101/mdmark/issues/130) | 表のコピーで Markdown の表か TSV かを選べ、絞り込み・列の表示の切り替えの後に見えている行と列をコピーする。クリップボードへ書けないときは中身を選択したパネルを出す。行のアンカーを押すと行を指す URL をコピーして短く知らせ、アドレスバーの URL もその行を指す |
| [#132](https://github.com/shuhei1101/mdmark/issues/132) | 集計が計算ごとに 1 行ずつ、先頭に計算の名前を付けて出る。`sum` / `avg` の列に数として読めないセルがあると、その列の集計を出さずに警告する。表の上の「集計」ボタンから出す計算を選べる |
| [#136](https://github.com/shuhei1101/mdmark/issues/136) | URL の `#見出しの id` が選ばれていないタブの中の見出しを指すとき、ページを開いたときと `hashchange` の両方で、そのタブを選んでから見出しへスクロールする |
| [#139](https://github.com/shuhei1101/mdmark/issues/139) | インラインコードが `badge:` だけ（頭の後ろが空、または空白だけ）のとき、バッジにせずインラインコードのまま出る |

<!-- /table -->

受付判断のレビューで決まった点:

- [#130](https://github.com/shuhei1101/mdmark/issues/130): コピーする行の URL は、アンカーの解決済みの `href`（`rewriteLinks` が書き換えた後の値）にする
- [#136](https://github.com/shuhei1101/mdmark/issues/136): `src/interact/sections.ts` の `revealHashTarget` は、タブの中の見出しの処理を `src/interact/tabs.ts` に任せる

子 Issue の本文から補う振る舞い:

<!-- table: data -->

| 項目 | 振る舞い |
| --- | --- |
| 表の横のはみ出し | 横にはみ出す表は今のまま表の中で横にスクロールし、ピン止めした列も今のまま留める |
| 固定ヘッダーの高さ | 使う側は、見出し行を留める位置の画面の上端からのずれを CSS カスタムプロパティで渡す。既定は 0 |
| 本文の幅 | VS Code 拡張機能のプレビューだけでなく、`mount` で描く文書全般に当てる |
| 色分けする言語 | 情報文字列の `dockerfile`（別名 `docker`）と `diff`（別名 `patch`）を色分けの対象に追加する。書き出した HTML には使った言語の分だけを埋める |
| 言語のラベル | 情報文字列の最初の語をそのまま表示する。言語の無いコードブロックにはラベルを出さない |
| 集計の計算の名前 | `sum` は合計、`avg` は平均、`count` は件数 |

<!-- /table -->

`未確定`: 本文の幅の既定（決める段: モック作成）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 既定の上限を外し（`--mdmark-content-width: none`）、行の長さを抑えたい使う側が CSS カスタムプロパティで上限を渡す | 広げた画面の幅をそのまま使える | 広い画面で 1 行が長くなり読みにくくなる |
| B | 既定の上限を広げる（例 72rem） | 広い画面でも 1 行の長さに上限が残る | 72rem より広い画面ではまた右側が空く |

推奨: A

[#119](https://github.com/shuhei1101/mdmark/issues/119) の終わりの条件が「画面の幅を広げると本文もその幅を使う」で、上限を残すと満たせない。
デザイン方針の「行の長さ 46rem まで」を書き換えるため、モックで見た目を合意する。

`未確定`: 狭い画面で畳む最終列と、畳む幅（決める段: モック作成）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 描いた文書の幅が 720px 未満のとき（コンテナクエリ）、最終列のどれかのセルが 1 行に収まらない表だけ最終列を畳む | 使う側がサイドバーを置いて本文が狭いときも効く。短い最終列は畳まない | 畳むかを描いた後に測る処理が要る |
| B | 画面の幅が 720px 未満のとき（メディアクエリ）、全ての表の最終列を畳む | CSS だけで決まる | サイドバーで本文が狭い画面では畳まない。短い最終列も畳む |

推奨: A

mdmark は使う側のページの一部に描かれるため、画面の幅より描いた文書の幅のほうが表の幅に効く。
720px は AI Monitor のドキュメントサイトの今の値。

`未確定`: 畳んだ最終列の開き方と行の詳細の両立（決める段: モック作成）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 行を押すと、その行の下に最終列の見出しと中身を出す。行の詳細を持つ行は、行の詳細の中身の上に最終列の中身を並べ、開閉を 1 つにまとめる | 1 つの行に開閉が 1 つで、押す場所に迷わない | 行の詳細の部品の振る舞いが変わる |
| B | 最終列の開閉と行の詳細の開閉を別々に持つ | 行の詳細の部品は変わらない | 1 つの行に開閉が 2 つ並ぶ |

推奨: A
