## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 区切りを作る時点 | モジュールの最上位で `Intl.Segmenter` を作らず、`findWords` が初めて区切りを使うときに作って以降は使い回す | 読み込み時に例外を出さない |
| `Intl.Segmenter` を持たない環境 | `Intl` に `Segmenter` が無いときは作らず、代わりの区切りで照合する | `未確定`（要件.md の `## 要望` の案。決める段: モジュール構成設計） |
| `Intl.Segmenter` を持つ環境 | 区切りと照合の結果を今と変えない | 既存の `find-words-cases.ts` のケースが Node と Chromium で通り続ける |
| 呼び出し側 | `findWords`・`buildDictionary` の引数と戻り値を変えない | `references.ts`・`terms.ts`・`html.ts`・`diagrams.ts` は触らない |
| 単体テスト | `Intl.Segmenter` を消した環境で `dictionary.ts` を読み込んで例外が出ないことと、代わりの区切りでの照合を確かめる | Node の単体テスト |
| 結合テスト | `Intl.Segmenter` を消した環境で配布物の入口を読み込み、`render` が文書を HTML 文字列にすることを確かめる | `tests/integration/lib/render.test.ts` に足すかはインターフェース定義設計で決める |
| 動作環境 | 非機能要件『対応ブラウザ』の決定値は変えない | - |
