# 要件

## 要望

既存の記法・点検へ、子 Issue 4 件の項目を追加する。
子ごとの範囲と背景は子の Issue の本文と、本文の `## 必読` に挙げた話し合いの記録が正。
今の書き方（座標を全て書いたフロー図・`<!-- code: -->` の引数・言語 `tree` のコードブロック・`check` の今の引数）は、そのまま同じ結果になる。

| 子 | 終わりの条件 |
| --- | --- |
| [#272](https://github.com/shuhei1101/mdmark/issues/272) | `start`・`question`・`action`・`result` のノードで `x`・`y`・`w`・`h` と線の `points` を省いた定義が、開始から上から下へ質問を並べ、YES / NO の先へアクションと結果を配置して描かれる。省いた定義も check の図の点検が配置後の座標で点検できる |
| [#288](https://github.com/shuhei1101/mdmark/issues/288) | Markdown の文字列、またはファイルと YAML のキーを受けて、描いたときの「書き方の警告」と同じ内容を返す点検が MCP と CLI にあり、dev-docs の `write_docs` と MindStella の `add`・`update` が書き込みのたびに呼べる。close のときに shuhei1101/dev-docs#89・shuhei1101/mindstella#404 へ着手できる旨をコメントし、確認:task-planner を付ける |
| [#294](https://github.com/shuhei1101/mdmark/issues/294) | コードブロック・ファイルツリーは既定で折り返さず、ブロックごとに記法で折り返すかを選べる。埋め込む側の `pre` への汎用の CSS で既定が変わらない |
| [#310](https://github.com/shuhei1101/mdmark/issues/310) | フロー図の部品のノードにリンク先の項目があり、ノードを押すとリンク先を開ける（図のドラッグでの移動・ノードのツールチップと両立する） |

`確定`: 記法の点検の入口（#288。A に決定。確認ログ）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | MCP の `check` と `mdmark check` に、Markdown の文字列（`text`）とファイルと YAML のキー（`file`・`key`）の引数を追加する | 点検の入口が 1 つのままで、使い方集と instructions の動線を変えずに済む | 設定と索引の点検と、渡した文字列の点検で、返すずれの範囲が引数で変わる |
| B | 記法の点検だけをする別のツールとサブコマンドを追加する | 入力と返すものが 1 つに決まり、書き込みのたびに呼ぶ側が扱いやすい | 点検の入口が 2 つになり、どちらを呼ぶかを使い方集と instructions で書き分ける |

推奨: A

Issue の参考の一案のとおりで、図の定義の点検（#187）と同じ経路で返せ、ずれの構造（`file`・`where`・`kind`・`message`）をそのまま使えるため。

`確定`: `id:{文書の ID}#{項目のパス}` のような http でないリンク先の扱い（#310。A に決定。確認ログ）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | ノードのリンク先は本文のリンクと同じ許可（`http`・`https`・`mailto`・相対パス）で扱い、`id:` は使う側が URL に変換してから定義に書く | 本文のリンクと同じ決まりで、mdmark に使う側の参照の形を持ち込まない | 使う側が変換の処理を持つ |
| B | `mount` にリンク先を解決する関数の引数を追加し、許可しないリンク先は使う側が開き方を決める | 定義に `id:` をそのまま書ける | 本文のリンクとノードのリンクで扱いが分かれ、書き出した HTML では関数を渡せない |

推奨: A

本文のリンクと同じ許可で扱えば、書き出した HTML でも同じ動きになり、dev-docs は画面の変換で mermaid の `click` を URL に置き換えるだけで済むため。

コードブロック・ファイルツリーの折り返しの記法（#294）は、コードブロックは `<!-- code: -->` の引数に、ファイルツリーは `<!-- tree: -->` の引数に `wrap` を追加する（`title=`・`fold=`・`open=` と同じ並び）。
既定（`wrap` なし）は今のまま折り返さない。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 判定フローチャート以外の種類（`llm`・`dm`・`script`・`mcp`・`data`・`external`）のノードの自動の配置 | #272 の要望は判定フローチャートの 4 種類だけ。構成図は層と枠で置き場所を決めるため、同じ配置の決まりで描けない | 予定なし |
| Mermaid と補足で書き、自動配置で描く新しい図 | 別の要望（新しい図の部品の追加） | #324 |
| dev-docs の `write_docs` と MindStella の `add`・`update` から点検を呼ぶ処理 | 呼ぶ側のリポジトリの変更 | shuhei1101/dev-docs#89・shuhei1101/mindstella#404 |
| MindStella のプレビューの `.md pre { white-space: pre-wrap; }` の修正 | 埋め込む側のリポジトリの変更（#294 の本文で shuhei1101/mindstella 側の Issue で対処すると決まっている） | 予定なし |
| シーケンス図の相手・ER 図のテーブルのリンク先 | #310 の要望はフロー図のノードだけ | 予定なし |
| ノードのリンク先の `id:` を mdmark が解決する仕組み | `## 要望` の #310 の扱いが A に決まり、使う側が変換する | 予定なし |
