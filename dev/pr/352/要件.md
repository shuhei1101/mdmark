# 要件

## 要望

記法を、子 Issue 2 件の終わりの条件のとおりに新設する。
子ごとの範囲と決まったことは子の Issue の本文と、#218 の本文の `## 必読` に挙げた話し合いの記録が正。
新しいマーカーを含まない文書は、今と同じ見た目で描ける。

<!-- table: data -->

| 子 | 終わりの条件 |
| --- | --- |
| [#161](https://github.com/shuhei1101/mdmark/issues/161) | 文書ごとに配色（ライト・ダーク・OS に合わせる）を指定でき、プレビューにも書き出した HTML にも当たる。目次の出し方や先頭へ戻るボタンなどのページ全体の見せ方の設定も、文書ごとに同じ場所に記載できる。`mdmark.config.yaml` にも同じ設定を書け、全文書の既定にできる |
| [#218](https://github.com/shuhei1101/mdmark/issues/218) | `<!-- cards -->` で囲んだリスト（リンク・説明・#192 の `icon:`）をカードの格子で描く |

<!-- /table -->

優先の順番は #163 の決めに従い、文書のマーカー → 近いフォルダの設定 → 上のフォルダの設定 → 端末の設定の順に、近い層ほど優先する。
新しいマーカーは、GitHub など mdmark の無い所では見えないか、元のリストのまま読める。

`未確定`: ページの設定の書き方（決める段: 単一ユースケース設計）

| 案 | 内容 |
| --- | --- |
| A | 文書の先頭の HTML コメントのマーカー（`<!-- page: theme=dark toc=hover -->`） |
| B | Markdown のフロントマター |

推奨: A

`<!-- features: … -->` と同じ書き方で揃い、フロントマターを読むほかのツールと干渉しないため（#161 のユーザーのコメント）。

`未確定`: ページの設定に入れる項目（決める段: 単一ユースケース設計）

| 案 | 内容 |
| --- | --- |
| A | 配色の明暗（ライト・ダーク・OS に合わせる）・テーマ（`colorTheme`）・右側の目次の出し方（`side-toc.mode`）・先頭へ戻るボタンのオン・オフ |
| B | 配色の明暗だけ |

推奨: A

#161 の終わりの条件が、目次の出し方と先頭へ戻るボタンも同じ場所に記載できることを求めるため。

`未確定`: VS Code の `mdmark.preview.theme`（明暗）と、設定ファイルの明暗の優先（決める段: 単一ユースケース設計）

| 案 | 内容 |
| --- | --- |
| A | 文書のマーカー → VS Code の設定（`auto` 以外のとき）→ 設定ファイル → OS の設定 |
| B | 文書のマーカー → 設定ファイル → VS Code の設定 → OS の設定 |

推奨: A

今の `mdmark.colorTheme`（VS Code の設定）が設定ファイルの `colorTheme` より優先しており、明暗も同じ順に揃えられるため。

`未確定`: cards のマーカーをオン・オフする features のキーの名前（決める段: 単一ユースケース設計）

| 案 | 内容 |
| --- | --- |
| A | 別の名前のキー（例: `card-grid`）を追加し、既定はオンにする |
| B | 既存の `features.cards`（リンクと添付のカード）で両方をオン・オフする |
| C | 既存の `features.cards` の名前を変え、空いた `cards` をカードの格子に使う |

推奨: A

`features.cards` は #263 でリンクと添付のカードのキーとして入っており、C は使う側の設定を書き換える移行が要り、B はリンクのカードだけを止められなくなるため。
