# 要件

## 要望

記法を、子 Issue 2 件の終わりの条件のとおりに新設する。
子ごとの範囲と決まったことは子の Issue の本文と、#218 の本文の `## 必読` に挙げた話し合いの記録が正。
新しいマーカーを含まない文書は、今と同じ見た目で描ける。

<!-- table: data -->

| 子 | 終わりの条件 |
| --- | --- |
| [#161](https://github.com/shuhei1101/mdmark/issues/161) | 文書ごとに配色（ライト・ダーク・OS に合わせる）を指定でき、プレビューにも書き出した HTML にも当たる。目次の出し方や先頭へ戻るボタンなどのページ全体の見せ方の設定も、文書ごとに同じ場所に記載できる。`mdmark.config.yaml` にも同じ設定を書け、全文書の既定にできる |
| [#218](https://github.com/shuhei1101/mdmark/issues/218) | `<!-- cards -->` で囲んだリスト（リンク・説明・#192 の `icon:`）をカードの格子で描く |

<!-- /table -->

優先の順番は #163 の決めに従い、文書のマーカー → 近いフォルダの設定 → 上のフォルダの設定 → 端末の設定の順に、近い層ほど優先する。
新しいマーカーは、GitHub など mdmark の無い所では見えないか、元のリストのまま読める。

決定（単一ユースケース設計）: ページの設定は、文書の先頭（最初の見出し・段落・表・リスト・コードブロックより前）の `<!-- page: scheme=dark theme=theme-slate toc=fixed -->` で書く。フロントマターは、読むほかのツールと干渉するため使わない（#161 のユーザーのコメント）。

決定（単一ユースケース設計）: page のマーカーに書けるのは、配色の明暗 `scheme`（`light`・`dark`・`auto`。`auto` は設定の明暗だけを外し、描く先の祖先の class → OS の設定の順で決める）・テーマ `theme`（`colorTheme` と同じ名前）・右側の目次の出し方 `toc`（`hover`・`fixed`）。右側の目次と先頭へ戻るボタンのオン・オフは、今ある `<!-- features: -side-toc -back-to-top -->` を同じ文書の先頭に書く（同じことを 2 つのマーカーで決められるようにしない）。設定ファイルには明暗のキーを追加し、テーマと目次の出し方は今の `colorTheme`・`side-toc.mode` を使う。

決定（単一ユースケース設計）: 知らないキー・値と、文書の先頭に無い page のマーカーは書き方の警告にして使わず、残りのキーと設定の値で描く。設定ファイルの知らない明暗の値は `mdmark check` のずれにする。

決定（単一ユースケース設計）: VS Code のプレビューの明暗は、文書のマーカー → `mdmark.preview.theme`（`auto` 以外のとき）→ 設定ファイルの明暗 → VS Code のテーマの順に決める。今の `mdmark.colorTheme` が設定ファイルの `colorTheme` より優先しており、明暗も同じ順に揃えるため。

決定（単一ユースケース設計）: cards の範囲のリストの項目は、最初のリンクがカードのリンクとタイトル、その前の `icon:名前` がアイコン、残りの文字が説明になる。リンクを持たない項目は、リンクではないカードにする。範囲の中身がリスト 1 つでないときは書き方の警告にして、中身を書いたとおりに描く。

決定（インターフェース定義設計）: cards のマーカーは新しい features のキー `card-grid`（既定はオン）でオン・オフする。既存の `features.cards` は #263 でリンクと添付のカードのキーとして入っており、名前を変えると使う側の設定を書き換える移行が要り、共用するとリンクのカードだけを止められなくなるため。設定ファイルの明暗のキーは `colorScheme`（`light`・`dark`・`auto`）にし、`colorTheme` と並べる。
