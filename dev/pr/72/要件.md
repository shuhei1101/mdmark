# 要件

## 要望

Claude Code で文書を書く人が、mdmark のリポジトリをプラグインのマーケットプレイスとして足してプラグインを入れると、mdmark の記法・部品・図の描き方・拡張の仕方を必要な分だけ読み、書き出し・まとめ・点検・索引の操作を Claude Code から呼べるようにする。

| 機能 | 振る舞い |
| --- | --- |
| プラグインを配る | リポジトリの直下に Claude Code のマーケットプレイスの定義を置き、`/plugin marketplace add shuhei1101/mdmark` で足して `plugin/` のプラグインを入れられるようにする |
| 使い方集の索引を入れる | プラグインの SessionStart のフックが、使い方集の索引（名前・読むとき・概要）だけを `additionalContext` で渡す。索引は 10,000 文字以内に収め、超えるときはビルドで止める |
| 使い方集を読む | MCP のツール `read_guide`（引数 `names: string[]`）が、索引の名前ごとに本文を返す。知らない名前は、その名前と近い名前を添えたエラーにする |
| 文書を書き出す | MCP のツール `export_html` が `mdmark export` と同じ処理で 1 文書を 1 枚の HTML に書き出し、書き出したパスを返す |
| 文書をまとめる | MCP のツール `build_site` が `mdmark build` と同じ処理で 1 枚の HTML にまとめ、書き出したパス・入れた文書の数・警告を返す |
| 点検する | MCP のツール `check` が `mdmark check` と同じ処理で点検し、ずれの一覧（ファイル・場所・種類・内容）を返す。点検は書き換えない |
| 文書を探す | MCP のツール `find_docs` が、設定の `index` の索引から、題名・別名・概要の部分一致・タグ（全てを持つ）・関係する文書（被参照を含む）で文書を引き、ID・パス・題名・概要・タグを返す |
| 索引を書き換える | MCP のツール `update_index` が、文書か用語の ID の項目を置き換え（無ければ足し、`null` で消す）、書く前に索引の Schema で検査し、合わなければ書かずにエラーを返す |
| 使い方集に入れるもの | 記法・部品・図の描き方・拡張の仕方。拡張は TypeScript を推奨し、配る前に JavaScript へ変換すること、拡張を書くときに linter を使うこと、Biome を推奨することを含める |

ツールの名前と引数は Issue の本文の一案（A-6）を元にし、インターフェース定義『ClaudeCodeプラグイン』で確定させた（`update_index` は、文書と用語の ID がそれぞれの一覧の中でだけ一意のため、引数 `kind` で `doc` / `term` を選ぶ）。
`export_html`・`build_site`・`check` は CLI と同じ処理を呼び、CLI と結果が食い違わない。

MCP サーバーは、CLI と同じ処理を束ねた JavaScript を `plugin/` に置き、プラグインの `.mcp.json` が `node ${CLAUDE_PLUGIN_ROOT}/...` で起動する。
束ねない実行時の依存は `plugin/package.json` と `plugin/package-lock.json` に版を固定して書き、プラグインを入れたときに Claude Code が入れる（PoC 検証の結果。[Claude Code プラグイン](./ClaudeCodeプラグイン.md) の `## PoC 結果`）。

使い方集は `guide/index.yaml` に索引（名前・読むとき・概要・本文のページ）だけを置き、本文は `docs/` の使い方・リファレンスのページを指す（ER 図『使い方集』）。

MCP のツールは引数 `config` を任意にし、省いたときは MCP サーバーの作業フォルダ（Claude Code のセッションのフォルダ）から CLI と同じく上へ設定ファイルを探す。
