# 要件

## 要望

knowledge の規約『MCP サーバー作成ルール』の `## SDK とトランスポート`・`## 構成`・`## 登録`（[shuhei1101/knowledge#50](https://github.com/shuhei1101/knowledge/issues/50) で入った）に、mdmark の MCP サーバーを合わせる。

### 待ち受け

- MCP サーバーを HTTP（Streamable HTTP）の常駐サーバーにし、stdio の待ち受けをやめる
- 1 つのプロセスを並行するセッションが共有する。ツールの処理はプロセスの中にセッションごとの状態を持たない
- 待ち受けるアドレスは `127.0.0.1`、パスは `/mcp` にする
- 既定のポートは 8782 にし、サーバーは起動時に環境変数 `MDMARK_PORT` を読み、あればそのポートで待ち受ける
- ポートを使えない（ほかのプロセスが使っている・`MDMARK_PORT` が数値でない）ときは、待ち受けずに理由と直し方を出して 0 以外で終わる

### プラグインの接続先

- `plugin/.mcp.json` は `"type": "http"` と `"url": "http://127.0.0.1:${MDMARK_PORT:-8782}/mcp"` で書き、`command`・`args` を持たない
- 利用者はポートがぶつかるときだけ、`~/.claude/settings.json` の `env` と、サーバーを起動する環境の両方に同じ `MDMARK_PORT` を書く

### 作業のフォルダ

- 常駐サーバーには、セッションの作業フォルダ（今の `CLAUDE_PROJECT_DIR`）が環境変数で渡らない
- 作業のフォルダを使うツール（`export_html`・`build_site`・`check`・`find_docs`・`list_tags`・`update_index`）は、作業のフォルダの絶対パスを引数で受ける
- 作業のフォルダの引数は、プラグインの PreToolUse のフックが mdmark のツールの呼び出しに入れる。エージェントには記載させない
- 使い方集（`read_guide`）と配布物は、作業のフォルダによらず、サーバーを起動したときのルートから読む

### 起動・停止・ポートの確認

- 常駐サーバーを起動する・止める・待ち受けているポートを確かめる手順を、公開ドキュメントの使い方のページに書く
- サーバーが起動していないときに Claude Code が MCP サーバーにつながらないことと、起動してから `/mcp` で接続し直す手順も同じページに書く

`未確定`: 常駐サーバーを起動する入口（決める段: 単一ユースケース設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | CLI に `mdmark serve` のコマンドを加え、`npx github:shuhei1101/mdmark#v{バージョン} serve` で起動する | 既存の `init`・`check` と同じ入口で、使うバージョンをタグで指せる。止める・ポートを確かめる手順も CLI の案内に載せられる | 初回の起動で依存を取るので待つ（PoC #73 では空の npm のキャッシュから 53 秒） |
| B | プラグインのキャッシュの `server/mcp.js` を `node` で起動する | 依存を取らずにすぐ起動する | キャッシュの場所がプラグインのバージョンごとに変わり、利用者が起動するパスを毎回探す |

推奨: A

常駐サーバーは端末で 1 回起動したら使い続けるので、初回の待ちより、起動のコマンドがバージョンをまたいで変わらない方が利用者の手間が少ない。

### 移行の案内

- 入れたプラグインが、常駐サーバーを起動しないと MCP のツールを使えなくなる。変更履歴と、プラグインを入れる使い方のページに、移行の手順（常駐サーバーを起動してからセッションを開き直す）を書く
