# 要件

## 要望

設定の `aliases` に並べるエイリアスの元の行を、alias-inject [v0.3.0](https://github.com/shuhei1101/alias-inject/tree/v0.3.0) の `schemas/aliases.schema.yaml` の構造で検証して取り込む。
v0.2.0 の構造の行は使用せず、`mdmark upgrade` の移行の手順で v0.3.0 の構造へ書き換える。

| 項目 | v0.2.0（今） | v0.3.0（変更後） |
| --- | --- | --- |
| 引用の種類 | `metadata.alias_type`（`{type: custom, value}` か `{type: ref, field}`）。`ref` ならレコードごとに種類を変更できる | 行の属性 `alias_type`（9 つの値の enum、行で必須）。行の全レコードが同じ種類 |
| `metadata` の値 | `{type: ref, field: 列名}` か `{type: custom, value: 値}` | 値を取る列の名前の文字列。入れ子の列は `meta.summary` のように `.` でつなぐ |
| `metadata` の要否 | 必須 | 任意 |
| 本文のファイルの列 | なし | `body_file`（`records` の要素の本文のファイルのパスの列。`name` が空の要素の名前に、その列の値のファイル名から拡張子を除いたものを使う） |

- 取り込む Schema を `schemas/alias-inject/v0.3.0/aliases.schema.json` に差し替え、`schemas/mdmark.config.schema.json` の `aliases` の `$ref` を v0.3.0 へ向ける
- `mdmark check` の `schema` のずれ（`src/cli/alias-schema.ts`）を v0.3.0 の Schema のエラーの場所・文言で出力する（判別子つきの枝がなくなる）
- `buildAliases` が行の `alias_type` と、列名の文字列の `metadata`（`.` でつないだ入れ子の列を含む）・`body_file` でエイリアスを作る
- 作ったエイリアス（`MdmarkAlias`）の形と、`mount`・`render`・`collectMatches` の `aliases` は変更しない
- 点検のずれの種類（`alias_records_missing`・`alias_field_missing`・`alias_unknown_type`・`alias_required_empty`・`duplicate_alias_row_id`・`duplicate_alias_id`）を、v0.3.0 の構造で起きうるものに見直す
- `migrations/next/` に、設定の `aliases` の行を v0.2.0 の構造から v0.3.0 の構造へ書き換える移行の手順を配置する

確定: レコードの列から種類を取っていた行（`alias_type: {type: ref, field: 列}`）の移行（[確認ログ](./確認ログ.md)で推奨の案に決まった）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 行を書き換えず、手で行を分けるよう `mdmark upgrade` の出力で通知する | 推測で書き換えない | 使う側が手で行を分ける |
| B | 移行の手順が行の `paths` のファイルを参照し、レコードの種類が 1 つだけならその値を行の `alias_type` にする。2 つ以上なら A と同じく通知する | 種類が 1 つの行は手を入れずに移行できる | 移行の手順が設定の外のファイルを参照する |

推奨: B

v0.3.0 は行の中でレコードを種類で絞る手段を持たず、種類が 2 つ以上の行は機械的に分けられない。
種類が 1 つの行は値が 1 つに決まるため、書き換えても意味が変わらない。

確定: `alias_type` 以外のキーの `{type: custom, value}`（行の全レコードに同じ値）の移行（[確認ログ](./確認ログ.md)で推奨の案に決まった）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | そのキーを `metadata` から除外する壊す手順（`destructive: true`）にし、除外したキーと値を出力に並べる | 移行の後に設定が v0.3.0 の Schema に合う | 定数の値が失われる |
| B | 書き換えずに通知し、使う側に YAML の列へ値を移してもらう | 値を失わない | 移行の後も設定が Schema に合わない |

推奨: A

v0.3.0 には行の全レコードに同じ値を記載する手段がない。
`mdmark upgrade` は移行の後の点検に合格してから設定のバージョンを書き換えるため、Schema に合わない行が残るとバージョンを上げられない。
壊す手順は `--yes` がないとき適用の前に確認を求めるため、使う側が値の消失に気づける。
