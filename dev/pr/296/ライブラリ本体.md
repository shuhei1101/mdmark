## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 束ねる単位 | 書き出しのとき、CLI が起動の処理のソースを入口にし、ビューの部品・色分けの本体と言語を静的な `import` で、拡張と外部ライブラリのモジュールをリテラルの動的 `import()` を返す関数で取り込む入口のモジュールを作り、esbuild で 1 つのスクリプトに束ねる（分割しない） | 束ねた後のスクリプトに `import(` は残らない。拡張の `load` の中の相対パスの動的 `import()` も、束ねるときに同じスクリプトの中へ取り込む |
| HTML の組み立て | 束ねた 1 つのスクリプトを `<script>` に入れて直接動かす。モジュールのコードを JSON の文字列で持つ項目（`modules`・`extensions`・`parts`・`syntax`）を書き出しの中身から除く | `dist/viewer.js` を埋める今の作りは、束ねたスクリプトに替わる |
| 起動の処理 | 束ねたスクリプトが持つ読み込み済みのモジュールを、外部ライブラリ・部品・色分けの読み込みへ指定し、拡張を 1 つずつ `try` で囲んで評価し `registerExtension` で登録する（例外を投げた拡張・外部ライブラリは飛ばして続ける）。`URL.createObjectURL` と URL を読む動的 `import()` を使わない | 埋めなかった外部ライブラリ・部品は、読むと失敗する読み込み済みの値にして知らせの枠にする（`data:` URL を使わない） |
| 部品・色分け・外部ライブラリの読み込み | URL の代わりに読み込み済みのモジュールを返す読み込みを指定できる経路を、`part-modules`・`highlight`・`libraries` に追加する | 指定が無いときは今の URL の動的 `import()` のまま |
| 外部への要求 | 開いてから描き終えるまでの要求を、ページ自身・`_files/` の下の動画と音声・画像の `data:` に限る | 非機能要件の決定値を修正 |
| 確かめ方 | 結合テスト・E2E で、`blob:` と `data:` のスクリプトを許さない CSP を当てた書き出しの HTML を開き、拡張・ビュー・色分け・外部ライブラリが描かれ CSP の違反が 0 件であることを確かめる | OneDrive の実機は確かめない（要件のスコープ外） |
| 既存機能への影響 | 配布物を CDN から読むページの `mount`（URL の動的 `import()`）と、VS Code 拡張機能の書き出しは変えない | - |
