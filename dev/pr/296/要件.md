# 要件

## 要望

`mdmark export`・`mdmark build` で書き出す HTML で、埋めた拡張・部品（ビュー）・色分け・外部ライブラリを起動の処理と一緒に 1 つのスクリプトに束ね、`<script>` で直接動かす。
`blob:` URL と動的 `import()` を使わない。

- 書き出した HTML の中に、`URL.createObjectURL`・`blob:` の URL・動的 `import()` の呼び出しが無い
- 書き出した HTML を、`blob:` と `data:` のスクリプトを許さない CSP（`script-src 'unsafe-inline'`）を当てて開いても、拡張の印・ビュー・コードブロックの色分け・外部ライブラリの印が、CSP を当てないときと同じに描かれ、CSP の違反が 0 件
- 書き出した HTML を開いてから描き終えるまでと文書を移った後に、ページ自身・`_files/` の下にコピーした動画と音声と画像の `data:` のほかへ要求しない（CDN を読まない今の決まりを保つ）
- 埋めなかった外部ライブラリ・部品の印は、今と同じく知らせの枠にし、ページの隣のファイルや CDN へ要求しない
- 読めない・登録できない拡張は、今と同じく飛ばしてほかの拡張と描画を続ける
- 部品・色分け・外部ライブラリの読み込みに、URL でなく読み込み済みのモジュールを指定する経路を加える。
  配布物を CDN から読むページの `mount` の読み込み（URL の動的 `import()`）は今のまま変えない

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| OneDrive の実機で書き出した HTML を開いて確かめること | OneDrive がどの制約（CSP・ファイルの扱い）で `blob:` を止めているかを手元で再現できないため、`blob:` と `data:` のスクリプトを許さない CSP を当てたブラウザで代わりに確かめる | 予定なし |
| VS Code 拡張機能の HTML への書き出し（`mdmark.exportHtml`） | jsDelivr の配布物を読む HTML で、CLI の書き出しと別の処理のため | 予定なし |
| mermaid のコードブロック | 後続の Issue が扱う | #190 |
