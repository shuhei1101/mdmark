## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 脚注の読み取り | 自前の block・inline・core のルールで、`[^ラベル]` と `[^ラベル]: 中身`、行内の `^[中身]` を読み、出てきた順に 1 からの番号を振る。ラベルは大文字小文字を区別せずに照合し、同じラベルの定義が複数あるときは最初の定義を採る。同じ脚注を複数回参照したときは同じ番号にする。定義の無い参照は書いた文字のまま出す | ライブラリ選定で決定（`要件.md` の `## 要望`） |
| 本文の番号 | 参照の場所に、印の色で角括弧付きの上付きの番号（`[1]`）を出し、ポインター・フォーカスでツールチップに脚注の中身を出す。キーボードで番号に移ってツールチップを開け、Esc で閉じる | 用語のツールチップと同じ操作。見た目は用語の下線と分ける |
| 番号の押下 | 番号を末尾の項目へのリンクにし、押す（Enter を含む）と閉じた一覧を開いて該当の項目を画面に入れ、フォーカスを項目へ移す | GFM の脚注と同じ移り方 |
| 用語の下線 | 番号のツールチップの中と末尾の一覧の中の脚注の中身には、用語の下線とやめた言い方のマーカーを付けない | ツールチップの中で別のツールチップが開く操作を避ける。一覧は本文の一部のため、用語の照合から除外する処理が要る |
| 末尾の一覧 | 本文の直後・関連文書の一覧の前に、見出し `脚注（{件数} 件）` の閉じた一覧を置く。一覧の各項目から本文の参照の場所へ戻れる | モックへの合意で決定（[確認ログ](./確認ログ.md)） |
| 印刷 | 印刷の前に末尾の一覧を開き、印刷の後に閉じ直す | 今の印刷の前後の折り畳みに揃える |
| 機能のオン・オフ | `features` に `footnotes`（既定 `true`）を追加する。オフのときは脚注のトークンを書いた文字に戻す（`## PoC 結果` の案 C） | インターフェース定義設計で決定 |
| 書き出し | 書き出した 1 枚の HTML・まとめた HTML でも同じに動く。まとめた HTML では、文書の中の `#` のリンクの書き換えの後も、戻るリンクと番号のリンクが開いている文書の中で移る | - |
| 既存機能への影響 | 脚注を記載していない文書の HTML は変えない | - |
| アクセシビリティ | 本文の番号とツールチップを、中身がリンクを持たないときは `role="tooltip"` と `aria-describedby`、持つときは `role="group"`・`aria-label` と `aria-details` で結ぶ | 用語のツールチップと同じ分け方 |

| 機能のオフ 案 B: 呼び出しごとに `parser.disable` / `enable` で脚注のルールを切り替える | 同上 | ❌ 定義の行がリンク参照の定義になる | [#312](https://github.com/shuhei1101/mdmark/pull/312)（closed） | 不採用。戻し忘れは次の呼び出しへ持ち越すため `finally` も要る |
| 機能のオフ 案 C: 解析器は 1 つのまま、`inline` の後・`footnote_tail` の前のコアルールで文書のマーカーから機能を決め、オフなら脚注のトークンを書いた文字に戻す | 同上。加えて、オンとオフを交互に流しても持ち越さず、コードブロックの中のマーカーを数えない | ✅ 4/4 | [#312](https://github.com/shuhei1101/mdmark/pull/312)（closed） | 採用 |

結論: 成立。
markdown-it-footnote を採り（`要件.md` の `## 要望` の推奨 A）、機能のオフは案 C で実現できる。

- オフのとき、プラグインを外した解析（案 A・B）では、`[^src]: 出典の説明` が markdown-it のリンク参照の定義として読まれ、本文の `[^src]` が `出典の説明` へのリンクになる。プラグインを通したうえで文字に戻す必要がある
- 案 C は、文書のマーカーを `html_block` のトークンから読むため、コードブロックの中のマーカーを数えない。今の `mdmark_take_marks`・`mdmark_resolve_features` は `footnote_tail` より後に動くため、脚注の機能だけは先に決める（インターフェース定義・モジュール構成で、機能の決め方を 2 か所に分けない置き方を決める）
- オフのとき、定義は書いた位置に段落として残る。定義の 2 段落目は字下げを外した段落になる
- 組み替えた番号のツールチップの中に、定義の段落の `<p>` が入る（`sup` の中のブロック要素）。部品設計で、ツールチップの中身を段落を持てる要素に置くか、段落を外すかを決める
- 行内の `^[…]` の参照は `meta.subId` を持たないため、`subId` の既定を 0 にする
