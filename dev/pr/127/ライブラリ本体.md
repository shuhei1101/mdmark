## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 索引の Schema | `docs[].related` の要素を、`to`・`type`・`when` を必須、`paths` を任意に持つオブジェクトにし、`type` を 5 つの値の列挙にする | 件数の上限と文字列の要素を残すかは要件の `未確定` |
| 移行の手順 | 文字列の要素を残すなら `migrations/no-steps.yaml` に `version: next`・`schema: mdmark.index.schema.json` の行を、残さないなら `migrations/next/` に移行の手順を置く | 要件の `未確定` の決着に従う |
| 索引の型と検査 | `MdmarkIndexDoc.related` に関連のオブジェクトの型を加え、`INDEX_SHAPE` の検査を要素のキーごとに当てる | 読む側が文字列とオブジェクトを同じ形で受け取れる読み取りの関数を置くかはモジュール構成設計で決める |
| 参照の表と関連文書の一覧 | `collectReferences` と参照の表を渡さないときの関連文書の一覧は、要素の `to` を相手として数える | 描いた結果は今と変わらない |
| findDocs | `relatedTo` で引いた各文書に、関係の種類・向き・`when` を添える | 逆向きの関係の名前はインターフェース定義設計で決める |
| 関連のずれの点検 | 片側だけの `change_together`・本文のリンクと重なる関連（・文字列の要素を残すならオブジェクトへの書き換え）を、ずれの種類として加える | ずれの種類の名前はインターフェース定義設計で決める |
| 直し忘れの検査 | `checkIndex` と `mdmark check` に任意の比べる基準を加え、基準から片方の文書だけが変わった `change_together` の組を知らせる | 要件の `未確定` を A で決めた場合 |
