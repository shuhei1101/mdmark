# 要件

## 要望

[#186](https://github.com/shuhei1101/mdmark/issues/186) の本文と、[追記のコメント](https://github.com/shuhei1101/mdmark/issues/186#issuecomment-6598893018) の要望。

<!-- table: data -->

| 要望 | 終わりの条件 |
| --- | --- |
| 使い方集を dev-docs の配信元から参照する | mdmark のクローン（develop の worktree）を登録した dev-docs の配信元 `mdmark` の `docs` の行から、タグ `topic:使い方集` で絞った `search_docs` で使い方集のページ（`guide/index.yaml` の各行の `page`）を検索・参照できる。プラグインは使い方集をコピーせず、dev-docs の端末の設定を書き換えない |
| MCP の `read_guide` を削除する | mdmark の MCP のツールが `export_html`・`build_site`・`check` の 3 つになる。`read_guide` を呼ぶ処理・設計書・文書・テストが残らない（破壊的変更） |
| dev-docs が無いときに知らせる | dev-docs が入っていない、または mdmark の配信元が登録されていない環境では、mdmark の MCP の instructions から「dev-docs が無いので見つかりません」と分かる |
| 動線を 2 工程にする | 書く前に該当の使い方集のページを dev-docs の `search_docs` で参照し、書いた後に点検する（mdmark の `check` と、図は使い方集の `diagram-check` の手順） |
| 注入文を置き場所で書き分ける | knowledge の規約『注入文の書き分けと書き方』（`claude-context-placement`）に従い、固定の使い方（使う場面・使わない場面・ツールの順序）は mdmark の MCP の instructions か、使い方集の配信元の説明書（配信元の設定の `instructions`）に記載する。SessionStart のフックは削除する |

<!-- /table -->

`確定`: 使い方集は mdmark のクローン（develop の worktree）を登録した配信元 `mdmark` から参照し、プラグインはコピーも登録もしない（[確認ログ](./確認ログ.md)）

`確定`: SessionStart のフックを削除し、dev-docs が無いときの扱いは instructions に事実として記載する（[確認ログ](./確認ログ.md)）
