## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 色分けする言語の判定 | 情報文字列の最初の語を言語とし、色分けに対応する言語（別名を含む）なら色分けの対象にする。対象外の言語と言語の無いコードブロックは今の HTML のまま | 少なくとも `yaml`・`typescript`（`ts`）・`python` を対象にする。対象の一覧は単一ユースケース設計で決める |
| 当てないコードブロック | ファイルツリー・図の部品の定義・埋め込んだ HTML として描くコードブロックは色分けの対象にしない | 記法を描くコアルールが先に取るコードブロックには印を付けない |
| 色分けの読み込み | 色分けの対象のコードブロックがある文書でだけ、色分けのライブラリと使う言語の文法を版を固定した URL から読み、描いた後に色を付ける | `未確定`（要件.md の読み込みの方式。決める段: PoC 検証） |
| 行の分け方との両立 | 色分けは行ごとの `mdmark-code-text` の中だけを書き換え、行番号・行の種類・行頭の `+`・`-` には触れない。行をまたぐトークン（複数行のコメント・文字列）も行ごとに閉じた要素に分ける | PoC 検証で確かめる |
| 読み込めないとき | 色分けのライブラリか文法を読めないときは、コードを色分けなしのまま残し、ブラウザのコンソールに読めなかった旨を出す。知らせの枠は出さない | コードは欠けずに読めるため、本文を枠で置き換えない |
| 書き出した HTML | CLI が文書の色分けの対象の言語を引き、色分けのライブラリとその言語の文法だけを書き出した HTML に埋める | 外へ要求しない（非機能要件『書き出した HTML の外部への要求』） |
| `render` | `未確定`（要件.md。推奨は色分けせず、`mount` が描いた後に色分けする） | 決める段: インターフェース定義設計 |
| 色 | 色分けの色を種類（キーワード・文字列・コメント・数値・型など）ごとの CSS 変数で持ち、ライトとダークを持つ | 種類の分け方と配色はモック作成で決める |
| 機能のオン・オフ | 機能を 1 つ足し、既定はオン。オフの文書では色分けのライブラリを読まない | 機能名は単一ユースケース設計で決める（行の強調の `highlight=` と取り違えない名前にする）。設定の Schema にキーを足し、移行の手順が要らない行を置く |
| 配布物の大きさ | `dist/index.js` に色分けのライブラリを束ねず、上限 384KB に収める | 足した後の実測を非機能要件の根拠に書く |
| 印刷 | 印刷でも色分けを出す | |
| アクセシビリティ | 色分けは見た目だけを変え、読み上げる文字と写す中身は変えない。色の対比は地の色に対して WCAG の AA（4.5:1）を満たす | |
| 外部ライブラリ | 選んだ色分けのライブラリの版を固定し、ライセンスを確かめて外部ライブラリの設計書を作る | 設計の中のライブラリ選定で決める |
| 既存機能への影響 | 色分けの対象でないコードブロックの HTML は変えない | |

<!-- /table -->
