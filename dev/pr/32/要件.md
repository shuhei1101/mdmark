# 要件

## 要望

文書を書く人が、サーバーを持たずに CLI で Markdown を HTML に書き出せ、複数の文書を参照・被参照・用語のツールチップが効く 1 枚の HTML にまとめられる。
書き出した HTML は CDN を含む外部を読まず、文書が使う外部ライブラリも含めて 1 枚で完結し、file:// で開ける。

<!-- table: data -->

| 項目 | 要件 |
| --- | --- |
| コマンド | `mdmark init`（雛形を置く）・`mdmark export`（1 文書を書き出す）・`mdmark build`（複数の文書を 1 枚にまとめる）・`mdmark check`（点検する）の 4 つを持つ。Node 24 以降（`package.json` の `engines`）で動く |
| 雛形を置く | 指定したフォルダ（既定は今のフォルダ）に、設定ファイル `mdmark.config.yaml`・使う側の CSS `theme.css`・索引の雛形・拡張のビルドの雛形（tsconfig とビルドのコマンド。既定は TypeScript、指定で JavaScript）を置く。既にあるファイルは上書きせず、置かなかったファイルの一覧を出す。雛形の正本はリポジトリの `templates/` に置く |
| 1 文書を書き出す | Markdown のパスを受け、設定の `features`・`libraries`・索引を当てて `render` と同じ本文を描き、記法の操作・用語のツールチップ・被参照が `mount` と同じに効く 1 枚の HTML を書く |
| 複数の文書を 1 枚にまとめる | 設定の `build` で対象を決める。`include`（対象の Markdown の glob）・`exclude`（外す glob）・`glossary`（用語集の表を持つ文書）・`entry`（最初に開く文書。既定は `include` で最初に当たった文書）・`out`（書き出す HTML のパス）。索引があれば `collectReferences` で作った参照の表を当て、文書をまたぐ被参照と用語のツールチップを効かせる |
| まとめた HTML の文書の行き来 | 開くと `entry` の文書を出す。文書の一覧から別の文書へ移れ、文書間のリンクは 1 枚の中の文書へ移る。移った文書をブラウザの戻る・進むで行き来でき、見出しのアンカーと目次のリンクは移った先の文書の中で効く |
| 1 枚で完結 | 書き出した HTML は、開いてから外部への要求を 0 件にする。配布物の JavaScript と CSS・`theme.css`・文書が使う外部ライブラリのモジュール・文書が相対パスで指す画像を埋める。読めない画像とモジュールは書き出しを止めず、警告に出す。`mdmark build` は、1 枚に含まれない文書へのリンク（書いたままの `href` で残す）も警告に出す。`mdmark export` は文書間のリンクが全て 1 枚に含まれないため、警告に出さない |
| 外部ライブラリの埋め方 | 書き出しの時に設定の `libraries` の URL（相対パスのローカルのファイルを含む）を読み、モジュールが import する先も含めて URL ごとに 1 つの ES モジュールに束ねて HTML に埋める。開いたときは埋めたモジュールを `blob:` URL に替えて対応表に渡し、`mount` の動的 `import()` で読む。書き出す環境は URL の先へ届く必要があり、届かないモジュールは警告に出す |
| 点検する | 設定ファイルの Schema、索引の Schema と索引と文書のずれ（`checkIndex`）、`build` の対象が 0 件でないことを確かめ、ファイル・場所・種類・内容の一覧で出す。ずれがあれば終了コードを 0 以外にする |
| 設定 | `build` のキーを設定の設計書と `schemas/mdmark.config.schema.json` に足す。`init` が置く `theme.css` を書き出しに埋めるため、使う側の CSS のパスを設定の `theme` で、埋める拡張のモジュールを `extensions` で指せるようにする |
| 誤りの扱い | 設定ファイルが無い・読めない・Schema に合わないとき、対象の文書が 0 件のとき、出力先へ書けないときは、原因と直し方の 1 文を出して終了コードを 0 以外にする |
| スクリプト | 文書に書いたスクリプトを実行しない今の条件（`render` のサニタイズ）を、書き出した HTML にも当てる |
| 完了の基準 | 索引・用語集の表・文書間のリンク・外部ライブラリの印・画像を持つ見本の文書群で、`init` → `check` → `build` と `export` を流し、書き出した HTML を file:// で開くと、外部への要求 0 件で描画・記法の操作・用語のツールチップ・被参照・文書の行き来が効き、非機能要件の対応ブラウザの E2E が通る |

<!-- /table -->

CLI の配り方と `registerExtension` で登録した拡張の扱いは、インターフェース定義設計で案 A に決めた。
CLI は `package.json` の `bin` に `mdmark` を足し、GitHub の版のタグから `npx github:shuhei1101/mdmark#v{版} {コマンド}` で呼ぶ。npm のレジストリには公開しない。
拡張は設定の `extensions` に拡張のモジュールのパスを書き、書き出しが束ねて HTML に埋め、描く前に `registerExtension` で登録する。
