## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 設定のキー | `mdmark.config.yaml` に `aliases`（エイリアスの元の行の配列）を追加する | 持たない設定は今のまま通る |
| スキーマの取り込み | alias-inject のタグ `v0.2.0` の `schemas/aliases.schema.yaml` をリポジトリへ取り込み、取り込んだタグを記録する。`mdmark.config.schema.json` の `aliases` はそれを指す | タグを上げるときは取り込み直して記録を書き換える |
| 元の YAML の読み取り | CLI が `paths` の glob を設定ファイルのあるフォルダから引き、YAML を `yaml` で読み、`records` があればその配列の要素ごと、無ければファイルごとに 1 件にする | glob の引き方は `build.include` と同じ |
| `metadata` の当て方 | キーごとに `ref` は列の値、`custom` は行の値を取り、書かないキーは同じ名前の列を取る。`name` が空ならファイル名（拡張子を除く）、`records` の行は `id` を使う。`alias_type` が `env` のエイリアスは配列に入れない | A-36 の決まり |
| エイリアスの種類の確かめ | `alias_type` の値が 9 つの種類に無いエイリアスと、種類の必須のキーが空のエイリアスは描くときに使わず、`mdmark check` のずれにする | 描くときは知らせを出さない |
| 照合の辞書 | `buildDictionary` に読み込んだエイリアスを受け、索引の `terms` の後・描く文書の表の前に入れる。`avoid` の種類と `term` の `avoid` は代わりの用語に入れる。`mount` に `env` のエイリアスを直接渡されても辞書に入れない | 機能は `glossary` |
| ツールチップ | `renderTermTip` に種類ごとの区分を加える。`command` はコマンドをコードとして出し、コピーのボタンを置く。`url` の URL はリンクにする | コピーは既存のクリップボードの処理を使う |
| `mount`・`render` | 読み込んだエイリアスを受けるキーを加え、照合の辞書へ渡す | 渡すのは `metadata` を当てた後のエイリアスの配列（要件）。キーの名前はインターフェース定義設計で決める |
| 書き出しとまとめ | `mdmark export`・`build` が作る関数で作ったエイリアス（`env` を含まない）を埋め込みのデータに入れ、起動の処理が `mount` へ渡す | |
| `mdmark check` | `aliases` のスキーマのずれ・元の YAML を読めない・ファイルが無い・`records` の配列が無い・`ref` の列が無い・必須のキーが空・`id` の重なりを返す | Claude Code プラグインの `check` も同じ処理を呼ぶ |
| 移行 | `migrations/no-steps.yaml` に `aliases` の追加の行を置く | 既存の設定を書き換えない |
| 既存機能への影響 | 索引の `terms[]`・`docs[]` と表の用語の照合・ツールチップは今のまま | `aliases` を持たない文書の HTML は変わらない |
| 配布ファイルのサイズ | ツールチップの区分の追加で `dist/index.js` が増える分を測り、非機能要件『配布ファイル 1 つのサイズ』を確かめる | |

結論は成立で、要件の `未確定`「`mdmark check` がスキーマで検証する方法」の案 A（JSON Schema の検証ライブラリを CLI の依存に追加する）が成り立つ。
採用の判断はモジュール構成設計のライブラリ選定で行う。

組んだずれの文（束ねる前と後で同じ）:

- `aliases の 2 行目（id: no-alias-type） の metadata`: `引用の種類（alias_type） がありません。記載してください。`
- `aliases の 3 行目（id: empty-paths） の paths`: `読む YAML が空です。1 件以上記載してください。`
- `aliases の 4 行目（id: unknown-type） の metadata.alias_type.value`: `引用の種類 は term・doc・command・url・skill・tool・path・env・avoid のどれかにしてください。`

最小再現コードの要点（[validate.ts](https://github.com/shuhei1101/mdmark/blob/2ec1dabbb4ba0ce8678d105f8b1a2e6877af1ce2/poc/aliases-schema/validate.ts)）:

- `new Ajv2020({ allErrors: true, strict: true, verbose: true })` に `aliases.schema.yaml` を `yaml` で読んで `addSchema(schema, id)` し、設定のスキーマの `properties.aliases` を `{ $ref: id }` にして `compile` する
- `narrow`: `anyOf` の下のエラーを `schemaPath` から枝の場所（`/properties/{キー}` とキーワードを剥がした場所）でまとめ、`const` のエラーを持つ枝（判別子の `type` が合わない枝）を落とす。枝のエラーが残った `anyOf` 自体も落とす
- `toMessage`: `required`・`minItems`・`minLength`・`enum`・`const`・`type`・`additionalProperties`・`anyOf` の文の型を持ち、`params` とスキーマの `title`（`verbose` で得る `parentSchema`）を埋める

既知の限界: 判別子が `const` でない `anyOf` が取り込むスキーマに増えると、枝を絞れずにずれが複数になる。v0.2.0 の `anyOf` は `metadataValue` と `alias_type` の 2 か所で、どちらも `type` の `const` が判別子。
