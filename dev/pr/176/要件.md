# 要件

## 要望

使う側が `mdmark.config.yaml` の `aliases` に「エイリアスの元の行」を並べ、プロジェクトの任意の YAML の列をエイリアスとして登録できるようにする。
Markdown の用語集の表と索引の `terms[]`・`docs[]` は今のまま残し、全てを同時に使える。
文書の中身を YAML から描くことはしない（D-85。エイリアスの登録だけの例外。D-119）。

<!-- table: data -->

| 項目 | 振る舞い |
| --- | --- |
| 設定の `aliases` | alias-inject v0.2.0 の `schemas/aliases.schema.yaml` の行（`id`・`enabled`・`paths[]`・`records`・`metadata`）を並べる。`paths` は設定ファイルのあるフォルダからの相対で、ファイルと glob を混ぜてよい。`enabled: false` の行は読まない |
| `metadata` の値 | キーごとに `{type: ref, field: 列名}`（文書の列から取る）か `{type: custom, value: 値}`（行の全文書に同じ値）。書かないキーは同じ名前の列の `ref`。`alias_type` は必ず書く |
| `records` | 書いた行はファイルのその配列の各要素を 1 件のエイリアスにし、書かない行は各ファイルを 1 件にする |
| エイリアスの種類 | `alias_type` は `term`・`doc`・`command`・`url`・`skill`・`tool`・`path`・`env`・`avoid`。種類ごとの必須のキーは alias-inject の定義（A-26）のとおり。照合する語は `name` と `aliases` |
| ツールチップ | 本文に出たエイリアスの語に下線を引き、種類ごとに次を出す。`term`: 名前・説明。`doc`: 名前・概要。`command`: 名前・説明・コマンド（コピーできる）・実行場所。`url`: 名前・説明・リンク。`skill`・`tool`・`path`: 名前・説明・スキル名／ツール名／パス。`avoid`: やめた言い方・置き換え先（今の索引の `avoid` と同じ波線の下線）。URL は文字列にリンクを埋め込んで出し、長い URL は 1 行に収めて末尾を「...」で省略する。区分の見出しは種類の順に「用語」「文書」「コマンド」「URL」「スキル」「ツール」「パス」「代わりの用語」。`env` のエイリアスは値にシークレットキーを含みうるため、エイリアスを作る関数で落とし、照合にも書き出しの埋め込みにも使わない（下線もツールチップも出さない） |
| `term` の `avoid` | `term` のエイリアスの `avoid` の言い方は、索引の `terms[].avoid` と同じく代わりの用語として出す |
| 優先の順 | 同じ語が複数の登録元にあるときは、索引の `terms` → 設定の `aliases`（行の並び、行の中は `paths` に当たったファイルとレコードの順） → 描く文書の表 → ほかの文書の表 |
| 機能のオン・オフ | エイリアスのツールチップは `features.glossary` でオン・オフする（文書の `<!-- features: -glossary -->` で外すとエイリアスも出さない） |
| `mount`・`render` | 今の `opts.index` と同じく、読み込んだエイリアスを渡すキーを持つ（dev-docs が渡す）。ブラウザは YAML のファイルを読まない |
| `mdmark export`・`build` | CLI が設定の `aliases` の YAML を読み、書き出す HTML の埋め込みのデータに入れて `mount` へ渡す |
| `mdmark check` | `aliases` を取り込んだスキーマで検証し、元の YAML が読めない・`paths` に当たるファイルが無い・`records` の配列が無い・`ref` の列が無い・`ref` で取った `alias_type` が 9 つの種類に無い・種類の必須のキーが空・行の `id` とエイリアスの `id` の重なりをずれとして返す |
| スキーマの取り込み | alias-inject のタグ `v0.2.0` の `schemas/aliases.schema.yaml` をリポジトリへ取り込み、取り込んだタグを記録する。`mdmark.config.schema.json` の `aliases` はそのスキーマを指す |

<!-- /table -->

`schemas/` を変えるので、`migrations/no-steps.yaml` に移行の手順が要らない行を置く（既存の設定は `aliases` を持たないまま通る）。

`mdmark check` は、JSON Schema の検証ライブラリを CLI の依存に追加し、取り込んだスキーマで検証する（配布物 `dist/index.js` には束ねない。ライブラリはモジュール構成設計のライブラリ選定で決める）。

`mount`・`render` には、`metadata` を当てた後のエイリアス（`alias_type`・`id`・`name`・`aliases`・`description` と種類ごとのキー）の配列を渡す。
元の行と読んだ YAML の中身からこの配列を作る純粋な関数を公開し、CLI と dev-docs が同じ関数を使う。
この関数は `env` のエイリアスを配列に入れない。

`collectMatches` にも同じキーを持たせ、エイリアスの一致を返す。
