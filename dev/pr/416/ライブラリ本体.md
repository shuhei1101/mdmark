## 変更方針

fail した 5 件を release の配布物で、操作ごとの時間切れを 10 秒にした spec の複製で実行し、止まった操作と `document.activeElement` を記録して原因を特定した。

<!-- table: data -->

| 対象 | 原因 | 方針 | 補足 |
| --- | --- | --- | --- |
| 『脚注を見る』`test_normal`・`test_normal_when_referenced_twice` | テスト。ポインターを番号 1 のツールチップの上に置いたまま番号 2 の `hover()` を呼ぶ。番号 1 は文書の先頭にあり上に収まらないため、ツールチップを下に開いて次の段落の番号 2 に重なる。ポインターがツールチップの上に残るため閉じず、`hover()` が重なりの解消を待ち続ける | 番号 2 へ移る前にポインターを番号とツールチップの外へ出し、番号 1 のツールチップが消えるのを待つ | 実装はシナリオの期待値（ツールチップの上へ移っても出たまま・離れたら閉じる）のとおり |
| 『脚注を見る』`test_normal_when_jump_to_list` | テスト。一覧の `summary` を押した後に `blur()` しても、Tab の起点は `summary` のまま変わらない。閉じた一覧の後ろにフォーカスできる要素が無いため、Tab でフォーカスが文書の外へ出る | `blur()` の代わりに 1 つ目の段落の先頭を押して Tab の起点を番号 1 の前にしてから Tab を押す | - |
| 『文書の先頭へ戻る』`test_normal_when_pressed_by_keyboard` | テスト。`blur()` の後の最初の Tab で先頭のセクションの開閉のボタンへフォーカスが移り、画面が先頭へスクロールしてボタンが `hidden` になる。`getByRole` は隠れた要素を検索しないため、`tabTo` の `evaluate` が要素を待ち続ける | `tabTo` はボタンの要素を Tab を押す前に一度だけ取得し、フォーカスとの一致をその要素で確認する | Tab を押し進めると末尾の近くでボタンが出直し、Tab で届く |
| 『複数の文書を1枚のHTMLにまとめる』`test_normal_when_footnotes` | 実装。まとめた HTML は同じ文書の中のアンカーの `href` を `#/{文書のパス}#{id}` に書き換える。`attachFootnotes` は `#` の後ろ全体を `id` として検索するため移る先が見つからず、既定の動作を止めずに文書の切り替えに任せる | `attachFootnotes` は `href` の最後の `#` の後ろを `id` として検索する | モジュール構成『操作』の `attachFootnotes` の説明と単体テストの行を修正した |
| E2E の待ち | - | 3 つの spec に操作ごとの時間切れ（`actionTimeout`）を指定し、届かないときは 300 秒を待たずに fail させる | - |
| 回帰の確認 | - | 脚注と先頭へ戻るボタンの単体テスト・結合テストと、3 つの spec の全件を Chromium と Firefox で実行する | - |
