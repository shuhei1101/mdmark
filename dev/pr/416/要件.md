# 要件

## 要望

Sprint v0.10.0 の E2E で fail した次の 5 件を、原因を特定し、実装かテストの誤っている側を修正して pass させる。

| シナリオ | テスト | fail の内容 |
| --- | --- | --- |
| 『脚注を見る』 | `test_normal` | 番号の `hover()` から先へ進まず 300 秒の時間切れ |
| 『脚注を見る』 | `test_normal_when_referenced_twice` | 番号の `hover()` から先へ進まず 300 秒の時間切れ |
| 『脚注を見る』 | `test_normal_when_jump_to_list` | 一覧を閉じた後に Tab と Enter で番号 1 から一覧へ移る操作で、期待したフォーカスが無い |
| 『複数の文書を1枚のHTMLにまとめる』 | `test_normal_when_footnotes` | まとめた HTML で、一覧の戻るリンクを押した後に本文の番号のリンクへフォーカスが無い |
| 『文書の先頭へ戻る』 | `test_normal_when_pressed_by_keyboard` | Enter で先頭へ戻った後、Tab でボタンへ届かず 300 秒の時間切れ |

- 期待値は、シナリオ『脚注を見る』『文書の先頭へ戻る』『複数の文書を1枚のHTMLにまとめる』の `expected` のとおりにする。シナリオの期待値は変えない
- 原因が実装にあるときは、`src/interact/footnotes.ts`・`src/interact/back-to-top.ts` などの操作を修正し、修正した動きを単体テストで確認する
- 原因がテストにあるときは、E2E の操作（`hover()` の当て方・Tab で届くまでの繰り返し）を修正する。修正したテストには操作ごとの時間切れを指定し、届かないときは 300 秒を待たずに fail させる
- 5 件と、同じ spec の残りのケースが、全件の実行で pass する
- 原因が入力の種類（ポインターとキー）による差だった場合は、計画の行のタグを `kind:部品の操作の不具合の修正` に差し替えるよう task-planner へ伝える
