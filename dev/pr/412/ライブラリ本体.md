## 変更方針

切り分けの結果、8 件はどれも E2E を書いた PR で一度も実行されていなかったテストで、Chromium の fail は全てテストの期待か準備が設計書と食い違っていた。
実装の修正は、Firefox で見つかったノードのリンクの上のドラッグの 1 件だけ。
`git bisect` で `test_normal_when_drag_on_linked_node` を辿ると、テストを足した [7d1c51af](https://github.com/shuhei1101/mdmark/commit/7d1c51af)（#328）の時点で既に fail していた。

<!-- table: data -->

| ケース | 誤っている側 | 方針 |
| --- | --- | --- |
| `test_normal_when_drag_on_linked_node` | テスト・実装（Firefox） | 2 回の拡大では図が横にはみ出さず、名前も表示する枠の外にあった。横に 100px より多く動かせるまで拡大し、名前を枠の縦の真ん中へ動かしてから押す。名前はノードを覆うリンクの下にあるため、動かさずに押す確認はマウスで名前の位置を押す。Firefox はリンクのドラッグ（`dragstart`）を始めて `pointercancel` で図のドラッグを止めていたため、`attachZoom` でノードのリンクの `dragstart` を止める |
| `test_normal_when_drag_on_chart_item` | テスト | 2 回の拡大では図が横にはみ出さなかった。横に 120px より多く動かせるまで拡大する |
| `test_normal_when_group_titles_stuck` | テスト | 横にスクロールした図ではタイトルの左端が枠の外にあり、`elementFromPoint` が何も返さなかった。タイトルの見えている部分で当てる。表示する枠が拡大で高くなり、処理の層を上へ出し切る余地が無かったため、リサイズハンドルの ↑ で枠を低くしてから動かす。縦のドラッグは、Firefox が画面の外への移動を配らないため、枠の中に収まる量ずつ分ける |

| `test_normal_when_flowchart` | テスト | シナリオ『図を描く』では凡例に 2 種類以上ある線の種類だけを出す。線が処理の流れの 1 種類だけの判定フローチャートの凡例から「処理の流れ」を外す |
| `test_normal_when_er_table` | テスト | テーブルの下端 663px にツールチップ 109px を足すと画面の高さ 720px を超え、部品設計『図のツールチップ』のとおり上に出ていた。テーブルの下に収まる位置までスクロールしてから開く |
| 複合 `test_normal` | テスト | 層の `hint` にも「返信の種類」があり、`first()` が層のツールチップを指していた。印の `aria-describedby` が指すツールチップで探す |
