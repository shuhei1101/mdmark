# 要件

## 要望

| 子 | 終わりの条件 |
| --- | --- |
| [#89](https://github.com/shuhei1101/mdmark/issues/89) | 導入先を `claude plugin list --json` の `installPath` から取り、シナリオ『ClaudeCodeにプラグインを入れる』の期待値の `Read from:` も合わせて直す。テスト実行方法の E2E の前提に、release で `dist/` と `plugin/` の生成物を commit・push してから流すことを加える |
| [#90](https://github.com/shuhei1101/mdmark/issues/90) | 要素の有無を、開きタグの文字列ではなく属性を許す形（`<p` と `>` の間に属性を許す正規表現や、HTML を解析した要素名）で確かめる |

#89 の E2E『ClaudeCodeにプラグインを入れる』の `test_normal` は、`claude plugin list --json` の出力から `mdmark@mdmark` の行を取り、その `installPath` を導入先として使う。
有効であることも同じ JSON の行から確かめる。
導入先が設定のフォルダ（`CLAUDE_CONFIG_DIR`）の下にあること、導入先に `hooks/hooks.json`・`.mcp.json`・`server/mcp.js`・`node_modules/esbuild` があること、導入先の MCP サーバーがツールの一覧を返すことの検証は変えない。

#90 の E2E『文書をHTML文字列にする』の `test_normal` は、見出し・段落・リスト・表・コードブロック・リンク・折り畳みの要素を、開始タグの属性の有無を問わずに確かめる。
`<script` と `<!--` を含まないことの検証は変えない。

完了の基準は、release/v0.7.0 のビルドした配布物と、`dist/` と `plugin/` の生成物を commit・push した作業ブランチで、2 つの `test_normal` が pass すること（『ClaudeCodeにプラグインを入れる』は Chromium のプロジェクトだけ、『文書をHTML文字列にする』は Chromium・Firefox の両方）。
