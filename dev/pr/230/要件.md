# 要件

## 要望

AI Monitor の配布物を v0.3.0 に揃え、準拠バージョンを v0.3.0 にする。
起点 Issue の「影響のある分類」の行ごとに、次を終わりの条件にする。

| 分類 | 終わりの条件 |
| --- | --- |
| サイトのレイアウト | `python -m ai_monitor.distribution import-site --version v0.3.0 --root {worktree}` が終了コード 0 で終わり、`docs/_theme/` が v0.3.0 の配布元の `docs/_theme/` と一致する（配布物リストの `excludes` の `docs/_theme/_data/nav.project.yml`・`docs/_theme/assets/*.ts` は mdmark の内容のまま）。直下に控え `ai-monitor-theme.yaml`（`source: copy` / `version: v0.3.0`）がある |
| テンプレート | `dev/テンプレート/` の `*.schema.yaml` のうち、v0.3.0 と違う `index.schema.yaml`・`テスト実行方法.schema.yaml`・`画面設計.schema.yaml`・`開発コマンド.schema.yaml` が v0.3.0 の内容と一致する。`python -m ai_monitor.design_docs convert --from v0.2.0 --to v0.3.0 --root {worktree}` を流し、続けて `validate` が誤り 0 件で終わる |
| テンプレート（開発コマンド） | 開発コマンドの `静的検査` の分類が、`refs` でテスト実行方法の `lint` 層（`dev/設計書/テスト/テスト実行方法#layers[lint]`）を指し、`commands` を持たない（v0.3.0 の `開発コマンド.schema.yaml` の「テストと静的検査の節はコマンドを持たず、`refs` でテスト実行方法を指す」）。`convert` が `refs` を追加しない場合は書くツールで追加する |
| テンプレート（テスト実行方法） | テスト実行方法の `lint` 層の `run_all` が、ルートの Biome の check・ルートの型検査・VS Code 拡張機能の型検査（`vscode/` の `typecheck`）を、どれかが失敗しても最後まで回し、1 つでも失敗したら失敗で終える 1 コマンドになっている（v0.3.0 の `テスト実行方法.schema.yaml` の `layers` の説明） |
| 規約・外部規約・判定・観点 | `v0.2.0..v0.3.0` で変わった規約・コーディング規約・判定フローチャート・チェックシート・観点を読み直し、従っていない mdmark の成果物を修正する。修正が 1 ファイルの書式の修正を超える（設計書の作り替え・実装の変更を伴う）ものは `## スコープ外` へ回して起票する |
| 準拠バージョン | `ai-monitor-version.ini` が `v0.3.0` |

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 配信設定（`docs/_config.yml` に配布元で増えたキーを追加する） | mdmark は `docs/_config.yml` を持たず、GitHub Pages のワークフロー（`.github/workflows/`）も無いため、追加する先が無い。新しく置くかは、公開ドキュメントを GitHub Pages で配信するかの判断で、追従の範囲を超える（この判断はレビューで確定する） | 予定なし |
| ルール索引（配布元のルール索引で増えた行を追加する） | 配布元のルール索引 `rules.global.yaml` は、モニターが AI Monitor のクローンからそのまま `RULE_INJECT_INDEXES_USER` で渡す。mdmark の [docs/rules.yaml](https://github.com/shuhei1101/mdmark/blob/develop/docs/rules.yaml) は mdmark 固有のルールだけを持つため、写す行が無い | 予定なし |
| フェーズ手順（エージェントの動きが変わる箇所の確認） | mdmark は固有のエージェントもフェーズの拡張も持たず、フェーズ手順は AI Monitor が持つ | 予定なし |
| プラグイン・設定スキーマ・MCP ツール | AI Monitor 側の `settings.yaml` と MCP `update_plugins` の操作で、mdmark の作業 PR の変更ではない（[Issue #15](https://github.com/shuhei1101/mdmark/issues/15) の判断と同じ） | 予定なし |
| v0.3.0 で増えたテンプレート（方針決め・観点・フェーズ.schema など）の `dev/テンプレート/` への取り込み | mdmark の `dev/テンプレート/` は設計書の種別の Schema だけを持ち、他のテンプレートは AI Monitor のドキュメントから読む | 予定なし |
