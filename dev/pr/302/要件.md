# 要件

## 要望

使い方集の `glossary`（[docs/使い方/書く/索引と用語集を書く.md](https://github.com/shuhei1101/mdmark/blob/develop/docs/%E4%BD%BF%E3%81%84%E6%96%B9/%E6%9B%B8%E3%81%8F/%E7%B4%A2%E5%BC%95%E3%81%A8%E7%94%A8%E8%AA%9E%E9%9B%86%E3%82%92%E6%9B%B8%E3%81%8F.md)）に、文書へタグを付与する手順として次の 2 つの工程を追加する。

1. タグを付与する前に、索引の `docs` の全ての文書の `tags` を参照し、使われているタグを全件取得する
   - mdmark の MCP には使われているタグを返すツールが無い（[#156](https://github.com/shuhei1101/mdmark/issues/156) で `list_tags` を削除済み）ため、索引の YAML の `docs[].tags` を参照する手順にする
   - 同じ概念の言い方・活用の違いだけのタグが使われていれば、新しく作らずにそのタグを使い回す
2. knowledge の規約『[タグと用語の登録](https://github.com/shuhei1101/knowledge/blob/master/docs/rule/dev-tag-term-registration.yaml)』と判定フローチャート『[タグの付与](https://github.com/shuhei1101/knowledge/blob/master/docs/flowchart/flowchart-tag-attach.yaml)』に沿って付与する
   - その語で探した人にこの文書が出てほしいタグは全て付与し、最も分量の多い主題のタグに `main: true` を付ける
   - 判定の本文は規約を参照し、mdmark のページに規約の本文のコピーを置かない
   - タグのマスター（語彙）は持たない前提で書く（D-169）。追加する工程は、索引の最上位の `tags`（語彙）と `aliases` を使わない

終わりの条件: `read_guide` に `glossary` を渡して返る本文に上の 2 つの工程があり、工程の中に語彙（最上位の `tags`）・`list_tags` への言及が無い。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 索引のタグの語彙（最上位の `tags`）と語彙に無いタグの点検の削除、使い方集（`glossary`・`index-schema`）・[索引と被参照](https://github.com/shuhei1101/mdmark/blob/develop/docs/%E3%81%AF%E3%81%98%E3%82%81%E3%81%AB/%E3%82%B3%E3%82%A2%E3%82%B3%E3%83%B3%E3%82%BB%E3%83%97%E3%83%88/%E7%B4%A2%E5%BC%95%E3%81%A8%E8%A2%AB%E5%8F%82%E7%85%A7.md)・[索引](https://github.com/shuhei1101/mdmark/blob/develop/docs/%E3%83%AA%E3%83%95%E3%82%A1%E3%83%AC%E3%83%B3%E3%82%B9/%E7%B4%A2%E5%BC%95.md) からの語彙の記述の削除 | 語彙の機能そのものを削除する別の Issue。この PR は語彙の記述を残したまま、語彙に依らない工程を追加する | [#179](https://github.com/shuhei1101/mdmark/issues/179) |
| mdmark 自身の索引のタグの見直し | Issue 本文で、dev-docs に載せる作業で行うと決めている | 予定なし |
| 使い方集の索引（`guide/index.yaml`）の `glossary` の `when`・`summary` | 文書の索引への記載にタグの付与が含まれ、既存の `when`（索引や用語集を記載するとき）で引ける | 予定なし |
