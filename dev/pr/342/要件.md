# 要件

## 要望

VS Code 拡張機能のプレビューの Webview の画面（`vscode/src/webview/`）を、knowledge の React の規約（`docs/rule/react-*`・`ui-*`）に沿って React（Vite + React Compiler + Tailwind v4 + shadcn/ui）で作り直す。

- 今の Webview の機能を全て再現する: 配布物の参照と `mount`・`update` での描画、読み込み中の表示と描けない理由、設定ファイルを読めない帯、再生できない動画・音声の通知、相対パスのアセットの差し替え、エディタとのスクロールの両方向の同期、`setState` による背面からの復帰、リンクの振り分け、配色の固定、差分のパネル（`diffSource`）、結合テスト用の `inspect`
- 拡張機能と Webview のメッセージ（`HostMessage`・`WebviewMessage`）と、拡張機能のコマンド・設定は変えない
- 状態の表示・帯・通知の見た目は shadcn/ui と Tailwind に合わせて作り直してよい。描いた文書（mdmark の `mount` の中身）の見た目は変えない
- 変えないもの: viewer（`src/viewer/`）、書き出す HTML の部品（`src/parts/`・`src/interact/`。表を含む）、CDN で配る `dist/index.js` の場所、公開の `mount`・`mountView`・`mountComments`
- 適用しない決定: API サーバーを持たないため、SPA とルーター（D-14・D-21）と orval の API クライアント（D-22）は適用しない
- モックを Storybook（`@storybook/react-vite`）+ MSW へ移す。Webview の部品は `.stories.tsx` をコンポーネントの横に配置する
- lint・検査・Git フックを導入する: ESLint の `eslint-plugin-better-tailwindcss`（任意値の禁止）・`eslint-plugin-boundaries`（import の向き）・`eslint-plugin-react-hooks`・`eslint-plugin-jsx-a11y`・複雑さの lint（`complexity`・`max-depth`・`max-params`・`sonarjs/cognitive-complexity` を error）、Storybook の `addon-a11y`、Playwright の axe、lefthook と直下の `package.json` の npm scripts
- 終わりの条件: 拡張機能の結合テスト（VS Code 1.141.0 と stable）・Webview の単体テスト・VS Code の E2E が全て pass し、追加した lint と a11y の検査で違反が 0 件

`未確定`: 今の server 形式のストーリー（`src/parts/*.stories.yaml` と Webview の `*.stories.yaml`）の扱い（決める段: PoC 検証で成立を確かめ、部品設計で確定）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | Storybook を `@storybook/react-vite` の 1 つにし、`src/parts` のストーリーを CSF（`.stories.ts`）へ書き換え、部品の HTML 文字列を描く共通のデコレーターで描く | Storybook が 1 つで、`addon-a11y` が全ての部品で有効になる。部品の描画のインターフェースと `@storybook/server-webpack5` を除外できる | `src/parts` のストーリーの全ファイルと、ストーリーの ID を参照する結合テストを書き換える |
| B | 今の server 形式の Storybook を部品用に残し、React の Storybook を別に起動し、composition（`refs`）で 1 つの画面にまとめる | `src/parts` のストーリーと結合テストを変えない | Storybook が 2 つになり、起動・依存・設定が 2 組になる。`addon-a11y` は部品で無効のまま |

推奨: A

決定: A（PoC 検証で `@storybook/react-vite` が server 形式の部品の HTML を同じストーリーの ID で描けることを確認し、部品設計で確定）

`未確定`: 複雑さの lint を error にする範囲（決める段: モジュール構成設計）

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| viewer（`src/viewer/`）の React 化 | 書き出す全ての HTML に React のランタイムが入る（Issue の範囲の決定） | 予定なし |
| 書き出す HTML の部品（`src/parts/`・`src/interact/`。表を含む）の React 化 | 書き出す HTML を CDN なしで 1 枚で完結させる（Issue の範囲の決定） | 予定なし |
| SPA・TanStack Router・TanStack Query・orval | Webview は 1 画面で、API サーバーを持たない | 予定なし |

| ライブラリ本体の部品のモック（`dev/mock/components/`）の Storybook への移し替え | 部品は React にせず、モックの HTML はそのまま開ける | 予定なし |
