## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 原因 | 390px × 844px の画面で、枠の左端は Storybook の `body` の `padding` 16px と描く先の要素（`.mdmark`）の `padding` 24px（`--mdmark-padding`）で 40px になり、352px の枠の右端が 392px になる。描く先の要素の内側の幅は 310px | `Single`・`Idle`・`Editing` で同じ値。ボタン（幅 99px）は収まり、scrollWidth は 390 |
| ストーリーの描き方 | `STATIC_POPOVER_STYLE` を `.mdmark-comment-add,.mdmark-comment-popover{position:static;max-width:100%}` にし、枠の幅を描く先の要素の内側に収める | `src/index.css` は変えない |
| 既存機能への影響 | 実際の文書の `position: fixed` の吹き出し・入力欄・ボタンの CSS は変えない | 390px より広い画面のストーリーでは、枠の幅は今と同じ 352px |
| 単体テスト | `storybook-render.test.ts` に `test_render_part_when_comment_popover` を追加し、`comment-bubble` の HTML の前の `style` を確認する | - |
| 結合テスト | 3 つのストーリーの結合テストに、`openStory` の `viewport` を 390px × 844px にして全ストーリーを開き、`pageOverflows` が `false` になるケースを追加する | 実装前に Red を確認する |

`修正の場所` はモジュール構成設計で A に決定した（ストーリーの描き方を修正する）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | ストーリーの描き方（`STATIC_POPOVER_STYLE`）を修正する | 実際の文書の表示に影響しない | 原因が部品の CSS にあれば直らない |
| B | 部品の CSS（`.mdmark-comment-popover` の `width`）を修正する | 狭い画面で枠の幅の計算を見直せる | 実際の文書の表示が変わりうる |

推奨: A

`position: fixed` では `calc(100vw - 32px)` が画面に収まり、`position: static` にしたストーリーでだけ描く先の要素の余白が加わるため。
