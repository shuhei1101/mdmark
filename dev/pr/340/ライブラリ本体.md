## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 原因の調査 | 390px × 844px の画面で `Parts/CommentBubble` の `Single` と `Parts/CommentForm` の `Idle` を開き、枠・描く先の要素（`.mdmark`）・Storybook の `body` の幅と余白の計算値を測り、392px になる内訳を特定する | 内訳はモジュール構成設計のレビュー依頼に記載する |
| 修正の場所 | 内訳がストーリーにだけある余白なら `STATIC_POPOVER_STYLE` で枠の幅を描く先の要素に収め、枠の幅の計算そのものが誤っているなら `src/index.css` を修正する | `未確定`（決める段: モジュール構成設計） |
| 既存機能への影響 | 実際の文書の `position: fixed` の吹き出し・入力欄の幅と位置は今と同じにする | 部品の CSS を修正した場合、`選んだ箇所にコメントする`・`部品をJavaScriptから使う` の E2E を実行する |
| 結合テスト | 3 つのストーリーの結合テストに、`openStory` の `viewport` を 390px × 844px にして全ストーリーを開き、`pageOverflows` が `false` になるケースを追加する | 実装前に Red を確認する |

`修正の場所` の案:

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | ストーリーの描き方（`STATIC_POPOVER_STYLE`）を修正する | 実際の文書の表示に影響しない | 原因が部品の CSS にあれば直らない |
| B | 部品の CSS（`.mdmark-comment-popover` の `width`）を修正する | 狭い画面で枠の幅の計算を見直せる | 実際の文書の表示が変わりうる |

推奨: A

`position: fixed` では `calc(100vw - 32px)` が画面に収まり、`position: static` にしたストーリーでだけ描く先の要素の余白が加わるため。
