# 要件

## 要望

文書を書く人が Markdown に印を書くと、mdmark が描いた文書に表の操作・注意書き・タブなどの表示が付く。
印に対応しない表示（GitHub など）でも本文は読める。
使う側は `registerExtension()` で自分の印を足せる。

<!-- table: data -->

| 項目 | 要件 |
| --- | --- |
| 印の書き方 | 1 か所に付ける印は `<!-- 名前: 引数 -->`、範囲を持つ印は `<!-- 名前: 引数 -->` 〜 `<!-- /名前 -->` で囲む。引数の無い印はコロンを省いて `<!-- 名前 -->` と書ける。引数は空白で区切り、種類・`+機能`・`-機能`・`キー=値`・`closed`・`open` を書ける |
| 印に対応しない表示 | 印は HTML コメントのため見えず、囲んだ Markdown はそのまま読める。印ではない記法（注意書き・ファイルツリー・バッジ）も、GitHub で書いた文字が残る書き方にする |
| 表 | `<!-- table: 種類 +機能 -機能 closed -->` 〜 `<!-- /table -->` で囲んだ表に、種類ごとの機能と見た目を付ける。機能は列の並べ替え・列と見出し行のピン止め・列の値での絞り込みで、`+機能`・`-機能` で足し引きする。`closed`・`open` は範囲を折り畳みに入れ、既定で閉じる・開く。囲まない表は既定の種類（ピン止めだけ）にする |
| 注意書き | 引用の 1 行目の `[!NOTE]`・`[!TIP]`・`[!IMPORTANT]`・`[!WARNING]`・`[!CAUTION]` を、種類ごとの題・色・アイコンを持つ枠にする。`[!NOTE]-` のように末尾に `-` を付けると閉じた折り畳みにする。知らない種類は `NOTE` として出す |
| タブ | `<!-- tabs -->` 〜 `<!-- /tabs -->` で囲んだ範囲を、最初に出る見出しの階層で区切り、見出しの文字をタブ名にしたタブで切り替えて見せる |
| ステップ | `<!-- steps -->` 〜 `<!-- /steps -->` で囲んだ番号付きリストを、番号と項目をつなぐ線を持つ手順に見せる |
| ファイルツリー | 言語 `tree` のコードブロックに罫線で書いたフォルダ構成を、フォルダとファイルの入れ子のツリーに見せる |
| バッジ | 頭に `badge:` を付けた行内のコードを、頭を外した文言の札に見せる。`badge\:` と打ち消した行内のコードは `\` を外したコードのまま出す |
| 目次 | 文書の `<!-- toc -->` の場所に、h2〜h3 の見出しを階層どおりに入れ子にし、各見出しへのリンクを持つ目次を置く |
| 見出しのアンカー | 見出しに GitHub と同じ規則の ID（同じ文字の見出しは `-1`・`-2` を付ける）と、その ID へのリンクを付ける |
| 節の開閉 | 見出し（h2〜h4）の節を見出しから開閉できる。URL の `#ID` が閉じた節の中を指すときは、その節を開いて移る。見出しの直後の `<!-- section: closed -->` はその節を閉じた状態で始め、`<!-- section: open -->` は開いた状態で始める |
| 行の詳細 | 表の直後の `<!-- row-detail: 行の位置 -->` 〜 `<!-- /row-detail -->` で囲んだ Markdown を、その表の行（見出し行を除いて 1 から数える）の下に開閉して出す |
| 図と表の番号 | `<!-- fig: ID -->` の直後の図と表に、種類ごとの通し番号（`図 1`・`表 1`）を付ける。本文の `#fig-ID` へのリンクの文字を、その図・表の番号にする |
| 機能のオン・オフ | 各記法を機能として、設定の `features` と文書の `<!-- features: +機能 -機能 -->` で切り替えられる。オフの記法は書いた Markdown を普通の Markdown として描く。機能の名前は記法ごとに `table`・`callout`・`tabs`・`steps`・`tree`・`badge`・`toc`・`anchors`・`sections`・`row-details`・`figures` で、既定はオン |
| 拡張の登録 | `registerExtension({ name, directive, load, schema })` で使う側が印を足す。文書に `directive` の印があるときだけ `load` を呼んでモジュールを読む。`schema` を渡すと、合わない引数の印の場所に合わない項目を書いた枠を出す |
| 拡張の言語 | 拡張は TypeScript と JavaScript のどちらでも書ける。拡張の型を TypeScript の型定義として配布物と一緒に配る |
| 書き手の誤り | 記法の印（`table`・`tabs`・`steps`・`section`・`row-detail`・`fig`）に知らない種類・`+機能`・`-機能`・キー・値を書いても、閉じの印の無い範囲・切れた参照・重なった ID・読めないファイルツリーを書いても、本文の描画を止めない。読めた指定だけを当てて描き、読めない指定とその直し方を、その箇所の書き方の知らせで書き手へ知らせる。`features` の印の知らない機能名は今のとおり知らせずに無視する |
| `render` と `mount` | `render` の HTML 文字列は、スクリプトを動かさなくても各記法の中身（全てのタブの中身・閉じた節の中身を含む）を読める。並べ替え・タブの切り替えなどの操作は `mount` が付け、`update` で付け直し、`destroy` で外す |
| 印刷 | 印刷の機能がオンのとき、印刷ではタブの全ての中身を縦に並べ、閉じた節・行の詳細・閉じた表と注意書きを開いて出す。印刷の後に元の状態へ戻す |
| アクセシビリティ | 付けた操作はキーボードで操作でき、選んだタブ・並べ替えの向き・開閉の状態を読み上げの属性で示す。注意書きの種類とタブの選択を色だけで見分けさせない |
| スクリプト | 文書に書いたスクリプト（`script` 要素・イベント属性・`javascript:` の URL）を実行しない今の条件を保つ |
| 完了の基準 | 全ての記法を含む見本の文書を、ビルドした配布物を読むページで `mount` すると各記法の表示と操作が働き、非機能要件の対応ブラウザの E2E が通る |

## スコープ外

<!-- table: data -->

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 表の件数の表示・列の表示の切り替え・集計の行・表のコピー・行へのリンク | 起点 Issue が挙げる表の機能は並べ替え・ピン止め・絞り込み・折り畳み・見た目の変更。この PR の表の印の `+機能` に載せて足す | 起票予定 |
| 同じ組のタブの選択を揃える・選んだタブを覚える | 起点 Issue が挙げるのはタブの切り替えまで。この PR のタブに載せて足す（含めるかはレビューで確定する） | 起票予定 |
| コードブロックの題・行番号・行の強調と、コードの行の印 | 起点 Issue の記法の一覧に無い。この PR の印の読み取りに載せて足す | 起票予定 |
| 用語集の表の印（`<!-- glossary: … -->`）と用語のツールチップ | 用語集を作る Issue が足す | [#5](https://github.com/shuhei1101/mdmark/issues/5) |
| `registerComponent()` と部品の JSON | 図・チャートの部品を作る Issue が足す | [#6](https://github.com/shuhei1101/mdmark/issues/6) |
| 未知の印と、拡張の引数の Schema 違反を知らせる `check` | CLI を作る Issue が足す | [#9](https://github.com/shuhei1101/mdmark/issues/9) |
