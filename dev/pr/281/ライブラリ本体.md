## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 図のツールチップのタッチでの閉じ方（#170） | ツールチップを開いている間だけ `document` に `pointerdown` を付け、対象が持ち主とツールチップの外なら閉じる | ドラッグの開始・図の操作のボタンへの `pointerdown` でも閉じる。マウスのホバーとキーボードの開閉は今のまま |
| 図のツールチップのタッチでの開閉の切り替え（#170） | 持ち主の `pointerdown` の `pointerType` が `touch` のとき、開いている持ち主のタップで閉じ、閉じている持ち主のタップで開く | `pointerType` が `touch` の `pointerenter` では開かず、タッチの開閉は `pointerdown` の切り替えだけで決める（タップでは `pointerenter` → `pointerdown` の順に来るため、`pointerenter` で開くと同じタップの `pointerdown` で閉じる）。`pointerType` が `mouse`・`pen` のときは切り替えない |
| 埋め込んだ HTML のヒント（#170） | 図のツールチップと同じ開閉の処理を通す | 持ち主の集め方だけが違い、開閉の処理は共通 |
| 用語のツールチップが同じ文書のリンクを覆う（#267） | Firefox で再現し、ツールチップの置き場所・閉じる条件と E2E の操作のどちらが誤っているかを切り分け、誤っている側を修正する | 実装を修正する場合は Chromium の振る舞いも変えないことを確かめる |
| 拡大した図のドラッグ（#273） | develop で再現し、表示する枠の余白の `pointerdown` がドラッグを始めない原因（枠の高さ・入れ子の変更でドラッグを受ける要素が変わった、か E2E の押す位置が余白でなくなった）を切り分け、誤っている側を修正する | Chromium と Firefox で pass させる |
| 単体テスト | `diagram-tips.browser.test.ts` に、タッチのタップでの開閉の切り替えと、外の `pointerdown` で閉じるケースを加える。閉じた持ち主へのタッチの 1 回のタップ（`pointerenter`・`pointerdown`・`pointerup`・`pointerleave`・`focus` を実際の順序で発火）でツールチップが開いたままになるケースを加える。開いた後に `pointerleave`・`blur` を発火させず（iOS の `:hover` が残る状態）、外の `pointerdown` だけで閉じるケースを加える。同じケースを、図の持ち主と、`div.mdmark-html` を渡したときのヒントの持ち主の両方で確かめる。#267・#273 で実装を修正したら、対応する単体テストを加える | マウスの `pointerdown` で切り替えないケースも加える |
| E2E | 『図の要素のツールチップを見る』に、タッチの端末で開いたツールチップを外のタップと持ち主のもう一度のタップで閉じるケースを加える | Playwright の `hasTouch` のコンテキストで流す |

## 実装

| 対象 | 原因 | 修正 |
| --- | --- | --- |
| #170 | `pointerenter`・`pointerleave` でポインターの種類を見ず、`closeLater` が `:hover` の残る持ち主を閉じない | `attachDiagramTips` の持ち主に、タッチの `pointerdown` での切り替えを追加し、タッチの `pointerenter`・`pointerleave` を無視する。開いている間は `document` の `pointerdown`（捕捉の段）で、ツールチップと持ち主の外なら閉じる（879c6c31） |
| #273 | E2E の前提の誤り。幅 640px のチャートを 2 回拡大しても 156%（1000px）で、1216px の表示する枠に横幅が収まり、横にドラッグする余地が無い。ドラッグの処理は設計どおり | `test_normal_when_embedded_chart` を、横にはみ出すまで拡大してからドラッグする手順に修正（137060ba）。Chromium・Firefox で pass |
| #267 | E2E の操作の誤り。`term.hover()` の直後、Chromium と Firefox のどちらでもツールチップは語の上（設計どおりの側）に出て、真上の行のリンクを覆う（下の実測）。リンクの中央の要素はどちらも `.mdmark-term-tip-meaning` で、ポインターがツールチップの上にある間は閉じない（WCAG 1.4.13 のとおり）。製品の振る舞いはブラウザで変わらず、Firefox だけ fail したのは Playwright の `click` の当たり判定の違い。要件の終了条件は「ポインターを外せば同じ文書のリンクを押せる」に変更した（[確認ログ](./確認ログ.md)） | `test_normal`・`test_normal_when_aliases` を、ポインターを本文の外へ動かしてツールチップが閉じたことを確かめてからリンクを押す手順に修正（68dc7710）。Chromium・Firefox で pass。用語のツールチップの実装と設計書は変えない |
