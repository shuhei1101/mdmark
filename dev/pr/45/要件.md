# 要件

## 要望

文書を書く人が、Markdown のコードブロックに書いた HTML をその場で描かせ、その中に Chart.js などのチャートと、ヒントの出る図を置ける。
読む人は、チャートを拡大・縮小・移動でき、図の要素と埋め込んだ HTML の中の用語・関連資料をツールチップで読める。

<!-- table: data -->

| 項目 | 要件 |
| --- | --- |
| HTML の表示 | 印を付けたコードブロックの HTML を、コードではなくその場の HTML として描く（D-9）。印の無い `html` のコードブロックは今のとおりコードとして出す |
| スクリプト | 埋め込んだ HTML に書いたスクリプト・イベントの属性は動かさない（D-22）。動くのは mdmark の部品だけで、今の `render` のサニタイズの条件を保つ |
| チャート | 埋め込んだ HTML の中に、データ（JSON）だけを書いたチャートを置ける。描くのは mdmark で、描き方は `未確定`（チャートの描き方）。外部ライブラリで描くときは、文書が使うときだけ読み込む（D-10・D-12） |
| チャートの拡大・移動 | チャートは拡大・縮小とドラッグでの移動ができる。拡大・縮小は #21 の図の部品と同じく右上のボタンとキーの `+`・`-`・`0` だけで行い、ホイールは文書のスクロールに使う。部品でない普通の HTML には拡大・縮小のボタンを付けない（D-43） |
| `data-hint` のヒント | 埋め込んだ HTML の任意の要素に `data-hint` 属性を書くと、その文がツールチップで出る。見た目と操作（ホバーとフォーカスで出る・Esc で消える・上に乗っても消えない）は #21 の図のツールチップと同じにする（D-46） |
| 部品の JSON のヒント | 図の部品の定義の `hint`・`io` も同じ見た目のツールチップで出す。要らないときはオプションで外せる（D-46） |
| 埋め込んだ HTML の中の用語 | 埋め込んだ HTML の中の文章にも、Markdown の本文と同じ用語集と関連資料のツールチップを出す（D-45） |
| 書き出し | `mdmark export`・`mdmark build` で書き出した 1 枚の HTML でも、埋め込んだ HTML・チャート・ツールチップが外を読まずに同じように動く |
| 完了の基準 | 埋め込んだ HTML・チャート・`data-hint`・部品の JSON のヒント・埋め込んだ HTML の中の用語のツールチップが、`mount` と書き出した HTML の両方で E2E で確かめられ、非機能要件の対応ブラウザで通る |

<!-- /table -->

図の部品の仕組み（文書に部品の定義を書いて描かせる口）と、フロー図・シーケンス図・グラフの部品は #21（[#42](https://github.com/shuhei1101/mdmark/pull/42)）で入っており、この PR はその仕組みに載せる。

`未確定`: HTML を描くコードブロックの見分け方（決める段: 単一ユースケース設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 印（`<!-- html -->` 〜 `<!-- /html -->` の範囲など、今の記法の印の形）で囲んだ `html` のコードブロックだけを描く | 今の記法の印と同じ書き方で、印に対応しない表示（GitHub）ではコードのまま読める | 印を 2 行書く |
| B | コードブロックの言語の後ろの指定（` ```html render ` など）で見分ける | 1 行で済む | 今の印と書き方が分かれ、言語の後ろの指定を読む処理が新しく要る |
| C | `html` のコードブロックを全て描く | 書き足しが要らない | HTML の書き方をコードで見せている今の文書（`docs/使い方/導入/文書を描く.md` など）まで描かれてしまう |

推奨: A

今の文書は `html` のコードブロックを書き方の見本として使っており、全てを描くと壊れる。今の記法の印と同じ形にすれば、書き方の警告・機能のオン・オフ・印に対応しない表示の扱いをそのまま使える。

`未確定`: チャートの描き方（決める段: 単一ユースケース設計の途中のライブラリ選定）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | Chart.js（と拡大・移動のプラグイン）を外部ライブラリとして文書が使うときだけ読み込み、mdmark の部品がデータから描く | 棒・円・散布図など種類が多く、Issue の一案（D-10）どおり | 外部ライブラリが 1 つ増え、書き出しに埋める量が増える |
| B | #21 の自前の SVG のグラフの部品を広げて使う | 外部ライブラリが増えず、見た目と操作が図の部品とそろう | 種類を足すたびに自前で描く処理が要る |

推奨: A

Issue は Chart.js などで描くことを挙げ、#21 のグラフの部品は折れ線だけを持つ。種類の多いチャートを自前で描き足すより、文書が使うときだけ読み込む今の口（#3）に載せるほうが少ない作りで済む。最終の採否は設計の途中のライブラリ選定で、配布物と書き出しのサイズと合わせて決める。
