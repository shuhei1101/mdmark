# 要件

## 要望

結合テスト（`npm run test:integration`）のメモリの使用を減らし、ほかの作業と重なっても全件を最後まで実行できるようにする。

| 要件 | 終わりの条件 |
| --- | --- |
| ブラウザの共有 | `integration-storybook` の Chromium のプロセスを、ファイルごとでなくプロジェクトで 1 つにする。各ファイルはそのブラウザにつないでページを開く。Vite の依存の事前バンドルを待つ温めは、ファイルごとでなくプロジェクトで 1 回にする |
| ページを閉じる | `openStory` で開いたページを、そのテストの終わりに閉じる |
| 並列の上限 | `vitest.config.ts` の `integration-storybook`・`integration-browser` に `maxWorkers` を設ける。値は CPU 数の半分（端末によらず式で決める） |
| 測定 | 修正の前と後で、同じ端末で `npm run test:integration` の所要時間と、実行中のメモリの使用の最大（テストのプロセスと Chromium の合計）を測り、`ライブラリ本体.md` の `## テスト結果` に記録する |
| 所要時間 | 修正の後の所要時間が、修正の前の 1.2 倍以内 |
| 全件 pass | 修正の後に `npm run test:integration` が全件 pass する |

`未確定`: ブラウザを共有する仕組み（決める段: 結合テスト作成）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `storybook-setup.ts` の `globalSetup` で `chromium.launchServer()` を起動して温め、`provide` で指定した `wsEndpoint` へ各ファイルが `chromium.connect()` でつなぐ | Chromium のプロセスがプロジェクトで 1 つになり、温めも 1 回になる | ファイルごとに接続を張る |
| B | 各ファイルの起動はそのままにして、`maxWorkers` の上限だけで同時の起動の数を抑える | 変更が少ない | Chromium のプロセスがワーカーの数だけ残り、温めもファイルごとのまま |

推奨: A

Issue の一案のとおりブラウザのプロセスを 1 つにでき、ファイルごとの温め（起動の直後に約 1 分）も無くなるため。
