## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 共有するブラウザ | `storybook-setup.ts` が Storybook の起動の後に Chromium を 1 つ起動して温め、つなぐ先を `provide` で各ファイルへ指定する。`globalSetup` の終わりにブラウザを閉じる | 仕組みは `未確定`（`要件.md` の `## 要望`） |
| ファイルごとの準備 | `createBrowserHolder` の `launch` は起動と温めをせず、共有するブラウザにつなぐだけにする。`close` は接続だけを切る | - |
| ページを閉じる | `openStory` で開いたページを、テストの終わり（`afterEach`）に閉じる | テストの中で閉じたページ（`card-grid.story.test.ts`）は二重に閉じても失敗しないようにする |
| 待ちの上限 | 温めの待ちの上限 `WARM_UP_TIMEOUT_MS` を `globalSetup` で使用する。`integration-storybook` の `hookTimeout` は、各ファイルの `beforeAll` が接続だけになるため、規約『資源の値の決め方』で導き直す | - |
| 並列の上限 | `integration-storybook`・`integration-browser` の `maxWorkers` を、`os.availableParallelism()` の半分（1 以上）にする | - |
| 測定 | 修正の前（develop）と後で、同じ端末で `npm run test:integration` を実行し、所要時間（vitest の Duration）と、実行中のメモリの使用の最大（テストのプロセスと Chromium の合計の RSS を 1 秒ごとに測った最大）を記録する | ほかの全件の実行と重ならない状態で測る |
| テスト実行方法 | 結合テスト（フロント）の説明の各ファイルの `beforeAll` の待ちの記載を、プロジェクトで 1 回の温めに修正し、並列の上限を記載する | - |
