# 要件

## 要望

設定を探して重ねる処理を 1 か所にまとめ、CLI（`export`・`build`・`check`・`upgrade`）・MCP（`export_html`・`build_site`・`check`）・VS Code 拡張機能（プレビュー・HTML に書き出す・ブラウザで開く・PDF に印刷）が、同じ探し方と同じ重ね方で設定を読む。

- 端末の設定: `${XDG_CONFIG_HOME:-~/.config}/mdmark/settings.yaml` を読む。環境変数 `MDMARK_CONFIG` があれば、そのパスを読む。ファイルが無ければ空の設定として扱う
- 端末の設定には `mdmark.config.yaml` と同じキーを書け、重ねる最初の層にする。重ね方の切り替えのキーは端末の設定だけが持つ
- 探し方: `--config`（MCP は `config`、VS Code 拡張機能は `mdmark.configPath`）を渡さないとき、今のフォルダ（MCP は `project_dir`、VS Code 拡張機能は Markdown のフォルダ）から上のフォルダへ `mdmark.config.yaml` を探す。渡したときは、そのファイルと端末の設定だけを重ねる
- 重ね方: 端末の設定 → 上のフォルダの設定 → 近いフォルダの設定の順に重ねる。マップはキーごとに重ね、それ以外の値（文字列・数・真偽値・配列）は後の設定の値で置き換える
- 重ねるか、上へ探して最初に見つかった 1 つだけを読むかを、端末の設定の `config.cascade`（真偽値）で切り替える。どちらでも端末の設定は最初の層に重ねる
- 書き出し（`export`・`build`）のときに端末の設定を重ねるかを、端末の設定の `config.applyToExport`（真偽値、既定 `true`）で切り替える。プレビューは常に端末の設定を重ねる
- 相対パスの値（`theme`・`extensions`・`libraries`・`html-scripts.url`・`syntax.url`・`index`・`assets.root`・`build`・`aliases` のファイル）は、その値を書いた設定ファイルのフォルダから解決する
- 上のフォルダに `mdmark.config.yaml` が 1 つも無いとき、CLI と MCP は今と同じ誤りにする（端末の設定だけでは書き出さない）。VS Code 拡張機能は端末の設定だけで描く
- `mdmark check` は、重ねた設定ファイル（端末の設定を含む）のそれぞれの形を検め、ずれにファイルのパスを出す
- `mdmark upgrade` は、今と同じく最も近い `mdmark.config.yaml` の `version` を書き換える。端末の設定と上のフォルダの設定は書き換えない
- 端末の設定が YAML として読めない・形に合わないときは、`mdmark.config.yaml` と同じ扱いにする（CLI・MCP は誤り、VS Code 拡張機能は設定ファイルを読めない帯）
- VS Code 拡張機能のプレビューと書き出す HTML に、重ねた設定の `theme` の CSS と `extensions` の拡張を当て、`mdmark export` が書き出す HTML と同じ見た目にする
- VS Code 拡張機能は、重ねた設定ファイル（端末の設定を含む）・`theme` の CSS・`extensions` のファイルを書き換えたら、プレビューを描き直す
- 端末の設定の JSON Schema を `schemas/` に置き、移行の手順が要らない変更として `migrations/no-steps.yaml` に行を置く
- 確かめる基準: 端末の設定に `features.callout: false`、上のフォルダの設定に `theme: ./theme.css`、近いフォルダの設定に `features.table: false` を書く。その下の文書を `mdmark export` で書き出した HTML と VS Code 拡張機能のプレビューの両方で、注意書きと表の機能がオフになり、同じ要素に `theme.css` の規則が当たる。最初の 1 つだけを読む切り替えにすると、`theme.css` の規則が両方で当たらなくなる
- `config.cascade` の既定は `false`（上へ探して最初に見つかった 1 つだけを読む今の動き）にする
- 優先の順番は、文書のマーカー（#161）→ 近いフォルダの設定 → 上のフォルダの設定 → 端末の設定の順に、近い層ほど優先する
