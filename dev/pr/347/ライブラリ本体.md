## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 設定を読む共通の処理 | 端末の設定のパスを決める・上へ `mdmark.config.yaml` を探す・読む・形を検める・重ねる処理を 1 つのモジュールにまとめ、CLI・MCP・VS Code 拡張機能が同じ関数を呼ぶ | モジュールの名前と置き場所はモジュール構成設計で決める。VS Code 拡張機能が束ねられるよう、`CliError` など CLI だけの型に依存させない |
| 端末の設定のパス | `MDMARK_CONFIG` があればその値、無ければ `XDG_CONFIG_HOME` か `~/.config` の `mdmark/settings.yaml` | 環境変数と home は引数で受け、テストで差し替えられるようにする |
| 重ね方 | 端末の設定 → 上のフォルダ → 近いフォルダの順に重ね、マップはキーごと、それ以外は後の値で置き換える | 重ねる前に、相対パスの値をそれを書いた設定ファイルのフォルダから絶対パスにする |
| 重ね方の切り替え | 端末の設定の `config.cascade`（真偽値、既定 `false`）で、重ねるか最初の 1 つだけかを切り替える | 端末の設定は常に最初の層に重ねる |
| 書き出しの切り替え | 書き出し（`export`・`build`）のときに端末の設定を重ねるかを、端末の設定の `config.applyToExport`（真偽値、既定 `true`）で切り替える | プレビューは常に端末の設定を重ねる |
| 結果の形 | 重ねた設定と、重ねた設定ファイルのパスの並び（端末の設定を含む）と、最も近い `mdmark.config.yaml` のパスを返す | 点検・版を上げる・VS Code 拡張機能の見張りが、パスの並びを使う |
| `mdmark export`・`mdmark build` | 重ねた設定で書き出す | `build.include` などの glob の基準は、`build` を書いた設定ファイルのフォルダ |
| `mdmark check` | 重ねた設定ファイルのそれぞれの形を検め、ずれの `file` にそのファイルのパスを入れる | 索引と文書のずれは重ねた設定の `index` で点検する |
| `mdmark upgrade` | 最も近い `mdmark.config.yaml` だけを対象にする | 移行の手順を当てるファイルの範囲は今のまま |
| エラー | 端末の設定を YAML として読めない・形に合わないときは、`mdmark.config.yaml` と同じ文で終了コード 1 にする。端末の設定が無いときは誤りにしない | 文にファイルのパスを入れる |
| JSON Schema | 端末の設定の Schema を `schemas/` に置き、`migrations/no-steps.yaml` に行を置く | `mdmark.config.yaml` の Schema のキーを取り込み、端末の設定だけのキーを足す |
| 雛形 | `mdmark init` が置く設定の雛形のコメントを、重ねて読むことに合わせる | - |
| 既存機能への影響 | 切り替えを最初の 1 つだけにしたとき、端末の設定が無ければ今と同じ設定で書き出す | 結合テストで今の書き出しの結果と比べる |
