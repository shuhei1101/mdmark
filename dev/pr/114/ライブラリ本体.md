## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 索引の Schema | 最上位に任意の `tags`（タグの語彙の並び。要素は `name` 必須、`group`・`description`・`aliases`・`deprecated` 任意）を加え、`docs[].tags` の要素を「空でない文字列」か「`name` 必須・`main` 任意のオブジェクト」のどちらかにする | 今の索引はそのまま新しい Schema に合う |
| 移行の手順 | `migrations/no-steps.yaml` に `version: next`・`schema: mdmark.index.schema.json` の行を、変えた後の Schema の sha256 と理由つきで加える | 移行の手順の Schema『移行の手順』のとおり |
| 索引の型と検査 | `MdmarkIndex` に語彙の型を、`MdmarkIndexDoc.tags` に文字列とオブジェクトの和の型を加え、`INDEX_SHAPE` の検査も合わせる | 文書のタグを読む側は、名前と主題かをそろえた形で受け取れるようにする（形はモジュール構成設計で決める） |
| タグのずれの点検 | 語彙を記載した索引だけで、未登録のタグ・やめたタグ・語彙の `name` の重複・`aliases` の重なり・振り替え先の無い `deprecated` を、ずれの種類として加える | 種類の名前は英語の識別子でインターフェース定義設計で決める。近い語彙のタグの選び方も同じ段で決める |
| findDocs | タグの AND / OR、語彙の `aliases` の解決、主題のタグの一致を上にする並びを加える | 件数・続き・返す量・返す形式は MCP の `find_docs` の側で組み立てる（Claude Code プラグインの計画書） |
