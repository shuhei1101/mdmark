# 要件

## 要望

knowledge の規約『タグと用語の登録』と『MCP サーバー作成ルール』の `## 読み取りのツール` に、索引のタグと `find_docs` を合わせる。
`find_docs` のリクエストとレスポンスは、Issue の「インターフェース定義（A-14）」の検索（`search_docs`）に合わせる。
A-14 のツール名・引数名は仮のため、mdmark では今のツール名 `find_docs` と引数の名前を残し、加える引数の名前はインターフェース定義設計で決める。

### タグの語彙

- 索引の最上位に、タグの語彙 `tags` を置ける
- 語彙の各タグは `name`（必須・語彙の中で一意）・`group`（`topic`・`kind`・`scope`・`tool` など）・`description`（「含める / 含めない / 例」の 3 点）・`aliases`（タグの別名）・`deprecated`（やめたタグの振り替え先のタグの `name`）を持つ
- 語彙は索引に 1 つだけ置き、同じ `name` のタグをグループごとに別に定義しない

### 文書のタグ

- `docs[].tags` の要素は、今の文字列に加えて `name` と `main`（主題のタグか。既定 `false`）を持つオブジェクトを受ける
- 今の文字列の並びの索引は、書き換えずにそのまま読める。索引の Schema を変えるので、`migrations/no-steps.yaml` に行を置く（CLAUDE.md の `## 設定・索引の Schema`）

### 点検

- 語彙（最上位の `tags`）を記載した索引では、`checkIndex`（`mdmark check` と MCP の `check`）が次をずれとして知らせる。どれも文書の読み込みを止めない
  - 文書のタグが語彙の `name` にも `aliases` にも無い（未登録の候補）。近い語彙のタグを添える
  - 文書のタグが `deprecated` のタグ。振り替え先のタグを添える
  - 語彙の `name` の重複と、`aliases` が別のタグの `name` か `aliases` と重なる
  - `deprecated` の振り替え先が語彙に無い
- 語彙を記載していない索引では、タグのずれを知らせない
- knowledge の規約『YAML』の `## MCP からの読み取り` は登録外のタグでの検索をエラーにすると定めるが、Issue の A-14（検索の `tags` の補足「語彙に無いタグは近いタグを添えて警告」）と規約『タグと用語の登録』の `## タグの語彙` に合わせて、検索でも拒否せず警告にする

### find_docs

- タグの絞り込みを、全てを持つ文書（AND、今の `tags`）と、どれかを持つ文書（OR）で切り替えられる
- 渡したタグが語彙の `aliases` に当たるときは、語彙の `name` のタグとして引く
- 語彙を記載した索引で、渡したタグが語彙に無いときは拒否せず、結果に警告と近い語彙のタグを添える
- 並びは、主題のタグ（`main: true`）が絞り込みのタグに当たる文書を上にし、同じ順位の中は索引の `docs` の並びにする
- 既定の件数 20・上限 100 の `limit` と `cursor` を持ち、結果の先頭に総件数・返した件数・当たった全件の合計文字数・`next_cursor` を返す
- 続きがあるとき（切り詰めたとき）は、絞り込める引数（タグ・語・件数だけ など）を案内する
- 当たった文書に付いているタグごとの件数を返す
- 各行に返す量を `view`（`brief` / `standard` / `full`、既定 `brief`）で選び、`include` / `exclude`（項目名の enum の配列）で足し引きできる。`view` で省いた項目は `omitted` に、取り方を添えて返す
- `brief` の各行は、ID・題・概要・タグ（主題のタグを示す）・文字数を返す
- 任意の `count_only`（既定 `false`）が `true` のときは、一覧を返さず、総件数・合計文字数・タグごとの件数だけを返す。手順で先に呼ぶことは強制しない
- 引数なしの呼び出しは、既定の件数の先頭ページ・`brief`・タグごとの件数・総件数・`next_cursor` を返す（全ての文書は返さない）
- 返す形式を `format`（`markdown` / `json`、既定 `markdown`）で選べる。`markdown` は一覧を Markdown の表で返し、structuredContent を返さない。`json` は structuredContent と text に同じ JSON を入れる
- 読み取りのツールとして `readOnlyHint` を付ける

`未確定`: `brief` に版（`rev`）を返すか（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 返さない | 索引が版を持たない今の形のまま足せる | A-14 の `brief` の項目と 1 つ違う |
| B | 文書のファイルの最後の commit の短い SHA を返す | A-14 の `rev` に近い値を返せる | 一覧のたびに git を呼ぶ。git の外の作業のフォルダでは取れない |

推奨: A

mdmark の索引は文書の版を持たず（R-2）、規約『MCP サーバー作成ルール』も版の出所を決めていないため、出所を決めないまま git に寄せない。

`未確定`: `include` で足せる項目と、`standard` / `full` の中身（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 索引と参照の表から取れる項目（パス・別名・関連する文書・被参照の数）に限る | 今の索引と `collectReferences` だけで返せる | D-52 の git の最終更新日時・最終更新者を返せない |
| B | A に git から取る最終更新日時・最終更新者を足す | D-52 の項目をそろえられる | git を呼ぶ処理と、git の外での扱いが増える |

推奨: A

D-52 は git の項目を `include` で指定したときだけ返すと決めており、指定しなければ動きが変わらないため、まず索引から取れる項目で `view` と `include` の形を入れる。

### タグの語彙を返すツール

- 語彙のタグごとに、名前・グループ・説明・別名・振り替え先・付いている文書の数を返す読み取りのツールを置く。付いている文書が 0 件のタグも返す
- 任意の `query` を受け、名前・別名・説明に当たるタグを返す
- 読み取りのツールとして `readOnlyHint` を付ける
- ツール名は A-14 の `list_tags` とし、引数名はインターフェース定義設計で決める

### update_index

- `kind` に `tag` を加え、語彙のタグを `name` で足す・置き換える・消せるようにする
- 書く前の索引のスキーマの検査は今と同じく当て、文書のタグのオブジェクトの形も検査する

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 用語・別名・タグの一致の前の正規化（NFKC・大文字小文字） | 別の Issue の範囲 | #102 |
| 索引の `related` に関係の種類と「いつ読むか」を持たせる | 別の Issue の範囲 | #103 |
| MCP サーバーを HTTP の常駐サーバーに移す | 別の Issue の範囲 | #111 |
| 1 つのセッションで同じ内容を 1 回だけ渡す（`session_id`・`agent_id`・`repeat_seen`） | A-14 で省く対象は関連・取得の末尾の用語の一覧・同じ版の本文で、検索の各行の概要文は省かない。mdmark の MCP は本文を返す取得のツールを持たず、`find_docs` には当たる対象が無い | 予定なし |
| 区間の変更一覧 `list_changes` と、取得のツールの差分モード（`diff_from`・`diff_to`・`context_lines`） | mdmark の MCP は文書の本文を返す取得のツールを持たず、索引は文書の版を持たない。A-14 の取得と区間の変更は knowledge の MCP（shuhei1101/knowledge#44・shuhei1101/knowledge#51）の範囲 | 予定なし |
| タグを描いた文書に出す | Issue はタグを描画に使うことを求めていない | 予定なし |
