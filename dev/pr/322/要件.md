# 要件

## 要望

右側の目次の次の 2 件の不具合を修正する。

| No | 事象 | 終わりの条件 |
| --- | --- | --- |
| 1 | ピン止めしていない目次を hover で開き、目次の枠が本文の表と重なると、表の見出し行が目次の上に重なり、目次が読めない・押せない | hover で開いた目次の枠が、表の見出し行・集計の行・ピン止めした列を含む本文の全ての要素より前に出て、枠の中の項目とボタンを読めて押せる |
| 2 | 文書をスクロールすると、右側の目次の上端が見切れた状態で追従する | 文書のどこまでスクロールしても、右側の目次（右端の線と、hover で開いた枠）の上端が見切れずに出る |

単一ユースケース設計の段で、v0.9.0 と develop の配布物を、画面より低くスクロールする要素の中に描いた場合とページ全体でスクロールする場合で再現した。
MindStella のプレビューが読む mdmark は v0.8.0 で、右側の目次を持たない。報告の画面は v0.9.0 以降の配布物を読んだ画面とみなす。

| No | 再現 | 原因 |
| --- | --- | --- |
| 1 | v0.9.0・develop とも再現（hover で開いた枠の中の点で、最も手前の要素が表の見出し行のセル） | `.mdmark-side-toc` は `position: sticky` で `z-index` を持たない。表の見出し行と集計の行のセルは `z-index: 3`、ピン止めした列のセルは `4` を持つため、同じ重なりの文脈で表の見出し行が目次の枠より前に描かれる |
| 2 | v0.9.0・develop とも、文書の末尾までスクロールしたときに再現（右端の線の上端が、見えている枠の上端より 12px（ページ全体のスクロール）・191px（画面より低くスクロールする要素）上に出る。v0.9.0 は hover で開く枠も同じだけ上に出る） | 右端の線の高さが `100dvh` から決まり、`aside` が画面の高さに近い。sticky の `aside` は描く先の要素の下端を越えられないため、末尾で押し上げられる。スクロールする要素が画面より低いときは、`aside` がスクロールする場所より高くなり、押し上げられる量が増える |
