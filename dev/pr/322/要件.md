# 要件

## 要望

右側の目次の次の 2 件の不具合を修正する。

| No | 事象 | 終わりの条件 |
| --- | --- | --- |
| 1 | ピン止めしていない目次を hover で開き、目次の枠が本文の表と重なると、表の見出し行が目次の上に重なり、目次が読めない・押せない | hover で開いた目次の枠が、表の見出し行・集計の行・ピン止めした列を含む本文の全ての要素より前に出て、枠の中の項目とボタンを読めて押せる |
| 2 | 文書をスクロールすると、右側の目次の上端が見切れた状態で追従する | 文書のどこまでスクロールしても、右側の目次（右端の線と、hover で開いた枠）の上端が見切れずに出る |

No 1 の原因の見込み（develop の `src/index.css`）: `.mdmark-side-toc` は `position: sticky` で `z-index` を持たず、重なりの順は 0 のまま。表の見出し行と集計の行のセルは `z-index: 3`、ピン止めした列のセルは `4` を持つため、同じ重なりの文脈で表の見出し行が目次の枠より前に描かれる。
No 2 の原因は未確認で、MindStella のプレビューの組み込み方（スクロールする場所・留めたトップバー・`--mdmark-sticky-top` の有無）と、[#320](https://github.com/shuhei1101/mdmark/pull/320) で入れた枠の位置の計算（`followPanelPosition`）を、develop の配布物で再現して切り分ける。

`未確定`: No 2 を develop で再現できなかった場合の扱い（決める段: 単一ユースケース設計）

| 案 | 内容 |
| --- | --- |
| A | MindStella と同じ組み込み方（スクロールする場所・留めたトップバー）の結合テストで、上端が見切れないことを確かめるテストだけを追加する |
| B | 再現できた組み込み方の原因だけを修正し、再現しない組み込み方は扱わない |

推奨: A

報告は v0.9.0 の配布物で、develop には #320 の枠の位置の変更が入っているため、変更後に起きないことをテストで残すほうが、#270 で位置を作り替えたときにも退行を見つけられるため。
