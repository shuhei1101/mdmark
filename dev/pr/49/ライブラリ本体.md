## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 行の差分 | 2 つのリビジョンの Markdown を行で比べ、前にだけある行を赤、後にだけある行を緑、同じ行を色なしで並べる | 比べるのは Markdown のソースの行（[要件](./要件.md)） |
| 文字の差分 | 消した行と足した行の対を語で比べ、変わった部分だけを濃い赤・濃い緑にする。日本語は `Intl.Segmenter` の語の区切りで比べ、持たないブラウザは文字ごとに比べる | 対応ブラウザの Firefox 98〜124 は `Intl.Segmenter` を持たない。単一ユースケース『文書の差分を見る』の `Intl.Segmenter` を消したシナリオは、配布物の読み込みが例外になる [#50](https://github.com/shuhei1101/mdmark/issues/50) が直るまで通らないため、#7 は #50 に依存させ、#50 が develop に入ってからマージする |
| 差分の計算 | 行と語の比較に jsdiff（npm の `diff`）の `diffLines`・`diffWords` を使う。`Intl.Segmenter` を持つブラウザでは `intlSegmenter` に渡し、持たないブラウザでは渡さずに文字ごとに比べる | `diff@8.0.4` の 2 つの関数だけを束ねて minify すると 7,072 バイトで、`intlSegmenter` を渡すと日本語を語の単位で比べた（[レビューの実測](https://github.com/shuhei1101/mdmark/pull/49#discussion_r4330919999)）。外部ライブラリの設計書はモジュール構成設計で足す |
| ミニマップ | 差分の行の位置から、消した行・足した行の印を、画面（スクロールする枠）の右端に貼り付けた縦の帯に並べる。印と帯の操作で差分を送る | 差分の部品と一緒に、部品の引数と行の位置の渡し方を決める（[確認ログ](./確認ログ.md)）。描く先の要素がスクロールする枠の中にあっても送れるよう、送る先（一番近いスクロールする祖先か、押した位置の行への `scrollIntoView`）を部品設計とモジュール構成設計で決める。1 つのページで 2 つ以上の差分を開いたときの帯の数を部品設計で、祖先の `transform`・`filter`・`contain` で `position: fixed` の基準が変わるときの置き場所と `z-index` をモジュール構成設計で決める（[レビュー](https://github.com/shuhei1101/mdmark/pull/49#discussion_r4336642227)） |
| 取り出し元 | `DiffSource` とリビジョンの型を公開する。`revisions` と `content` の Promise を待って描き、待つ間に描き直しや片付けがあればその結果を捨てる | 入口は `mount` の引数 `diffSource`（[確認ログ](./確認ログ.md)） |
| 埋め込んだ HTML | 差分の中の `<!-- html -->` 〜 `<!-- /html -->` の範囲ごとに、既定はソースの色分けで出し、切り替えるとその範囲の前と後のリビジョンを今の埋め込んだ HTML の描画で並べる | 前か後にしか無い範囲は、ある側だけを描く |
| 部品 | リビジョンの選択・差分の行・ミニマップ・埋め込んだ HTML の切り替えを部品設計に足し、Storybook のストーリーで状態を並べる | 置き方と見た目はモック作成で決める |
| 取り出せないとき | `revisions`・`content` が reject したか、返した値がリビジョンの形に合わないときは、差分の場所に知らせの枠を出し、文書は描く | リビジョンの形が合わないときは、使う側の開発者の誤りで読む人の操作では起きないため、E2E のシナリオでなくインターフェース定義の異常系に書く |
| 色 | 差分の色を `--mdmark-color-*` の CSS 変数で持ち、ライト・ダークと使う側の上書きに乗せる | 色の値はデザイン方針に合わせる |
| アクセシビリティ | 行頭の `-`・`+` の印と読み上げの名前で、消した行・足した行を色に頼らず伝える。リビジョンの選択と切り替えはキーで操作できる | WCAG 2.2 の 1.4.1 |
| サンプルの取り出し元 | Git（コミット間）と YAML（項目ごとの変更履歴）の取り出し元を書き、テストで差分を出せることを確かめる | 使い方のページにコードとして載せる（[確認ログ](./確認ログ.md)） |
| 非機能要件 | 足した後の配布ファイル 1 つのサイズが、今のビルドの上限の検査に通ることを確かめる | 余りは約 33KB で、jsdiff の 2 つの関数（7,072 バイト）を束ねても収まる |
| シナリオの対応テストファイル | E2E テスト作成でテストファイルを置いた時点で、複合・単一ユースケースの `test_file` を足す | 書くツールは、テストファイルが無い `test_file` を書き込まない |
