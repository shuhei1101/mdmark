# 要件

## 要望

リポジトリの直下に `dev-docs.yaml` を置き、mdmark の既存の文書とファイルを dev-docs の配信元として配信する。
配信元に登録した後、`search_docs` の `group_by: tags` でタグの一覧が返り、タグで絞り込んだ `search_docs` で文書が返る。

dev-docs.yaml の書式は dev-docs の develop の `docs/リファレンス/設定.md` に従う（D-171・D-173〜D-177）。

- `documents[]` の行は、設計書の種類ごとに 1 行にする。行の `schema` は `dev/テンプレート/{種類}.schema.yaml` を指し、`metadata` は列の対応（`name: title`）だけを書く
- 行の `type`・`custom`・`defaults[]`・front matter は使わない
- Markdown・ソースコードなど YAML の設計書でないファイルは、管理用の YAML（`files.yaml`）に 1 行 1 ファイルで載せ、`records: files`・`body_file: path` の行で配信する
- `files.yaml` には、除外の条件（生成物・ロック・バイナリ・ベンダーのコード・再エクスポートだけのファイル・空のファイル）に当たらないファイルをテストも含めて全て載せる
- `files.yaml` の行の値
  - `description`: 1 文で「何を受け持つか」と「どんなときに読むか」。関数の一覧は書かない
  - `tags`: `topic`・`tool` だけ。`kind`・`scope` は付けない
  - `related`: `implements`（コード → 設計書。モジュール構成・インターフェース定義・部品設計の `implementation` と 1 対 1 のファイルは必ず書く）・`tests`（テスト → コード）・`see_also` を、コード側にだけ書く
- タグはマスターを持たない。付ける前に `search_docs` の `group_by: tags`（`source: "*"`）で使われているタグを引き、同じ意味のタグがあれば使い回す（D-169）
- `files.yaml` の行は、dev-docs の `/dev-docs:setup` が作る行を元にし、`description`・`tags`・`related` を埋める
- 配信元にした後に、dev-docs の管理の MCP `check_project` で、メタデータの列の欠け・索引に無いファイル・ファイルが無い行が 0 件になる
