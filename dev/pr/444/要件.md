# 要件

## 要望

`global-setup` が MCP の常駐サーバー（`mdmark serve`）を、規約『ローカルサーバーの立て方』の systemd --user の unit で起動できるようにする。

- unit は `~/.config/systemd/user/{サービス名}.service` に置き、`systemctl --user enable --now {サービス名}` で端末の起動時に自動で起動する
- unit には `MDMARK_PORT`・`MDMARK_CONFIG`・`MDMARK_STATE_DIR` を、tmux のセッションへ渡している値と同じ値で書く
- 起動の後は今と同じく、ポートが待ち受けるまで待ち（上限 120 秒）、`tools/list` でつながることを確かめる
- unit が既にあり待ち受けていればもう一度起動せず、待ち受けていなければ再起動する。ポートをほかのプロセスが待ち受けていれば起動しない
- tmux のセッションで動いている常駐サーバーから unit へ移すときは、tmux のセッションを閉じてから unit を起動し、同じポートに 2 つのプロセスを立てない
- `setup.js status`・`start-server` の結果、MCP の `instructions`、SessionStart の案内、`global-setup` の最後の報告に、常駐サーバーが unit と tmux のどちらで動いているか・ログの見方（`journalctl --user -u {サービス名}` か `serve.log`）・止め方を出す
- 端末の設定の Schema（`serve.tmuxSession`）を変える・キーを追加するときは、`migrations/` に移行の手順か `migrations/no-steps.yaml` の行を置く

`未確定`: unit と tmux の選び方（決める段: 単一ユースケース設計）

| 案 | 内容 |
| --- | --- |
| A | systemd --user が使える端末では unit で起動し、使えない端末（macOS・systemd を有効にしていない WSL）では今の tmux で起動する。端末の設定のキーで、どちらかに固定できる |
| B | 端末の設定のキーで選び、既定は今の tmux のままにする |
| C | unit に置き換え、tmux での起動を削除する |

推奨: A

規約の決まりに既定で合わせつつ、systemd --user の無い端末でも今と同じく `global-setup` だけで起動できるため。
