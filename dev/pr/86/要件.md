# 要件

## 要望

使う側のブラウザが読む JS の配布ファイル（`dist/index.js`・`dist/view.js`・`dist/comments.js`・`dist/viewer.js`）が、対応ブラウザの下限（Chrome 99・Firefox 98・Safari 16.4）に無い API を使っていないかを、配布物を作るたびに確かめる。
下限に無い API を見つけたら、API の名前と配布ファイルを出して終了コード 1 で止める。
有無を確かめてから使う API（`src/knowledge/dictionary.ts`・`src/diff/panel.ts` の `Intl.Segmenter` など）では止めない。
同じ設定で確かめて、v0.6.0 のソース（モジュールの最上位で `new Intl.Segmenter` を呼ぶ）を束ねた JS では止まり、作業ブランチのソースを束ねた JS では止まらない。
下限の版は `BROWSER_TARGETS` と同じ値から取り、2 か所に書かない。

確かめは、配布ファイルと同じ入口・同じ `BROWSER_TARGETS` で minify せずに束ねた JS を、MDN の browser-compat-data で下限の版と照らして行う（PoC で成立。結果は計画書『ライブラリ本体』の `## PoC 結果`）。

確かめは、`npm run build` が配布物を書いた後に、配布ファイルのサイズの検査と並べて流す。
下限に無い API を見つけたときは、サイズの上限超過と同じく書いた配布物を消す。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| `mdmark export`・`mdmark build` が [src/cli/embed.ts](https://github.com/shuhei1101/mdmark/blob/develop/src/cli/embed.ts) で束ねて埋める外部ライブラリのモジュール | 使う側が設定で指す外部のコードで、mdmark の配布物ではない | 予定なし |
| 配布ファイルの CSS が下限に無い機能を使っていないかの確かめ | CSS は下限に無い機能を当てても読み込みと公開関数は止まらない。`color-mix()` の前に不透明の値を置く書き方のように下限の版への退避を既に持ち、機械の検出は誤検出になる。判断はレビューで確定する | 予定なし |
| Safari 16.4 の実機での動作確認 | 手元（WSL2）で Safari を動かせず、クラウドの実機は費用が発生する。確かめ方を案 A に決めた場合、API の有無は静的な確かめで覆う | 予定なし |
| [dev/設計書/開発コマンド/開発コマンド.yaml](https://github.com/shuhei1101/mdmark/blob/develop/dev/%E8%A8%AD%E8%A8%88%E6%9B%B8/%E9%96%8B%E7%99%BA%E3%82%B3%E3%83%9E%E3%83%B3%E3%83%89/%E9%96%8B%E7%99%BA%E3%82%B3%E3%83%9E%E3%83%B3%E3%83%89.yaml) の『ビルド・生成』の `effects` に残る配布ファイルの古い上限（256KB） | 非機能要件『配布ファイル 1 つのサイズ』の決定値（384KB）と食い違う。今回の要望に含まれない | [#92](https://github.com/shuhei1101/mdmark/issues/92) |
| E2E『配布物をビルドして検査する』の `test_normal` が、クローンの `npm run typecheck`（`vscode/tests/integration/run.ts` の `@vscode/test-electron` が無い TS2307）で止まり、後のシナリオが走らない | develop でも同じに起きる既存の不具合で、今回の要望に含まれない | [#91](https://github.com/shuhei1101/mdmark/issues/91) |
