## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| フロントマターの判定 | 1 行目が `---` だけの行で、2 行目以降に `---` か `...` だけの行がある範囲をフロントマターとする。閉じる行が無ければフロントマターとしない | - |
| 除外 | markdown-it で解析する前に、フロントマターの範囲の改行以外の文字を空白にする（`splitFrontmatter`）。後ろの行の行番号と文字の位置が元の Markdown のまま保たれ、描く処理と参照の照合（`parseDocument`）が同じ関数を使用できる | markdown-it のブロックのルールで 1 つのトークンにする案は、描く解析器と `parseDocument` の解析器の両方にルールを足すことになり、空白にする案は 1 つの関数で済むため採らなかった |
| 機能 | 機能 `frontmatter` を追加し、既定をオフにする。設定の `features.frontmatter` と文書の `features` のマーカーで切り替える | 既定がオフの機能は `comments` と同じ扱い |
| 表示 | 機能がオンのとき、本文の先頭の閉じた折りたたみ（見出し `フロントマター`）に、フロントマターを言語 `yaml` のコードブロックのまま出す。見出し・目次・右側の目次には出さない | [確認ログ](./確認ログ.yaml) |
| 取り込む文書 | `include` で取り込む文書のフロントマターも同じく除外する | 取り込む文書のフロントマターは表示しない |
| 参照の照合 | 参照の表・本文の参照の取り出し・索引の点検も、描く処理と同じ判定の関数でフロントマターを除外してから照合する | [確認ログ](./確認ログ.yaml) |
| ページの設定 | フロントマターの後ろの `<!-- page: ... -->` を、今と同じく文書の先頭のマーカーとして解釈する | ページの設定を文書で指定するシナリオを壊さない |
| CLI・MCP | `mdmark export`・`mdmark build`・`export_html`・`build_site` は `render` の変更に従い、処理を加えない | - |
| 既存機能への影響 | 1 行目が `---` でない文書の描き方は変えない | 1 行目の `---` を区切り線として使う文書は、閉じる行があるとフロントマターになる |
| 配布物のサイズ | 配布物のサイズの検査の上限を超えない | - |
