# 要件

## 要望

文書の 1 行目が `---` だけの行で、それより後に `---` か `...` だけの行がある文書は、1 行目からその行までをフロントマターとし、描く前に本文から除外する。

- 除外したフロントマターは、段落・見出し・目次・右側の目次・用語の下線・記載の警告の対象にしない
- 除外した後も、本文の要素の元の行番号（`data-source-line`）は、元の Markdown の行番号のまま
- 機能 `frontmatter` を追加し、既定をオフにする。オンのときだけ、フロントマターを本文の先頭に本文と見分けの付く表示で出す
- 機能 `frontmatter` は、ほかの機能と同じく設定の `features.frontmatter` と文書の `<!-- features: +frontmatter -->` で切り替える
- 対象は `mount`・`render`・`mdmark export`・`mdmark build`・MCP の `export_html`・`build_site`・VS Code 拡張機能のプレビューと書き出し・取り込む文書（`include`）
- 1 行目が `---` でない文書と、閉じる行が無い文書は、今と同じ描き方にする

`未確定`: フロントマターを出すときの表示の形式（決める段: モック作成）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | キーと値の 2 列の表にし、本文の先頭の閉じた折りたたみに入れる | 本文と見分けが付き、読む人が値だけを取得できる | YAML を解釈する処理が要る |
| B | 言語 `yaml` のコードブロックのまま、本文の先頭の閉じた折りたたみに入れる | 解釈が要らず、記載したとおりに出る | 入れ子の無い短いフロントマターでも、コードとして出る |

推奨: A

Issue の一案で、`title`・`tags` のような最上位のキーと値を並べる用途が多く、表のほうが読み取りやすいため。

`未確定`: 表にするときの YAML の解釈（決める段: モジュール構成設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 最上位の `キー: 値` の行だけをキーと値にし、入れ子・複数行の値は記載した文字のまま値の欄に出す | 配布物に YAML のライブラリをまとめず、サイズの上限に影響しない | 入れ子の値は表の中で構造にならない |
| B | YAML のライブラリを配布物にまとめ、入れ子の値も構造にする | どの YAML も正しく解釈する | 配布物のサイズが増える |

推奨: A

ライブラリ本体は YAML を読み込まず、配布物のサイズを検査しているため。

`未確定`: VS Code 拡張機能での切り替え（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `mdmark.config.yaml` の `features.frontmatter` だけで切り替える（拡張機能は今と同じく `features` を `mount` に指定する） | プレビューと書き出しが同じ設定ファイルでそろう | 設定ファイルを配置せずに切り替えられない |
| B | `settings.json` に `mdmark.preview.frontmatter` を追加し、設定ファイルの値より優先する | 設定ファイルを配置せずに切り替えられる | 同じ機能の切り替えが 2 か所になる |

推奨: A

[#163](https://github.com/shuhei1101/mdmark/issues/163) で設定ファイルの読み方を CLI・MCP・VS Code 拡張機能に共通にした方針と合い、端末の設定（`settings.yaml`）で端末ごとの既定も配置できるため。
