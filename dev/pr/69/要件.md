# 要件

## 要望

mdmark のリポジトリの `vscode/` に、Markdown のプレビューを mdmark で描く VS Code 拡張機能を作る。
プレビューは独自の Webview パネルに出し、その中で mdmark の `mount` と、戻り値の `update` を呼んで描く。

| 機能 | 振る舞い |
| --- | --- |
| プレビューを開く | Markdown を開いているとき、コマンド `mdmark.openPreviewToSide`（既定のショートカット `Shift+Alt+D`、Mac は `Shift+Option+D`。エディタのタイトルにもボタンを置く）で横の列に、`mdmark.openPreview` で同じ列にプレビューを開く。ショートカットとボタンは Markdown を開いているときだけ効く |
| 配布物を読む | mdmark の配布物は同梱せず、Webview が jsDelivr の版付きの URL（`https://cdn.jsdelivr.net/gh/shuhei1101/mdmark@{タグ}/dist/`）から読む。版なしの URL は使わない |
| 読む版を決める | 設定 `mdmark.version` の既定 `latest` は、プレビューを開くときに GitHub のタグ一覧から最新の `vX.Y.Z` を選ぶ（`vscode-` で始まるタグは拾わない）。タグ一覧を取れないときは前回の版を使う。`v0.1.0` のように書くとその版に固定する |
| 描けないとき | 配布物を読めない（オフライン・版が無い）ときは、プレビューに描けない理由を出す |
| ライブ更新 | 打つたびに `mdmark.preview.updateDelayMs`（既定 300 ミリ秒）待って描き直す。`mdmark.preview.liveUpdate` が `false` のときは保存したときに描き直す。プレビューが背面から表に戻ったときは全文を送り直す |
| スクロールの同期 | エディタとプレビューのスクロールを両方向に合わせる。`mdmark.preview.scrollPreviewWithEditor`・`mdmark.preview.scrollEditorWithPreview` で片方ずつ切れる |
| テーマに合わせる | VS Code のライト・ダークに合わせてプレビューの配色を切り替える。`mdmark.preview.theme`（`auto` / `light` / `dark`。既定 `auto`）で固定できる |
| リンクを開く | 外部の URL は既定のブラウザで、`.md` へのリンクは VS Code で開き、`#` で始まるリンクはプレビューの中で移る |
| ローカル画像 | Markdown からの相対パスの画像をプレビューに出す |
| 設定ファイル | `mdmark.configPath`（既定 `mdmark.config.yaml`。ワークスペースの直下から）の `features`・`libraries` だけを `mount` に渡す。ファイルが無ければ mdmark の既定で描く。保存するとプレビューを描き直す。`libraries` の相対 URL は設定ファイルのフォルダを基準にする |
| リロード | `mdmark.refreshPreview`（コマンドパレットの表示は「mdmark: プレビューをリロード」。描けないときのボタンは「リロード」）で設定ファイルと配布物を読み直して描く |
| 設定ファイルを開く | `mdmark.openConfig` で設定ファイルを開く。無ければ雛形を作るかを尋ね、尋ねずに作らない |
| HTML に書き出す | `mdmark.exportHtml` で、開いている Markdown を mdmark で描く HTML を `mdmark.export.outputDir`（空なら Markdown と同じフォルダ）に書き出す |
| ブラウザで開く | `mdmark.openInBrowser` で書き出した HTML を既定のブラウザで開く |
| PDF に印刷 | `mdmark.printToPdf` で書き出した HTML をブラウザで開き、印刷のダイアログを出す。「PDF に保存」は印刷のダイアログで選ぶ |
| 拡張機能の版と配布 | `vscode/` に独自の `package.json` を置き、拡張機能のタグは `vscode-v{版}` にして mdmark の `v{版}` と混ぜない。GitHub Actions が `vscode-v{版}` のタグで .vsix を作り、GitHub Release に添える |

mdmark の側では次を変える。

| 変更 | 要る理由 |
| --- | --- |
| ブロックに元の行番号の属性を出し、sanitize で許す | スクロールの同期 |
| ダークの配色を、今の `prefers-color-scheme` に加えて、描く先の親の class（`vscode-dark` など）でも切り替える | VS Code のテーマに合わせる |
| Webview に組み込むときの CSP に要るものと、Webview の中では印刷が効かないことを使い方に書く | 使う側の手引き |

`未確定`: ブロックに出す元の行番号の属性名（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `data-source-line` のように、`data-line` と別の名前にする | 図の線の種類（`src/parts/diagram.ts`）と、[PR #65](https://github.com/shuhei1101/mdmark/pull/65) のコードブロックの行番号が使う `data-line` とぶつからない | VS Code の組み込みのプレビューと属性名が揃わない |
| B | `data-line` にする | VS Code の組み込みのプレビューと揃う | 図の線とコードブロックの行の `data-line` の要素を、スクロールの同期で拾い分ける必要がある |

推奨: A

`data-line` は既に図の線の種類と、コードブロックの行の番号の意味で使われており、別の意味を重ねると CSS の当たり先とスクロールの同期の拾う先が混ざる。

`未確定`: `libraries` の相対 URL を Webview で読める URL に直す場所（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | mdmark に、相対 URL を解決する基準を渡す口を足す（今は `document.baseURI` 固定） | 他の使う側も基準を変えられる | mdmark の公開の口が増える |
| B | 拡張機能が設定ファイルのフォルダを基準に絶対 URL へ直し、Webview で読める URL にして `config.libraries` で渡す | mdmark を変えない | 拡張機能が URL を直す処理を持つ |

推奨: B

Webview で読める URL への変換（`asWebviewUri`）は拡張機能にしかできず、どちらの案でも拡張機能が URL を直す処理を持つため、mdmark の口を増やす理由が無い。

`未確定`: 印刷と書き出しのコマンドをこの作業 PR に含めるか（決める段: 単一ユースケース設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 含める | Issue の要望が 1 つの作業 PR でそろう | 作業 PR が大きくなる |
| B | 別の Issue に切り出す | プレビューを先に出せる | 書き出す HTML の形をプレビューと別に決め直す |

推奨: A

書き出す HTML はプレビューと同じく jsDelivr の配布物を読んで `mount` で描く形にでき、プレビューの描き方をそのまま使える。

`未確定`: 書き出す HTML の形（決める段: 単一ユースケース設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 拡張機能が、jsDelivr の配布物を読んで `mount` で描く HTML を組む | 拡張機能だけで完結し、Node と CLI が要らない | 開くときにネットに繋がっている必要がある |
| B | mdmark の CLI の `mdmark export` を呼ぶ | 外を読まない 1 枚の HTML になる | 書く人の手元に Node 24 と CLI が要る |

推奨: A

Issue の機能一覧が「配布物は jsDelivr を参照する」としており、プレビューと同じくオフラインで描けないことを許している。

| 組み込みの Markdown プレビューへの差し込み（`markdown.markdownItPlugins`） | 組み込みは markdown-it 14 で描き、morphdom が DOM を戻すため図がチラつく。mdmark の解析器も差し込める形になっていない | 予定なし |
| mdmark の配布物の同梱と、オフラインでの描画 | mdmark を直すたびに拡張機能を上げ直すことになり、mdmark の要件「使う側へ複製して配る形は取らない」（[PR #12](https://github.com/shuhei1101/mdmark/pull/12) の要件.md）とも食い違う | 予定なし |
| 外から CSS・parser を足す口（`mdmark.config.yaml` の `theme`・`extensions` を読むことを含む） | 厚くすると Markdown Preview Enhanced と同じ土俵になる。利用者が足せるのは `features`・`libraries` と拡張機能の動きの設定だけにする | 予定なし |
| 端末の Chrome（puppeteer-core）で PDF を直接作る | Chrome が要り、WSL などで壊れやすい | 予定なし |
| Marketplace・Open VSX への公開の自動化 | 公式手順の PAT（Azure DevOps の global PAT）が 2026-12-01 に止まり、代わりの OIDC は Marketplace 側が未対応。対応したら足す | 起票予定 |
