# 要件

## 要望

描いた文書の表示を、子 Issue 2 件の終わりの条件まで改善する。
子ごとの範囲と決定事項は子の Issue の本文・コメントと、本文の `## 必読` に挙げた話し合いの記録が正。

| 子 | 終わりの条件 |
| --- | --- |
| [#269](https://github.com/shuhei1101/mdmark/issues/269) | `--mdmark-heading-rule-width` の既定値が `1px` になり、h1・h2 の下に線が出る。`docs/リファレンス/API.md` の CSS 変数の表の既定値も修正されている（線を出したくない使う側は `0` を当てる） |
| [#286](https://github.com/shuhei1101/mdmark/issues/286) | 右側の目次の上端の「目次」のラベルが無く「すべて展開」「すべて折りたたむ」「ピン止め」の 3 つのボタンだけになり、ピン止めのアイコンがモックで提示してユーザーが選んだものに変わり、hover で開く目次が Notion の出し方を調査して合わせた画面の上端寄りの位置に出る |

#269 は、追加の要望（[コメント](https://github.com/shuhei1101/mdmark/issues/269#issuecomment-6596086244)）と確認事項への回答（[コメント](https://github.com/shuhei1101/mdmark/issues/269#issuecomment-6596168217) の案 B）で、次の範囲まで広がっている。

| 要素 | 変更後 |
| --- | --- |
| 見出し 1・見出し 2 | 下に `--mdmark-heading-rule-width`（既定 `1px`）の線を引く。線の色は区切り線より薄い新しい枠線の色の CSS 変数、文字と線の間は `0.3em` |
| 見出し 3 以降 | 線を引かない（変更なし） |
| 区切り線（`hr`） | 太さを GitHub と同じ `0.25em` にする |
| 新しい枠線の色の CSS 変数 | `src/index.css` の全てのテーマのライト・ダークと、`dev/mock/assets` のテーマに追加する |

今の文書・設定はそのまま描ける。
見出しの線を出したくない使う側は `--mdmark-heading-rule-width` に `0` を当て、区切り線はレイヤーの外の CSS で上書きして以前の見た目に戻せる。

`未確定`: 新しい枠線の色の CSS 変数の名前と、テーマごとの値（決める段: モック作成）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `--mdmark-color-border-muted` を追加し、各テーマの `--mdmark-color-border` と `--mdmark-color-bg` の中間の色を値にする | 既存の `--mdmark-color-border`・`--mdmark-color-muted` の名前の付け方に揃い、GitHub の `borderColor-muted` と同じ意味で読める | テーマごとに 16 か所の値を決める必要がある |
| B | 新しい変数を追加せず、`color-mix()` で `--mdmark-color-border` を `--mdmark-color-bg` へ寄せた色を見出しの規則に直接書く | テーマごとの値が要らない | 使う側が見出しの線の色だけを上書きできない。#269 の決定（新しい CSS 変数を追加する）と食い違う |

推奨: A

#269 の確認事項の回答で新しい CSS 変数を追加すると決まっており、使う側がテーマの CSS で色を変えられるため。
値はモックで見出しの線と区切り線を並べて決め、ユーザーの合意を得る。

`未確定`: ピン止めのボタンのアイコン（決める段: モック作成）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | lucide の `panel-right`（押した後は `panel-right-close` 系の塗り）にする | 目次を右の列に留める動きを形で示せる | ピン止めの比喩から離れる |
| B | lucide の `pin` のまま、傾けずに細い線で描き、押した後は塗る | ピン止めの比喩を保てる | 今の見た目からの変化が小さい |
| C | lucide の `pin` と `pin-off` で、押す前と押した後を切り替える | 押した後に外す操作だと分かる | 押す前のアイコンは今と同じ |

推奨: A

ユーザーが良くないとしたのはピンの形の見た目で、目次を右の列に留める動きは右のパネルの形のほうが伝わるため。
モックで A・B・C を並べてユーザーが選ぶ。

`未確定`: hover で開く目次の縦の位置（決める段: モック作成）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | Notion と同じく、目次の枠を右端の線の位置によらず画面の上端から一定の余白（`--mdmark-sticky-top` を足した位置）に出し、項目が多いときは枠の中でスクロールする | 文書のどこを読んでいても同じ場所に出る。#286 の決定（画面の上端寄り）のとおり | 右端の線から枠までが離れる |
| B | 右端の線の上端に揃えて出し、枠の上端が画面の上端より下に行くときだけ画面の上端寄りへ寄せる | 線と枠が近い | 読む位置で出る場所が変わり、今の違和感が残る |

推奨: A

#286 の決定は画面の上端寄りに出すことで、Notion の出し方を調べて合わせる要件のため。
Notion の右側の目次の実際の位置はモック作成で調べ、余白の値をモックで提示する。
