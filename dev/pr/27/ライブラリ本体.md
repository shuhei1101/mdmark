## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 索引の形 | 文書と用語の 2 つの表を ER 図 `dev/設計書/ER図/索引.yaml`（新規）に書き、JSON Schema `schemas/mdmark.index.schema.json`（新規）で縛る | 索引の版は `schema` の整数 |
| 索引の受け渡し | `mount`・`render` の `opts` に、読んだ索引・描く文書の `id`・参照の表を足す。参照の表は公開する `collectReferences` が作り、インターフェース定義 `dev/設計書/インターフェース定義/ライブラリ本体/参照の表を作る.ts.yaml`（新規）に書く。mdmark は YAML とファイルを読まない | - |
| 設定 | `index`（索引のパス。使う側のサーバーと CLI が読む）と `features.glossary`・`features.backlinks` を、設定の設計書と Schema に足す | - |
| 用語集の表 | `glossary` の範囲の印を #19 の範囲の印の読み取りに載せ、`キー=値` の引数で列を指す。別名のセルは「、」と「,」で区切る | 表に無い列名は書き方の警告 |
| 用語の照合 | 解析器のトークンの上で本文の文字列を `Intl.Segmenter`（`ja`・`word`）で区切り、始まりと終わりが区切りに揃う語と別名を、長い語を先に照合する。用語の `id` ごとに節で最初に出たところだけに下線を付ける。コード・リンク・見出し・用語集の表の中は照合しない。`render` と `mount` は同じ HTML を出す | 区切り方は実行環境の辞書に依るため、対応ブラウザの実ブラウザの単体テストと Node の単体テストで、要件とシナリオの語（`印刷`・`ワークスペース` 等）の区切りを確かめる |
| ツールチップ | 用語の意味（見出し「用語」）と、文書の別名に一致した文書（見出し「関連文書」）を、下線の要素の隣の本文の要素として出す。`mount` がポインター・フォーカス・Esc の操作を付け、`update` で付け直し、`destroy` で外す | #6 の `data-hint` のツールチップが同じ部品を使える形にする |
| 文書の別名 | 索引の文書の `aliases` を、用語と同じ照合（語の区切り・節ごとに最初の 1 回・長い語を先に）に載せる | 用語と文書の別名が同じ語のときは、1 つの下線に両方を出す |
| 被参照 | 被参照の一覧を部品にし、算出した参照の表から文書の末尾に「関連文書」の題で描く。リンクの `href` は描いた文書の `path` から見た参照元の相対パスにする | - |
| 点検 | 索引と、文書のパスの一覧と本文を受けて、ずれの一覧を返す関数を公開し、インターフェース定義 `dev/設計書/インターフェース定義/ライブラリ本体/索引を点検する.ts.yaml`（新規）に書く。ファイルを読むのは呼ぶ側（#9・#11） | 索引の形は TypeScript で検査し、`schemas/` の Schema とキー・型・必須が食い違わないことを単体テストで確かめる（配布物に検査のライブラリを束ねない） |
| 印刷 | 印刷の CSS で用語の下線とツールチップを外す | - |
| サニタイズ | 用語の下線・ツールチップ・被参照の一覧の要素・属性・class を許可に足す。索引の値は Markdown として解析せず、文字として出す | mdmark が出した要素にだけ付ける `data-mdmark-own` に載せる |
| アクセシビリティ | 下線の要素をフォーカスでき、意味だけのツールチップは `aria-describedby` で指して `role="tooltip"` を持つ。関連文書のリンクを持つツールチップは、キーボードで中のリンクへフォーカスを移せる非モーダルの枠にする | 枠の作法（WAI-ARIA の役割と、フォーカスの出入り）は部品設計で決める |
| 性能 | 束ねた後の配布ファイル 1 つのサイズが、非機能要件の上限に収まる | - |
| 既存機能への影響 | 索引を渡さず、用語集の表も無い文書の出力を変えない | - |
