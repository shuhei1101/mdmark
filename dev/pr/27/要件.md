# 要件

## 要望

文書を書く人が索引に文書のメタデータと用語を書くと、mdmark が描いた文書の用語と文書の別名に、意味と関連文書のツールチップが付き、文書を参照している文書の一覧が出る。
本文の表を印で囲むと、その表の用語も用語集に入る。
使う側は、索引と文書のずれを点検の処理で見つけられる。

<!-- table: data -->

| 項目 | 要件 |
| --- | --- |
| 索引 | 使う側が YAML の索引に、索引の版（`schema`）・文書（`id`・`path`・`title`・`description`・`aliases`・`tags`・`related`）・用語（`id`・`term`・`aliases`・`meaning`）を書く。文書の `path` は索引のファイルからの相対パス、`related` は関連する文書の `id`。索引の形を JSON Schema（`schemas/`）で縛る |
| 索引の場所 | 設定ファイルの `index` に索引のパスを書く。mdmark はブラウザでファイルを読まず、使う側のサーバーが読んだ索引のオブジェクトと、描く文書の `id` を `mount`・`render` に渡す |
| 用語のツールチップ | 索引の用語と、用語集の表から入れた用語の語・別名が本文に出たら、破線の下線を引き、ポインターを乗せたときとフォーカスしたときに意味のツールチップを出す。ツールチップは Esc で消え、ツールチップの上にポインターを移しても消えない（WCAG 1.4.13）。同じ用語（語と別名を合わせた用語の `id`）は節ごとに最初に出たところだけに付ける。語の始まりと終わりが本文の語の区切り（`Intl.Segmenter` の `word` の区切り）に揃うところだけを照合し、長い語の一部（`印刷` の中の `印`）には付けない。コード・リンク・見出し・用語集の表の中の語には付けない。ツールチップの見出しは、意味を「用語」、文書の別名に一致した文書を「関連文書」にする |
| 文書の別名 | 索引の文書の `aliases` に一致した本文の語にも、用語と同じ規則で破線の下線を付け、ツールチップの「関連文書」に、一致した文書の題・描いた文書の `path` から見た相対パスのリンク・`description` を出す。用語にも一致するときは、用語 → 関連文書の順に並べる。件数が多くて収まらないときは、ツールチップの中をスクロールする。描いた文書自身は出さない。「節ごとに最初に出たところだけ」は文書の `id` ごとに数え、用語とは別に数える（用語を数え終えた語でも、文書の別名として節で初めて出たなら、「関連文書」だけのツールチップで下線を付ける） |
| 用語集の表 | `<!-- glossary: term=列名 meaning=列名 aliases=列名 -->` 〜 `<!-- /glossary -->` で囲んだ表の、用語・意味・別名の列から用語を入れる。`term`・`meaning` は必須、`aliases` は任意で、別名のセルは「、」か「,」で区切る（「・」は別名の中の文字として扱う）。索引を渡したときは、ほかの文書の用語集の表から入れた用語も効く。同じ語が複数あるときは、索引の `terms`・描く文書の表・ほかの文書の表（索引の `docs` で先に並ぶ文書）の順で優先する |
| 被参照 | 被参照は保存せず、索引の `related`・本文の文書間のリンク・文書の別名の出現から描くときに算出する。描いた文書の末尾に、その文書を参照している文書（自分自身を除く）の一覧を「関連文書」の題で、文書の題と、描いた文書の `path` から見た相対パスのリンクで出す。用語が出る文書の一覧は出さない |
| 参照の表 | 索引と全ての文書の本文を受けて、文書ごとの被参照と、各文書の用語集の表の用語をまとめた参照の表を返す関数（`collectReferences`）を公開する。使う側のサーバーと #9 のビルドがこの表を作り、`mount`・`render` に渡す。表を渡さないときは、被参照を索引の `related` だけから出し、ほかの文書の用語集の表の用語を照合しない |
| 点検 | 索引に無い文書・索引にあって消えた文書・`related` の切れた `id`・用語の重複（索引の `terms` どうし・索引の `terms` と用語集の表・用語集の表どうし）・Schema に合わない索引を見つけ、ファイル・場所・種類・内容の一覧で返す処理を持つ。CLI の `mdmark check`（#9）と MCP の `check`（#11）がこの処理を呼ぶ |
| 機能のオン・オフ | 用語のツールチップを `glossary`、被参照の一覧と文書の別名（下線とツールチップの「関連文書」）を `backlinks` の機能にし、設定の `features` と文書の `<!-- features: +機能 -機能 -->` で切り替えられる。既定はオン。オフの `glossary` は用語集の表を普通の表として描く。オフの `backlinks` は末尾の一覧を出さず、文書の別名だけに一致する語に下線を付けず、ツールチップから「関連文書」の区分を外す |
| 索引を渡さないとき | 用語集の表から入れた用語だけでツールチップを付け、被参照を出さない。索引も用語集の表も無い文書の出力は今と変わらない |
| 印刷 | 印刷では用語の下線を外し、ツールチップを出さない。被参照の一覧は、リンクの後ろに URL を出す今の印刷の扱いで出す |
| 書き手の誤り | 索引が Schema に合わないときも、用語集の表の列名が表に無いときも、本文の描画を止めない。用語集の表の誤りは、その箇所の書き方の警告で知らせる |
| `render` と `mount` | `render` の HTML 文字列は、スクリプトを動かさなくても用語の意味と被参照の一覧を読める。ツールチップの操作は `mount` が付け、`update` で付け直し、`destroy` で外す |
| アクセシビリティ | 下線の付いた用語と文書の別名はキーボードでフォーカスでき、ツールチップの意味を読み上げで伝える。関連文書のリンクを持つツールチップは、キーボードで中のリンクへフォーカスを移せる枠にする。用語であることを色だけで見分けさせない |
| スクリプト | 文書に書いたスクリプト（`script` 要素・イベント属性・`javascript:` の URL）を実行しない今の条件を、索引の値（題・意味など）にも当てる |
| 完了の基準 | 索引と用語集の表を持つ見本の文書群を、ビルドした配布物を読むページで `mount` すると、用語のツールチップと被参照が出て、点検の処理がずれを返し、非機能要件の対応ブラウザの E2E が通る |
