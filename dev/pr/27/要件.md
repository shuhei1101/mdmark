# 要件

## 要望

文書を書く人が索引に文書のメタデータと用語を書くと、mdmark が描いた文書の用語に意味のツールチップが付き、文書を参照している文書の一覧が出る。
本文の表を印で囲むと、その表の用語も用語集に入る。
使う側は、索引と文書のずれを点検の処理で見つけられる。

<!-- table: data -->

| 項目 | 要件 |
| --- | --- |
| 索引 | 使う側が YAML の索引に、索引の版（`schema`）・文書（`id`・`path`・`title`・`description`・`aliases`・`tags`・`related`）・用語（`id`・`term`・`aliases`・`meaning`）を書く。文書の `path` は索引のファイルからの相対パス、`related` は関連する文書の `id`。索引の形を JSON Schema（`schemas/`）で縛る |
| 索引の場所 | 設定ファイルの `index` に索引のパスを書く。mdmark はブラウザでファイルを読まず、使う側のサーバーが読んだ索引のオブジェクトと、描く文書の `id` を `mount`・`render` に渡す |
| 用語のツールチップ | 索引の用語と、用語集の表から入れた用語の語・別名が本文に出たら、破線の下線を引き、ポインターを乗せたときとフォーカスしたときに意味のツールチップを出す。ツールチップは Esc で消え、ツールチップの上にポインターを移しても消えない（WCAG 1.4.13）。同じ用語は節ごとに最初に出たところだけに付ける。コード・リンク・見出し・用語集の表の中の語には付けない |
| 用語集の表 | `<!-- glossary: term=列名 meaning=列名 aliases=列名 -->` 〜 `<!-- /glossary -->` で囲んだ表の、用語・意味・別名の列から用語を入れる。`term`・`meaning` は必須、`aliases` は任意で、別名のセルは「・」か「,」で区切る。索引の `terms` と同じ語があれば索引を優先する |
| 被参照 | 被参照は保存せず、索引の `related`・本文の文書間のリンク・用語の出現から描くときに算出する。描いた文書に、その文書を参照している文書の一覧を出す。用語にも、その用語が出る文書を出す |
| 点検 | 索引に無い文書・索引にあって消えた文書・`related` の切れた `id`・用語の重複（索引の `terms` どうしと、索引の `terms` と用語集の表）・Schema に合わない索引を見つけ、ファイル・場所・種類・内容の一覧で返す処理を持つ。CLI の `mdmark check`（#9）と MCP の `check`（#11）がこの処理を呼ぶ |
| 機能のオン・オフ | 用語のツールチップを `glossary`、被参照を `backlinks` の機能にし、設定の `features` と文書の `<!-- features: +機能 -機能 -->` で切り替えられる。既定はオン。オフの `glossary` は用語集の表を普通の表として描く |
| 索引を渡さないとき | 用語集の表から入れた用語だけでツールチップを付け、被参照を出さない。索引も用語集の表も無い文書の出力は今と変わらない |
| 書き手の誤り | 索引が Schema に合わないときも、用語集の表の列名が表に無いときも、本文の描画を止めない。用語集の表の誤りは、その箇所の書き方の警告で知らせる |
| `render` と `mount` | `render` の HTML 文字列は、スクリプトを動かさなくても用語の意味と被参照の一覧を読める。ツールチップの操作は `mount` が付け、`update` で付け直し、`destroy` で外す |
| アクセシビリティ | 下線の付いた用語はキーボードでフォーカスでき、読み上げでは `role="tooltip"`・`aria-describedby` で意味を伝える。用語であることを色だけで見分けさせない |
| スクリプト | 文書に書いたスクリプト（`script` 要素・イベント属性・`javascript:` の URL）を実行しない今の条件を、索引の値（題・意味など）にも当てる |
| 完了の基準 | 索引と用語集の表を持つ見本の文書群を、ビルドした配布物を読むページで `mount` すると、用語のツールチップと被参照が出て、点検の処理がずれを返し、非機能要件の対応ブラウザの E2E が通る |

<!-- /table -->

`未確定`: 被参照の算出に要る、ほかの文書の本文の渡し方（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `mount`・`render` には索引と文書の `id` だけを渡し、被参照は `related` だけから出す | 渡すものが増えない | 本文のリンクと用語の出現からの被参照が、描くときに出ない |
| B | 索引と文書の本文を受けて参照の表を返す関数を公開し、使う側のサーバーが算出した表を `mount`・`render` に渡す | 描くたびにほかの文書の本文を渡さずに済み、#9 のビルドも同じ関数を使える | 使う側のサーバーが表を作って持つ |
| C | `mount`・`render` にほかの文書の本文も渡す | 使う側が算出の手順を持たない | 描くたびに全ての文書の本文を読み、解析する |

推奨: B

本文のリンクと用語の出現から算出する要望を、ファイルを読めないブラウザでも満たせ、描く処理は表を引くだけで済む。

`未確定`: 文書と用語の被参照の見せ方（決める段: モック作成）

| 案 | 内容 |
| --- | --- |
| A | 文書の末尾に、参照している文書の一覧の節を置く。用語の被参照はツールチップの中に出す |
| B | 文書の題の下に件数を出し、押すと一覧を開く。用語の被参照は用語集の表の行に出す |

推奨: A

本文を読み終えた場所で次に読む文書を選べ、`render` の HTML でも一覧として読める。
