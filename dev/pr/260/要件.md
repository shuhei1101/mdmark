# 要件

## 要望

mdmark の MCP サーバーが出すツールから `find_docs`・`list_tags`・`update_index` をなくす。

- `tools/list` が返すツールは `read_guide`・`export_html`・`build_site`・`check` の 4 つにする。外した 3 つの名前で `tools/call` を呼ぶと、MCP SDK が知らないツールとして返すエラーになる
- `read_guide`・`export_html`・`build_site`・`check` の引数・戻り値・挙動は変えない
- プラグインの PreToolUse のフックは、`project_dir` を入れる対象を `check`・`export_html`・`build_site` だけにする（`plugin/hooks/hooks.json` の `matcher` と `src/plugin/pre-tool-use.ts` の `PROJECT_DIR_TOOLS`）
- 3 つのツールからしか使っていないライブラリの関数・型・定数（`findDocs`・`listTags`・`countTags`・`updateIndexFile`・`applyIndexUpdate`・`requireIndexWithDocuments`・`src/plugin/results.ts` の `find_docs`・`list_tags` の結果の整形など）を、実装・設計書・テストから外す。`check` など残る処理が使うもの（`buildTagVocabulary`・`resolveTag`・`nearestTag`・`readDocTag` など）は残す
- 索引（`mdmark.config.yaml` の `index`）のスキーマと、描画・点検での索引の使い方（用語集・被参照・`check` のずれの検出）は変えない。索引のスキーマの説明文から 3 つのツールの名前を外すため、移行の手順が要らない変更として `migrations/no-steps.yaml` に行を置く
- 3 つのツールを説明する設計書・公開ドキュメント・使い方集（`plugin/guide/`）から、3 つのツールの記述を外す
- 確かめる基準: `mdmark serve` で起動した常駐サーバーへつないだクライアントの `tools/list` が 4 つのツールを返し、`src/`・`plugin/hooks/`・`schemas/`・`docs/`・`dev/設計書/`・`plugin/guide/`・`tests/` に `find_docs`・`list_tags`・`update_index` の名前が残らない（`docs/はじめに/変更履歴.md` の過去の行を除く）

| 項目 | 理由 | 対応予定 |

| 索引のタグの語彙（最上位の `tags`）と、語彙に無いタグの点検をやめる | 要望は索引そのものを変えない。語彙は 3 つのツールが主な使い道だが、`check` のずれの検出にも使っている | #179 |

| `dist/`・`plugin/scripts/` の配布物から 3 つのツールを外す | 配布物は release でバージョンごとに入れ直す（`v0.9.0 の配布物を入れる` など）。作業 PR では入れない | 予定なし |

| 文書と UI 文言の語の修正 | 語の選び方の修正は別の Issue が扱い、この PR の後に入れる | #105 |
