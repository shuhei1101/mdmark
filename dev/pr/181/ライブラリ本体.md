## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| テーマの値の組 | `src/index.css` の `@layer mdmark` の中に、テーマごとの明るい配色と暗い配色の `--mdmark-color-*` の値を置く。今の値を既定のテーマにする | テーマは既定のテーマと theme-paper・theme-slate・theme-contrast（[要件](./要件.md)） |
| テーマの当て方 | 描く先の要素にテーマを示す class か属性を付け、今の明暗の class と同じく `:root:has()` で当てる | class か属性かはモジュール構成設計で決める |
| 設定のキー | `mdmark.config.yaml` にテーマを選ぶキーを追加する。既存の `theme` とは別の名前にし、知らない名前は既定のテーマにする | キー名はインターフェース定義設計で決める |
| 書き出し | `mdmark export`・`build` は、設定で選んだテーマを書き出す HTML の描く先に当てる | MCP の `export_html`・`build_site` は同じ処理を呼ぶ |
| 点検 | `mdmark check` は、知らないテーマの名前をずれとして返す | - |
| 移行 | `schemas/mdmark.config.schema.json` の変更に、`migrations/no-steps.yaml` の行を置く | 既存の設定はそのまま通る |
| 既存機能への影響 | テーマを選ばない使う側の見た目は今と同じ。使う側の CSS は選んだテーマより勝つ | - |
| アクセシビリティ | 全テーマの明るい配色と暗い配色で、本文・リンク・注意書きの文字と地のコントラストを今の配色と同じ基準で満たす | - |
| 性能 | テーマの値の組を足した後も、配布物の CSS のサイズを非機能要件の上限に収める | - |
