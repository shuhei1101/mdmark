# 要件

## 要望

文書を書く人が、描いた文書の配色を mdmark に入れた複数のテーマから設定で選べるようにする。
VS Code のプレビューを見ながら、プレビューから mdmark の設定を開いて変えられるようにする。

<!-- table: data -->

| 項目 | 振る舞い |
| --- | --- |
| テーマの置き場所 | テーマは mdmark 本体の配布物（`dist/index.css`）に入れ、デザイントークン（`--mdmark-color-*` の CSS 変数）の値の組で作る。テーマごとに明るい配色と暗い配色の組を持つ |
| テーマに入れる変数 | 配色の変数（`--mdmark-color-*` と `color-scheme`）だけ。配置の変数（`--mdmark-content-width`・`--mdmark-table-max-height`・余白・角丸）と書体の変数は入れず、全テーマで共通にする |
| 選べるテーマ | 既定のテーマに加え、theme-paper・theme-slate・theme-contrast の 3 つを入れる（[確認ログ](./確認ログ.md)） |
| 既定のテーマ | 今の配色（開発者ツール × スイス）を既定のテーマとして残す。テーマを選ばない使う側の見た目は変わらない |
| 明暗との組み合わせ | 選んだテーマの中で、今の明暗の決め方（OS の設定・`mdmark-theme-light` / `mdmark-theme-dark` の class・`mdmark.preview.theme`）がそのまま明暗を選ぶ |
| 使う側の CSS | 使う側が層の外に書いた CSS（設定の `theme` の CSS を含む）は、選んだテーマより勝つ |
| ライブラリ本体の設定 | `mdmark.config.yaml`（`mount` の `opts.config`）にテーマを選ぶキーを追加する。既存の `theme`（使う側の CSS のパス）の意味は変えず、別の名前のキーにする。知らないテーマの名前は既定のテーマにする |
| テーマを選ぶ設定の置き場所 | `mdmark.config.yaml` のキーを正にし、VS Code の設定にも同じ選択を持たせる。VS Code の設定が設定ファイルに勝ち、VS Code の設定が空のときは設定ファイルに従う |
| 書き出し | `mdmark export`・`mdmark build`（MCP の `export_html`・`build_site` を含む）は、設定で選んだテーマで描く HTML を書き出す |
| 点検 | `mdmark check` は、テーマを選ぶキーに知らないテーマの名前があるとずれとして返す |
| 印刷 | 印刷では選んだテーマの明るい配色を使う |
| VS Code のプレビュー | プレビューは選んだテーマで描く。設定を変えるとリロードせずに描き直す |
| 設定を開くコマンド | コマンドパレットに mdmark の設定を開くコマンドを追加し、VS Code の設定画面を mdmark の項目に絞って開く |
| プレビューのボタン | VS Code のエディタのタイトルバー（`editor/title`）にプレビューのときだけ歯車のボタンを出し、押すと VS Code の設定画面を mdmark の項目に絞って開く |

<!-- /table -->

`schemas/` を変えるので、`migrations/no-steps.yaml` に移行の手順が要らない行を置く（既存の設定はテーマを選ぶキーを持たないまま通る）。

## スコープ外

<!-- table: data -->

| 項目 | 理由 | 対応予定 |
