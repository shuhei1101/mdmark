# 要件

## 要望

既存の記法・点検へ、子 Issue 7 件の項目を追加する。
子ごとの範囲と決まったこと（検討事項 D-8〜D-10・D-12・D-24・D-25・D-50・D-51・D-70〜D-75・D-201）は子の Issue の本文と、本文の `## 必読` に挙げた話し合いの記録が正。
今の書き方（グラフの 4 種類と 4 系列・表のマーカーの引数・タブ・注意書きの `[!種類]` と `-`・コードの行の 3 つのマーカー）は、そのまま同じ見た目で描ける。

| 子 | 終わりの条件 |
| --- | --- |
| [#159](https://github.com/shuhei1101/mdmark/issues/159) | 面・積み上げ・横棒・ドーナツ・レーダー・バブル・折れ線と棒の組み合わせなどを描け、5 つ以上の系列を色・点のマーカー・塗りの模様の組でライトとダークの両方で見分けられる |
| [#183](https://github.com/shuhei1101/mdmark/issues/183) | `header-rows=N`・`row-header=N` と `^^`・`<<` で多段の見出し・行見出し・セルの結合を描き、並べ替え・絞り込みの後は隣り合う同じ値だけを結合し直し、ボタンを最下段の見出しに置く |
| [#187](https://github.com/shuhei1101/mdmark/issues/187) | `mdmark check`（MCP の check）が、ブラウザー無しで定義の誤り・ノードの重なり・はみ出し・線の横切り・ラベルの長さをずれとして返す |
| [#191](https://github.com/shuhei1101/mdmark/issues/191) | タブのマーカーの入れ子の開きと閉じが対応し、見出しの太字のタブ名がタブのボタンでも強調され、見た目をデザイントークンで変えられる |
| [#216](https://github.com/shuhei1101/mdmark/issues/216) | 注意書きが種類の後ろのタイトル・`+`・入れ子を受け、コードの行末の `[!code focus]`・`[!code error]`・`[!code warning]` を描く |
| [#244](https://github.com/shuhei1101/mdmark/issues/244) | テーブル・列・関係の定義から ER 図を描き、拡大・縮小・移動・全画面・ツールチップが既存の図の部品とそろい、列の多いテーブルを畳め、使い方集の diagrams に書き方がある |
| [#249](https://github.com/shuhei1101/mdmark/issues/249) | tree を除くすべてのコードブロックでインデントによる畳む・開く（Shift で入れ子もまとめて）と縦線が付き、`fold=` で最初から畳め、コピーは畳んだ行も含む |

グラフの種類を増やす描き方（#159）: 設計のライブラリ選定で A に決定した（d3-shape・Chart.js・Apache ECharts と比べた[案のスレッド](https://github.com/shuhei1101/mdmark/pull/275#discussion_r4450490072)）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 今の SVG のグラフの部品のまま種類と系列を追加する | 書き出した HTML が外部へ要求しない 1 枚のまま。図の枠・凡例・見た目の決まりを今の部品と共有できる | 種類ごとの描画を自前で書き、配布物が大きくなる |
| B | Chart.js を、グラフのある文書でだけバージョンを固定した URL から読む | 種類の多さと描画の品質をライブラリに任せられる | 書き出しへの埋め込みと、図の枠・凡例・色と模様の組の見た目の決まりへの合わせ込みが要る。canvas で描くため #160（項目の値のツールチップ）の作りが変わる |

推奨: A

書き出した HTML を外部へ要求しない 1 枚にする決まりと、色・点のマーカー・塗りの模様の組で系列を見分ける今の見た目の決まりを、そのまま保てるため。

モックの確認で、ユーザーの指摘により次を追加する（[確認ログ](./確認ログ.md)）。

- 表: 並べ替えの順を既定 → 降順 → 昇順 → 既定にし、見出し行と本文の行の地の色を分ける。帯のボタン「列の表示」を「列設定」、「絞り込みを外す」を「絞り込みを解除」にし、UI の文言を漢語・外来語に統一する。並べ替えの順と絞り込みの欄の文言は、同じ操作を持つビューの表形式にも当て、コピーできないときの知らせの文言はファイルツリーにも当てる（既存の表・ビュー・ファイルツリーも変わる）
- コード: 畳んだ行の ⋯ を押しても展開する。帯の言語のラベルとファイルのアイコンの間隔を広げる
- ER 図: テーブルの種類（マスター・トランザクション）を見出しの札と種類の既定の色で示し、`color=` でテーブルの色を指定できる

タブの入れ子の数え方（#191）: モジュール構成設計で A に決定した（タブの読み取りの `findTabsClose` で入れ子を数え、共通の `findClose`（`src/render/syntax/tokens.ts`）は変えない）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 共通の `findClose` は変えず、タブの読み取りの中で入れ子を数える | タブ以外のマーカーの閉じの対応を変えない | 他のマーカーで入れ子が要るときに同じ処理を書く |
| B | 共通の `findClose` で入れ子を数える | 全てのマーカーで入れ子が対応する | 表・ステップ・行の詳細・ビュー・図・用語集・HTML の閉じの対応も変わり、回帰の範囲が広がる |

推奨: A

要望はタブの入れ子だけで、他のマーカーの閉じの対応を変える理由が無いため。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| ビューのマーカーで囲んだ表での多段の見出し・`^^` の引き継ぎ | ビューは表のマーカーの読み取りを使い回すが、要望は表のマーカーの表だけを挙げる。ボード表示は列の値でカードを分けるため、ビューで読むかは別に決める。ここではビューの表は対象外とし、確定はレビューへ持ち越す | 予定なし |
| 共通の `findClose` での入れ子の対応（タブ以外のマーカーの入れ子） | 要望はタブの入れ子だけ（`## 要望` の推奨 A） | 予定なし |
| ヘッドレスブラウザーで描いて実際の文字の幅で測る図の点検 | D-12 で見送った案 B | 予定なし |
| 注意書きの種類の追加（success・question・example など） | D-50 で見送った案 B | 予定なし |
| グラフの点・棒・円の項目の値のツールチップ | 別の要望 | #160 |
| 表の列の並べ替え | 別の要望。#183・#245 の後に入れる | #184 |
| 設定の表のキーの列の階層と折りたたみ | 別の要望。#249 の操作と揃える後続 | #250 |
| dev-docs の汎用の描画の見直し（ER 図をこの部品で出す） | dev-docs リポジトリの作業。#244 の完了後に着手できる旨を連絡する | 予定なし |
| はみ出す表の既定のピン止め・`pin=`・`wide=`・真偽値の ✓ 表示（#245） | task-planner の指示で切り出し、先に完了させる | #283 |
