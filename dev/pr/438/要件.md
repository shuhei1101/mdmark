# 要件

## 要望

<!-- table: data -->

| 項目 | 要件 |
| --- | --- |
| 選んだ列だけを留める | ピン止めのボタンを押した列だけが留まる。複数の列を選べ、留めた列のボタンをもう一度押すとその列だけを解除する |
| 留める位置 | 留めた列は、その列より左を表示している間は表の右端に、その列を過ぎて右へスクロールした後は左端に留まる。複数の列を留めたときは、左端・右端のそれぞれで留めた列が重ならずに並ぶ |
| 動きの切り替え | 選んだ列だけを留める動きと、今の「押した列までを留める」動きを設定で選べる。既定は選んだ列だけを留める動き |
| ボタン | ピン止めのボタンは増やさない（列ごとに 1 つのまま） |
| 既存の動きとの兼ね合い | 既定のピン止め（行見出しの列・先頭の列）・`-pin`・`pin=`・表がはみ出す間だけ留めること・列の表示の切り替え・列の並べ替え・多段の見出し・印刷を、新しい動きでも成り立たせる |

<!-- /table -->

`未確定`: 既定を変えた後の `pin=列名` の意味（決める段: 単一ユースケース設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 設定の動きに従う（選んだ列だけの動きでは、`pin=` の列だけを留める）。移行の手順は作らない | 記法の意味が設定の動きに統一される | 既存の文書で `pin=` の列より左の列が留まらなくなる |
| B | 設定の動きに従い、`mdmark upgrade` の移行の手順で、既存の設定に今の動きを書き込む | 既存の文書の見え方がバージョンを上げても変わらない | 移行した利用者は、新しい既定の動きを自分で選び直す必要がある |
| C | `pin=` はどちらの動きでも「その列までを留める」のまま、選んだ列だけの動きはボタンを押したときだけにする | 既存の文書の見え方が変わらない | 描いた直後と、押した後で留め方が違う |

推奨: A

Issue の「既定は選んだ列だけを留める動きにする」に合わせ、記法の意味を設定の動きで 1 つに決められる。`pin=` に複数の列名を記載できるようにすれば、今の見え方も記載で作り直せる。

`未確定`: 設定のキーの名前と値（決める段: 単一ユースケース設計）

| 案 | 内容 |
| --- | --- |
| A | `table.pin: each`（既定）/ `through` |
| B | `features.table` をオブジェクトにして `pin` を持たせる |

推奨: A

既存の設定は `side-toc.mode` のように機能ごとのキーで値を持っており、`features.table` の真偽値の意味を変えずに済む。
