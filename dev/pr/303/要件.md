# 要件

## 要望

既存の記法へ、子 Issue 3 件の項目を追加する。
子ごとの範囲と決まったこと（検討事項 D-2・D-76〜D-86）は子の Issue の本文と、本文の `## 必読` に挙げた話し合いの記録が正。
追加する項目は全て既定でオフか、マーカーの引数を記載した表・範囲だけに効き、今の文書は同じ見た目で描ける。

| 子 | 終わりの条件 |
| --- | --- |
| [#184](https://github.com/shuhei1101/mdmark/issues/184) | 表の機能に列の並べ替え（既定はオフ）があり、見出しのドラッグ＆ドロップと、キーボードでも使える列のメニューの左右へ動かす操作で列を動かせる。見出しのボタン（並べ替え・絞り込み・ピン止め）とドラッグの当たり判定が分かれ、ピン止めした列との兼ね合いと、多段の見出し（#183）で結合した見出しの下の列の動かし方が決まっている |
| [#241](https://github.com/shuhei1101/mdmark/issues/241) | `<!-- html -->` の範囲の HTML に、同じ範囲の `css`（その範囲の HTML にだけ当てる）と `ts`・`js`（既定のエクスポートの関数を範囲の根の要素で呼ぶ）で見た目と動きを追加でき、設定の機能（既定はオフ）でオンにしたときだけ動く。`export`・`build` の書き出しでも動く。型を外す場所・範囲ごとに許すか・Schema と移行の手順が決まっている |
| [#250](https://github.com/shuhei1101/mdmark/issues/250) | 表のマーカーの引数 `tree=キー` で 1 つの列をドットと `[]` で区切った階層で描き、表に無い親の行の補完・末尾の名前とツールチップ・全体のパスのコピー・#249 と揃えた折りたたみ・型のバッジと必須の *・親を残す絞り込み・行の選択の縦線がある。`example=` などで YAML の見本と結び、表と見本の行が連動し、見本の表示の切り替えとタブがある（見本の書き方と設定.md の置き換えの扱いが決まっている） |

`書き出した HTML を 1 つの script に束ねる #189 との関係`（#241）: #189 は develop へ入っている。
書き出した HTML では、範囲の `ts`・`js` を #189 の束ねた 1 つの script に加え、`blob:` URL と動的 `import()` を使わずに動かす。

`未確定`: TypeScript の型を外す場所と配布物のサイズ（#241。決める工程: 設計のライブラリ選定）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 書き出しは CLI が今の依存の esbuild で変換して束ね、`mount` と VS Code のプレビューは範囲に `ts` がある文書でだけ、変換のライブラリをバージョンを固定した URL から読む（配布物に束ねない） | 配布物のサイズの上限（512KB、今は約 507KB）を超えない。書き出した HTML は外へ要求しない 1 枚のまま | 変換のライブラリを外部ライブラリとして採用し、読めないときの知らせの枠が要る |
| B | 変換のライブラリを配布物に束ねる | 外へ要求せずにどの経路でも変換できる | 配布物のサイズの上限を大きく超え、全ての利用者が読む量が増える |
| C | `js` だけを許し、`ts` は書く人が変換してから記載する | 変換が要らない | 終わりの条件の `ts` を満たさない |

推奨: A

色分けのライブラリと同じく使う文書でだけ読む扱いにでき、配布物のサイズと書き出した HTML の決まりをそのまま保てるため。

範囲ごとにも許すか（#241）: 単一ユースケース設計で A に決定した（設定の `features.html-scripts`、既定はオフ。文書の `<!-- features: +html-scripts -->` で上書きできる）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 設定の機能（例 `features.html-scripts`、既定はオフ）だけで許す。文書の `<!-- features: +html-scripts -->` での上書きは今の機能と同じ優先順で効く | 記法が増えない。オン・オフの仕組みが他の機能と同じ | 1 つの文書の中で範囲ごとに許す・許さないを分けられない |
| B | A に加えて、`<!-- html: script -->` のように範囲ごとに許す | 範囲ごとに分けられる | 範囲のマーカーの引数が増え、機能のオン・オフと二重の判定になる |

推奨: A

範囲ごとに分けたい要望は Issue に無く、文書の単位のオン・オフで足りるため。

`未確定`: 範囲の `css` を範囲の HTML にだけ当てる手段（#241。決める工程: モジュール構成設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | セレクタの前に範囲の根の要素の属性を付けて書き換える | 対応ブラウザの下限（Chrome 99・Firefox 98・Safari 16.4）で効く。範囲の中の mdmark の部品（チャート・ヒント・用語のツールチップ）に `dist/index.css` がそのまま当たる | `@media` などの入れ子の規則も書き換える処理が要る |
| B | `@scope` で囲む | 書き換えが要らない | 対応ブラウザの下限で効かない |
| C | 範囲の HTML を Shadow DOM に入れる | 外の CSS と完全に分かれる | 範囲の中の mdmark の部品に `dist/index.css` が当たらず、用語のツールチップなどの位置の計算も変わる |

推奨: A

対応ブラウザの下限を変えずに、範囲の中の mdmark の部品の見た目と操作を今のまま保てるため。

結合した見出しの下の列とピン止めした列の動かし方（#184）: モック作成で A に決定した（[確認ログ](./確認ログ.md)）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 結合した見出しの下の列はその見出しの範囲の中だけで動かし、ピン止めした列とピン止めしていない列の境はまたがせない | 多段の見出しとピン止めの範囲が崩れない | 範囲の外へは動かせない |
| B | どこへでも動かし、動かした後に結合とピン止めの範囲を決め直す | 自由に動かせる | 結合した見出しが分かれ、ピン止めの範囲が変わる |

推奨: A

結合した見出しとピン止めは書く人が決めた構造で、列を動かす操作で変わると読む人が元の表と対応を取れなくなるため。

YAML の見本の結び方と表示の既定（#250）: モック作成で A に決定した。見本は表の下に置く（[確認ログ](./確認ログ.md)）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 表のマーカーの引数 `example=見出し` で、その見出しの下の `yaml` のコードブロックを見本にし、複数の見本はタブのマーカー（`tabs`）で切り替える。見本は既定で表示する | 今のタブの記法を使い回せる。マーカーに対応しない表示（GitHub）では見出しとコードブロックのまま読める | 表と見本が離れた場所に記載される |
| B | 表のマーカーの範囲の中に `yaml` のコードブロックを並べる | 表と見本が 1 か所にまとまる | 表のマーカーの範囲に表以外の中身を置く読み取りが要る |

推奨: A

D-85 の例の書き方のまま、複数の見本の切り替えを既存のタブの部品で表せるため。

`docs/リファレンス/設定.md` の表を `tree=` の書き方へ置き換えるか（#250）: 単一ユースケース設計で A に決定した

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 置き換える | 要望の発端の表で効果を確かめられ、記法の見本にもなる。キーの列は全体のパスのままなので GitHub でも読める | 公開ドキュメントの差分が大きくなる |
| B | 置き換えない | 差分が小さい | 要望の発端の困りごとが残る |

推奨: A

`tree=` はキーの列の文字を変えずに描き方だけを変えるため、置き換えても GitHub での読み方は今と同じで、困りごとだけが解消するため。

モックの確認で、ユーザーの指摘により次を変更する（[確認ログ](./確認ログ.md)）。

- 表の列の並べ替え（#184）: 見出しに列の操作を置かず、表の上の帯の「列設定」を「テーブル設定」（アイコンだけのボタン。名前はツールチップと読み上げ）に変え、列名の一覧で表示・非表示（目のアイコン）と並べ替え（つまみのドラッグ＆ドロップと ↑・↓ キー）をまとめる。今の `+columns` の一覧（チェックボックス）も目のアイコンに置き換わる
- #172（PR #308）との進め方: #308 のマージを待って取り込み、アイコンだけのボタンとバッジは #172 のまま、名前と一覧だけを変える

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| ビューのマーカーで囲んだ表での列の並べ替え・`tree=` | ビューは表のマーカーの読み取りを使い回すが、要望は表のマーカーの表だけを挙げる。ここではビューの表は対象外とし、確定はレビューへ持ち越す | 予定なし |
| 階層の表の並べ替え | D-81 で付けないと決めた | 予定なし |
| キーから同じ名前の見出しへの § のリンクの自動の付与 | D-86 で見送った案 B | 予定なし |
| 長い説明を 1 行で切り「続きを見る」で開く | D-82 で見送った案 B | 予定なし |
| 列の表示・非表示のボタンのアイコン化とメニューの見出しの見直し | 別の要望。同じ表の見出しの帯を触るが、どちらを先に入れても相手の変更を作り替えない | #172 |
