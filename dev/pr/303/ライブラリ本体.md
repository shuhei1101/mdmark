## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 列の並べ替え（#184） | 表の機能に列の並べ替え `+reorder` を追加し、どの種類にも既定では入れない。表の上の帯のテーブル設定（アイコンだけのボタン）の列名の一覧で、つまみのドラッグ＆ドロップと、つまみにフォーカスして ↑・↓ キーで列を動かす | モック作成で決定（確認ログ） |
| 当たり判定（#184） | 列を動かす操作を見出しに置かず、テーブル設定の一覧に分ける。見出しのボタン（並べ替え・絞り込み・ピン止め）を押しても列は動かない | モック作成で決定 |
| 結合とピン止めとの兼ね合い（#184） | 結合した見出しの範囲の中だけで動かし、ピン止めの境をまたがせない。テーブル設定の一覧を、ピン止めの列・範囲・範囲の外の列に分ける | モック作成で A に決定 |
| 列の順の保ち方（#184） | 並べ替え・絞り込み・結合し直しの後も、読む人が動かした列の順を保つ。ページを開き直すと Markdown に記載した順に戻る | 単一ユースケース設計で決定 |
| 階層の表（#250） | 表のマーカーの引数 `tree=キー` で指定した列を、ドットと `[]` で区切った階層で描き、表に無い親の行を薄い斜体のキーだけで補う。末尾の名前・インデント・縦線で親子を示し、ポインターを乗せると全体のパスのツールチップ、⧉ で全体のパスをコピーする | 決まったことは D-76〜D-80・D-83 |
| 折りたたみ（#250） | 子を持つ行に ▾・▸ を縦線の後ろ・キーのすぐ左に出し、Shift で入れ子もまとめて畳む・開く。既定は開く。操作は #249 のコードブロックの折りたたみと揃える | D-79 |
| 型・必須・既定（#250） | 表のマーカーの引数 `type=列名`・`required=列名`・`default=列名`（`tree=` の表でだけ読む）で列を指定する。型は色の違うバッジ、`a \| b` の列挙は値のチップ、必須の列は出さずにキーの後ろの赤い *、既定は薄い等幅で出す | 単一ユースケース設計で決定 |
| 絞り込みと並べ替え（#250） | 絞り込みは当たった行の親の行も残し、当たった単語に色を付ける。`tree=` の表には行の並べ替えを付けない | D-81 |
| 行の選択（#250） | 行を押して選ぶと、同じ親を持つ行の範囲にその階層の縦線を濃く引き、もう一度押すと解除する | D-84 |
| YAML の見本（#250） | `example=見出し` とタブのマーカーで見本を結び、表の下に置いて既定で表示する。表の行を押すと見本の行に色を付け、見本の行を押すと表の行を選ぶ。選んだキーが開いたタブに無いときは見本に色を付けない。表示の切り替えは「見本を隠す」「見本を表示」のボタン（`aria-expanded`） | モック作成で A に決定 |
| テーブル設定（#184・#172） | 今の「列設定」のボタンと一覧を「テーブル設定」に置き換え、`+reorder`・`+columns` のどちらかがある表に置く。#308 のマージを待って取り込み、アイコンだけのボタンと隠した列の数のバッジは #172 のまま、ツールチップと読み上げを「テーブル設定」にし、一覧を目のアイコンとつまみにする | モック作成で決定（確認ログ） |
| 範囲に置ける言語（#241） | 範囲に置けるコードブロックを `html`（1 つ・必須）・`css`・`ts`・`js` にする。`ts` と `js` はどちらか 1 つ | 同じ言語を 2 つ置いた範囲は今と同じく書き方の警告にする |
| 範囲のスクリプトの機能（#241） | 設定の機能 `features.html-scripts`（既定はオフ）でオンにしたときだけ `css`・`ts`・`js` を当てる。オフのときは今のとおり `html` だけを描き、`css`・`ts`・`js` のコードブロックはコードのまま出す。差分のプレビューでは動かさない | 範囲ごとには許さない（単一ユースケース設計で決定） |
| 範囲の `ts`・`js`（#241） | 既定のエクスポートの関数を、範囲の HTML の根の要素を引数に呼び、返した `destroy` を描き直しと片付けのときに呼ぶ | 型を外す場所は要件の `## 要望` の `未確定`（推奨 A） |
| 範囲の `css`（#241） | 範囲の HTML にだけ当てる | 手段は要件の `## 要望` の `未確定`（推奨 A） |
| 範囲の `html`（#241） | 機能がオンでも、範囲の `html` に記載した `<script>`・`on` で始まる属性・`javascript:` の URL は今のとおり落とす | 動きは範囲の `ts`・`js` だけで追加する |
| 書き出し（#241） | `mdmark export`・`mdmark build` は範囲の `ts` を変換し、#189 の束ねた 1 つの script に加える。`blob:` URL と動的 `import()` は使わない | 変換に使う esbuild は CLI の今の依存 |
| Schema と移行の手順（#241） | `schemas/mdmark.config.schema.json` の `features` に省いてよい機能のキーを追加し、範囲のスクリプトの設定の下に省いてよい変換のライブラリの URL のキー（`syntax.url` と同じ構造。既定は `https://cdn.jsdelivr.net/npm/@babel/standalone@8.1.1/+esm`。名前はインターフェース定義設計で決める）を追加し、`migrations/no-steps.yaml` に行を追加する（古い設定もそのまま新しい Schema に合う） | 既定はオフで、今の設定の読み方は変わらない |

| 印刷 | 印刷の前に畳んだ階層の行と隠した YAML の見本を開き、印刷の後に戻す | 単一ユースケース設計で決定 |

結論: 成立。
範囲の `ts` を esbuild の `transform`（`loader: ts`・`format: 'iife'`・`globalName`）で変換し、既定のエクスポートを範囲ごとの登録の関数へ渡す形にすると、書き出した HTML でも VS Code のプレビューの CSP の下でも、CSP を緩めずに範囲の根の要素で呼べる。
VS Code の経路では、配布物がページの `script[nonce]` の `nonce` プロパティを読み、範囲のコードを同じ nonce を付けた `script` 要素で動かす。
変換した範囲のコードは 1,438 バイトで、登録の関数と呼び出しの処理を合わせても配布物のサイズへの影響は小さい。

設計のライブラリ選定へ引き継ぐ条件: ブラウザで型を外す変換のライブラリは、純粋な JS で動き、`eval`・`new Function`・WebAssembly・Worker を使わないものに限る（VS Code のプレビューの CSP に `'unsafe-eval'`・`'wasm-unsafe-eval'`・`worker-src` が無いため）。

最小再現コードの要点（[poc/html-scripts/run.mjs](https://github.com/shuhei1101/mdmark/blob/da2f32fc5af13a4570fb4c36b1bc5b3e02eb5936/poc/html-scripts/run.mjs)）:

- `compileRange`: esbuild の `transform` で ts を IIFE にし、`window.__mdmarkHtmlScripts.register(id, __mdmarkRange.default)` で包む。両経路で同じ変換結果を使う
- `distJs` の `mount`: `document.querySelector("script[nonce]")?.nonce` を読み、`script.nonce = nonce` と `textContent` に範囲のコードを入れた `script` 要素を `head` へ追加し、登録した関数を `[data-mdmark-html-root]` の要素で呼ぶ
- `RUNTIME` の `rerender`: 返った `destroy` を呼んでから呼び直す
