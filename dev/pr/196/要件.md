# 要件

## 要望

文書を書く人が、VS Code の差分ビューで見ている Markdown の変更を、mdmark で描いたプレビューの上で、追加・変更した箇所が色分けされた状態で読めるようにする。

<!-- table: data -->

| 項目 | 振る舞い |
| --- | --- |
| 対象の差分ビュー | 変更前と変更後の両方が Markdown のテキストの差分ビュー（Git の作業ツリーの変更・ステージした変更・コミットの差分を含む） |
| 変更前と変更後の取得 | 差分ビューの 2 つの側の URI から、拡張機能が変更前と変更後の Markdown を読む。Git の履歴を拡張機能が自分で読まない |
| 表示の場所 | 既存の mdmark のプレビューのパネルに描く。差分ビューから開いたプレビューは、開いた時点で差分を出した状態にする |
| 色分け | 追加した箇所と変更した箇所を、削除した箇所と見分けられる色で出す。色は `--mdmark-color-diff-*` の CSS 変数で取り、選んだテーマ（[#120](https://github.com/shuhei1101/mdmark/issues/120)）がそのまま当たる。色が見分けられなくても、マーカーと読み上げの名前で追加・削除を区別できる |
| 変更後の側の書き換え | 変更後の側が書き換えられる文書（作業ツリーのファイル）なら、書き換えると、今の描き直しの設定（`mdmark.preview.liveUpdate`）に従って差分を描き直す |
| 差分ビューでない場合 | 差分ビューでないエディタから開いたプレビューは、今のとおり 1 つの文書を描く |
| 差分に対応しない mdmark のバージョン | `mdmark.version` で差分に対応しないバージョンを読んだときは、描けない理由をプレビューに出す |

<!-- /table -->

決定: 色分けを、描いた結果の上に出すか、Markdown のソースの行に出すか（B に決定。[確認ログ](./確認ログ.md)）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 既存の差分表示（[#7](https://github.com/shuhei1101/mdmark/issues/7)）を開いた状態で出す。色分けは Markdown のソースの行で、埋め込んだ HTML の範囲だけ描いた結果に切り替えられる | ライブラリ本体の追加が開いた状態で描く指定だけで済む | 見出し・表・図は描いた結果で比べられず、Issue の「mdmark でレンダリングした状態」に当たらない |
| B | 変更後の文書を描き、追加・変更したブロックに追加の色を当て、削除したブロックを削除の色でその位置に差し込んで出す | Issue の「レンダリングした状態で、追加・変更した箇所が色分けされた形」に当たる | ライブラリ本体に、描いた結果のブロックと Markdown の差分を対応づける描き方を新しく作る |
| C | B を既定で出し、既存の差分表示（A）に切り替えられる | 行の中の語の違いを A で確かめられる | 切り替えの UI と、2 つの描き方の両方を保つ |

推奨: B

Issue が求めているのは描いた結果の上での色分けで、A では見出し・表・図の変更を描いた形で読めない。
行の中の語の違いは、VS Code の差分ビューそのものが左右に並べて出しているので、プレビューに A を重ねて持たせる必要は薄い。

決定: プレビューを差分で開く操作（A に決定。[確認ログ](./確認ログ.md)）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 差分ビューで既存の「プレビューを横に開く」（`mdmark.openPreviewToSide`）を押すと、差分で描いたプレビューを開く | 覚える操作が増えない | 差分ビューで変更後の文書だけのプレビューを開く手段が無くなる |
| B | 差分で開く別のコマンドを追加し、差分ビューのエディタのタイトルバーにだけボタンを出す | 文書だけのプレビューと差分のプレビューを選べる | コマンドとボタンが 1 つ増える |

推奨: A

差分ビューを開いている人が見たいのは変更で、変更後だけのプレビューは差分ビューの外で開けば足りる。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 差分ビューの 2 つの側以外のリビジョン（Git の履歴）をプレビューで選び直すこと | 要望は差分ビューで見ている変更を読むことで、リビジョンは差分ビューを開く側（VS Code の Git の機能）で選べる | 予定なし |
| Markdown でない文書の差分ビュー | mdmark が描くのは Markdown だけ | 予定なし |
| Source Control のグラフから開く複数ファイルの差分エディター | タブの入力のクラスが stable API に無く、型で変更前と変更後を引けない。実行時の `textDiffs[]` は提案中の API の構造で、変わっても型の検査で気づけない（[PoC 結果](./VSCode拡張機能.md)）。グラフからは 1 ファイルの差分ビューを開いてからプレビューを開く | 予定なし |
| VS Code の webview の React への移行 | 別の目的の作業で、この PR は今のバニラ TS の webview に差分を加える | [#173](https://github.com/shuhei1101/mdmark/issues/173) |
