結論は成立。
要件.md の位置の表し方を、行と行の中の始まりと終わりで確定した。

見本は、段落の 1 行と複数行・リストの入れ子・引用の入れ子・表のセル・強調の中・エスケープ（`\*`）・実体参照（`&amp;`・`&#x30EF;`）・同じ語が先に行内のコードとリンクの文字にある行・リンクの URL に別名の綴りがある行・見出し・字下げした段落・埋め込んだ HTML とその中の実体参照の後ろ・`<!-- flow -->` の定義とその中の JSON のエスケープ（`\"`・`\u30a2`）の後ろ・HTML の中の `<mdmark-flow>` の定義。
検証のスクリプトは `parseDocument` と同じコアルールの解析器を使い、`render` が描く文書のほかの記法のコアルール（注意書き・タブなど）は通さない。
照合の範囲（`matchableChildren` が選ぶ `text` の子）はほかの記法のコアルールに左右されないため、結論はこの違いに左右されない。
見本に入れていない参照形式のリンク（`[文字][ref]`）・画像の中の文字・HTML のブロック（コードブロックでない生の HTML）は、モジュール構成設計で戻し方を決め、単体テストに見本として入れる。

最小再現コードの要点（`poc/term-position.ts`）。

```ts
// 本文の cursor から、照合した文字を 1 文字ずつ当て、各文字の本文の位置を返す
function align(body: string, cursor: number, text: string): { offsets: number[]; end: number } {
  const offsets: number[] = [];
  let at = cursor;
  for (let i = 0; i < text.length; ) {
    const char = text[i] as string;
    if (body.startsWith(char, at)) { offsets.push(at); at += 1; i += 1; continue; }
    // エスケープ（\*）は 2 文字で 1 文字
    if (body[at] === "\\" && body[at + 1] === char) { offsets.push(at); at += 2; i += 1; continue; }
    // 実体参照（&amp;）は戻した文字の長さぶん同じ位置を指す
    const entity = /^&(#\d+|#x[0-9a-f]+|[a-z0-9]+);/i.exec(body.slice(at));
    if (entity) { /* decodeHTML した文字が続けば、その長さぶん進める */ }
    // 記法の記号・字下げ・引用の印など、文字に出ない本文の文字を飛ばす
    at += 1;
  }
  offsets.push(at);
  return { offsets, end: at };
}
```

diff の見どころは `inlineOffsets`（子のトークンの種類ごとに本文の cursor を進める。`code_inline` は記号と中身を、`link_close` は `](…)` を入れ子の括弧ごと飛ばす）と、表のセルで同じ行から始まる行内のトークンを前のセルの続きから当てるところ。
