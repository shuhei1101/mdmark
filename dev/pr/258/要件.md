# 要件

## 要望

使う側が `mount` の `opts.config` に `labels.paramCopy`（文字列）を渡すと、操作できる部品の今の値をコピーするボタン（`button.mdmark-param-copy`）のアイコンの後ろの文字をその文言で描く。

- 省いたとき・文字列でないとき・空文字のときは、今の「今の値を写す」で描く（ボタンの読み上げの名前が空にならないようにする）
- ボタンの読み上げの名前は、描いた文字と同じ文言にする（ボタンの文字から名前が付く今の作りのまま、`aria-label` は付けない）
- 部品を描き直したとき（`mount` の `update` など）も、同じ設定の文言で描く
- `render` に渡した `opts.config` でも同じ文言で描く
- `mdmark.config.yaml` に書いた `labels.paramCopy` は、`mdmark export`・`mdmark build`（MCP の `export_html`・`build_site` も同じ処理）が書き出す 1 枚の HTML に埋める設定にも写し、開いたときに同じ文言で描く
- `mdmark.config.yaml` の `labels` がマップでない・`labels.paramCopy` が空でない文字列でないときは、`tooltips.placement` と同じく、`mdmark check` は `schema` のずれ、`mdmark export`・`mdmark build` は設定ファイルの誤り（終了コード 1）にする
- 設定の JSON Schema に `labels.paramCopy` を追加し、移行の手順が要らない変更として `migrations/no-steps.yaml` に行を置く
- `labels` は部品の文言の設定をまとめるマップにする。この PR で持つキーは `paramCopy` だけにし、知らないキーは読まずに残す（`features` の知らない名前と同じ扱い）
- 確かめる基準: `labels.paramCopy: "コピー"` を渡して描いた文書で、`button.mdmark-param-copy` の `textContent` が `コピー`、読み上げの名前が `コピー` になり、スライダーを動かして部品の一部を描き直した後も変わらない

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| VS Code 拡張機能のプレビュー・書き出す HTML へ `labels` を通す | 拡張機能は `mdmark.config.yaml` から `features`・`libraries`・`side-toc`・`colorTheme` だけを取り出して渡しており、`labels` を通すには拡張機能の設定の読み取りとテンプレートの修正が要る。要望は `mount` と 1 枚の HTML で、拡張機能を挙げていない。この PR の `labels` が入ってから成り立つ | 起票予定 |
| 写した結果の知らせの文言と、写せなかったときの JSON の読み上げの名前を設定で替える | 要望はボタンの文言だけ | 予定なし |
| 既定の文言「今の値を写す」の語の修正 | 語の選び方の修正は別の Issue が扱う | #105 |
