# 要件

## 要望

- フロー図のノードの種類 `dm` の既定の `tag`・凡例の名前・CSS 変数 `--mdmark-color-diagram-dm` の説明を、利用側の固有の用語「意思決定モデル」を含まない汎用の名前にする
- 使用方法・リファレンス・見本・設計書・モック・Storybook・テストから「意思決定モデル」を無くす（`dev/pr/` を除き、develop で `git grep "意思決定モデル"` が 0 件）
- 使用方法『図を描く』に、判定の質問のノードは `question`、`dm` は別の用途であることを示し、判定の質問のノードを描く人が `question` を選べるようにする

`未確定`: `dm` の扱いと表示名（決める段: 単一ユースケース設計。表示名は画面に出る名称のためユーザーへ確認する）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `dm` のキーを残し、表示名だけを汎用の名前（「判断（AI）」など）に替える | 既存の文書の `dm` がそのまま描ける。破壊的変更にならない | `question` と意味が近く、使い分けの説明が要る |
| B | `dm` を廃止して `question` に統一し、`dm` を指定した文書に書き方の警告で移行を促す | 同じ用途の種類が 1 つになる | 既存の文書が警告になり、`破壊的変更` と移行の手順が要る。構成図の LLM のレイヤーに配置する判断用のノードの種類が無くなる |

推奨: A

`dm` は構成図の LLM のレイヤーに配置する判断用の処理のノードで、判定フローチャートの質問（`question`）とは配置する図が違う。
キーを残せば既存の文書と CSS 変数を変えずに修正できる。
