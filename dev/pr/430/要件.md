# 要件

## 要望

`npm run test:unit`（全件）で、`tests/unit/scripts/baseline.test.ts` の `test_to_browserslist` が時間切れで失敗しないようにする。
`scripts/baseline.ts` の読み込みの時間を、最初のテストの待ちから除外する。
ファイルの 19 件のテストの検証の内容は変えない。

終わりの条件:

- 単体テストの全件実行が pass する
- `baseline.test.ts` の最初のテストの所要時間に `scripts/baseline.ts` の読み込みの時間が含まれない

読み込みの時間の除外の方式は案 A にする（単体テスト作成で確定）。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `baseline.test.ts` で `scripts/baseline.ts` を `beforeAll` で 1 回読み、各テストはその結果を使用する。`beforeAll` の待ちは `hookTimeout` で読み込みに見合う値にする | 読み込みの時間がテストごとの待ちから除外され、unit の全テストの待ちは変えない | テストの準備の書き方が他の `scripts/` の単体テストと統一されなくなる |
| B | `vitest.config.ts` の unit の `testTimeout` を 30 秒より大きくする | 1 行の変更で済む | unit の全テストの待ちが延び、本当に止まったテストの検出が遅れる。同じ値を負荷に合わせて広げ続けることになる |

推奨: A

時間切れの元は読み込みの時間を最初のテストが負う作りで、待ちの上限を広げても負荷が増えれば再び起きる。
