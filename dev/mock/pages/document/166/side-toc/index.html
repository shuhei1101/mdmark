倉庫ごとの在庫と出荷の数を、毎朝の点検で確かめる手順をまとめた文書です。数は毎朝 9 時の棚卸しの結果で更新します。

点検は、第一倉庫・第二倉庫・冷蔵室の 3 か所を、担当者が順に回って行います。点検の結果は、その日の出荷の前までに記録します。

初めて点検を担当する人は、この節を読んでから使い方の節へ進みます。点検の順番と記録の書き方は、倉庫によらず同じです。

点検の途中で在庫の数が合わないときは、その場で数え直し、合わない数と棚の番号を記録に残します。

点検の担当者は、倉庫の入館証と、在庫の文書を開ける端末を持っています。端末は社内の無線 LAN につながっている必要があります。

冷蔵室の点検には防寒着が要ります。冷蔵室の中にいる時間は、1 回につき 15 分までにします。

棚卸しの結果が 9 時までに出ていないときは、前日の数で点検し、記録にその旨を書きます。

在庫の文書は、Chrome と Edge の最新版で開きます。スマホでは閲覧だけができます。

古いブラウザで開くと、表の並べ替えと右側の目次が使えないことがあります。

点検は、毎朝の点検と、出荷の前の点検の 2 つに分かれます。どちらも同じ記録の表に書きます。

毎朝の点検は全ての棚を回り、出荷の前の点検はその日に出荷する品の棚だけを回ります。

記録の表は、倉庫ごとの節に置いてあります。点検が済んだ棚には、点検した時刻と担当者の名前を書きます。

9 時の棚卸しの結果が出たら、第一倉庫から順に回ります。棚の札と在庫の文書の数を見比べ、合わない棚を記録します。

第一倉庫の次は第二倉庫、最後に冷蔵室を回ります。冷蔵室は温度の記録も合わせて確かめます。

全ての棚を回ったら、合わなかった棚の数を倉庫ごとに合計し、記録の表の最後の行に書きます。

合わなかった棚が 5 つを超えるときは、倉庫の責任者へ知らせ、棚卸しをやり直すかを決めてもらいます。

出荷の 1 時間前に、その日に出荷する品の棚を回ります。出荷する数が棚に揃っているかを確かめます。

揃っていない品は、出荷の担当者へ知らせ、出荷の数を減らすか、別の倉庫から回すかを決めてもらいます。

臨時便の出荷があるときは、臨時便の 30 分前にも同じ点検をします。

点検の記録を CLI で 1 枚の HTML にまとめるときは、端末の環境ごとに Node.js を入れます。

Windows

winget で Node.js を入れてから、点検の CLI を使います。

Windows の注意

PowerShell の実行ポリシーで npx が止まるときは、管理者でない端末から実行します。

macOS

Homebrew で Node.js を入れてから、点検の CLI を使います。

macOS の注意

Apple シリコンの端末では、Homebrew の入る場所が /opt/homebrew になります。

点検の手順に書いていない場面の扱いです。普段の点検では開かなくて構いません。

停電や端末の故障で在庫の文書を開けないときは、紙の点検表に書き、復旧してから記録の表へ写します。

停電で 9 時の棚卸しの結果が出ていない朝は、前日の紙の点検表を使って第一倉庫から回ります。

点検で使う言葉と、記録の表の列の意味です。

棚卸しは、倉庫の全ての品の数を数え、在庫の文書の数を実際の数に合わせる作業です。毎朝 9 時に結果が出ます。

点検は、棚卸しの結果と棚の札が合っているかを、担当者が見て確かめる作業です。

臨時便は、決まった便の外に出す出荷です。数量は前日の夕方に決まります。

倉庫・棚の番号・在庫の数・点検した時刻・担当者の 5 つの列を持ちます。

合わなかった棚は、在庫の数の列に実際に数えた数を括弧で添えます。
