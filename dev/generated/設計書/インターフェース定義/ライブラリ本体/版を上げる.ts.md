# 版を上げる

> 種類: operation<br>
> 値: `mdmark upgrade [--plan] [--yes] [--config {設定ファイル}]`（CLI。`npx github:shuhei1101/mdmark#v{目標の版} upgrade` で呼ぶ）<br>

文書を書く人が、設定の手元の版から呼んだ CLI の版までの移行の手順を版の順に設定・索引・文書へ当て、`mdmark check` と同じ点検が通ったら設定の `version` を呼んだ CLI の版にする。当てる前に写しを取り、失敗したら写しから戻す。

tests/integration/lib/upgrade.test.ts

True

設定・索引・文書を書き換え、設定ファイルのあるフォルダの `.mdmark/backup/{日時}/` に写しを置く。`--plan` は何も書き換えない

排他しない。同じフォルダで同時に流さないことを前提にする

## リクエスト

| パラメータ | 型 | 必須 | デフォルト | 置き場所 | 説明 | 例 |
| --- | --- | --- | --- | --- | --- | --- |
| --plan | boolean | - | false | argument | 何も書き換えず、当てる版ごとの手順・変更履歴の行・壊す手順の有無を出す | - |
| --yes | boolean | - | false | argument | 壊す印のある手順を、確かめずに当てる。値を聞く手順と手元の版の問いは飛ばさない | - |
| --config | string | - | なし（今のフォルダから上のフォルダへ順に `mdmark.config.yaml` を探し、最初に見つかったものを使う） | argument | 使う設定ファイルのパス | docs/mdmark.config.yaml |
| 標準入力 | string | - | なし（問いが無ければ読まない） | argument | 問いへの答え。問い 1 つに 1 行を読む。問いは手元の版（設定に `version` が無いとき）→ 値を聞く手順（当てる順）→ 壊す手順の確かめ（`--yes` が無いとき）の順に出す | v0.3.0 |

## レスポンス

| フィールド | 型 | 説明 | 補足 |
| --- | --- | --- | --- |
| 標準出力 | string | `手元の版: {版}`・`目標の版: {版}` の後に、当てる版ごとに `{版}:` の行と手順 1 つ 1 行（`  {種類}: {説明}`。壊す印のある手順は種類の後ろに `（壊す手順）`）、`変更履歴:` の行と変更履歴の行 1 つ 1 行（`  {バージョン} {PR} {変更}`）を出す。最後に、当てたときは `写し: {パス}` と `版を {目標の版} にしました`、`--plan` のときは `--plan のため書き換えていません`、当てる手順が無いときは `手元の版が目標の版と同じです。当てる手順はありません` を出す | 写しのパスは設定ファイルのあるフォルダからの相対パス。手順のない版は行を出さない |
| 標準エラー | string | 問いの文と、誤りの原因と直し方の 1 文。点検が通らないときは、`mdmark check` と同じ形のずれの行を出す | - |
| 終了コード | 0 \| 1 | 当てたとき・`--plan` で示したとき・当てる手順が無いときは 0、それ以外は 1 | - |

```text
手元の版: v0.3.0
目標の版: v0.5.0
v0.4.0:
  rename_key: `build.out` を `build.output` に改める
v0.5.0:
  replace_mark（壊す手順）: 印 `<!-- note -->` を `<!-- callout -->` に書き換える
変更履歴:
  v0.4.0 #40 版を上げるときに移行の手順を当てる mdmark upgrade を作る
  v0.5.0 #45 注意書きの印の名前を揃える
写し: .mdmark/backup/20261017120000
版を v0.5.0 にしました
```

## 例外

| 例外 | 発生条件 | 補足 |
| --- | --- | --- |
| なし（正常終了） | 手順を当てて点検が通り、版を書き換えた。`--plan` で示した。手元の版が目標の版と同じ。終了コード 0 | - |
| 壊す手順を断った（終了コード 1） | `--yes` が無く、壊す手順の確かめに `y` 以外を答えた | 何も書き換えず、写しも取らない。`--yes` で確かめずに当てられることを出す |
| 手順の失敗（終了コード 1） | 手順を当てる途中で、`call` のスクリプトが 0 以外で終わったか、ファイルを書けなかった | 写しから戻し、失敗した版・手順の説明・理由を出す |
| 点検のずれ（終了コード 1） | 全ての手順を当てた後の点検でずれが 1 件以上ある | 写しから戻し、ずれの行を出す |
| 手元の版が新しい（終了コード 1） | 手元の版が呼んだ CLI の版より新しい | 手元の版と目標の版と、`npx github:shuhei1101/mdmark#{手元の版} upgrade` など手元の版以上の CLI で呼び直すことを出す |
| 手元の版の書式の誤り（終了コード 1） | 設定の `version` か、問いへの答えが `v{MAJOR}.{MINOR}.{PATCH}` に合わない | 書式を示す |
| 答えが無い（終了コード 1） | 問いに答える前に標準入力が終わった | 何も書き換えない。答える問いを出す |
| 手順のファイルの誤り（終了コード 1） | 当てる版の `steps.yaml` が読めないか、`schemas/mdmark.steps.schema.json` に合わないか、`call` のスクリプトが無い | 何も書き換えない。版と合わないところと、mdmark を入れ直すことを出す |
| 設定ファイルが無い・読めない（終了コード 1） | `--config` のファイルが無い、今のフォルダと上のフォルダに `mdmark.config.yaml` が無い、または YAML として読めない | `mdmark check` と同じ文を出す |

## 制約

| 項目 | 制約 | 決定値 | 補足 |
| --- | --- | --- | --- |
| 目標の版 | ビルドが呼んだ CLI（`dist/cli.js`）に埋めた版（ライブラリ本体の `version()` と同じ出所）。`version.ini` は読まない。引数では受けない | - | hotfix のビルドは `version.ini` を上げず `--version` で打つタグの版を埋める。引数で古い版を受けると、呼んだ CLI の形で点検して目標の版では正しい設定を戻してしまう |
| 手元の版 | 設定の `version`。無ければ標準エラーに `手元の版（v{MAJOR}.{MINOR}.{PATCH}）を入れてください:` を出し、標準入力の 1 行を手元の版にする（`--plan` のときも聞く） | dev/設計書/設定/ライブラリ本体#settings[version] | - |
| 版の比較 | `v{MAJOR}.{MINOR}.{PATCH}` の 3 つの数を左から数として比べる | - | - |
| 当てる版 | パッケージの `migrations/` の直下の `v{版}` のフォルダのうち、手元の版より新しく目標の版以下のものを版の昇順に当てる。`migrations/next/` は読まない | dev/設計書/ER図/移行の手順#tables[migrations/{版}/steps.yaml] | - |
| 手順の検め | 当てる全ての版の `steps.yaml` を、問いと書き換えの前に `schemas/mdmark.steps.schema.json` で検める。1 つでも合わなければ何も書き換えない | - | - |
| 問いの順 | 手元の版 → 値を聞く手順（当てる順。キーが既にある `set_default` は聞かない）→ 壊す手順の確かめ（`--yes` が無く壊す印の手順が 1 つ以上あるとき 1 回だけ）の順に、全て書き換えの前に聞く。`--plan` では手元の版だけを聞く。確かめは `y` だけを承諾とする | - | - |
| 写し | 書き換えの前に、設定ファイルと、手順が書き換えうる全てのファイル（`file`・`files` が指すものと、`replace_mark` の対象の文書）を、設定ファイルのあるフォルダの `.mdmark/backup/{yyyymmddHHMMSS}/` へ、そのフォルダからの相対パスを保って写す。`.mdmark/.gitignore`（中身は `*`）が無ければ置く。当てた後も消さない | - | 日時は利用者の手元の時刻 |
| 戻し | 手順の失敗か点検のずれで、写しの全てのファイルを元の場所へ書き戻す。`call` のスクリプトは `files` に挙げたものだけを書き換える | - | - |
| 当て直し | `rename_key` は元のキーがあり新しいキーが無いときだけ名前を変え、他は何もしない。`set_default` はキーが無いときだけ足す。`map_values` は値が読み替えの表の元の値のときだけ替える。`replace_mark` は `from` を `to` に書き換える（`to` は `from` を含まない）。`call` のスクリプトは当て直しても結果が変わらないように書く | dev/設計書/ER図/移行の手順#tables[migrations/{版}/steps.yaml] | 写しから戻せずに止まっても（Ctrl-C など）、次の `upgrade` が同じ手元の版から当て直せる |
| YAML の書き換え | 設定と索引はコメント・キーの並び・触らないキーの書き方を残して書き換える | dev/設計書/外部ライブラリ/yaml# | - |
| 文書 | `replace_mark` と `files` の `documents` が指す文書は、設定の `build` の対象（`include` に当たり `exclude` に当たらないもの）と索引の文書。同じ文書は 1 回だけ扱う | - | - |
| スクリプトの呼び方 | `node {スクリプト} --config {設定ファイルの絶対パス}` を設定ファイルのあるフォルダで流し、終了コード 0 以外を失敗にする。スクリプトの拡張子は `.js` か `.mjs`。待ち時間は制限なし | - | スクリプトは同じ版の mdmark の開発者が書き、利用者が Ctrl-C で止められる。`npx` が入れたパッケージは `node_modules` の下にあり、Node はそこの `.ts` の型を落とさない（`ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING`）ため `.ts` は受けない |
| 点検 | 全ての手順を当てた後に、`mdmark check` と同じ点検（呼んだ CLI の形）を流す。ずれが 0 件のときだけ版を書き換える | dev/設計書/インターフェース定義/ライブラリ本体/設定と索引を点検する.ts# | - |
| 版の書き換え | 設定の `version` を目標の版にする。無ければ最上位の先頭に足す | - | - |
| 変更履歴 | パッケージの `docs/はじめに/変更履歴.md` の表のうち、バージョンの列が手元の版より新しく目標の版以下の行を、表の並びで出す。PR の列はリンクの文字（`#40`）だけを出す | - | - |
| 動く Node の版 | Node 24 以降 | dev/設計書/非機能要件/非機能要件#requirements[CLI が動く Node の版] | - |
