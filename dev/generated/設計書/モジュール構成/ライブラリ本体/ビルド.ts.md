# ライブラリ本体 / ビルド

`npm run build` が実行するビルドのスクリプト。版を決めて検査し、esbuild で `dist/` を書き、配布ファイルのサイズを検査する。Node.js v24 が型を消して `node scripts/build.ts` で直接実行する。

- tests/unit/scripts/build.test.ts
- tests/unit/scripts/migrations.test.ts

## ディレクトリ構成

```tree
scripts/
├── build.ts       # 版の決定と検査・esbuild の呼び出し・束ねたライブラリのライセンスの書き出し・サイズの検査
└── migrations.ts  # スキーマを変えた版に移行の手順があるかの点検
```

### postcssStubPlugin

postcssStubPlugin

postcss の差し替え

scripts/build.ts

esbuild のプラグイン。`postcss` の import を、`parse` を呼ぶと例外を投げる空の部品に差し替える

`{ name: "stub-postcss", setup }`。`setup` は `onResolve({ filter: /^postcss$/ })` で名前空間 `stub` に向け、`onLoad` で `module.exports = { parse() { throw new Error("postcss は配布物に含めない") } }` を返す

`dist/viewer.js` は `dist/index.js` と同じ設定（対応ブラウザの `target`・`postcssStubPlugin`・版の `define`）で、ライブラリ本体を含めて 1 つに束ねる。`dist/cli.js` は `platform: node`・`target: node24`・`format: esm`・`banner.js` に `#!/usr/bin/env node` で束ね、`yaml` と `esbuild` を `external` にして `package.json` の `dependencies` から読む。どちらも `UNSIZED_OUTPUTS` に入れ、サイズを検めない

`dist/viewer.js` は書き出した HTML の `<script type="module">` にそのまま置くため、書いた後に `assertNoScriptClose` で検める。esbuild は文字列・テンプレート文字列の `</script` を大文字と小文字によらず `<\/script` に替えるため（外部ライブラリ『esbuild』の動作確認）、この検査は esbuild の振る舞いが変わったときの備え

### checkMigrations

checkMigrations

移行の手順を点検する

scripts/migrations.ts

スキーマを最新の版のタグから変えたのに移行の手順も手順なしの一覧の合う行も無いこと、release のビルドで出していない版の手順が残ること、手順の形の誤りを、直し方つきの文で返す

順に、`migrations/` の全ての `steps.yaml`（`next` と `v{版}`）を `validateSteps` で検め、`call` のスクリプトがあることと `no-steps.yaml` の形を確かめる → `latestVersionTag` が `undefined` か、比べる版がタグより古ければそこで終える → 比べる版がタグと同じなら `next`、新しければ `v{比べる版}` を見る版にし、新しいときは `migrations/next/` と `version: next` の行が残っていれば誤りにする → `CHECKED_SCHEMAS` ごとに `git show {タグ}:schemas/{名前}` と今の中身を比べ、違うものは見る版の `steps.yaml` か、見る版・その Schema・今の中身の SHA-256（`node:crypto`）の合う行があれば通す。タグに無い Schema は比べない
