# 版を上げる

文書を書く人が `mdmark upgrade` を流し、設定の手元の版から目標の版までの移行の手順を版の順に当て、点検を通してから設定の版を書き換え、その範囲の変更履歴を受け取る。

10

tests/e2e/単一ユースケース/版を上げる.spec.ts

文書を書く人

新しい版が出て、文書を書く人がその版の CLI と配布物を使いたくなった

- 文書を書く人の手元に Node 24 以降がある
- 手元に `mdmark.config.yaml` がある

手元の版より新しく目標の版以下の版の移行の手順が版の順に当たり、`mdmark check` と同じ点検が通り、設定の `version` が目標の版になる。当てた版の範囲の変更履歴の行と、写しのフォルダの場所が出る。

手順の途中で失敗したとき・当てた後の点検が通らないときは、書き換えた全てのファイルを写しから戻し、設定の `version` を変えない。次の `upgrade` は同じ手元の版から当て直せる。

### 正常シナリオ

正常シナリオ

#### セットアップ

| セットアップ | 説明 | 補足 |
| --- | --- | --- |
| 手元の版が古いフォルダ | `version: v0.3.0` の設定・索引・文書 2 つを持つフォルダ。設定と索引は v0.3.0 の Schema に合う | - |
| Mock | 呼んだ CLI の版を `v0.5.0` に、移行の手順のフォルダと変更履歴をテスト用のものに差し替える | `v0.4.0` は設定のキーの名前を変える手順、`v0.5.0` は文書の印を書き換える手順を持つ。どちらも壊す印と値を聞く指定を持たない。変更履歴は v0.3.0・v0.4.0・v0.5.0 の行を持つ |

#### フロー

sequenceDiagram
  actor W as 文書を書く人
  participant C as mdmark CLI
  participant F as フォルダ
  W->>C: mdmark upgrade
  C->>F: 設定の version を読む
  C->>C: 手元の版 v0.3.0 と目標の版 v0.5.0 を比べ、v0.4.0・v0.5.0 の手順を読む
  C->>F: 書き換えうるファイルを写しのフォルダへ写す
  C->>F: v0.4.0・v0.5.0 の手順を版の順に当てる
  C->>C: mdmark check と同じ点検を流す（ずれ 0 件）
  C->>F: 設定の version を v0.5.0 にする
  C-->>W: 当てた手順・変更履歴の行・写しのフォルダの場所・終了コード 0

#### 期待値

- 設定のキーの名前が v0.4.0 の手順のとおりに変わり、文書の印が v0.5.0 の手順のとおりに書き換わっている
- 設定の `version` が `v0.5.0`
- 設定ファイルのコメントと、手順が触らないキーの値と並びが残っている
- 出力に v0.4.0・v0.5.0 の変更履歴の行が出て、v0.3.0 の行が出ない
- 出力に写しのフォルダの場所が出て、そのフォルダに当てる前の設定・文書がある
- 終了コードが 0
