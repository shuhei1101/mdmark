# ER 図: 移行の手順

mdmark の開発者が版ごとに書き、`mdmark upgrade` が使う側の設定・索引・文書へ当てる移行の手順と、配布物のビルドが読む手順なしの一覧。どちらもリポジトリの `migrations/` に置き、版のタグのパッケージに入る。`steps.yaml` の形は `schemas/mdmark.steps.schema.json`（JSON Schema draft 2020-12）で縛る。

## テーブル

### migrations/{版}/steps.yaml

migrations/{版}/steps.yaml

移行の手順

YAML

1 つの版で当てる移行の手順の並び。最上位は `steps`（手順の並び、必須）だけを持ち、この表の行は `steps` の要素 1 つ

~20

設定・索引の形か文書の印を変える版ごとに 1 ファイル

削除しない（古い版の利用者が当てる）

全件

`{版}` は `v{MAJOR}.{MINOR}.{PATCH}`。出していない版の手順は `migrations/next/steps.yaml` に置き、release で `version.ini` を上げる commit で `migrations/v{版}/` へ移す。版のフォルダが無い版は手順なしとして飛ばす。どの手順も、既に当たった後の状態に当てても結果が変わらない。

| to | 新しいキー・印 | string | - | 空でない。`replace_mark` は `from` を含まない | - | `rename_key` は新しいキーのパス、`replace_mark` は書き換えた後の印の文字列 | build.output | - | `rename_key`・`replace_mark` で必須 |

| files | 書き換えるもの | array | - | - | - | `call` のスクリプトが書き換えうるもの。当てる前に写しを取る対象になる | [index] | 'config' / 'index' / 'documents'（設定の `build` の対象と索引の文書） | `call` で必須 |
