# 差分を表示する仕組み

取り出し元から 2 つのリビジョンの本文を受け、行と文字を比べて描く流れと、埋め込んだ HTML の切り替え、描いた文書のブロックの色分け

使う側が渡した取り出し元から、読む人が文書の変更を色分けで読めるようになるまでの考え方。
手順は [差分を表示する](../../使い方/導入/差分を表示する.md)。

## 取り出し元は使う側が持つ

mdmark は Git や YAML の読み方を持たない。
使う側が、リビジョンの一覧を返す `revisions` と、リビジョンごとの本文を返す `content` を持つ取り出し元（`DiffSource`）を書き、`mount` の `diffSource` に渡す。
リビジョンは文書の変更の 1 回分で、`id`・`at` と、任意の `label`・`author` を持つ。

mdmark は取り出し元を、読む人が差分を開いたときだけ呼ぶ。
`mount` を呼んだだけでは呼ばない。

## 開いてから描くまでの流れ

1. 読む人が、題の後ろに付いた「変更を見る」のボタンを押す。題を残して本文を隠す
2. `revisions` を呼び、リビジョンの一覧を受ける。形が合うかを確かめる
3. 一番新しいリビジョンを後、その 1 つ前を前に選び、`content` をそれぞれ呼ぶ
4. 2 つの本文を比べ、差分の行を描く
5. 読む人が前と後を選び直すたびに、選んだ 2 つの本文を呼び直して描き直す

リビジョンが 1 つだけのときは、比べる相手が無いため `content` を呼ばず、その旨を知らせる。
取り出し元の待ちが 1 秒を過ぎると読み込み中の枠を出し、2 秒を過ぎると回る表示を足す。
待つ間に選び直す・閉じる・`update`・`destroy` があると、前の待ちの結果は描かない。
待ちを時間で打ち切るかは取り出し元が決め、打ち切るときは reject で返す。

## 差分の出し方

`mount` の `diffMode` が、差分の出し方を決める。

| `diffMode` | 出し方 |
| --- | --- |
| `button`（既定） | 上の流れのとおり、読む人が「変更を見る」を押してから描く |
| `open` | 描いた時点で「変更を見る」を押した状態にして、2 から先の流れを進める。押し直すと閉じ、`update` の後も開いた状態で描き直して取り出し元を呼び直す |
| `blocks` | 「変更を見る」と差分の場所を置かず、描いた文書のブロックに色を当てる（下の「描いた文書のブロックを色分けする」） |

`open` は、取り出し元を呼ぶきっかけがボタンから描いた時点に変わるだけで、差分の行の描き方は `button` と同じ。
知らない値は `button` として扱う。

## 行と文字の比べ方

`button`・`open` で比べるのは、描いた結果ではなく Markdown のソースの行。

1. 2 つのソースを行ごとに比べ、前にだけある行を削除した行、後にだけある行を追加した行、両方にある行を同じ行にする
2. 変わった塊の中で、削除した行と追加した行を前から順に対にする
3. 対の行を語ごとに比べ、変わった語だけを濃い色にする

語の区切りは `Intl.Segmenter`（`ja`・`word`）で決めるため、日本語の文も語の切れ目で比べる。
`Intl.Segmenter` を持たないブラウザでは、1 文字ずつ比べる。

削除した行は赤、追加した行は緑で出す。
色が見分けられなくても読めるよう、行頭に `-`・`+` の印を置き、読み上げの名前に「削除した行」「追加した行」を持たせる。
色は `--mdmark-color-diff-*` の CSS 変数で決まり、使う側が上書きできる（[テーマを上書きする](../../使い方/カスタマイズ/テーマを上書きする.md)）。
2 つの本文が同じときは行を出さず、変更が無いことを知らせる。

## 埋め込んだ HTML

差分の中の `<!-- html -->` 〜 `<!-- /html -->` の範囲は、範囲の右端に「HTML」のラベルを置く。
既定はソースの行と文字の色分けで、本文のほかの行と同じように読める。

前か後で中身が変わった範囲だけ、「ソース」「プレビュー」のボタンを持つ。
「プレビュー」を押すと、範囲の前と後の HTML を、文書に描くときと同じ埋め込んだ HTML の描き方（`script` 要素とイベントの属性を落とす）で並べる。
プレビューでも、書いたスクリプトは動かない。
「ソース」を押すと、行の色分けに戻る。

前か後にしか無い範囲は、無い側に「{前か後}のリビジョンには、この範囲がありません」を出す。

## ミニマップ

長い差分は、画面の右端のミニマップで送れる。
差分の行を出している間、差分の一番近いスクロールする祖先（無ければ画面）の右端に、その高さいっぱいの縦の帯を貼り付ける。

- 帯は、送り先の全体を写し、削除した行を左半分の赤、追加した行を右半分の緑の印で並べる。続いた同じ種類の行は 1 つの印にまとめる
- 今見えている範囲を、枠で示す
- 印や帯を押すと、その位置を送り先の中ほどに置くよう差分を送る。押したまま上下に動かすと、動かした位置に合わせて送る

帯は読み上げの対象にしない。
差分を閉じる・選び直す・`destroy` で、帯と受け取りを外す。
印刷では帯を隠す。

## 描いた文書のブロックを色分けする

`blocks` で比べるのは、描いた結果のブロック。
見出し・表・図の変更を、描いた見た目のまま読める。
行の中の語の違いは色分けしない。

1. 変更後の文書（`markdown`）を、色を当てずに描く
2. `revisions` を呼び、2 つ以上あれば 2 番目を前、1 番目を後として、`content` を 1 回ずつ呼ぶ
3. 前と後の Markdown をそれぞれ今の描き方で描き、ブロックに分ける
4. 2 つのソースを行ごとに比べ、後のブロックの範囲に追加した行があれば、そのブロックに追加の色を当てる
5. 前のブロックの範囲の行が全て消えていれば削除の候補にし、書き換えと入れ替えを見分けて、削除したブロックを変更前の位置に差し込む

`update` のたびに取り出し元を呼び直し、待つ間に前の結果を捨てる。
リビジョンが 1 つのとき、2 つの本文が同じとき、取り出し元を待つ間は、色を当てずに描いたままにする。

### ブロックの分け方

ブロックは、本文の直下か節の中身の直下にある、見出し・段落・リスト・表・コードブロック・注意書き・埋め込んだ HTML の範囲などの要素。
節は、中身の中のブロックに分ける。
リストは外側の項目、表は本文の行を、それぞれ 1 つのブロックにする。
ブロックが受け持つ行の範囲は、ブロックの [元の行番号](../../リファレンス/用語集.md) から、次のブロックの元の行番号の前まで。

### 書き換えと入れ替えの見分け方

前のブロックの削除の候補と、追加の色を当てた後のブロックを、同じ変えた塊の中で前から順に対にして、対のブロックの文字を語ごとに比べる。

| 同じ文字の数 | 見分け | 出すもの |
| --- | --- | --- |
| 長い方の文字の数の半分以上 | 書き換え | 追加の色だけ。削除は出さない |
| 半分未満 | 入れ替え | 削除したブロックと追加の色の両方 |

対にならない削除の候補は、削除したブロックにする。

### 削除したブロックの差し込み位置

削除したブロックは、前の文書で直前にあった変えていないブロックと同じ親の、その後ろに差し込む。
同じ節に直前のブロックが無ければ、前の文書で属していた節の中身の先頭に、節に属していなければ本文の先頭に差し込む。
見出しごと消した節は、見出しと節の中身を 1 つの削除したブロックにして、同じ決まりで差し込む。
リストの項目と表の行は、前の文書で直前にあった項目・行の後ろ（無ければリスト・表の先頭）に差し込む。
後の文書にそのリスト・表が無いときは、リスト・表ごと削除したブロックにする。

削除したブロックの中の要素は、元の行番号と見出しのアンカーの `id` を持たない。
スクロールを合わせる先にも、見出しのアンカーにもならない。
番号付きリストの削除した項目は番号を使わず、後ろの項目の番号を進めない。

### 色と読み上げ

追加・変更したブロックは追加の色の面と左の余白の `+`、削除したブロックは削除の色の面と `−` で出す。
先頭に、読み上げだけに出す「追加:」「削除:」を置くため、色が見分けられなくても区別できる。
色は `--mdmark-color-diff-add-bg`・`--mdmark-color-diff-del-bg`・`--mdmark-color-diff-add-sign`・`--mdmark-color-diff-del-sign` で決まり、使う側が上書きできる。
節の開閉・右側の目次・見出しのアンカーは、色分けしない描き方のまま使える。

## 取り出せないとき

`revisions` か `content` が reject したか、返した値がリビジョンの形に合わないときは、例外を投げず、差分の場所に知らせの枠を出す。
文書の本文は描いたまま残り、読む人は本文に戻れる。

| 起きたこと | 差分の場所 |
| --- | --- |
| `revisions` を取り出せない | 差分の場所の全体を、「変更の履歴を表示できません」の知らせの枠にする |
| `content` を取り出せない | 選ぶ欄を残し、差分の行の場所を「このリビジョンの本文を表示できません」の知らせの枠にする。別のリビジョンを選び直すと差分を描き直す |

取り出し元の関数の名前・文書の `id`・リビジョンの `id`・元のエラーは `console.error` に出る。

`blocks` では差分の場所が無いため、色を当てずに描いた本文を残し、本文の先頭を「変更を表示できません」の知らせの枠にする。
文言は `revisions` と `content` のどちらを取り出せないときも同じ。
