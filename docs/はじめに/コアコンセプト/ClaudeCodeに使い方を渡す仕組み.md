# Claude Code に使い方を渡す仕組み

使い方集を dev-docs で必要な分だけ参照させ、CLI と同じ処理をツールで呼ぶ流れ

Claude Code のプラグインが、mdmark の使い方と操作を Claude Code に渡す考え方。
入れ方と使い方は [プラグインを入れる](../../使い方/ClaudeCodeで使う/プラグインを入れる.md) と [MCP のツールを使う](../../使い方/ClaudeCodeで使う/MCPのツールを使う.md)。

## 使い方集を dev-docs で参照する

使い方集は、mdmark のリポジトリの `docs/` の使い方・リファレンスのページで、dev-docs の配信元 `mdmark` の公開ドキュメントの行（`docs`）でタグ `topic:使い方集` を付けて配る。
Claude Code は、dev-docs の `search_docs` で `docs` の行の文書をタグ `topic:使い方集` で絞って一覧を検索し、作業に要るページだけを本文まで参照する。
セッションの開始では何も入れないため、使い方集を参照しない作業では文脈が増えない。
ページの選び方は、配信元の説明書（`dev-docs.yaml` の `instructions`）にある。

参照するのは、dev-docs の配信元に登録した mdmark のクローンのページで、プラグインは使い方集を持たない。
dev-docs が無い、または配信元 `mdmark` が登録されていないときは、使い方集は参照できない。

## 動線を instructions に置く

MCP サーバーは、接続したときの `instructions` に、書く前に使い方集を参照し、書いた後に `check` で点検する順序を記載する。
`instructions` は事実の文で記載し、Claude Code の文字数の上限に収める。

## CLI と同じ処理をツールで呼ぶ

`export_html`・`build_site`・`check` は、CLI の `mdmark export`・`build`・`check` と同じ処理を呼ぶ。
同じ文書・設定・索引では、CLI と同じ結果になる。

作業のフォルダを使うツールは、作業のフォルダの絶対パスを引数 `project_dir` で受ける。
常駐サーバーにはセッションの作業のフォルダが環境変数で渡らないため、プラグインの PreToolUse のフックが、ツールの呼び出しのたびにセッションのフォルダを `project_dir` に入れる。
設定ファイルは、そのフォルダから上のフォルダへ順に探す。
ツールの `config` に別のパスを渡すと、そのファイルを使う。

## 常駐サーバーで動かす

MCP サーバーは、文書を書く人が `mdmark serve` で起動する常駐のサーバー。
127.0.0.1 の Streamable HTTP で待ち受け、プラグインの `.mcp.json` がその URL へつなぐ。
並行して開いたセッションが同じプロセスを共有するため、サーバーはセッションごとの状態を持たず、呼び出しごとに処理する。
起動の手順は [MCPサーバーを起動する](../../使い方/ClaudeCodeで使う/MCPサーバーを起動する.md)。

サーバーが起動していないと、そのセッションでは MCP サーバーだけが接続に失敗する。
起動してから `/mcp` で接続し直すと、セッションを開き直さずにツールを呼べる。

PreToolUse のフックは、束ねた JavaScript で、`node` が起動する。
プラグインは束ねたフックだけを持ち、依存を入れない。

## 使い方集の索引が正

使い方集のページの一覧は、リポジトリの `guide/index.yaml` が正。
ビルドが索引の検査を通し、無いページを指す行があるときは止まる。
