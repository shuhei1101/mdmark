# 索引と被参照

索引を正にし、被参照を描くときに算出し、ずれを点検で見つける仕組み

使う側が書いた索引から、本文の用語のツールチップと、文書を参照している文書の一覧が描かれるまでの考え方。
書き方は [索引と用語集を書く](../../使い方/書く/索引と用語集を書く.md)。

## 索引が正

文書のメタデータ（題・概要・別名・関連）と用語の意味は、使う側が書く索引の YAML だけに持つ。
索引の形は [索引](../../リファレンス/索引.md)。
mdmark はブラウザでファイルを読まない。
使う側のサーバーが索引と文書を読み、読んだオブジェクトを `mount`・`render` と、参照の表を作る `collectReferences`、本文の参照を取り出す `collectMatches`、ずれを見つける `checkIndex` に渡す。

用語は、索引の `terms` のほかに、文書の用語集の表（[用語集の表](../../リファレンス/記法.md#用語集の表)）からも入る。
同じ語が複数あるときは、索引の `terms`、描く文書の表、ほかの文書の表（索引の `docs` で先に並ぶ文書）の順に優先する。

## 被参照は保存しない

ある文書を参照している文書（被参照）は、どこにも書かずに、描くときに算出する。
参照は、次のどれかで数える。

| 参照 | 数え方 |
| --- | --- |
| `related` | 参照元の文書の `related` に、参照先の `id` がある |
| 本文のリンク | 参照元の本文のリンクが、参照先の `path` を指す |
| 文書の別名 | 参照元の本文に、参照先の `aliases` が出る |

自分自身は数えない。
参照される側の文書に、参照元を書き足す必要は無い。
文書を書き換えると、参照の表を作り直した次の描画から反映される。

## 参照の表

被参照を描く文書が、ほかの文書の本文を読まずに済むよう、使う側が全ての文書から参照の表を作って渡す（[参照の表を作る](../../リファレンス/API.md#参照の表を作る)）。
参照の表は、文書ごとの被参照と、各文書の用語集の表から入れた用語を持つ。
参照の表を渡さないときは、被参照を索引の `related` だけから出し、ほかの文書の用語集の表の用語を照合しない。

## 描かれ方

描く文書の本文に出た用語の語・別名と、文書の別名に、破線の下線を引き、意味と関連文書のツールチップを付ける。
文書の末尾には、その文書を参照している文書の一覧を、題「関連文書」で置く。
索引を渡さないときは、用語集の表から入れた用語だけにツールチップを付け、被参照の一覧を出さない。
索引も用語集の表も無い文書は、これまでどおりに描く。

索引が Schema に合わなくても、用語集の表の列名が表に無くても、本文の描画は止まらない。
合わない文書・用語は除いて使い、用語集の表の誤りはその箇所の書き方の警告で知らせる。

## 画面を出さない参照の取り出し

下線とツールチップは画面に描くものだが、使う側の処理が同じ補足を画面なしで受け取りたいことがある（AI へ本文を返すときなど）。
`collectMatches` は、索引と文書の本文を渡すと、描いた文書の下線・ツールチップと同じ照合で、本文に出た用語・文書の別名の一致を返す（[本文の参照を取り出す](../../リファレンス/API.md#本文の参照を取り出す)）。
返すのは、参照先の種類・`id`・タイトル・短い説明と、一致した文字列・本文の中の位置。
同じ実行環境で描いた文書の下線と同じ語が一致し、ツールチップの節ごとの最初の 1 回の制限は効かず、同じ参照先の出現を全て返す。

## ずれの点検

索引と文書は別々に書くため、文書を移した・消したときにずれが出る。
`checkIndex` が、索引に無い文書・索引にあって消えた文書・`related` の切れた `id`・用語の重複・本文に出た用語のやめた言い方・Schema に合わない索引を、ファイル・場所・種類・内容の一覧で返す（[索引を点検する](../../リファレンス/API.md#索引を点検する)）。
ずれの種類は [点検が返すずれ](../../リファレンス/索引.md#点検が返すずれ)。
