# 設定を重ねて読む仕組み

端末の設定と、文書のフォルダから上のフォルダの設定ファイルを重ねる順・切り替え・相対パスの基準・優先の順番

CLI（`export`・`build`・`check`）・MCP のツール（`export_html`・`build_site`・`check`）・VS Code 拡張機能のプレビューと書き出しは、同じ処理で設定を探して重ねる。
キーの一覧は [設定](../../リファレンス/設定.md)。

## 重ねる層

<!-- table: data -->

| 順 | 層 | 場所 |
| --- | --- | --- |
| 1 | 端末の設定 | 環境変数 `MDMARK_CONFIG` のパス。無ければ `${XDG_CONFIG_HOME:-~/.config}/mdmark/settings.yaml` |
| 2 | 上のフォルダの設定 | 起点のフォルダより上のフォルダの `mdmark.config.yaml`（遠い順） |
| 3 | 近いフォルダの設定 | 起点のフォルダから上へ最初に見つかった `mdmark.config.yaml` |
| 4 | 文書の印 | 文書の中の `<!-- features: … -->` など（`mount` が最後に重ねる） |

<!-- /table -->

起点のフォルダは、CLI は今のフォルダ、MCP は `project_dir`、VS Code 拡張機能は Markdown のフォルダ。
後の層ほど優先し、同じキーは後の層の値になる。
端末の設定が無ければ、空の設定として扱う。

## 重ね方

- マップ（`features`・`libraries`・`tooltips` など）はキーごとに重ねる
- それ以外の値（文字列・数・真偽値・配列）は、後の層の値で置き換える
- 相対パスの値（`theme`・`extensions`・`libraries`・`html-scripts.url`・`syntax.url`・`index`・`assets.root`・`build`・`aliases`）は、重ねる前に、その値を書いた設定ファイルのフォルダから解決する

## 切り替え

端末の設定だけが持つ `config` のキーで切り替える。
`mdmark.config.yaml` に書いても読まない。

| キー | 既定 | 切り替えるもの |
| --- | --- | --- |
| `config.cascade` | `false` | `true` のとき 2 の上のフォルダの設定を全て重ねる。`false` のときは 3 の近い 1 つだけを端末の設定に重ねる |
| `config.applyToExport` | `true` | `false` のとき、書き出し（`export`・`build`）で 1 の端末の設定を重ねない。プレビューは常に重ねる |

`--config`（MCP は `config`、VS Code 拡張機能は `mdmark.configPath`）を渡したときは上へ探さず、そのファイルと端末の設定だけを重ねる。

## 読めない設定ファイル

重ねる設定ファイルのどれかが YAML として読めない・設定の形に合わないときは、そのファイルを重ねない。

- CLI と MCP: 読めないファイルと行（形に合わないときはキー）を示して誤りで終える
- VS Code 拡張機能: 端末の設定 → 上 → 近いの順で最初の 1 つを、文書の先頭の帯に出す。プレビューは前に使った設定（無ければ残りの設定）で、書き出しは残りの設定で描く

## 端末の設定のフォルダ

端末の設定のファイルと同じフォルダの `templates/css/` に、CSS のテンプレートと索引 `templates.yaml` を置く。
`MDMARK_CONFIG` で端末の設定を別の場所にすると、テンプレートのフォルダもその隣になる。
テンプレートは設定として重ねず、MCP のツールで配置した CSS を `theme` から当てる（[MCP](../../リファレンス/MCP.md#css-のテンプレートの一覧を返す)）。

`mdmark check` は、重ねた設定ファイルのそれぞれと端末の設定の形を点検する。
`mdmark upgrade` が書き換えるのは、最も近い `mdmark.config.yaml` だけ。
