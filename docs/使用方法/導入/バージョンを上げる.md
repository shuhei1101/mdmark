# バージョンを上げる

`mdmark upgrade` で移行の手順を適用して、設定・索引・文書を新しいバージョンに合わせる

mdmark の新しいバージョンを使用し始めるときに実行する。
呼んだ CLI のバージョンが目標のバージョンになり、設定の `version`（手元のバージョン）より新しく目標のバージョン以下のバージョンの移行の手順を、バージョンの順に適用する。

## 前提

- Node 24 以降
- 設定ファイル `mdmark.config.yaml` を今のフォルダか上のフォルダに配置している（[雛形を置く](../書き出す/雛形を配置する.md)）
- 目標のバージョンのタグが公開されている（[変更履歴](../../はじめに/変更履歴.md) に載っているバージョン）

## 手順

### 適用する範囲を確認する

#### `--plan` で呼ぶ

```bash
npx github:shuhei1101/mdmark#v{目標のバージョン} upgrade --plan
```

`{目標のバージョン}` は上げる先のバージョンの `{MAJOR}.{MINOR}.{PATCH}`。
手元のバージョンは設定の `version`。
`version` が無い設定（v0.3.0 までの `init` が配置した設定）では、標準エラーに質問が出るので、標準入力に手元のバージョンを `v{MAJOR}.{MINOR}.{PATCH}` の構造で回答する。
何も書き換えず、適用するバージョンごとの手順・変更履歴の行・壊す手順の有無を出す。

```text
手元のバージョン: v0.3.0
目標のバージョン: v0.5.0
v0.4.0:
  rename_key: `build.out` を `build.output` に改める
v0.5.0:
  replace_mark（壊す手順）: マーカー `<!-- note -->` を `<!-- callout -->` に書き換える
変更履歴:
  v0.4.0 #40 バージョンを上げるときに移行の手順を適用する mdmark upgrade を作る
  v0.5.0 #45 注意書きのマーカーの名前を統一する
--plan のため書き換えていません
```

手元のバージョンが目標のバージョンと同じときは `手元のバージョンが目標のバージョンと同じです。適用する手順はありません` と出て、ここで終わる。

#### 壊す手順を参照する

`（壊す手順）` が付いた手順は、適用すると値が失われる。
適用してよいかを、手順の説明と変更履歴の行から決める。

### 移行の手順を適用する

#### `upgrade` を呼ぶ

```bash
npx github:shuhei1101/mdmark#v{目標のバージョン} upgrade
```

次の順に処理する。

1. 手元のバージョンを聞く（設定に `version` が無いときだけ）
2. 値を聞く手順の質問に回答する（手順がキーを追加するために値を聞くときだけ）
3. 壊す手順を適用してよいかの確認に `y` で回答する（壊す手順があるときだけ）
4. 設定・索引・文書のコピーを `.mdmark/backup/{日時}/` に取り、手順をバージョンの順に適用する
5. `mdmark check` と同じ点検を実行し、ずれが 0 件なら設定の `version` を目標のバージョンに書き換える

質問は標準エラーに出て、回答は 1 問 1 行で標準入力から読み込む。
`y` 以外を回答すると、何も書き換えずに終わる。
`--yes` を付けると、壊す手順の確認だけを飛ばす。
手元のバージョンと、値を聞く手順の質問は飛ばさない。

適用した手順・変更履歴の行・コピーの場所が出る。

```text
コピー: .mdmark/backup/20261017120000
バージョンを v0.5.0 にしました
```

#### 利用側のページの配布物の URL のタグを書き換える

`upgrade` が書き換えるのは設定・索引・文書だけ。
利用側のページに記載した配布物の URL のタグは、手で `v{目標のバージョン}` に書き換える（[配布物を読み込む](./配布物を読み込む.md)）。

#### 失敗したとき

手順の失敗と点検のずれは、コピーから全てのファイルを戻し、設定の `version` を変えずに終了コード 1 で終わる。
標準エラーに、失敗したバージョン・手順・理由か、`mdmark check` と同じ構造のずれの行が出る。
原因を修正して、同じ `upgrade` をもう一度呼ぶ。
次の `upgrade` は、同じ手元のバージョンからもう一度適用する。

そのほかの終了コード 1 は [CLI](../../リファレンス/CLI.md#版を上げる)。

## 反映

即時。`upgrade` が終わると、設定の `version` が目標のバージョンになり、手順の変更が設定・索引・文書に入っている。
ページは、URL のタグを書き換えて再読み込みしたときから目標のバージョンを読み込む。

## 確認

#### 設定のバージョンが目標のバージョンになっている

`mdmark.config.yaml` の `version` が `v{目標のバージョン}` になっている。
書き換えるのは、今のフォルダから上へ最初に見つかった `mdmark.config.yaml` だけで、上のフォルダの設定と端末の設定は書き換えない。

#### 点検が通る

```bash
npx github:shuhei1101/mdmark#v{目標のバージョン} check
```

`ずれ 0 件` が出る（[点検する](../書き出す/点検する.md)）。

## 元に戻す

`.mdmark/backup/{日時}/` のコピーのファイルを、設定ファイルのあるフォルダの同じ相対パスへ戻し、ページの URL のタグも戻す。
`.mdmark/` は中身が `*` の `.gitignore` を持つため、git の対象にならない。
コピーが要らなくなったら削除する。
