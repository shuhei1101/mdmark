# セットアップする

プラグインのスキルで、端末の設定と常駐サーバー、文書のフォルダの設定を、項目ごとに確認しながら用意する手順

| スキル | 単位 | すること |
| --- | --- | --- |
| `/mdmark:global-setup` | 端末ごとに 1 回。再インストール・端末の移行・プラグインの更新の後にも使用する | 端末の設定を作る・移行し、tmux のセッションで常駐サーバーを起動して、つながることを確認する |
| `/mdmark:setup` | 文書のフォルダごと | 文書のフォルダの `mdmark.config.yaml` を作る・修正する |

## 前提

- [プラグインを入れる](./プラグインを入れる.md)
- 手元に Node 24 以降と tmux 3.4 以降がある。tmux が無い端末は [MCPサーバーを起動する](./MCPサーバーを起動する.md) の手順で起動する
- 手元から GitHub と npm のレジストリへ届く

## 手順

### 端末をセットアップする

#### `global-setup` を呼ぶ

```text
/mdmark:global-setup
```

Claude Code が次の順に進め、書き換える前に内容を示して確認を取る。

<!-- steps -->

1. 端末の設定のパスを示す。`MDMARK_CONFIG` が無ければ `${XDG_CONFIG_HOME:-~/.config}/mdmark/settings.yaml`
2. 端末の設定があり `version` が古ければ、`mdmark upgrade --settings` と同じ手順で移行する。無ければ雛形から作る
3. 設定のキーを 1 つずつ、今の値と既定を示して聞く
4. 回答した値で端末の設定を記載する。パスが既定と違うときは、`~/.claude/settings.json` の `env` に `MDMARK_CONFIG` を記載する
5. tmux のセッション（既定 `mdmark-mcp`）で常駐サーバーを起動し、`tools/list` でつながることを確認する。既に待ち受けていればもう一度起動しない
6. 作ったもの・記載したキー・セッション名・ログの場所・止め方を示す

<!-- /steps -->

記載することを断ると、端末の設定と `settings.json` は書き換えない。
常駐サーバーのログは `${XDG_STATE_HOME:-~/.local/state}/mdmark/serve.log`（`MDMARK_STATE_DIR` で変える）。

### 文書のフォルダをセットアップする

#### `setup` を呼ぶ

文書のフォルダを作業のフォルダにしたセッションで呼ぶ。

```text
/mdmark:setup
```

`mdmark.config.yaml` のキーを 1 つずつ、今の値・端末の設定で重なる値・既定を示して聞き、回答した値で記載する。
無ければ `mdmark init` と同じ雛形から作り、あれば回答したキーだけを書き換えて、コメントとほかのキーを残す。
端末の設定だけが持つキー（`config.*`・`serve.*`）は聞かない。

## 反映

端末の設定と `mdmark.config.yaml` は、次のツールの呼び出しから読み込まれる。
`settings.json` の `env` を記載したときは、セッションをもう一度開く。
常駐サーバーを起動したセッションは、`/mcp` で `plugin:mdmark:mdmark` をもう一度接続するとツールを呼べる。

## 確認

#### 常駐サーバーが動いている

```bash
tmux has-session -t =mdmark-mcp && tail -n 20 ~/.local/state/mdmark/serve.log
```

ログに `http://127.0.0.1:{ポート}/mcp` の行がある。

#### セッションの開始で通知が出ない

新しいセッションを開いても、常駐サーバーが待ち受けていないことの通知が出ない。

## 元に戻す

```bash
tmux kill-session -t =mdmark-mcp
```

常駐サーバーを止める。
作った端末の設定・`mdmark.config.yaml`・`settings.json` の `env` の `MDMARK_CONFIG` は残るので、要らなければ削除する。
