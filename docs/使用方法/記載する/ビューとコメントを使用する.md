# ビューとコメントを使用する

ビューのマーカーの記載方法・ボードと表形式の切り替え・列の絞り込み・コメントを付ける手順

項目の表をボード表示と表形式のビューで見せるとき、表形式のビューを列で絞り込めるようにするとき、読者が本文の選んだ箇所にコメントを付けられるようにするときに実行する。

## 前提

- [文書を描く](../導入/文書を描く.md)
- コメントを付けるときは、コメントの読み込みと保存の関数を用意できる（保存先は利用側が持つ）

## 手順

### ビューを配置する

#### 項目の表をマーカーで囲む

```markdown
<!-- view: group=状態 -->

| タイトル | 状態 | 担当 |
| --- | --- | --- |
| 配色の変数を洗い出す | 未着手 | 佐藤 |
| 余白の変数を決める | 進行中 | 鈴木 |
| 印刷の見え方を確認する | 未着手 | 佐藤 |

<!-- /view -->
```

表の前に `<!-- view: 引数 -->`、後ろに `<!-- /view -->` を記載する。
範囲の最初の表が項目になる。
見出しの行が列名、本文の行が項目、セルの文字が値。
`group=列名` で、ボード表示で列に分ける列を決める。

ボード表示は、`group=` の列の値ごとの列を、表に出た順に横に並べる。
列の見出しに、値のアイコン・値・項目の数が出る。
項目は表の行の順に並び、先頭の列の値がタイトルになり、残りの列は列名と値の組で出る。
`group=` の列と空の値は項目に出さない。
描く先の幅に収まらない列は、ボードの中で横にスクロールする。

ビューの上に、「ボード」「表」の切り替えが出る。
`group=` を記載しないと切り替えを配置せず、表形式のビューだけを描く。
閉じのマーカーの記載を忘れると、マーカーから文書の終わりまでが範囲になり、記載の警告が出る。

#### 描いた直後のビューを選ぶ

```markdown
<!-- view: group=状態 default=table -->
```

`default=board` か `default=table` で、描いた直後に出すビューを決める。
省くと、`group=` があればボード表示、無ければ表形式のビューを出す。

#### ボードの列の見出しのアイコンを変える

```markdown
<!-- view: group=状態 icons=未着手:inbox,完了:archive -->
```

`icons=値:アイコンの名前,…` で、`group=` の列の値ごとのアイコンを上書きする。
記載しなかった値は既定のアイコンになる。

<!-- table: data -->

| 値 | 既定のアイコン |
| --- | --- |
| 未着手 | `circle-dashed` |
| 進行中 | `circle-dot` |
| 保留 | `circle-pause` |
| 完了 | `circle-check` |
| 中止 | `circle-x` |
| 上に無い値 | `circle` |

<!-- /table -->

使用できるアイコンは、上の 6 つと `inbox`・`archive`・`clock`・`flag`・`star`・`bug`・`eye`・`lock`・`zap`・`ban`。
使用できない名前を記載すると、その値の列には既定のアイコンを付けて描き、記載の警告が出る。
アイコンはスクリーンリーダーに含めず、列の見出しは値と項目の数だけがスクリーンリーダーに伝えられる。

### 表形式のビューを列で絞り込む

#### 絞り込む列を決める

```markdown
<!-- view: group=状態 default=table filter=担当,タイトル:text -->
```

`filter=列名:種類` で、絞り込みを付ける列と種類を決める。
記載方法は [表に機能を付ける](./表に機能を付ける.md#絞り込む列を決める) の `filter=` と同じで、種類は `select`（値を選ぶ）・`text`（文字を含む行）・`date`（期間）。
種類を省くと `select`。
絞り込みのボタンは、ここで決めた列の見出しにだけ付く。

絞り込みは表形式のビューにだけ該当する。
ボード表示は常に全ての項目を出し、列の見出しの項目の数も変わらない。
ボード表示から表形式に戻すと、絞り込みは残っている。
ビューの上に、全ての列を検索する検索欄と件数は配置しない。

### 記載方法の誤りを修正する

#### 記載の警告を読み込む

次の誤りは、ビューを描いたうえで、範囲の上に記載の警告が出る。

<!-- table: data -->

| 誤り | 描き方 |
| --- | --- |
| `group=` の列が表に無い | ボードにせず、表形式のビューで描く。「ボード」のボタンは押せない |
| `filter=` の列が表に無い | その列に絞り込みを付けずに描く |
| `filter=` の種類が `select`・`text`・`date` でない | その列に絞り込みを付けずに描く |
| `icons=` に使用できないアイコンの名前がある | その値の列に既定のアイコンを付けて描く |
| 範囲に表が無い | 範囲の中身をそのまま描く |

<!-- /table -->

警告の文言は [書き方の警告](../../リファレンス/記法.md#書き方の警告) を参照する。

### コメントを付けられるようにする

#### `comments` をオンにする

```yaml
features:
  comments: true
```

コメントの機能は既定でオフ。
利用側のサーバーが `mdmark.config.yaml` を読み込んだオブジェクトを、`mount` の `config` に指定する（[文書を描く](../導入/文書を描く.md)）。
文書の `<!-- features: +comments -->` でも、その文書だけオンにできる（[機能をオン・オフする](../カスタマイズ/機能をオン・オフする.md)）。

#### コメントの読み込みと保存の関数を指定する

```js
import { mount } from "https://cdn.jsdelivr.net/gh/shuhei1101/mdmark@{タグ}/dist/index.js";

mount(document.querySelector("#doc"), {
  markdown,
  config: { features: { comments: true } },
  docId: "guide",
  commentStore: {
    load: ({ docId }) => fetch(`/api/comments/${docId}`).then((res) => res.json()),
    save: ({ docId, comment }) =>
      fetch(`/api/comments/${docId}`, {
        method: "POST",
        headers: { "content-type": "application/json" },
        body: JSON.stringify(comment),
      }).then((res) => res.json()),
    update: ({ docId, id, body }) =>
      fetch(`/api/comments/${docId}/${id}`, {
        method: "PATCH",
        headers: { "content-type": "application/json" },
        body: JSON.stringify({ body }),
      }).then(() => undefined),
    remove: ({ docId, id }) =>
      fetch(`/api/comments/${docId}/${id}`, { method: "DELETE" }).then(() => undefined),
  },
});
```

mdmark はコメントを保存しない。
利用側の保存先を呼ぶ `load` と `save` を `commentStore` に指定し、コメントを付ける対象の ID を `docId` に指定する。

| 関数 | 受け取る値 | 返却する値 |
| --- | --- | --- |
| `load` | `{ docId }` | そのコメントの配列を返却する `Promise` |
| `save` | `{ docId, comment }` | 保存したコメントを返却する `Promise` |
| `update`（任意） | `{ docId, id, body }` | 本文を書き換え終えたら解決する `Promise` |
| `remove`（任意） | `{ docId, id }` | 削除し終えたら解決する `Promise` |

`comment` は、選んだ文字 `quote`・その前の最大 32 文字 `prefix`・後の最大 32 文字 `suffix`・コメントの本文 `body` の文字列。
`save` が返却するコメントと `load` が返却する配列の要素は、これに空でない文字列の `id` を加えたもの。
`load` は描くたび（`mount`・`update`）に 1 回呼ぶ。
`update` を指定すると吹き出しのコメントごとに「編集」を、`remove` を指定すると「削除」を出す。
指定しないボタンは出さない。
`commentStore` を指定して `docId` を指定しないと、`mount` は何も描かずに `TypeError` を投げる。

利用側が自分で記載した要素にコメントを付けるときは [部品をJavaScriptから使う](../カスタマイズ/部品をJavaScriptから使用する.md)。

#### 読者の操作を確認する

コメントは、読者が次の順で付ける。

<!-- steps -->

1. 本文の文字を、段落・リストの項目・表のセル・見出し・引用のどれか 1 つの中で選ぶ。選んだ文字の終わりの下に「コメント」のボタンが出る。
2. ボタンを押す。選んだ文字の下に入力欄が開き、本文の欄にフォーカスが移る。
3. コメントを記載し、「コメントを保存」を押す。入力欄が閉じ、選んだ文字にマーカーが付く。
4. マーカーを押す（フォーカスして Enter・Space でもよい）。付いたコメントの吹き出しが開く。

<!-- /steps -->

入力欄の中・ビューの切り替え・コード・既にあるマーカーの中で文字を選んでも、ボタンは出ない。
入力欄は「キャンセル」か Esc で閉じる。
本文があるときは、`記載したコメントを捨てて閉じますか？` と確認する。
入力欄の外を押しても閉じない。
吹き出しは、閉じるボタン・外側を押す・Esc で閉じる。
選んだ文字とコメントの本文は文字として出し、HTML として解釈しない。

#### コメントを修正・削除する

`commentStore` が `update`・`remove` を持つとき、吹き出しのコメントの本文の右上に「編集」「削除」のアイコンのボタンが出る。

<!-- steps -->

1. 「編集」を押す。そのコメントの本文が入力欄に替わり、本文の欄にフォーカスが移る。
2. 本文を書き換えて「保存」を押す。`update` が `{ docId, id, body }` で 1 回呼ばれ、吹き出しの本文が書き換わる。
3. 「削除」を押す。そのコメントの下に `このコメントを削除しますか? 削除すると元に戻せません。` と「キャンセル」「削除」が出る。
4. 確認の「削除」を押す。`remove` が `{ docId, id }` で 1 回呼ばれ、コメントが吹き出しから消える。最後のコメントを削除すると、マーカーも削除される。

<!-- /steps -->

入力欄と削除の確認は、「キャンセル」か Esc で閉じる。

#### 保存できないときの動きを知る

本文を記載せずに保存すると、入力欄のそばに `コメントを記載してから保存してください。` と出る。
`save` が失敗すると、入力欄と記載した本文を残し、`コメントを保存できませんでした。記載したコメントは残っています。もう一度「コメントを保存」を押してください。` と出る。
どちらも選んだ文字にマーカーは付かない。
`save` の失敗は `console.error` にも出る。

修正で本文を空にして保存すると、同じく `コメントを記載してから保存してください。` と出る。
`update` が失敗すると、入力欄と書き換えた本文を残し、`コメントを保存できませんでした。記載したコメントは残っています。もう一度「保存」を押してください。` と出る。
`remove` が失敗すると、コメントとマーカーを残して削除の確認を開いたまま、`コメントを削除できませんでした。もう一度「削除」を押してください。` と出る。
どちらの失敗も `console.error` に出る。

#### 本文を書き換えたときのもう一度付きを知る

`mount`・`update` で描くたびに、コメントごとに、前後の文字を含めた `prefix + quote + suffix` が一致する箇所を探す。
無ければ、`quote` が 1 か所だけ一致する箇所に付ける。
どちらも見つからないコメントは、文書の末尾の `箇所が見つからないコメント` の一覧に、選んだ文字と本文を並べる。
同じ箇所のコメントは 1 つのマーカーにまとめ、吹き出しに並べる。

#### 余白のマーカーからコメントへ移る

`mount` で描いた文書では、本文の列の右の余白に、コメントの箇所の行の高さで余白のマーカーが出る（右側の目次がある文書では、本文の列と右側の目次の間に出る）。
余白のマーカーを押す（フォーカスして Enter・Space でもよい）と、箇所が画面の中ほどまでスクロールし、その箇所の吹き出しが開く。
吹き出しを開いている箇所の余白のマーカーは、地と文字の色が反転する。

- 同じ行に複数の箇所があるときは、1 つの余白のマーカーにまとめて箇所の数を添える。押すと行の最初の箇所の吹き出しが開く
- 閉じたセクション・選ばれていないタブ・閉じた行の詳細の中の箇所は、開くボタン（見出し・タブ・行の詳細の開閉）の行に破線の余白のマーカーが出る。押すと開いてから箇所へ移る
- 余白のマーカーが上下で重なるときは、下の余白のマーカーを重ならない位置まで下げる
- 箇所が見つからないコメントには、余白のマーカーを出さない
- `mountComments` で付けたコメントには、余白のマーカーを出さない

余白の列の幅は CSS 変数 `--mdmark-comment-margin-width` で変える（[テーマの CSS 変数](../../リファレンス/API.md#テーマの-css-変数)）。

### 印刷と書き出しでの見え方を知る

印刷では、ビューは今出しているほうを出し、切り替えと絞り込みのボタンを出さない。
コメントはマーカーの地の色を削除して下線だけを残し、ボタン・入力欄・吹き出し・余白のマーカーを出さない。

`mdmark export`・`mdmark build` で書き出した 1 枚の HTML でも、ビューと列の絞り込みは外を読み込まずに動く（[文書を書き出す](../書き出す/文書を書き出す.md)）。
書き出した HTML はコメントの読み込みと保存の関数を持たないため、コメントは付かない。

## 反映

即時。`mount` と `update` で描くたびに、そのとき描く文書のマーカーでもう一度決める。

## 確認

#### ボード表示が描かれている

```js
document.querySelectorAll(".mdmark .mdmark-view-column").length
```

`group=` の列の値の種類の数が出る。
列の見出しに値と項目の数が出て、ビューの前後にマーカーの文字が出ていない。

#### 切り替えが働く

「表」を押す。

```js
document.querySelector(".mdmark .mdmark-view-switch-item[data-mode='table']").getAttribute("aria-pressed")
```

`true` が出る。
表の行が項目の数だけ並び、ボード表示は隠れる。

#### 列の絞り込みが働く

`filter=` で指定した列の見出しの絞り込みのボタンを押し、値を選ぶか文字を入れる。
その値・文字に合う行だけが表に残る。
ボード表示に切り替えると、全ての項目が出る。
表形式に戻すと、絞り込みが残っている。

#### コメントが付く

`comments` をオンにして `commentStore` を指定した文書で、本文の文字を選ぶ。
「コメント」のボタンが出る。
本文を記載して保存すると、`save` が `{ docId, comment: { quote, prefix, suffix, body } }` で 1 回呼ばれる。

```js
document.querySelector(".mdmark .mdmark-comment-mark").textContent
```

選んだ文字が出る。
マーカーを押すと、記載したコメントの吹き出しが開く。

```js
document.querySelectorAll(".mdmark .mdmark-comment-margin .mdmark-comment-marker").length
```

本文の列の右に、コメントの箇所がある行の数だけ余白のマーカーが出る。
余白のマーカーを押すと、箇所までスクロールして吹き出しが開く。

#### コメントを修正・削除できる

`commentStore` に `update`・`remove` を指定した文書で、マーカーから吹き出しを開く。
コメントの右上に「編集」「削除」のボタンが出る。
「編集」で本文を書き換えて「保存」を押すと、`update` が 1 回呼ばれて吹き出しの本文が変わる。
「削除」と確認の「削除」を押すと、`remove` が 1 回呼ばれてコメントが消える。

#### コメントが付かない

`comments` をオフ（既定）にした文書で、本文の文字を選ぶ。
ボタンが出ず、`load` も呼ばれない。
`comments` をオンにして `commentStore` を指定しないと、ボタンは出ず、`console.error` に読み込みと保存の関数が要ることが 1 回だけ出る。

#### 記載の警告が出る

`group=` に表に無い列名を記載して描く。
範囲の上にタイトル `記載の警告` の枠が出て、「ボード」のボタンが押せず、表形式のビューが描かれる。

## 元に戻す

ビューは、マーカーと閉じのマーカーを削除すると、表が普通の表に戻る。
機能ごと止めるときは、[機能をオン・オフする](../カスタマイズ/機能をオン・オフする.md) で `views` をオフにする。
コメントは、`comments` をオフにするか `commentStore` を指定しないと、ボタンが出なくなる。
保存したコメントは利用側の保存先に残るため、削除するときは保存先で削除する。
