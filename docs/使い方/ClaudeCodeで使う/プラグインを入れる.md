# プラグインを入れる

マーケットプレイスを追加してプラグインを入れ、次のセッションから使い方の索引とツールを受け取る手順

Claude Code で mdmark の文書を書き始める前に実行する。

## 前提

- 手元に Claude Code・git・Node 24 以降がある
- 手元から GitHub と npm のレジストリへ届く
- MCP の常駐サーバーを起動する（[MCPサーバーを起動する](./MCPサーバーを起動する.md)）。起動していなくてもプラグインは入るが、MCP サーバーだけが接続に失敗する

## 手順

### マーケットプレイスを追加する

#### リポジトリを追加する

```text
/plugin marketplace add shuhei1101/mdmark
```

ターミナルからは `claude plugin marketplace add shuhei1101/mdmark` で追加できる。
バージョンを固定するときは `shuhei1101/mdmark#v{バージョン}` とタグを書く。
リポジトリの直下の `.claude-plugin/marketplace.json` を読み、プラグイン `mdmark` を載せる。

### プラグインを入れる

#### プラグインを入れる

```text
/plugin install mdmark@mdmark
```

ターミナルからは `claude plugin install mdmark@mdmark` で入れられる。
Claude Code が `plugin/` をキャッシュへ写す。
プラグインは束ねたフックだけを持ち、依存を入れない。

### 次のセッションを開く

プラグインは、入れた後に開くセッションから使える。
入れる前から開いているセッションには反映されない。

## 反映

次に開くセッションから。
そのセッションの開始で、SessionStart のフックが使い方集の索引を渡し、MCP サーバー `plugin:mdmark:mdmark` が常駐サーバーの `http://127.0.0.1:${MDMARK_PORT:-8782}/mcp` へつながる。

## 確認

#### プラグインが有効になっている

```bash
claude plugin list
```

`mdmark@mdmark` が有効として出る。

#### MCP サーバーがつながっている

新しいセッションで `/mcp` を開く。
`plugin:mdmark:mdmark` がつながっていて、ツールが並ぶ（[MCP](../../リファレンス/MCP.md)）。
接続に失敗しているときは、常駐サーバーを起動してから、`/mcp` で接続し直す（[MCPサーバーを起動する](./MCPサーバーを起動する.md)）。

## 子プロセスで起動していたプラグインからの移行

MCP サーバーを子プロセス（stdio）で起動していたバージョンのプラグインを入れている場合、新しいバージョンのプラグインは、常駐サーバーを起動しないと MCP のツールを使えない。

<!-- steps -->

1. 新しいバージョンのプラグインへ更新する
2. 常駐サーバーを起動する（[MCPサーバーを起動する](./MCPサーバーを起動する.md)）
3. セッションを開き直す

<!-- /steps -->

## 元に戻す

```text
/plugin uninstall mdmark@mdmark
/plugin marketplace remove mdmark
```

プラグインとマーケットプレイスの追加を外す。
手元の他のプラグインの設定は変わらない。
