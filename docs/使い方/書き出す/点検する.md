# 点検する

`mdmark check` で設定と索引を点検し、ずれを直す手順

書き出す前と、設定・索引・文書を書き換えた後に実行する。

## 前提

- [雛形を置く](./雛形を置く.md)（設定ファイル `mdmark.config.yaml` を今のフォルダか上のフォルダに置いている）
- Node 24 以降

## 手順

### 点検する

#### `check` を呼ぶ

```bash
npx github:shuhei1101/mdmark#v{版} check [--config {設定ファイル}] [--base {git の ref} | --text {Markdown} | --file {ファイル} --key {YAML のキー}]
```

`--config` を省くと、今のフォルダから上のフォルダへ順に `mdmark.config.yaml` を探し、最初に見つかったものを使う。
`--base` は、直し忘れを検査するときだけ渡す（[直し忘れを検査する](#直し忘れを検査する)）。
`--text`・`--file` は、文字列や YAML のキーの中の記法だけを点検するときに渡す（[文字列と YAML のキーの記法を点検する](#文字列と-yaml-のキーの記法を点検する)）。
設定・索引・文書は書き換えない。

次を点検する。

- 設定が `schemas/mdmark.config.schema.json` に合うこと。`build.glossary`・`build.entry` が `build.include` に当たらないこと、`theme`・`extensions` のファイルと `assets.root` のフォルダが無いこと、`extensions` の拡張を読み込めないことも、合わないものとして出す
- 設定に `index` があるとき、索引が `schemas/mdmark.index.schema.json` に合うことと、索引と文書のずれ。索引のフォルダの下の拡張子 `.md` のファイルのうち `build.exclude` に当たらないものを文書として確かめる
- 設定に `build` があるとき、`build.include` に当たり `build.exclude` に当たらない文書が 0 件でないこと
- 設定に `aliases` があるとき、行が取り込んだ Schema に合うことと、行の `paths` に当たった YAML からエイリアスを作れること。`enabled` が `false` の行は読まない
- 索引の文書と `build` の対象の文書の本文に、知らない印が無いこと。記法の印・`features`・`libraries` の対応表・`extensions` の拡張の印・`check.ignore` の名前のどれにも当たらない印を出す。コードブロックとインラインコードの中は見ない
- 索引の文書と `build` の対象の文書が相対パスで指す画像（動画の `poster` を含む）・動画・音声と、添付のカードにするファイルが、文書のフォルダか設定の `assets.root` のフォルダにあること。コードブロックとインラインコードの中・絶対 URL・`#` で始まるリンクは見ない
- 索引の文書と `build` の対象の文書の `flow`・`sequence`・`chart`・`param` の印の中の部品の定義を読めること。フロー図は、箱が重ならないこと・図の幅と高さに収まること・線が `from`・`to` でない箱を通らないこと・箱の文字が箱に収まること。座標を省いた判定フローチャートは、mdmark が配置した後の座標で確かめる

#### ずれの一覧を読む

ずれ 1 つが 1 行で、最後に件数の行が出る。

```text
docs/index.yaml:docs[1].path: missing_doc: `old.md` が見つかりません。文書を戻すか、索引の `docs[1]` を消してください。
mdmark.config.yaml:build: schema: `build.out` がありません。書き出す HTML のパスを書いてください。
ずれ 2 件
```

行は `{ファイル}:{場所}: {種類}: {内容}` で、場所が空のときは `{ファイル}: {種類}: {内容}`。
ファイルは設定ファイルのあるフォルダからの相対パス。
種類と意味は [CLI](../../リファレンス/CLI.md#設定と索引を点検する)。
内容に、何が合わないかと直し方が書いてある。

#### ずれを直して点検し直す

内容に従って設定・索引・文書を直し、`check` をもう一度呼ぶ。
`avoided_term` は、内容に書いた行のやめた言い方を、代わりに使う用語の語に書き直す。
やめた言い方を使い続けるときは、索引の用語の `avoid` か、用語集の表のやめた言い方の列から外す。
`unregistered_tag` は、内容に書いたタグを、索引の `tags` に語彙として足すか、近いタグに直す。
`deprecated_tag` は、文書のタグを、内容に書いた振り替え先のタグに直す。
`duplicate_tag` は、索引の `tags` の同じ `name` を 1 つにまとめる。
`tag_alias_conflict` は、内容に書いた重なった先のタグと重ならないよう、`aliases` を直す。
`broken_tag_replacement` は、`deprecated` を索引の `tags` にある `name` に直すか、振り替え先のタグを語彙に足す。
`untyped_related` は、文字列の関連を、`to`・`type`・`when` を持つオブジェクトに書き換える。
`one_sided_change_together` は、内容に書いた相手の文書にも、自分への `change_together` を記載する。
`related_link_overlap` は、本文でリンクしている相手を `related` から外すか、本文のリンクを外す。
`broken_ref` は、`related` の `to` を索引にある文書の `id` に直す。
`unknown_mark` は、内容に書いた行の印の名前を直す。
`missing_file` は、内容に書いた行のパスを直すか、そのパスにファイルを置く。
ファイルを 1 か所にまとめて置いているときは、設定の `assets.root` がそのフォルダを指しているかを確かめる（[アセットのルート](../../リファレンス/設定.md#アセットのルート)）。
`diagram_invalid` は、内容に書いた書き方の警告のとおりに部品の定義を直す。`diagram_node_overlap`・`diagram_node_overflow`・`diagram_wire_crosses_node` は、内容に書いた箱の `x`・`y`・`w`・`h` を直す。`diagram_label_too_long` は、箱の文字を短くするか箱の `w` を広げる。
`aliases` のずれは、内容に書いたファイルと場所を、次のように直す（キーの書き方は [エイリアスの元の行](../../リファレンス/設定.md#エイリアスの元の行)）。

`extensions` の拡張を読み込めないと出たときは、拡張のモジュールが読み込みの時点で使うブラウザの API（`HTMLElement`・`window` など）を、`load` の中へ移す。
他のツールへの指示（`<!-- prettier-ignore -->` など）のように印として書いていないコメントは、設定の `check.ignore` に名前を足す（[点検から外す名前](../../リファレンス/設定.md#点検から外す名前)）。
`ずれ 0 件` になるまで繰り返す。

#### 直し忘れを検査する

`change_together` の組のうち片方の文書だけを直したことを検査するときは、比べる基準の git の ref を `--base` に渡す。

```bash
npx github:shuhei1101/mdmark#v{版} check --base origin/develop
```

基準と HEAD の merge-base から作業ツリーまでに変わったファイルを引き、片方の文書だけが変わった組を `missed_change_together` で出す。
内容に書いた変わった側の文書の内容を確かめ、変わっていない側の文書も直す。
直さなくてよいときは、`change_together` の関連を見直す。
`--base` を省くと、直し忘れを検査しない。

CI で流すときは、基準の ref と HEAD の merge-base を引けるよう、checkout の `fetch-depth` を `0` にして履歴を全て取得する。

#### 文字列と YAML のキーの記法を点検する

文書のファイルではなく、Markdown の文字列や、YAML のファイルのキーの値に書いた記法を点検するときは、`--text` か `--file` と `--key` を渡す。

```bash
echo '<!-- tabz -->' | npx github:shuhei1101/mdmark#v{版} check --text -
npx github:shuhei1101/mdmark#v{版} check --file records.yaml --key items[0].body
```

`--text -` は標準入力から Markdown を読む。
`--key` は `.` でキーを、`[位置]` で配列の要素をたどる。
描いたときに出る書き方の警告・知らない印・図の配置のずれを、設定と索引の点検と同じ `{ファイル}:{場所}: {種類}: {内容}` の行で出す。
`--text` のファイルは `-`、場所は文字列の行。
`--file` の場所は YAML のファイルの行で、ブロックスカラー（`|`・`>`）の値は値の中の行をファイルの行に置き換える。
設定ファイルがあれば `features`・`libraries`・`extensions`・`check.ignore` を当て、無ければ既定の設定で点検する。
設定・索引・`build` の対象は点検しない。
`--text`・`--file` は `--base` と一緒に渡せず、`--file` と `--key` は一緒に渡す。

dev-docs や MindStella のように YAML のキーへ Markdown を書き込むツールは、書き込むたびにこの点検を呼ぶ。
Claude Code からは MCP の `check` に `text` か `file`・`key` を渡す（[MCP のツールを使う](../ClaudeCodeで使う/MCPのツールを使う.md)）。

#### 点検できないとき

設定ファイルが無いときは、探した場所と `mdmark init` で置けることを標準エラーに出す。
設定ファイルを YAML として読めないときは、ファイルと読めない行と直し方を標準エラーに出す。
`--base` の ref と HEAD の merge-base を引けないときは、渡した ref と引けない理由と、ref を直すか履歴を取得する直し方を標準エラーに出す。
`--file` のファイルが無いか読めないとき、`--key` のキーが無いか値が文字列でないとき、一緒に渡せない引数を渡したときは、原因と直し方を標準エラーに出す。
どれも終了コード 1 で終わる。

## 反映

即時。`check` を呼ぶたびに、その場の設定・索引・文書を点検する。

## 確認

#### ずれが 0 件になっている

標準出力が `ずれ 0 件` の 1 行になり、終了コードが 0 になる。
ずれがあるときの終了コードは 1。

## 元に戻す

`check` は何も書き換えないため、戻すものは無い。
