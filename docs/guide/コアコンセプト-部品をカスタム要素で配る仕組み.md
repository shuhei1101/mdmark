# 部品をカスタム要素で配る仕組み

mdmark の部品をカスタム要素として jsDelivr から配り、アプリの画面が `@0` で更新に追従し、操作をイベントで受け取る流れ

## 配る

部品のカスタム要素は、文書を描く配布物と同じ `dist/index.js` に入れて配る。
ページが `dist/index.js` を読み込むと、配布物が持つカスタム要素（今は `<mdmark-table>`）を `customElements` に登録する。
別の参照の配布物が先に同じ名前を登録していれば、登録しない。
Node で `render` を使用するときは `customElements` が無いため、何もしない。

## 更新に追従する

アプリの画面は、配布物を `@0`（メジャーバージョンの範囲）の URL で読み込む。
mdmark が 0.x のタグを出すと、アプリの依存の更新とビルドをせずに、CDN のキャッシュが切れた後のページの読み込みから変更後のタグの配布物になる。
0.x の間に部品のカスタム要素へ破壊的変更を出すときは、使用する側のアプリも同時に合わせる。
バージョンを固定したいアプリは、`v{MAJOR}.{MINOR}.{PATCH}` のタグで読み込む（[配布物を読み込む](./導入-配布物を読み込む.md)）。

## 描く

アプリの画面は、要素の JavaScript のプロパティにデータを指定する。
要素は次のマイクロタスクで指定を確認し、Markdown の記法と同じ部品の HTML を要素の中に描いて、文書の部品と同じ操作を付ける。
Shadow DOM を使用しないため、ページが読み込んだ `dist/index.css` とページの CSS がそのまま適用される。
指定に誤りがあると、例外を投げずに要素の中に通知を出し、ページのほかの要素は動く。

## 操作を受け取る

利用者の操作のうち、アプリの処理（詳細を開く・保存する）に結び付けるものは、要素から `CustomEvent` で通知する。
並べ替え・絞り込みなど表示だけの操作は要素の中で完結し、データを指定し直しても状態を保つ。
mdmark はデータを保存しない。
保存はアプリがイベントを受けて行い、データを指定し直す。

## ほかの部品を追加する

部品のカスタム要素は、登録する関数の一覧に 1 つ加えると追加できる。
表のほかの部品も、同じ方式で後から配る。
