# バージョンを上げる仕組み

バージョンごとの移行の手順をバージョンの順に当て、コピーから戻し、点検してからバージョンを書き換える流れ

`mdmark upgrade` が、設定・索引・文書を新しいバージョンに合わせる考え方。
手順は [バージョンを上げる](./導入-バージョンを上げる.md)。

## 適用するまでの流れ

1. 目標のバージョンを、呼んだ CLI のバージョンにする。引数では受けない。手元のバージョンは設定の `version` から読み込み、無ければ聞く
2. 手元のバージョンが目標のバージョンと同じなら何も当てず、手元のバージョンが新しければ手元のバージョン以上の CLI でもう一度呼ぶことを示して止まる
3. 手元のバージョンより新しく目標のバージョン以下のバージョンの `steps.yaml` を、バージョンの順に読み込み、構造が合うかを確認する。1 つでも合わなければ何も書き換えない
4. 値を聞く手順の質問と、壊す手順の確認を、書き換えの前に聞く
5. 書き換えうるファイルのコピーを取り、手順をバージョンの順に適用する
6. `mdmark check` と同じ点検を実行し、ずれが 0 件のときだけ設定の `version` を目標のバージョンに書き換える

手順を持たないバージョンは飛ばす。
`--plan` は 3 で止まり、何も書き換えない。

## 移行の手順

バージョンごとの `migrations/{バージョン}/steps.yaml` に、mdmark の開発者が手順を並べる。
手順の種類は次の 5 つ。

| 種類 | 適用すること |
| --- | --- |
| `rename_key` | 設定・索引のキーの名前を変える |
| `set_default` | 設定・索引に無いキーを追加する。値は手順に記載するか、利用者に聞く |
| `map_values` | 設定・索引のキーの値を、表のとおりとして解釈する |
| `replace_mark` | 文書のマーカーを書き換える |
| `call` | 宣言で記載できない移行を、同梱のスクリプトで適用する |

どの手順も、既に該当した後の状態に適用しても結果が変わらない。
値が失われる手順には壊すマーカーが付き、`--yes` が無いとき適用する前に確認する。
設定・索引はコメント・キーの並び・触らないキーの記載方法を残して書き換える。

## 失敗したとき

手順の失敗か点検のずれがあると、コピーの全てのファイルを元の場所へ戻し、設定の `version` を変えない。
コピーは、設定ファイルのあるフォルダの `.mdmark/backup/{日時}/` に残る。
戻す前に止まっても（`Ctrl-C` など）、設定の `version` は手元のバージョンのままなので、次の `upgrade` が同じ手元のバージョンからもう一度適用する。
手順がもう一度適用しても結果の変わらない構造のため、該当した手順をもう一度当てても壊れない。

## 変更履歴

適用した範囲（手元のバージョンより新しく目標のバージョン以下）の変更履歴の行を、手順と一緒に出す。
行は [変更履歴](./変更履歴.md) の表から取る。
