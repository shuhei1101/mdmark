# 索引と用語集を記載する

索引に文書と用語を記載し、表から用語集に用語を入れる手順

文書の用語に意味のツールチップを付けるとき、文書を参照している文書を文書の末尾に出すとき、索引と文書のずれを見つけるときに実行する。

## 前提

- [文書を描く](./導入-文書を描く.md)
- 利用側のサーバーが、索引の YAML と文書の Markdown を読み込める

## 手順

### 索引に文書と用語を記載する

#### 索引の YAML を記載する

```yaml
schema: 2
docs:
  - id: arch
    path: 設計/arch.md
    title: アーキテクチャ
  - id: api
    path: api.md
    title: API
    description: mount と render の引数
    aliases: [公開関数]
    related:
      - to: arch
        type: requires
        when: 公開関数の前提の構成を確認するとき
terms:
  - id: workspace
    term: ワークスペース
    aliases: [WS]
    meaning: 話し合いの記録を配置するフォルダ
    avoid: [作業場]
```

`path` は索引のファイルからの相対パスで記載する。
`avoid` に、使用しないことにした言い方を並べる。
本文に出ると、描いた文書では波線のマーカーとツールチップが付き、点検も通知する（[索引と文書のずれを点検する](#索引と文書のずれを点検する)）。
キーと型は [索引](./索引.md)。
索引の場所は、設定の `index` に記載する（[索引の場所](./設定.md#索引の場所)）。

#### 索引と文書の `id` を指定して描く

利用側のサーバーが索引の YAML を読み込み、読み込んだオブジェクトと描く文書の `id` を `mount` に指定する。

```js
mount(document.querySelector("#doc"), { markdown, index, docId: "arch" });
```

本文に出た用語の単語・別名に破線の下線が付く。
下線は、同じ用語（単語と別名を合わせた用語の `id`）の、セクションごとに最初に出たところだけに付く。
単語の始まりと終わりが本文の単語の区切りに一致するところだけを照合するため、`印刷` の中の `マーカー` には付かない。
`Intl.Segmenter` を持たないブラウザ（Firefox 124 以前）では、英数字の連なりを 1 単語とし、それ以外の文字を 1 文字ずつ区切って照合する。
英字の単語の一部（`WSL` の中の `WS`）には付かないが、`印刷` の中の `マーカー` には付く。
コード・リンク・見出し・用語集の表の中の単語には付かない。

照合の前に、索引・用語集の表の単語と本文の文字の両方を、NFKC・英字の小文字化・前後の空白の除去で正規化する。
全角と半角（`ＡＰＩ` と `API`）、英字の大文字と小文字（`Api` と `API`）だけが違う単語は同じ単語として照合し、下線は本文に記載したままの文字に付く。
活用形・送り仮名・別の言い方のように、正規化しても同じにならない揺れは、`aliases` に記載する。

ポインターを乗せるかフォーカスすると、見出し「用語」に意味を出したツールチップが開く。
ツールチップの上へポインターを移しても開いたままで、Esc で閉じる。
タッチの端末では、単語のタップで開き、ツールチップと単語の外のタップか、同じ単語のもう一度のタップで閉じる。ツールチップの中のリンクとボタンのタップでは閉じない。
索引を指定しないときは、用語集の表から入れた用語だけが付く。

索引の用語の `avoid` と用語集の表の `avoid.column` の列に並べたやめた言い方が本文に出ると、波線のマーカーが付く。
やめた言い方も、用語と同じ正規化をして照合する。
マーカーは、同じやめた言い方の、セクションごとに最初に出たところだけに付き、用語の下線とは別に数える。
ポインターを乗せるかフォーカスすると、見出し「代わりの用語」に代わりの用語の単語と意味を出したツールチップが開き、開閉の操作は用語のツールチップと同じ。
同じやめた言い方を複数の用語が持つときは、次の順で先の用語が代わりの用語になる（点検の `avoided_term` と同じ順）。

| 優先 | やめた言い方を持つ場所 | 代わりの用語 |
| --- | --- | --- |
| 先 | 索引の `terms` の用語の `avoid` | その用語 |
| 後 | 索引の `docs` の順の文書の用語集の表の行。描く文書が `docs` に無いときは、描く文書の表をほかの文書の表より先にする | その行の用語の列と意味の列の文字 |

用語の単語・別名の一部として出たところ（`ワーク` をやめた言い方にしたときの `ワークスペース`）には付かず、コード・リンク・見出し・用語集の表の中にも付かない。
色は CSS 変数 `--mdmark-color-avoided-underline` で変える（[テーマの CSS 変数](./API.md#テーマの-css-変数)）。
`glossary` をオフにすると、マーカーもツールチップも付かない。

### 文書の関連を記載する

#### 関連に相手・関係の種類・いつ読み込むかを記載する

```yaml
docs:
  - id: api
    path: api.md
    title: API
    related:
      - to: arch
        type: requires
        when: 公開関数の前提の構成を確認するとき
```

`to` に相手の文書の `id`、`type` に関係の種類、`when` にいつ読み込むかの 1 文を記載する。
`type` は `requires`（前提）・`references`（参照）・`replaces`（置き換え）・`part_of`（一部）・`change_together`（一緒に修正する）のどれか。
関連が該当するファイルを絞るときは、`paths` に glob の並びを記載する。
キーと型は [索引](./索引.md#関連の要素)。

関連は片側だけに記載する。
`change_together` だけは、両側に記載する。
片側にしか記載していない `change_together` は、点検が通知する。
本文でリンクしている相手は、`related` と本文のリンクのどちらか一方にする（`change_together` を除く）。
文字列の要素（`related: [arch]`）も読み込めるが、`type` と `when` を持たない関連として扱い、点検がオブジェクトへの書き換えを求める。

### 主題のタグを記載する

#### 使用されているタグを取得する

タグを付与する前に、索引の `docs` の全ての文書の `tags` を参照し、使用されているタグを全件取得する。
付与するタグと同じ概念の言い方・活用の違いだけのタグが使用されていれば、新しく作成せずにそのタグを使い回す。

#### 付与するタグを決める

付与するかは、knowledge の規約『[タグと用語の登録](https://github.com/shuhei1101/knowledge/blob/develop/docs/rule/dev-tag-term-registration.yaml)』と判定フローチャート『[タグの付与](https://github.com/shuhei1101/knowledge/blob/develop/docs/flowchart/flowchart-tag-attach.yaml)』で決める。
その単語で探した人にこの文書が出てほしいタグは全て付与し、最も分量の多い主題のタグに `main: true` を付ける。

#### 文書に主題のタグを付ける

文書の `tags` に、タグの名前の文字列か、`name` と `main` を持つオブジェクトを記載する。
その文書の主題を表すタグは、`main: true` を付けたオブジェクトで記載する。

```yaml
docs:
  - id: arch
    path: 設計/arch.md
    title: アーキテクチャ
    tags: [設計, { name: topic:mcp, main: true }]
```

文字列で記載したタグは、`main: false` と同じ。

### 表から用語集に用語を入れる

#### 表を `glossary` のマーカーで囲む

```markdown
<!-- glossary: {"term": {"column": "用語"}, "aliases": {"column": "別名"}, "meaning": {"column": "意味"}} -->

| 用語 | 別名 | 意味 |
| --- | --- | --- |
| マーカー | マーカー、オン・オフのマーカー | HTML コメントで記載する指定 |

<!-- /glossary -->
```

`term.column`・`meaning.column` に、用語と意味の列の見出しの文字を記載する。
別名の列は `aliases.column` に記載し、別名のセルは「、」か「,」で区切る。
「・」は別名の中の文字として扱うため、`オン・オフのマーカー` は 1 つの別名になる。
やめた言い方の列は `avoid.column` に記載し、セルは別名と同じく区切る。
索引の文書の本文にやめた言い方が出ると、点検が通知する（[索引と文書のずれを点検する](#索引と文書のずれを点検する)）。
この列のやめた言い方にも、索引の用語の `avoid` と同じく、描いた文書で波線のマーカーと、その行の用語を代わりの用語にしたツールチップが付く。
ほかの文書の表のやめた言い方は、`collectReferences` の戻り値を `references` に指定したときに有効になる。
表は普通の表として描き、表の中の単語には下線を付けない。

索引に同じ単語があるときは、索引の意味をツールチップに出す。
同じ単語かどうかは、正規化した後で判定する。
設定の `aliases` にも同じ単語があるときの順は [設定の `aliases` で YAML からエイリアスを登録する](#設定の-aliases-で-yaml-からエイリアスを登録する)。
索引を指定し、`collectReferences` の戻り値を `references` に指定すると、ほかの文書の用語集の表から入れた用語も有効になる。

列名が表に無いときも、表と本文は描かれる。
その箇所に記載の警告が出て、この表からは用語を入れない。

### 設定の `aliases` で YAML からエイリアスを登録する

#### 設定に元の行を記載する

プロジェクトの YAML（用語・コマンド・URL などの一覧）を、表に発生させずにエイリアスとして登録する。

```yaml
aliases:
  - id: terms
    paths: ["terms/*.yaml"]
    alias_type: term
    records: terms
    metadata:
      name: term
      description: meta.meaning
  - id: commands
    paths: ["commands/*.yaml"]
    alias_type: command
```

`paths` に、読み込む YAML のパスか glob を、`mdmark.config.yaml` のあるフォルダからの相対パスで記載する。
`records` を記載すると、ファイルのそのキーの配列の要素ごとに 1 件のエイリアスを作り、記載しないと各ファイルを 1 件にする。
`alias_type` に、行の全てのレコードのエイリアスの種類を記載する。省略できない。
`metadata` に、エイリアスのキーごとに値を取るレコードの列の名前を記載する。入れ子の列は `meta.meaning` のように `.` でつなぐ。
記載しないキーは、同じ名前の列から取る。
種類の違うレコードは、種類ごとに行を分ける。
キーと種類は [エイリアスの元の行](./設定.md#エイリアスの元の行)。
索引の `terms` と用語集の表は今のまま使用でき、全てを同時に使用できる。

#### エイリアスを作って指定する

CLI の `export`・`build` は、設定の `aliases` の YAML を読み込み、書き出す HTML に埋める（[CLI](./CLI.md#文書を-html-に書き出す)）。
VS Code 拡張機能も同じく読み込み、プレビューと書き出す HTML に下線とツールチップを出す（[設定ファイルのキー](./VSCode拡張機能.md#設定ファイルのキー)）。
利用側のサーバーが `mount` で描くときは、行の `paths` に該当した YAML を読み込み、`buildAliases` で作った配列を `opts.aliases` に指定する。

```js
const { aliases, problems } = buildAliases({ rows: config.aliases, sources });
mount(document.querySelector("#doc"), { markdown, aliases });
```

`sources` は、行の `paths` に該当したファイルを YAML として読み込んだ中身の並び（[エイリアスを作る](./API.md#エイリアスを作る)）。
使用できない行・レコードは除かれ、`problems` にずれとして返る。
`env` のエイリアスは、値にシークレットキーを含みうるため、作られず、照合も書き出しへの埋め込みもされない。

#### ツールチップを読み込む

本文に出たエイリアスの名前・別名に、用語と同じ規則で破線の下線が付き、種類ごとに区分の見出しの下へ内容を出したツールチップが開く。

<!-- table: {"kind": "data"} -->

| 種類 | 区分の見出し | 出す内容 |
| --- | --- | --- |
| `term` | 用語 | 名前・説明 |
| `doc` | 文書 | 名前・説明 |
| `command` | コマンド | 名前・説明・コマンド・実行場所 |
| `url` | URL | 名前・説明・リンク |
| `skill` | スキル | 名前・説明・スキル名 |
| `tool` | ツール | 名前・説明・ツール名 |
| `path` | パス | 名前・説明・パス |
| `avoid` | 代わりの用語 | やめた言い方の置き換え先 |

<!-- /table -->

`command` のコマンドはコードで出し、`コピー` のボタンを押すとクリップボードへ書き込む。
書き込めたらボタンが `コピーしました` になって 2 秒で戻り、書き込めないときは `コピーできませんでした` のまま残る。
`url` は URL の文字列にリンクを埋め、長い URL は 1 行に収めて末尾を「...」で省略する。
http・https でない URL（`javascript:` など）は、リンクにせず文字で出す。
`avoid` の種類と、`term` の `avoid` の言い方は、用語のやめた言い方と同じく波線のマーカーと「代わりの用語」のツールチップが付く。
`glossary` をオフにすると、エイリアスの下線もツールチップも付かない。

同じ単語が複数の登録元にあるときは、次の順で先の意味を出す。

| 優先 | 登録元 |
| --- | --- |
| 1 | 索引の `terms` |
| 2 | 設定の `aliases`（行の並び。行の中は `paths` に該当したファイルとレコードの順） |
| 3 | 描く文書の用語集の表 |
| 4 | ほかの文書の用語集の表（索引の `docs` で先に並ぶ文書） |

### 被参照と関連文書を出す

#### 参照の表を作って指定する

利用側のサーバーが、索引と全ての文書の本文から参照の表を作る。

```js
const references = collectReferences({ index, documents });
mount(document.querySelector("#doc"), { markdown, index, docId: "arch", references });
```

`documents` は、文書のパスから Markdown を参照する表で、パスは索引のファイルからの相対パスで記載する。
文書を書き換えたら、参照の表を再作成する。

文書の末尾に、その文書を参照している文書が、タイトル「関連文書」のリンクの一覧で並ぶ。
文書を参照しているのは、次のどれかに該当する文書で、自分自身は並ばない。

- `related` にその文書の `id`（オブジェクトの要素は `to`）を記載した
- 本文のリンクがその文書の `path` を指す
- 本文にその文書の `aliases` が出る

`aliases` は、全角と半角・英字の大文字と小文字の違いを無視して照合する。
参照されていない文書には、一覧を配置しない。
参照の表を指定しないときは、索引の `related` だけから出す。

#### 文書の別名を記載する

索引の文書の `aliases` に記載した単語が本文に出ると、用語と同じ規則で下線が付く。
ツールチップの見出し「関連文書」に、一致した文書のタイトル・リンク・`description` が並ぶ。
描いた文書自身は並ばない。
用語にも一致する単語は、「用語」→「関連文書」の順に並ぶ。
関連文書のリンクはキーボードで、単語の次の Tab から中へ移れる。
関連文書が多いときは、ツールチップの中をスクロールする。

文書の別名の数え方は用語とは別で、文書の `id` ごとに、セクションで最初に出たところだけに下線が付く。
用語を数え終えた単語でも、文書の別名としてセクションで初めて出たなら、「関連文書」だけのツールチップで下線が付く。

### 画面を出さずに本文の参照を取り出す

#### `collectMatches` を呼ぶ

利用側の処理（AI へ本文を返却するサーバーなど）が、索引と文書の本文を指定し、本文に出た用語・文書の別名の一致を受け取る。

```js
const { byDocument, avoided, targets } = collectMatches({ index, documents });
```

`documents` は `collectReferences` と同じ、文書のパスから Markdown を参照する表。
複数の文書を指定できる。

`byDocument` は、文書の `id` から、その文書の本文の一致の並びを参照する表。
要素は、参照先の種類（`kind`）・`id`・`title`・`description` と、一致した文字列（`text`）・本文の位置（`line`・`start`・`end`）を持つ。
`avoided` は、文書の `id` から、その文書の本文に出たやめた言い方の並びを参照する表。
要素は、代わりの用語の種類（`kind`）・`id`・`title`・`description` と、一致したやめた言い方（`text`）・本文の位置（`line`・`start`・`end`）を持つ。
`glossary` がオフの文書は、空の並びになる。
`targets` は、指定した全ての文書の参照先を、重なりを除いてまとめた並び。
`aliases` に `buildAliases` で作ったエイリアスを指定すると、エイリアスの一致も返却する（`kind` が `alias` で、種類は `aliasType`）。
`avoid` の種類のエイリアスは `avoided` に返却し、`env` は返却しない。
キーと型は [本文の参照を取り出す](./API.md#本文の参照を取り出す)。

一致の規則は、描いた文書の下線とツールチップと同じ。
照合の前の正規化も同じで、`text` は照合した索引・用語集の表に記載した表記のまま返却する。
本文に記載した表記は、本文の位置（`line`・`start`・`end`）から参照する。
同じ実行環境で、`mount` に同じ索引・設定と、同じ `documents` から `collectReferences` で作った参照の表（`references`）を指定して描いた下線と、同じ単語が一致する。
単語の区切りは実行環境に依る（`Intl.Segmenter` の有無と辞書で決まる）ため、サーバーで取り出してブラウザで描くときは、一致が変わることがある。
ただし、ツールチップの、セクションごとに最初の 1 回だけに下線を付ける制限は有効にならず、同じ参照先の出現を全て並べる。
やめた言い方のマーカーの、セクションごとに最初の 1 回だけに付ける制限も有効にならず、`avoided` には同じやめた言い方の出現を全て並べる。
位置は、本文の Markdown の行（1 から）と、その行の中の UTF-16 の位置（0 から）で、本文に記載したままの範囲を指す。

### 索引と文書のずれを点検する

#### `checkIndex` を呼ぶ

```js
const issues = checkIndex({ index, documents, indexFile: "docs/index.yaml" });
```

`index` は読み込んだ値をそのまま指定する。
`documents` に、索引のフォルダにある文書のパスと本文を指定する。
索引に無い文書・索引にあって削除された文書・`related` の切れた `id`・文字列の関連・片側だけの `change_together`・本文のリンクと重なる関連・用語の重複・本文に出た用語のやめた言い方・Schema に合わない索引が、ファイル・場所・種類・内容の一覧で返る。
ずれが無ければ、空の一覧が返る。
用語の重複は、単語と別名を正規化した後に同じになるものも数え、本文に出たやめた言い方も正規化して照合する。
`changedPaths` に、比べる基準から変わった文書のパスを指定すると、`change_together` の組のうち片方の文書だけが変わった組が、修正漏れとして `missed_change_together` で返る。
パスの引き方は呼ぶ側が決める（`mdmark check --base` は git の merge-base から参照する。[点検する](./書き出す-点検する.md)）。
種類は [点検が返却するずれ](./索引.md#点検が返却するずれ)。

## 反映

即時。`mount` を呼ぶと、その場で描かれる。
`update` は、`mount` に指定した索引と参照の表で本文を再描画する。
索引や文書を書き換えたときは、参照の表を再作成し、再読み込みした値を指定して `mount` をもう一度呼ぶ。

## 確認

#### 用語のツールチップが出る

下線の付いた単語にポインターを乗せる。
意味のツールチップが出て、ツールチップの上へポインターを移しても出たままになる。
Tab で下線の付いた単語へフォーカスしても出て、Esc で閉じる。

#### エイリアスのツールチップが出る

設定の `aliases` の YAML に記載した名前が本文に出る文書を描き、下線の付いた単語にポインターを乗せる。
種類の区分の見出しの下に、名前と説明が出る。

#### 被参照の一覧が出る

文書の末尾に、タイトル `関連文書` の一覧がある。

```js
document.querySelector(".mdmark .mdmark-backlinks-title").textContent
```

`関連文書` が出る。
一覧のリンクの `href` は、描いた文書の `path` を基準にした相対パスになっている。

#### 本文の参照が返る

本文に索引の用語の単語を含めた文書を指定して `collectMatches` を呼ぶ。

```js
collectMatches({ index, documents }).byDocument["arch"].map((m) => m.text)
```

本文に出た用語・文書の別名の `text` が、本文の頭からの順に並ぶ。

#### 点検がずれを返却する

索引から文書を 1 つ削除した状態で `checkIndex` を呼ぶ。
その文書の行が `orphan_doc` で返る。

## 元に戻す

`mount` から `index`・`docId`・`references`・`aliases` を削除すると、索引を指定しない文書と同じに描く。
用語集の表のマーカーを削除すると、表は普通の表に戻る。
機能を止めるときは、[機能をオン・オフする](./カスタマイズ-機能をオン・オフする.md) で `glossary`・`backlinks` をオフにする。
