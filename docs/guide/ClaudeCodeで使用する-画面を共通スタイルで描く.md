# 画面を共通スタイルで描く

mod のプラグイン mdmark-style を入れ、Claude Code の返答と発言を mdmark の共通スタイルで描く手順

mdmark-style は、Claude Code の返答の表・見出し・注意書き・コードブロック・開閉の範囲を mdmark の共通スタイルで描き、返答と発言の用語に下線・カード・脚注を付ける。
返答に記載した mdmark のマーカーは画面に出さず、描き方に使用する。
ターミナル版・デスクトップ版・VS Code の拡張機能で同じように動く。

## 前提

- 手元に Claude Code がある
- マーケットプレイス `mdmark` を追加している（[プラグインを入れる](./ClaudeCodeで使用する-プラグインを入れる.mark.md)）
- 用語のマーカーを付けるときは、用語を記載した索引と `mdmark.config.yaml` がある（[索引と用語集を記載する](./記載する-索引と用語集を記載する.mark.md)）

## 手順

### プラグインを入れる

```text
/plugin install mdmark-style@mdmark
```

ターミナルからは `claude plugin install mdmark-style@mdmark` で入れられる。
プラグイン mdmark とは別に入れ、別に外せる。

### 用語集を指定する

用語のマーカーを付けるときだけ、`~/.config/mdmark-style/settings.yaml` の `global.glossary` に、用語を取る `mdmark.config.yaml` のパスを記載する。
設定ファイルを別の場所に置くときは、`~/.claude/settings.json` の `env` に `MDMARK_STYLE_CONFIG` でパスを記載する。

```yaml
global:
  glossary: ~/notes/mdmark.config.yaml
```

キーの一覧と既定は [設定](./設定.mark.md#画面を描く-mod-の設定) にある。
全てのキーの見本は、プラグインの中の `settings.sample.yaml`。

### 次のセッションを開く

入れた後に開くセッションから描き換わる。
設定ファイルと用語集は描くたびに読み直すため、書き換えた後は Claude Code を開き直さなくてよい。

## 描き換えるもの

| 部品 | 描き方 |
| --- | --- |
| 表 | 罫線で囲む。`<!-- table: {"kind": "data"} -->` の表は見出しの行を太字にする。端末の幅を超えるとき、デスクトップ版は表の中で横にスクロールし、ターミナル版・VS Code はセルの中で折り返す |
| 見出し | 太字と見出しの色で描き、`#` を描かない |
| 注意書き | `> [!NOTE]` などの 5 種を、種類の色の縦線とラベルで描く |
| コードブロック | 背景の面の中に色分けして描き、言語のラベルとコピーのボタンを付ける。`<!-- code: title=ファイル名 lines -->` と行末の `[!code ++]` などで、タイトル・行番号・行の色を付ける |
| 開閉の範囲 | `<!-- details: タイトル -->` 〜 `<!-- /details -->`・`<!-- section: closed -->` の見出しのセクション・`> [!TIP]-` の注意書きを、押すと開くボタンにする |
| 用語 | 返答と発言の用語の最初の出現に下線を付け、ポインターを乗せるとカードで意味を出し、本文の後ろに脚注を並べる |

図（mermaid・map）と埋め込んだ HTML は、コードブロックとして描く。
部品ごとのオン・オフは設定の `parts` で切り替える。

セッションの開始で、モデルにマーカーの記載方法を 1 つの文で渡す（`inject_marker_guide`）。

## 確認

#### プラグインが有効になっている

```bash
claude plugin list
```

`mdmark-style@mdmark` が有効として出る。

#### 返答が描き換わる

新しいセッションで、表と注意書きを含む返答を頼む。
表が罫線で囲まれ、注意書きが種類の色の縦線で描かれ、`<!-- ... -->` のマーカーが画面に出ない。

#### 描き換わらないとき

`claude --debug` で開き、デバッグログに `mdmark-style` の行があるかを確認する。
設定ファイルを YAML として読み込めないときは、返答を Claude Code の元の描画で描き、デバッグログに理由を出す。
