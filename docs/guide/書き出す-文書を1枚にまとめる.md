# 文書を1枚にまとめる

設定の `build` を記載し、`mdmark build` で複数の文書を 1 枚にまとめる手順

複数の Markdown を、文書の一覧と文書間のリンクで行き来できる、CDN を読み込まない 1 枚の HTML にして配るときに実行する。

## 前提

- [雛形を配置する](./書き出す-雛形を配置する.md)（設定ファイル `mdmark.config.yaml` を今のフォルダか上のフォルダに配置している）
- Node 24 以降
- 文書が外部ライブラリのマーカーを持つときは、書き出す手元から設定の `libraries` の URL の先へ届く

## 手順

### まとめる文書を決める

#### 設定に `build` を記載する

```yaml
build:
  include: ["**/*.md"]
  exclude: ["下書き/**"]
  glossary: ["用語集.md"]
  entry: README.md
  out: dist/docs.html
```

パスと glob は、設定ファイルのあるフォルダからの相対パスで記載する。
キーは [まとめる設定](./設定.md#まとめる設定)。

- `include`: まとめる Markdown の glob。必須
- `exclude`: `include` に該当した文書から除外する glob
- `glossary`: 用語集の表を持つ文書。表の用語を、まとめた全ての文書で有効にしる
- `entry`: 最初に開く文書。省くと `include` で最初に該当した文書
- `out`: 書き出す HTML のパス。必須

文書は `include` の glob の並びで並べ、同じ glob の中はパスの順に並べる。
拡張子が `.mark.md` の文書も末尾が `.md` のため、`**/*.md` に該当してまとめる対象に入る。
複数の glob に該当した文書は、最初の 1 つだけを残す。

#### 索引を書き込むと被参照が有効になる

設定の `index` に索引を書き込むと、索引と文書から参照の表を作って埋め、文書をまたぐ被参照と用語のツールチップが有効になる。
索引の記載方法は [索引と用語集を記載する](./記載する-索引と用語集を記載する.md)。
索引が無くても、`build.glossary` の文書の用語集の表の用語は、まとめた全ての文書で有効になる。

### まとめる

#### `build` を呼ぶ

```bash
npx github:shuhei1101/mdmark#v{バージョン} build [--config {設定ファイル}]
```

`--config` を省くと、端末の設定と、今のフォルダから上のフォルダの `mdmark.config.yaml` を重ねて読み込む（[設定を重ねて読み込む仕組み](./コアコンセプト-設定を重ねて読み込む仕組み.md)）。
`build.out` に HTML を書き込み、既にあれば上書きする。

```text
書き出した: dist/docs.html（文書 3 件）
```

埋まるものは [文書を書き出す](./書き出す-文書を書き出す.md) と同じ。
外部ライブラリはまとめる文書のどれかにマーカーがあるものだけを埋め、同じ URL は 1 つだけ埋める。
画像はそれぞれの文書のフォルダを基準に探し、無ければ設定の `assets.root` で探して埋める。
複数の文書が指す同じ画像は 1 回だけ埋める。
動画・音声は埋めず、`build.out` と同じフォルダの `{build.out のファイル名から拡張子を除いた名前}_files/`（`dist/docs_files/`）へ、同じファイルを 1 回だけコピーする。

#### 警告を読み込む

[文書を書き出す](./書き出す-文書を書き出す.md) の警告に加えて、次を標準エラーに出す。
警告があっても終了コードは 0。

- まとめた HTML に含まれない文書へのリンク。リンクは記載したままの `href` で残る。まとめるなら `build.include` に追加する
- `build.glossary` がまとめる文書に該当しないパス。飛ばす
- `build.entry` がまとめる文書に該当しないパス。まとめる文書の最初の 1 つを開く

```text
警告: README.md: `下書き/メモ.md` へのリンクはまとめた HTML に含まれません。記載したままのリンクで残します。まとめるなら `build.include` に追加してください。
```

#### まとめられないとき

設定ファイルが無い・読み込めない・Schema に合わないとき、設定に `build` が無いとき、`build.include` に該当し `build.exclude` に該当しない文書が 0 件のとき、`build.out` か動画・音声のコピー先の `_files/` へ書き込めないときは、原因と修正方法の 1 文を標準エラーに出し、終了コード 1 で終わる。
HTML は記載しない。

### 読み込む

#### HTML を file:// で開く

まとめた HTML 1 つを、配る先へコピーして開く。
動画・音声を持つ文書をまとめたときは、HTML と隣の `_files/` を一緒に写す。
開くと `build.entry` の文書が描かれ、画面の左に文書の一覧が並ぶ。
開いている文書の行は背景で示す。
開いてから文書を移っても、ページ自身・`_files/` の下のファイルと画像の `data:` のほかへ要求しない。
開くブラウザは Chrome 99・Firefox 98・Safari 16.4 以上。

文書の一覧の文書を選ぶ、まとめた文書へのリンクを押す、関連文書のリンクを押すと、1 枚の中の文書へ移る。
移った文書をブラウザの戻る・進むで行き来できる。
見出しのアンカーと目次のリンクは、移った先の文書の中で有効になる。

開いている文書と見出しは URL の `#` が指し、`#/{文書のパス}` か `#/{文書のパス}#{見出しの ID}` の構造で記載する。
`#` が文書を指していないか、まとめた文書に無い文書を指しているときは、`build.entry` の文書を出す。

幅が 60rem 未満では文書の一覧を左に配置せず、文書の上の帯の「文書の一覧」のボタンで、一覧のパネルを重ねて開く。
文書を選ぶ・背景を押す・Esc・閉じるボタンでパネルを閉じる。
パネルの開閉は履歴に追加しない。

印刷では文書の一覧を出さず、開いている文書だけを出す。
外観は、設定の `theme` の CSS で変える（[テーマを上書きする](./カスタマイズ-テーマを上書きする.md)）。
開いている文書の行の背景は、CSS 変数 `--mdmark-color-current-bg` で変える。

## 反映

即時。`build` が終わると、`build.out` に HTML が記載されている。

## 確認

#### HTML が記載されている

`build.out` のパスに HTML があり、標準出力に `書き出した: {build.out}（文書 {件数} 件）` の行が出て、終了コードが 0 になる。
件数が、まとめたい文書の数と合っている。

#### 文書を行き来できる

HTML と隣の `_files/` だけを空のフォルダへコピーして file:// で開く。
`build.entry` の文書が描かれ、文書の一覧にまとめた文書が並ぶ。
一覧で別の文書を選ぶと、その文書が描かれ、ブラウザの戻るで元の文書に戻る。
ブラウザの開発者ツールのネットワークに、ページ自身・`_files/` の下のファイルと画像の `data:` のほかの要求が出ない。

## 元に戻す

`build.out` の HTML と隣の `_files/` を削除する。
設定の `build`・文書・索引は `build` が書き換えない。
