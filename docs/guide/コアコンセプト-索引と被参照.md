# 索引と被参照

索引を正にし、被参照を描くときに算出し、ずれを点検で見つける仕組み

利用側が記載した索引から、本文の用語のツールチップと、文書を参照している文書の一覧が描かれるまでの考え方。
記載方法は [索引と用語集を記載する](./記載する-索引と用語集を記載する.md)。

## 索引が正

文書のメタデータ（タイトル・概要・別名・関連）と用語の意味は、利用側が記載する索引の YAML だけに持つ。
索引の構造は [索引](./索引.md)。
mdmark はブラウザでファイルを読み込まない。
利用側のサーバーが索引と文書を読み込み、読み込んだオブジェクトを `mount`・`render` と、参照の表を作る `collectReferences`、本文の参照を取り出す `collectMatches`、ずれを見つける `checkIndex` に指定する。

用語は、索引の `terms` のほかに、文書の用語集の表（[用語集の表](./記法.md#用語集の表)）と、設定の `aliases` が指す YAML から作るエイリアスからも入る。
エイリアスは、プロジェクトの任意の YAML の列を、用語・コマンド・URL などの種類つきで登録するもので、元の行の記載方法は [エイリアスの元の行](./設定.md#エイリアスの元の行)。
mdmark はブラウザで YAML を読み込まない。
CLI の `export`・`build` と VS Code 拡張機能のプレビュー・書き出しが設定の `aliases` の YAML を読み込んで `mount` に指定し、利用側のサーバーは `buildAliases` で作った配列を `mount`・`render`・`collectMatches` の `aliases` に指定する。
同じ単語が複数あるときは、索引の `terms`、設定の `aliases`（行の並び。行の中は `paths` に該当したファイルとレコードの順）、描く文書の表、ほかの文書の表（索引の `docs` で先に並ぶ文書）の順に優先する。
同じ単語かどうかは、NFKC・英字の小文字化・前後の空白の除去で正規化した後で比べる。

タグは、索引の `docs[].tags` に自由な文字列で記載する。
文書のタグには、その文書の主題を表すマーカー（`main: true`）を付けられる。
タグは文書を描くことには使用しない。

## 被参照は保存しない

ある文書を参照している文書（被参照）は、どこにも記載せずに、描くときに算出する。
参照は、次のどれかで数える。

| 参照 | 数え方 |
| --- | --- |
| `related` | 参照元の文書の `related` に、参照先の `id` がある（オブジェクトの要素は `to` が参照先の `id`） |
| 本文のリンク | 参照元の本文のリンクが、参照先の `path` を指す |
| 文書の別名 | 参照元の本文に、参照先の `aliases` が出る |

文書の別名の出現は、別名と本文の文字を正規化して比べて数える。
自分自身は数えない。
参照される側の文書に、参照元を追記する必要は無い。
文書を書き換えると、参照の表を再作成した次の描画から反映される。

## 関連は片側だけに記載する

索引の `related` の要素は、相手（`to`）・関係の種類（`type`）・いつ読み込むか（`when`）を持つ。
記載するのは関連を持つ側の文書だけで、逆向きは保存せず、描くときに算出する。
描くときは、相手の文書の末尾の関連文書の一覧に、その文書を参照している文書として並ぶ。
`change_together` だけは、両側に記載する。

## 参照の表

被参照を描く文書が、ほかの文書の本文を読み込まずに済むよう、利用側が全ての文書から参照の表を作って指定する（[参照の表を作る](./API.md#参照の表を作る)）。
参照の表は、文書ごとの被参照と、各文書の用語集の表から入れた用語を持つ。
参照の表を指定しないときは、被参照を索引の `related` だけから出し、ほかの文書の用語集の表の用語を照合しない。

## 描かれ方

描く文書の本文に出た用語の単語・別名と、文書の別名に、破線の下線を付け、意味と関連文書のツールチップを付ける。
索引の用語と用語集の表のやめた言い方が本文に出たときは、波線のマーカーを引き、代わりの用語の単語と意味のツールチップを付ける。
エイリアスの名前・別名にも同じ下線を付け、種類ごとの区分（用語・文書・コマンド・URL・スキル・ツール・パス）のツールチップを付ける。
エイリアスの `avoid` の種類と、`term` のエイリアスの `avoid` の言い方も、やめた言い方として扱う。
やめた言い方は参照先を持たないため、被参照の一覧にも `collectMatches` の `byDocument`・`targets` にも数えない。
文書の末尾には、その文書を参照している文書の一覧を、タイトル「関連文書」で配置する。
索引を指定しないときは、用語集の表から入れた用語だけにツールチップを付け、被参照の一覧を出さない。
索引も用語集の表も無い文書は、これまでどおりに描く。

索引が Schema に合わなくても、用語集の表の列名が表に無くても、本文の描画は止まらない。
合わない文書・用語は除いて使用し、用語集の表の誤りはその箇所の記載の警告で通知する。

## 画面を出さない参照の取り出し

下線とツールチップは画面に描くものだが、利用側の処理が同じ補足を画面なしで受け取りたいことがある（AI へ本文を返却するときなど）。
`collectMatches` は、索引と文書の本文を指定すると、描いた文書の下線・ツールチップと同じ照合で、本文に出た用語・文書の別名の一致を返却する（[本文の参照を取り出す](./API.md#本文の参照を取り出す)）。
返却するのは、参照先の種類・`id`・タイトル・短い説明と、一致した文字列・本文の中の位置。
一致した文字列は索引・用語集の表に記載した表記で返却し、本文の表記は本文の中の位置から参照する。
本文に出たやめた言い方は、`byDocument`・`targets` には入れず、代わりの用語（種類・`id`・タイトル・短い説明）と一致した文字列・本文の中の位置つきで `avoided` に返却する。
同じ実行環境で描いた文書の下線と同じ単語が一致し、ツールチップのセクションごとの最初の 1 回の制限は有効にならず、同じ参照先の出現を全て返却する。

## ずれの点検

索引と文書は別々に記載するため、文書を移した・削除したときにずれが出る。
`checkIndex` が、索引に無い文書・索引にあって消えた文書・`related` の切れた `id`・文字列の関連・片側だけの `change_together`・本文のリンクと重なる関連・用語の重複・本文に出た用語のやめた言い方・Schema に合わない索引を、ファイル・場所・種類・内容の一覧で返却する（[索引を点検する](./API.md#索引を点検する)）。
ずれの種類は [点検が返却するずれ](./索引.md#点検が返却するずれ)。

設定の `aliases` のずれ（元の YAML を読み込めない・列が無い・`id` の重なりなど）は、`checkIndex` ではなく `mdmark check` が、`buildAliases` と同じ規則で返却する（[点検する](./書き出す-点検する.md)）。

`change_together` の組のうち片方の文書だけが変わった修正漏れは、比べる基準から変わった文書のパスを指定したときだけ点検する。
`mdmark check` は `--base` に指定した git の ref と HEAD の merge-base から、変わったファイルを参照する。
