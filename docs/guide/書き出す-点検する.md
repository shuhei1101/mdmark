# 点検する

`mdmark check` で設定と索引を点検し、ずれを修正する手順

書き出す前と、設定・索引・文書を書き換えた後に実行する。

## 前提

- [雛形を配置する](./書き出す-雛形を配置する.md)（設定ファイル `mdmark.config.yaml` を今のフォルダか上のフォルダに配置している）
- Node 24 以降

## 手順

### 点検する

#### `check` を呼ぶ

```bash
npx github:shuhei1101/mdmark#v{バージョン} check [--config {設定ファイル}] [--base {git の ref} | --text {Markdown} | --file {ファイル} --key {YAML のキー}]
```

`--config` を省くと、端末の設定と、今のフォルダから上のフォルダの `mdmark.config.yaml` を重ねて読み込み（[設定を重ねて読み込む仕組み](./コアコンセプト-設定を重ねて読み込む仕組み.md)）、重ねた設定ファイルと端末の設定のそれぞれの構造を点検する。
`--base` は、修正漏れを検査するときだけ指定する（[修正漏れを検査する](#修正漏れを検査する)）。
`--text`・`--file` は、文字列や YAML のキーの中の記法だけを点検するときに指定する（[文字列と YAML のキーの記法を点検する](#文字列と-yaml-のキーの記法を点検する)）。
設定・索引・文書は書き換えない。

次を点検する。

- 設定が `schemas/mdmark.config.schema.json` に合うこと。`build.glossary`・`build.entry` が `build.include` に該当しないこと、`theme`・`extensions` のファイルと `assets.root` のフォルダが無いこと、`extensions` の拡張を読み込めないことも、合わないものとして出す
- 設定に `index` があるとき、索引が `schemas/mdmark.index.schema.json` に合うことと、索引と文書のずれ。索引のフォルダの下の拡張子 `.md` のファイルのうち `build.exclude` に該当しないものを文書として確認する
- 設定に `build` があるとき、`build.include` に該当し `build.exclude` に該当しない文書が 0 件でないこと
- 設定に `aliases` があるとき、行が取り込んだ Schema に合うことと、行の `paths` に該当した YAML からエイリアスを作れること。`enabled` が `false` の行は読み込まない
- 索引の文書と `build` の対象の文書の本文に、知らないマーカーが無いこと。記法のマーカー・`features`・`libraries` の対応表・`extensions` の拡張のマーカー・`check.ignore` の名前のどれにも該当しないマーカーを出す。コードブロックとインラインコードの中は見ない
- 索引の文書と `build` の対象の文書が相対パスで指す画像（動画の `poster` を含む）・動画・音声と、添付のカードにするファイルが、文書のフォルダか設定の `assets.root` のフォルダにあること。コードブロックとインラインコードの中・絶対 URL・`#` で始まるリンクは見ない
- 索引の文書と `build` の対象の文書の include のマーカーの取り込み先が、設定ファイルのフォルダ（無ければ文書のフォルダ）の中にあり、ファイル・見出し・行の範囲があること。取り込みが循環しないこと
- 索引の文書と `build` の対象の文書のうち、拡張子が `.md` で `.mark.md` でない文書（純粋な `.md`）が、mdmark のマーカーを含まないこと。含む文書は、拡張子を `.mark.md` に変えるよう提案する。設定の `check.suggestMarkExtension` を `false` にすると提案しない
- 索引の文書と `build` の対象の文書の `chart`・`param`・`er` のマーカーの中の部品の定義を読み込めること
- 索引の文書と `build` の対象の文書に、廃止した `flow`・`sequence` の範囲が無いこと（同じ名前の拡張を `extensions` に記載しているときを除く）

#### ずれの一覧を読み込む

ずれ 1 つが 1 行で、最後に件数の行が出る。

```text
docs/index.yaml:docs[1].path: missing_doc: `old.md` が見つかりません。文書を戻すか、索引の `docs[1]` を削除してください。
mdmark.config.yaml:build: schema: `build.out` がありません。書き出す HTML のパスを記載してください。
ずれ 2 件
```

行は `{ファイル}:{場所}: {種類}: {内容}` で、場所が空のときは `{ファイル}: {種類}: {内容}`。
ファイルは設定ファイルのあるフォルダからの相対パス。
種類と意味は [CLI](./CLI.md#設定と索引を点検する)。
内容に、何が合わないかと修正方法が記載してある。

#### ずれを修正してもう一度点検する

内容に従って設定・索引・文書を修正し、`check` をもう一度呼ぶ。
`avoided_term` は、内容に記載した行のやめた言い方を、代わりに使用する用語の単語に書き換える。
やめた言い方を使用し続けるときは、索引の用語の `avoid` か、用語集の表のやめた言い方の列から除外する。
`include_target_missing` は、マーカーのパス・見出しの ID・行の範囲を修正するか、取り込むファイルを設定ファイルのフォルダの中に配置する。
`include_circular` は、内容に記載した循環の順のマーカーのどれかを取り除く。
`untyped_related` は、文字列の関連を、`to`・`type`・`when` を持つオブジェクトに書き換える。
`one_sided_change_together` は、内容に記載した相手の文書にも、自分への `change_together` を記載する。
`related_link_overlap` は、本文でリンクしている相手を `related` から除外するか、本文のリンクを削除する。
`broken_ref` は、`related` の `to` を索引にある文書の `id` に修正する。
`unknown_mark` は、内容に記載した行のマーカーの名前を修正する。
`plain_md_with_marks` は、文書の拡張子を `.mark.md` に改名し、索引とリンクのパスを合わせる。既存の文書の拡張子をまだ移さないときは、設定の `check.suggestMarkExtension` を `false` にする（[拡張子の提案](./設定.md#拡張子の提案)）。
`unknown_mark_arg` は、誤記ならマーカーのキーの名前を修正する。新しいバージョンで追加されたキーなら、mdmark のバージョンを上げる。
`legacy_mark` は、`mdmark upgrade` で JSON に書き換えるか、内容に記載した記載方法で書き直す。
`mark_option_invalid` は、内容に記載した記載の警告のとおりに引数を修正する。`mark_option_unapplied` は、当たらない設定を削除するか、当たるように機能・キーを足す。
`missing_file` は、内容に記載した行のパスを修正するか、そのパスにファイルを配置する。
ファイルを 1 か所にまとめて配置しているときは、設定の `assets.root` がそのフォルダを指しているかを確認する（[アセットのルート](./設定.md#アセットのルート)）。
`diagram_invalid` は、内容に記載した記載の警告のとおりに部品の定義を修正する。`retired_diagram` は、`mdmark upgrade` で map の範囲へ書き換えるか（[バージョンを上げる](./導入-バージョンを上げる.md)）、[Mermaidと補足で図を描く](./図を描く-Mermaidと補足で図を描く.md) のとおりに map の範囲で記載し直す。
`aliases` のずれは、内容に記載したファイルと場所を、次のように修正する（キーの記載方法は [エイリアスの元の行](./設定.md#エイリアスの元の行)）。

<!-- table: {"kind": "data"} -->

| 種類 | 修正方法 |
| --- | --- |
| `schema`（`aliases[1].alias_type` のような場所） | 設定の `aliases` の行を、内容に従って Schema に合わせる。`alias_type` は `term`・`doc`・`command`・`url`・`skill`・`tool`・`path`・`env`・`avoid` のどれかにする |
| `alias_no_files` | `paths` を、YAML のあるパスか glob に修正する |
| `alias_unreadable` | YAML の字下げと記載方法を修正する |
| `duplicate_alias_row_id` | 後の行の `id` を変える |
| `alias_records_missing` | ファイルに `records` のキーの配列を記載するか、`records` を修正する |
| `alias_field_missing` | レコードに `metadata` に記載した列を記載するか、`metadata` の列の名前を修正する |
| `alias_required_empty` | レコードに、内容に記載した空のキーの値を記載する |
| `duplicate_alias_id` | 後のレコードの `id` を変える |

`extensions` の拡張を読み込めないと出たときは、拡張のモジュールが読み込みの時点で使用するブラウザの API（`HTMLElement`・`window` など）を、`load` の中へ移す。
他のツールへの指示（`<!-- prettier-ignore -->` など）のようにマーカーとして記載していないコメントは、設定の `check.ignore` に名前を追加する（[点検から除外する名前](./設定.md#点検から除外する名前)）。
`ずれ 0 件` になるまで繰り返す。

#### 修正漏れを検査する

`change_together` の組のうち片方の文書だけを修正したことを検査するときは、比べる基準の git の ref を `--base` に指定する。

```bash
npx github:shuhei1101/mdmark#v{バージョン} check --base origin/develop
```

基準と HEAD の merge-base から作業ツリーまでに変わったファイルを引き、片方の文書だけが変わった組を `missed_change_together` で出す。
内容に記載した変わった側の文書の内容を確認し、変わっていない側の文書も修正する。
修正しなくてよいときは、`change_together` の関連を見直す。
`--base` を省くと、修正漏れを検査しない。

CI で実行するときは、基準の ref と HEAD の merge-base を参照できるよう、checkout の `fetch-depth` を `0` にして履歴を全て取得する。

#### 文字列と YAML のキーの記法を点検する

文書のファイルではなく、Markdown の文字列や、YAML のファイルのキーの値に記載した記法を点検するときは、`--text` か `--file` と `--key` を指定する。

```bash
echo '<!-- tabz -->' | npx github:shuhei1101/mdmark#v{バージョン} check --text -
npx github:shuhei1101/mdmark#v{バージョン} check --file records.yaml --key items[0].body
```

`--text -` は標準入力から Markdown を読み込む。
`--key` は `.` でキーを、`[位置]` で配列の要素をたどる。
描いたときに出る記載の警告・描くときに無視するマーカーの知らない引数・知らないマーカー・図の配置のずれを、設定と索引の点検と同じ `{ファイル}:{場所}: {種類}: {内容}` の行で出す。
`--text` のファイルは `-`、場所は文字列の行。
`--file` の場所は YAML のファイルの行で、ブロックスカラー（`|`・`>`）の値は値の中の行をファイルの行に置き換える。
設定ファイルがあれば `features`・`libraries`・`extensions`・`check.ignore` を当て、無ければ既定の設定で点検する。
設定・索引・`build` の対象は点検しない。
`--text`・`--file` は `--base` と一緒に指定できず、`--file` と `--key` は一緒に指定する。

dev-docs や MindStella のように YAML のキーへ Markdown を書き込むツールは、書き込むたびにこの点検を呼ぶ。
Claude Code からは MCP の `check` に `text` か `file`・`key` を指定する（[MCP のツールを使用する](./ClaudeCodeで使用する-MCPのツールを使用する.md)）。

#### 点検できないとき

設定ファイルが無いときは、探した場所と `mdmark init` で配置できることを標準エラーに出す。
設定ファイルを YAML として読み込めないときは、ファイルと読み込めない行と修正方法を標準エラーに出す。
`--base` の ref と HEAD の merge-base を参照できないときは、指定した ref と参照できない理由と、ref を修正するか履歴を取得する修正方法を標準エラーに出す。
`--file` のファイルが無いか読み込めないとき、`--key` のキーが無いか値が文字列でないとき、一緒に指定できない引数を指定したときは、原因と修正方法を標準エラーに出す。
どれも終了コード 1 で終わる。

## 反映

即時。`check` を呼ぶたびに、その場の設定・索引・文書を点検する。

## 確認

#### ずれが 0 件になっている

標準出力が `ずれ 0 件` の 1 行になり、終了コードが 0 になる。
ずれがあるときの終了コードは 1。

## 元に戻す

`check` は何も書き換えないため、戻すものは無い。
