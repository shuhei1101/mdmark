# 設定

設定のキーと既定の一覧

`mdmark.config.yaml` に書き込むキーの一覧。
mdmark はブラウザで YAML を読み込まない。
利用側のサーバーが `mdmark.config.yaml` を読み込んだオブジェクトを、`mount` と `render` の `opts.config` に指定する（[文書を描く](./API.md#文書を描く)）。
どのキーも省ける。省いたキーには既定を適用する。
設定の構造の正は、リポジトリの `schemas/mdmark.config.schema.json`（JSON Schema）に配置する。
この一覧のキーは全て Schema が検め、この一覧にないキーを記載しても、mdmark は読み込まず、Schema も拒まない。
CLI・MCP のツール・VS Code 拡張機能は、端末の設定と上のフォルダの `mdmark.config.yaml` を重ねて読み込み、書き出しとプレビューに使用する（[設定を重ねて読み込む仕組み](./コアコンセプト-設定を重ねて読み込む仕組み.md)）。
`theme`・`extensions`・`build`・`check`・`aliases`・`assets` は CLI・MCP のツール・VS Code 拡張機能が読み込み、`mount` と `render` は読み込まない。
`version` は `mdmark upgrade` だけが読み込む。

## 機能の既定

機能ごとのオン・オフの既定を決める。
文書の `<!-- features: {"機能": false} -->` が、その文書だけ上書きする（優先順は [文書を描く仕組み](./コアコンセプト-文書を描く仕組み.md)）。

| 項目 | 内容 |
| --- | --- |
| 型 | キーが機能名、値が真偽値のオブジェクト |
| 既定 | `comments`・`html-scripts`・`frontmatter` を除く全ての機能が `true` |
| 許す値 | 値は `true` か `false`。知らない機能名と、真偽値でない値は無視する |

```yaml
features:
  print: false
```

## コメントの機能

読者が本文の選んだ箇所にコメントを付けられるようにする。
利用側が `mount` にコメントの読み込みと保存の関数（`opts.commentStore`）と `opts.docId` を指定したときだけ有効になる（[文書を描く](./API.md#文書を描く)）。
オフのときは、文字を選んでもコメントのボタンを出さず、読み込みと保存の関数の `load` も呼ばない。
オンで読み込みと保存の関数を指定しないときは、ボタンを出さず、`console.error` に読み込みと保存の関数が要ることを 1 回だけ出す。
記載方法は [ビューとコメントを使用する](./記載する-ビューとコメントを使用する.md)。

| 項目 | 内容 |
| --- | --- |
| 型 | 真偽値 |
| 既定 | `false` |
| 既定がオフの理由 | コメントは利用側の保存先が要り、使用しない文書で文字を選ぶたびにボタンを出さないため |

```yaml
features:
  comments: true
```

## フロントマターの表示の機能

オフのときもフロントマターは本文から除外し、本文・見出し・目次に出さない。
フロントマターの判定は [フロントマター](./記法.md#フロントマター)。

| 項目 | 内容 |
| --- | --- |
| 型 | 真偽値 |
| 既定 | `false` |
| 既定がオフの理由 | フロントマターは文書を扱う道具のためのメタデータで、読者に向けた本文ではないため |

```yaml
features:
  frontmatter: true
```

## 外部ライブラリの対応表

マーカーの名前から、外部ライブラリのモジュールの URL を参照する。
mdmark が持つ既定の対応表に重ね、同じ名前は URL を上書きし、対応表に無い名前は追加する。
このバージョンは既定の対応表を持たない。
追加した名前のマーカーは図のマーカーとして扱い、読み込めないときの通知ブロックのタイトルは `この図を表示できません` になる。

| 項目 | 内容 |
| --- | --- |
| 型 | キーがマーカーの名前、値が URL の文字列のオブジェクト |
| 既定 | `{}` |
| 許す値 | キーは英小文字で始まり、英小文字・数字・`-` だけを持つ。値は文字列の URL で、相対 URL はページの `document.baseURI` を基準に解決する。書式に合わないキーと、文字列でない値は無視する |

```yaml
libraries:
  my-chart: /assets/my-chart.js
```

モジュールは、`draw(slot, options)` を名前付きで export する。
`slot` はマーカーの場所の要素、`options` はマーカーに記載した JSON のオブジェクト（引数の無いマーカーは `{}`）で、`draw` は同期でも `Promise` を返却する非同期でもよい。
文書に `<!-- my-chart: {"type": "bar"} -->` と記載すると、`slot` と `{ type: "bar" }` を指定して `draw` を呼ぶ。
前の書き方（`<!-- my-chart: a b -->`）のマーカーは描かずに、記載の警告を出す。

## 色分けのライブラリの読み込み先

コードブロックの色分けに使用するライブラリ（highlight.js）の `es/` フォルダの URL を記載する。
本体を `{url}core.min.js`、言語を `{url}languages/{言語}.min.js` から読み込む。
`libraries` とは別のキーで、文書にマーカーを記載させない。
`mount` が読み込み、`render` は読み込まない。
CLI は `mdmark.config.yaml` のあるフォルダを基準に相対パスを解決し、書き出す HTML に使用する言語の分だけを埋める（[文書を書き出す](./書き出す-文書を書き出す.md)）。

| 項目 | 内容 |
| --- | --- |
| 型 | 文字列 |
| 既定 | `https://cdn.jsdelivr.net/npm/@highlightjs/cdn-assets@11.12.0/es/` |
| 許す値 | 末尾が `/` の URL かパス。`mount` は相対パスをページの `document.baseURI` を基準に解決し、文字列でない値を無視して既定を適用する。CLI は文字列でない値を設定ファイルの誤りにする |

```yaml
syntax:
  url: /vendor/highlightjs/es/
```

差し替える先には、`@highlightjs/cdn-assets` の `es/` フォルダをそのまま配置する。
色分けのオン・オフは `features.syntax`（[記法の機能](#記法の機能)）で決める。

## 範囲のスクリプトの変換のライブラリの読み込み先

埋め込んだ HTML の範囲の `ts`・`js` を CommonJS に変える変換のライブラリ（@babel/standalone）の ES モジュールの URL を記載する。
`mount` は、`features.html-scripts` がオンで範囲に `ts`・`js` がある文書でだけ読み込む。
`libraries` とは別のキーで、文書にマーカーを記載させない。
`render` は読み込まない。CLI の `export`・`build` は esbuild で変換するため、この URL を読み込まない。

| 項目 | 内容 |
| --- | --- |
| 型 | 文字列 |
| 既定 | `https://cdn.jsdelivr.net/npm/@babel/standalone@8.1.1/+esm` |
| 許す値 | URL かパス。`mount` は相対パスをページの `document.baseURI` を基準に解決し、文字列でない値を無視して既定を適用する。CLI は文字列でない値を設定ファイルの誤りにする |

```yaml
html-scripts:
  url: /vendor/babel-standalone/babel.mjs
```

読み込めないときは、範囲の前に通知ブロックを出し、範囲の `html`・`css` は描いたまま残す。
範囲のスクリプトのオン・オフは `features.html-scripts`（[記法の機能](#記法の機能)）で決める。

## mermaid の設定

言語 `mermaid` のコードブロックを図にするライブラリ（mermaid）の読み込み先と、図のテーマを記載する。
`mount` は、`features.mermaid` がオンで mermaid のコードブロックがある文書でだけ `url` を読み込む。
`render` は読み込まない。CLI の `export`・`build` は、mermaid のコードブロックがある文書のときだけ `url` のモジュールを 1 枚の HTML に埋め、開いたときに `url` を読み込まない。

<!-- table: {"kind": "data"} -->

| キー | 型 | 既定 | 説明 |
| --- | --- | --- | --- |
| mermaid.url | 文字列 | `https://cdn.jsdelivr.net/npm/mermaid@12.3.0/dist/mermaid.esm.min.mjs` | mermaid の ES モジュールの URL かパス。`mount` は相対パスをページの `document.baseURI` を基準に解決する |
| mermaid.theme | 文字列 | `mdmark` | `mdmark`（描いた文書の配色から作る mdmark の外観のテーマ）か、mermaid のテーマの名前（`default`・`neutral`・`dark`・`forest`・`base`）。知らない名前は `mdmark` にする |
| mermaid.themeVariables | オブジェクト | なし | mermaid のテーマの変数（`primaryColor` など）を上書きする値。`theme` で選んだテーマの変数に重ねる。値が文字列のキーだけを受ける。`useGradient`・`dropShadow` は上書きできない |

<!-- /table -->

```yaml
mermaid:
  theme: mdmark
  themeVariables:
    primaryColor: "#e0f2f1"
```

`mount` は文字列でない `url`・`theme` と、オブジェクトでない `themeVariables` を無視して既定を適用する。CLI は設定ファイルの誤りにする。
テーマ `mdmark` は、配色の明暗が変わると図を再描画し、印刷では明るい配色の図を出す。
読み込めないときは、コードブロックの前に通知ブロックを出してコードブロックのまま残す。
mermaid のコードブロックのオン・オフは `features.mermaid`（[記法の機能](#記法の機能)）で決める。

## map の設定

[map](./記法.md#map) の図の見た目と、状態の保ち方を記載する。
`mount` が読み込み、`render` は読み込まない。CLI の `export`・`build` は、書き出す HTML にコピーする。

<!-- table: {"kind": "data", "tree": {"key": {"column": "キー"}}} -->

| キー | 型 | 既定 | 説明 |
| --- | --- | --- | --- |
| map.node_fit | `height` か `width` の文字列 | `height` | 名前の長いノードの広げ方。`height` は幅を上限 220px のまま折り返して高さを増やし、`width` は幅を上限 360px まで広げてから折り返す |
| map.url_state | 真偽値 | `true` | 中へ入ったグループと、シーケンス図の中だけを描くブロックを、URL のクエリ文字列 `map-{図の番号}` にも保つか。`false` ではクエリ文字列を読みも書きもせず、sessionStorage だけに保つ |
| map.kinds | オブジェクト | なし | Mermaid のクラス名（`:::名前`）ごとのノードの種類。値は `label`（種類の行の名前）・`icon`（Lucide のアイコンの名前）・`shape`（`rounded`・`rect`・`pill`・`double`。既定 `rounded`）・`color`（[色の名前](./記法.md#文字の色)） |
| map.lines | オブジェクト | なし | Mermaid の矢印（`-->`・`-.->`・`==>`）ごとと、補足の `layout` の `line` で指す名前ごとの線の種類。値は `dash`（`solid`・`dashed`・`dotted`・`dash-dot`・`long-dash`。既定 `solid`）・`width`（`thin`・`normal`・`thick`。既定 `normal`）・`head`（`filled`・`open`・`none`。既定 `filled`）・`color`（色の名前） |

<!-- /table -->

```yaml
map:
  node_fit: width
  kinds:
    store:
      label: 保存先
      icon: database
      shape: rect
      color: purple
  lines:
    "-.->":
      dash: dashed
      head: open
```

| 項目 | 内容 |
| --- | --- |
| 許す値 | `mount` と CLI の書き出しは、記載の値・色の名前に無い値を無視して既定にする。CLI は、オブジェクトでない `map` を設定ファイルの誤りにし、記載の値・色の名前に無い値を `mdmark check` の `schema` のずれにする |
| Lucide に無いアイコンの名前 | `mount` は無視し、`mdmark check` が `map_unknown_icon` で通知する |
| 設定に無いクラスと線の名前 | 図の前に記載の警告を出し、種類の行の無いノード・既定の線で描く。`mdmark check` が `map_unknown_class`・`map_unknown_line` で通知する |

mdmark はノードと線の種類を持たない。種類の名前・アイコン・形・色は利用側が決める。

## ツールチップを出す場所

本文の用語・文書の別名・脚注のツールチップを、持ち主（下線の単語・脚注の番号）の上と下のどちらに先に出すかを決める。図の部品の中の用語もこの値に従う。
`top` は上に出し、上に収まらないときだけ下に出す。
`bottom` は下に出し、下に収まらず上に収まるときだけ上に出す。
`mount` が読み込み、`render` は読み込まない。

| 項目 | 内容 |
| --- | --- |
| 型 | `top` か `bottom` の文字列 |
| 既定 | `top` |
| 許す値 | `top`・`bottom`。`mount` は他の値を無視して `top` にし、CLI は他の値を設定ファイルの誤りにする |

```yaml
tooltips:
  placement: bottom
```

`top` は上に出し、上に収まらないときだけ下に出す。

side-toc:

## 表のピン止めの動き

表のピン止め（[表](./記法.md#表)）の動きを決める。
`each` は押した列だけを留め、留めた列はその列より左を表示している間は表の右端に、過ぎた後は左端に留まる。
`through` は押した列までを表の左端に留める。
どちらも、留める列を左から順に足して表の幅に収まらない列から右は留めず、その列のボタンを押したまま、破線のピンで留まっていないことを示す。
マーカーの `pinned` もこの動きに従う。
`mount` が読み込み、`render` は読み込まない。

| 項目 | 内容 |
| --- | --- |
| 型 | `each` か `through` の文字列 |
| 既定 | `each` |
| 許す値 | `each`・`through`。`mount` は他の値を無視して `each` にし、CLI は他の値を設定ファイルの誤りにする |

```yaml
table:
  pin: through
```

## 長文の列の最小の幅

表（[表](./記法.md#表)）の長文の列（改行で分けた 1 行が 20 文字以上のセルを持つ列）の最小の幅を、em の数で決める。
列の最も長い行の方が短ければ、その幅を最小の幅にする。
列ごとの `columns.{列名}.width.min` を記載した列は、そちらを優先する。
`mount` が読み込み、`render` は読み込まない。

| 項目 | 内容 |
| --- | --- |
| 型 | 数 |
| 既定 | `45` |
| 許す値 | 0 より大きい数。`mount` は他の値を無視して `45` にし、CLI は他の値を設定ファイルの誤りにする |

```yaml
table:
  long_column_min: 30
```

## 今の値をコピーするボタンの文言

操作できる部品（[操作できる部品を作る](./図を描く-操作できる部品を作る.md)）の今の値をコピーするボタンの、アイコンの後ろに描く文言を決める。
ボタンのスクリーンリーダー向けの名前もこの文言になる。
`labels` は部品の文言をまとめるマップで、知らないキーは読み込まない。
`mount` と `render` が読み込み、`update` で再描画したときも `mount` に指定した文言のまま描く。
CLI の `mdmark export` と `mdmark build` は、この値を書き出す HTML の `mount` に指定する。

| 項目 | 内容 |
| --- | --- |
| 型 | 文字列 |
| 既定 | `今の値をコピーする` |
| 許す値 | 空でない文字列。`mount` は空文字と文字列でない値を無視して既定の文言で描き、CLI は `labels` がマップでないときと、空でない文字列でない値を設定ファイルの誤りにする |

```yaml
labels:
  paramCopy: コピー
```

## 索引の場所

索引の YAML のパスを記載する。
パスは、`mdmark.config.yaml` のあるフォルダからの相対パスで記載する。
索引の文書の `path` は、この索引のファイルのあるフォルダからの相対パスで記載する（[索引](./索引.md#文書)）。
mdmark はブラウザでファイルを読み込まず、`mount` と `render` もこのキーを読み込まない。
利用側のサーバーがこのパスの YAML を読み込み、読み込んだオブジェクトと描く文書の `id` を `opts.index`・`opts.docId` に指定する（[文書を描く](./API.md#文書を描く)）。
索引の構造は [索引](./索引.md)。
CLI はこのパスの索引と、索引の文書を読み込み、参照の表を作って書き出しに埋める。

| 項目 | 内容 |
| --- | --- |
| 型 | 文字列 |
| 既定 | なし。省くと索引を指定しない文書と同じに描く |

```yaml
index: docs/index.yaml
```

## エイリアスの元の行

プロジェクトの任意の YAML（用語・コマンド・URL などの一覧）を、Markdown の用語集の表に発生させずに、エイリアスとして登録する。
行の構造は alias-inject の `schemas/aliases.schema.yaml` が決め、mdmark は取り込んだタグ `v0.3.0` のスキーマで検める。
パスは、`mdmark.config.yaml` のあるフォルダからの相対パスで記載する。
CLI の `export`・`build` が行の `paths` の YAML を読み込み、[`buildAliases`](./API.md#エイリアスを作る) で作ったエイリアスを書き出す HTML に埋める。
VS Code 拡張機能のプレビューと書き出す HTML も同じく読み込み、作ったエイリアスで下線とツールチップを出す。
`mount` と `render` はこのキーを読み込まない。利用側が `buildAliases` で作った配列を `opts.aliases` に指定する（[文書を描く](./API.md#文書を描く)）。
記載方法は [索引と用語集を記載する](./記載する-索引と用語集を記載する.md#設定の-aliases-で-yaml-からエイリアスを登録する)。

| 項目 | 内容 |
| --- | --- |
| 型 | オブジェクトの配列 |
| 既定 | なし。省くとエイリアスを使用しない |
| 許す値 | 行のキーは下表。読み込めない行・使用できない行は書き出しを止めず、警告に出す。`mdmark check` が、スキーマのずれとエイリアスのずれを返却する |

```yaml
aliases:
  - id: terms
    paths: ["terms/*.yaml"]
    alias_type: term
    records: terms
    metadata:
      name: term
      description: meta.meaning
```

<!-- table: {"kind": "data", "tree": {"key": {"column": "キー"}, "type": {"column": "型"}, "required": {"column": "必須"}, "default": {"column": "既定"}}} -->

| キー | 型 | 必須 | 既定 | 説明 |
| --- | --- | --- | --- | --- |
| aliases[].id | 文字列 | ✓ |  | 行の `id`。`aliases` の中で一意にする。重なった後の行は読み込まず、`duplicate_alias_row_id` のずれにする |
| aliases[].enabled | 真偽値 |  | `true` | `false` の行は読み込まず、ずれにもしない |
| aliases[].paths | 文字列の配列 | ✓ |  | 読み込む YAML のパスか glob。ファイルと glob を混ぜてよい。1 つ以上書く。並びは記載した順で、glob の中はパスの順 |
| aliases[].alias_type | 文字列 | ✓ |  | 行の全てのレコードのエイリアスの種類。下の 9 つのどれか |
| aliases[].records | 文字列 |  |  | 記載すると、ファイルのこのキーの配列の要素ごとに 1 件のエイリアスを作る。記載しないと、各ファイルを 1 件にする |
| aliases[].body_file | 文字列 |  |  | レコードの本文のファイルのパスを持つ列の名前。`name` が空のレコードの名前に、その列の値のファイル名から拡張子を除いたものを使用する |
| aliases[].metadata | オブジェクト |  |  | エイリアスのキーごとに、値を取るレコードの列の名前 |

<!-- /table -->

`metadata` のキーは、`id`・`name`・`aliases`・`description`・`related`・`command`・`cwd`・`url`・`avoid`・`skill`・`tool`・`path`・`port`・`replacement`。
値は列の名前の文字列で記載し、入れ子の列は `meta.summary` のように `.` でつなぐ。
列がレコードに無いと `alias_field_missing` のずれにする。
記載しないキーは、同じ名前の列から取る（列が無ければ持たない）。
行と `metadata` のほかのキーは、拒まず使用しない。

文字列のキーは、文字列・数・真偽値を文字列にして前後の空白を除き、それ以外の値は空とみなす。
`aliases`・`avoid`・`related` は、文字列なら 1 件の並びにし、並びなら文字列の要素だけを残す。
`name` が空のときは、`body_file` の列のファイル名から拡張子を除いたもの、それも空なら `records` を記載した行ではレコードの `id`、記載しない行ではファイル名から拡張子を除いたものにする。

`alias_type` は次の 9 つのどれかで、種類ごとの必須のキーが空のレコードは `alias_required_empty` のずれにして使用しない。
照合する単語は `name` と `aliases`。

<!-- table: {"kind": "data"} -->

| `alias_type` | 区分 | 必須のキー |
| --- | --- | --- |
| `term` | 用語 | `id`・`name`・`description` |
| `doc` | 文書 | `id`・`name`・`description` |
| `command` | コマンド | `id`・`name`・`command` |
| `url` | URL | `id`・`name`・`url` |
| `skill` | スキル | `id`・`name`・`skill` |
| `tool` | ツール | `id`・`name`・`tool` |
| `path` | パス | `id`・`name`・`path` |
| `env` | ツールチップを出さない | `id`・`name` と、`url`・`port` のどちらか |
| `avoid` | 代わりの用語 | `id`・`name`・`replacement` |

<!-- /table -->

`env` は値にシークレットキーを含みうるため、`buildAliases` が配列に入れず、`mount` などに直接渡されても照合しない。
書き出した HTML にも埋めない。
`alias_type` が 9 つの種類に無い行は、`mdmark check` がスキーマのずれにし、`buildAliases` に直接渡されたときは `alias_unknown_type` のずれにする。
v0.2.0 の記載方法（`metadata.alias_type` と `{type: ref, field}`・`{type: custom, value}`）の行は、`mdmark upgrade` が今の記載方法へ書き換える（[バージョンを上げる](./導入-バージョンを上げる.md)）。
エイリアスの `id` は、指定したエイリアスの中で一意にする。重なった後のレコードは使用せず、`duplicate_alias_id` のずれにする。

## 選ぶテーマ

描いた文書の配色を、mdmark に入れたテーマから選ぶ。
明暗は今の決め方（OS の設定・class）のまま、選んだテーマの中で明るい配色とダークの配色を選ぶ。
印刷では、選んだテーマの明るい配色になる。
`mount` が読み込み、`render` は読み込まない。
CLI の `mdmark export` と `mdmark build` は、この値を書き出す HTML の `mount` に指定する。
[利用側の CSS](#利用側の-css) の `theme` とは別のキーで、利用側が層の外に記載した CSS は選んだテーマに勝つ。
テーマごとの変数の値は [選べるテーマ](./API.md#選べるテーマ)。

| 項目 | 内容 |
| --- | --- |
| 型 | 文字列 |
| 既定 | `dev-swiss` |
| 許す値 | `dev-swiss`・`theme-paper`・`theme-slate`・`theme-contrast`。`mount` は知らない名前と文字列でない値を無視して `dev-swiss` にする。CLI は知らない名前を、`mdmark check` のずれ（`unknown_color_theme`）と書き出しの警告にする |

```yaml
colorTheme: theme-slate
```

VS Code のプレビューと書き出しは、VS Code の設定 `mdmark.colorTheme` が空のときだけこのキーを使用する（[設定ファイルのキー](./VSCode拡張機能.md#設定ファイルのキー)）。

## 配色の明暗

描いた文書の配色を、明るい配色・ダーク・OS に合わせるのどれにするかを決める。
`light`・`dark` は、描く先の祖先の class（`mdmark-theme-light`・`mdmark-theme-dark`）と OS の設定より優先する。
`auto` は今の決め方（祖先の class・OS の設定）のまま。
文書の先頭の [ページの設定](./記法.md#ページの設定) の `scheme` が、その文書だけこの値より優先する。
印刷では明るい配色になる。
`mount` が読み込み、`render` は読み込まない。
CLI の `mdmark export` と `mdmark build` は、この値を書き出す HTML の `mount` に指定する。

| 項目 | 内容 |
| --- | --- |
| 型 | 文字列 |
| 既定 | `auto` |
| 許す値 | `light`・`dark`・`auto`。`mount` は知らない値と文字列でない値を `auto` にする。CLI は知らない値を、`mdmark check` のずれ（`unknown_color_scheme`）にする |

```yaml
colorScheme: dark
```

VS Code のプレビューは、VS Code の設定 `mdmark.preview.theme` が `auto` のときだけこのキーを使用する。VS Code の書き出しは、`mdmark.preview.theme` によらずこのキーを使用する（[設定ファイルのキー](./VSCode拡張機能.md#設定ファイルのキー)）。

## 利用側の CSS

CLI が書き出す HTML に、配布物の CSS の後で埋める利用側の CSS のパスを記載する。
パスは、`mdmark.config.yaml` のあるフォルダからの相対パスで記載する。
手順は [文書を書き出す](./書き出す-文書を書き出す.md)。

| 項目 | 内容 |
| --- | --- |
| 型 | 文字列 |
| 既定 | なし。利用側の CSS を埋めない |
| 許す値 | ファイルのパス。読み込めないときは書き出しを止めず、警告に出す |

```yaml
theme: theme.css
```

## 拡張のモジュール

CLI が書き出す HTML にまとめて埋め、描く前に `registerExtension` で登録する拡張のモジュールのパスを並べる。
各モジュールは、`registerExtension` に指定する拡張を既定の export にする（拡張の構造は [拡張を登録する](./API.md#拡張を登録する)）。
`mdmark check` はモジュールを Node で読み込んで `directive` を取るため、読み込みの時点でブラウザの API（`HTMLElement`・`window` など）を使用せず、使用するのは `load` の中だけにする。
パスは、`mdmark.config.yaml` のあるフォルダからの相対パスで記載する。

| 項目 | 内容 |
| --- | --- |
| 型 | 文字列の配列 |
| 既定 | `[]`。拡張を埋めず、拡張のマーカーは知らないマーカーとして取り除かれる |
| 許す値 | TypeScript か JavaScript のファイルのパス。読み込めない・まとめられないものは書き出しを止めず、警告に出す |

```yaml
extensions:
  - extensions/example.ts
```

## まとめる設定

`mdmark build` が 1 枚の HTML にまとめる文書と、書き出す先を決める。
パスと glob は、`mdmark.config.yaml` のあるフォルダからの相対パスで記載する。
手順は [文書を1枚にまとめる](./書き出す-文書を1枚にまとめる.md)。

| 項目 | 内容 |
| --- | --- |
| 型 | オブジェクト |
| 既定 | なし。`mdmark build` は、`build` が無いことを出して終了コード 1 で終わる |

```yaml
build:
  include: ["**/*.md"]
  exclude: ["下書き/**"]
  glossary: ["用語集.md"]
  entry: README.md
  out: dist/docs.html
```

<!-- table: {"kind": "data"} -->

| キー | 型 | 必須 | 既定 | 説明 |
| --- | --- | --- | --- | --- |
| `build.include` | 文字列の配列 | 必須 | なし | まとめる Markdown の glob。`**`・`*`・`?` を使用でき、該当するのは拡張子 `.md` のファイルだけ。1 つ以上書く。文書は glob の並びで並べ、同じ glob の中はパスの順に並べ、重なりは最初の 1 つだけを残す |
| `build.exclude` | 文字列の配列 | 任意 | `[]` | `include` に該当した文書から除外する glob。記載方法は `include` と同じ |
| `build.glossary` | 文字列の配列 | 任意 | `[]` | 用語集の表（`glossary` のマーカー）を持つ文書のパス。表の用語を、まとめた全ての文書で有効にしる。索引が無いときも有効になる。まとめる文書に該当しないパスは、`mdmark check` で `schema` のずれにし、`mdmark build` では飛ばして警告に出す |
| `build.entry` | 文字列 | 任意 | `include` で最初に該当した文書 | 開いたとき、URL の `#` が文書を指していないときに出す文書のパス。まとめる文書に該当しないときは、`mdmark check` で `schema` のずれにし、`mdmark build` では既定を適用して警告に出す |
| `build.out` | 文字列 | 必須 | なし | まとめた HTML を書き込むパス。拡張子 `.html` で記載する。既にあれば上書きし、親のフォルダが無ければ作る |

<!-- /table -->

`build.include` と `build.out` が無いと、`mdmark build` は終了コード 1 で終わり、`mdmark check` は `schema` のずれにする。

## アセットのルート

文書のフォルダからの相対パスにファイルが無いとき、同じ相対パスで探すフォルダを書き込む。
画像・動画を文書ごとのフォルダに配置せず、1 か所にまとめて配置するときに使用する。
パスは、`mdmark.config.yaml` のあるフォルダからの相対パスで記載する。
`mdmark export`・`mdmark build`・`mdmark check` と VS Code のプレビューが読み込む。

| 項目 | 内容 |
| --- | --- |
| 型 | 文字列 |
| 既定 | なし。文書のフォルダからの相対パスだけで探す |
| 許す値 | フォルダのパス。無いフォルダは `mdmark check` が `schema` のずれにし、書き出しは警告に出して文書のフォルダだけで探す |

```yaml
assets:
  root: assets
```

## 点検から除外する名前

`mdmark check` が文書の本文の知らないマーカーとして通知しない、マーカーと同じ記載方法の HTML コメントの名前を並べる。
`<!-- prettier-ignore -->`・`<!-- markdownlint-disable -->` のような他のツールへの指示を記載した文書で使用する。

| 項目 | 内容 |
| --- | --- |
| 型 | 文字列の配列 |
| 既定 | `[]`。マーカーに該当しない名前を全て知らないマーカーとして通知する |
| 許す値 | 英小文字で始まり、英小文字・数字・`-` が続く名前。合わないと `mdmark check` は `schema` のずれにする |

```yaml
check:
  ignore:
    - prettier-ignore
    - markdownlint-disable
```

## 手元のバージョン

この設定・索引・文書が合わせてある mdmark のバージョンを記載する。
`mdmark init` が呼んだ CLI のバージョンを記載し、`mdmark upgrade` が移行の手順を適用して点検が通った後に、呼んだ CLI のバージョンへ書き換える。
手順は [バージョンを上げる](./導入-バージョンを上げる.md)。
`mount`・`render`・`export`・`build`・`check` は、値で振る舞いを変えない。
端末の設定も同じキーを持ち、`/mdmark:global-setup` が作るときに記載し、`mdmark upgrade --settings` が書き換える。

| 項目 | 内容 |
| --- | --- |
| 型 | 文字列 |
| 既定 | なし。`mdmark upgrade` が手元のバージョンを聞く（v0.3.0 までの `init` が配置した設定） |
| 許す値 | `v{MAJOR}.{MINOR}.{PATCH}` の構造。合わないと `mdmark check` は `schema` のずれにする |

```yaml
version: v0.4.0
```


## 重ねて読み込むか

端末の設定（`settings.yaml`）だけに記載する。
`true` のとき、文書のフォルダから上のフォルダの `mdmark.config.yaml` を全て重ねる。
`false` のときは、上へ探して最初に見つかった 1 つだけを端末の設定に重ねる（[設定を重ねて読み込む仕組み](./コアコンセプト-設定を重ねて読み込む仕組み.md)）。

| 項目 | 内容 |
| --- | --- |
| 型 | 真偽値 |
| 既定 | `false` |
| 許す値 | `true`・`false`。`mdmark.config.yaml` に書き込んでも読み込まない |

```yaml
config:
  cascade: true
```

## 書き出しに端末の設定を重ねるか

端末の設定（`settings.yaml`）だけに記載する。
`false` のとき、`mdmark export`・`mdmark build`（MCP の `export_html`・`build_site` と VS Code 拡張機能の書き出しも同じ）で端末の設定を重ねない。
プレビューと `mdmark check` の構造の点検は、この値によらず端末の設定を読み込む。

| 項目 | 内容 |
| --- | --- |
| 型 | 真偽値 |
| 既定 | `true` |
| 許す値 | `true`・`false`。`mdmark.config.yaml` に書き込んでも読み込まない |

## 常駐サーバーの起動の方法

端末の設定（`settings.yaml`）だけに記載する。
`/mdmark:global-setup` が `mdmark serve` を起動する方法で、`auto` は systemd --user が使える端末では unit、使えない端末では tmux のセッションで起動する。
`systemd`・`tmux` にすると、その方法に固定し、もう一方の方法で動いている常駐サーバーを止めてから起動する。
手順は [セットアップする](./ClaudeCodeで使用する-セットアップする.md)。

| 項目 | 内容 |
| --- | --- |
| 型 | 文字列 |
| 既定 | `auto` |
| 許す値 | `auto`・`systemd`・`tmux`。`mdmark.config.yaml` に書き込んでも読み込まない |
| 反映 | `/mdmark:global-setup` をもう一度呼ぶ |

```yaml
serve:
  launcher: auto
```

## 常駐サーバーの unit の名前

端末の設定（`settings.yaml`）だけに記載する。
`/mdmark:global-setup` が `~/.config/systemd/user/{名前}.service` に作って起動する systemd --user の unit の名前で、MCP の `instructions` もこの名前を伝える。

| 項目 | 内容 |
| --- | --- |
| 型 | 文字列 |
| 既定 | `mdmark-mcp` |
| 許す値 | 英数字・`_`・`-`。`mdmark.config.yaml` に書き込んでも読み込まない |
| 反映 | 常駐サーバーをもう一度起動する |

```yaml
serve:
  systemdUnit: mdmark-mcp
```

## 常駐サーバーの tmux のセッション名

端末の設定（`settings.yaml`）だけに記載する。
`/mdmark:global-setup` が `mdmark serve` を起動する tmux のセッション名で、MCP の `instructions` もこの名前を伝える。
手順は [セットアップする](./ClaudeCodeで使用する-セットアップする.md)。

| 項目 | 内容 |
| --- | --- |
| 型 | 文字列 |
| 既定 | `mdmark-mcp` |
| 許す値 | 英数字・`_`・`-`。`mdmark.config.yaml` に書き込んでも読み込まない |
| 反映 | 常駐サーバーをもう一度起動する |

```yaml
serve:
  tmuxSession: mdmark-mcp
```

## 端末の設定の場所

端末の設定のファイルのパスを、環境変数 `MDMARK_CONFIG` で決める。
無いときは `${XDG_CONFIG_HOME:-~/.config}/mdmark/settings.yaml` を読み込み、そのファイルも無ければ空の設定として扱う。
端末の設定には `mdmark.config.yaml` と同じキーと、`config` のキーを記載できる。
## MCP サーバーのポート

`mdmark serve` が 127.0.0.1 で待ち受けるポートを、環境変数 `MDMARK_PORT` で決める。
設定ファイルには記載しない。
プラグインの `.mcp.json` の接続先 `http://127.0.0.1:${MDMARK_PORT:-8782}/mcp` も同じ環境変数で決まるため、変えるときは `~/.claude/settings.json` の `env` と `mdmark serve` を起動する環境の両方に同じ値を設定する。
手順は [MCPサーバーを起動する](./ClaudeCodeで使用する-MCPサーバーを起動する.md)。

| 項目 | 内容 |
| --- | --- |
| 型 | 整数（環境変数の値は文字列） |
| 既定 | `8782` |
| 許す値 | 1〜65535 の整数。範囲外・整数でない値だと、`mdmark serve` は待ち受けずに終了コード 1 で終わる |
| 反映 | `mdmark serve` をもう一度起動し、Claude Code のセッションをもう一度開く |

```json
{
  "env": {
    "MDMARK_PORT": "18782"
  }
}
```

## 状態の配置場所

`/mdmark:global-setup` が tmux のセッションで動かす常駐サーバーのログ（`serve.log`）を記載するフォルダを、環境変数 `MDMARK_STATE_DIR` で決める。unit で動かすときのログは journal に出す。
無いときは `${XDG_STATE_HOME:-~/.local/state}/mdmark`。

| 項目 | 内容 |
| --- | --- |
| 型 | パス |
| 既定 | `${XDG_STATE_HOME:-~/.local/state}/mdmark` |
| 反映 | 常駐サーバーをもう一度起動する |
