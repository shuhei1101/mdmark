# フローチャートの決まり

処理の順番を描くフローチャートの外観の決まり（時系列・ループの帯・分岐）

処理の順番や時刻の流れを描く、map の構成図とシーケンス図が守る決まり。
ノード・線・タイトルと凡例・交差・ツールチップ・操作は [構成図の決まり](./構成図の決まり.md) と同じ。

## 時系列

- 時系列は左から右。シーケンス図は、参加者を記載の順に左から右へ、メッセージを時刻の順に上から下へ並べる
- 拡大して下へ動かしても、参加者の行は表示する枠の上端に留める
- 呼ぶメッセージは `->>`（実線と塗った矢じり）、応答のメッセージは `-->>`（破線と開いた矢じり）で分ける

## ループの戻り

- シーケンス図の繰り返しは、繰り返すメッセージを `loop` 〜 `end` で囲み、ブロックのラベルに戻り先と繰り返す条件を記載する（例 `1 へ戻る（次の問い合わせ）`）
- 構成図の戻りの線は、ほかの線を横切る箇所を増やさない。横切るときは横の線が縦の線を飛び越える

## 分岐

- 分岐は、1 つのノードから複数の線を出し、線のラベルに分かれる条件を記載する
- 分かれた線は、どれも同じ線の種類（`-->`）にし、線のラベルの条件で見分ける。色や模様で分けない
- 分かれた先から戻るときは、ループの帯を経由する

## 判定フローチャート

- 質問の YES / NO で結果を決める図は、map の `flowchart TB` に開始・質問・アクション・結果のノードを記載し、システムのグループを持たない
- 開始と結果は `([…])`、質問は `{…}`、アクションは `[…]` の形にし、設定の `map.kinds` の種類のクラス（`start`・`question`・`action`・`result`）の色・アイコン・名前でも見分ける
- 開始から上から下へ質問を並べ、質問から出る線のラベルを `YES`・`NO` にする
- アクションは不合格のときの対応、結果は判定を通った先の結論に使用する
