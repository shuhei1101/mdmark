# Claude Code に使用方法を提供する仕組み

ガイドを dev-docs で必要な分だけ参照させ、CLI と同じ処理をツールで呼ぶ流れ

Claude Code のプラグインが、mdmark の使用方法と操作を Claude Code に提供する考え方。
入れ方と使用方法は [プラグインを入れる](./ClaudeCodeで使用する-プラグインを入れる.md) と [MCP のツールを使用する](./ClaudeCodeで使用する-MCPのツールを使用する.md)。

## ガイドを dev-docs で参照する

ガイドは、mdmark のリポジトリの `docs/` の使用方法・リファレンスのページで、dev-docs の配信元 `mdmark` の公開ドキュメントの行（`docs`）でタグ `topic:ガイド` を付けて配る。
Claude Code は、dev-docs の `search_docs` で `docs` の行の文書をタグ `topic:ガイド` で絞って一覧を検索し、作業に要るページだけを本文まで参照する。
セッションの開始では何も入れないため、ガイドを参照しない作業では文脈が増えない。
ページの選び方は、配信元の説明書（`dev-docs.yaml` の `instructions`）にある。

参照するのは、dev-docs の配信元に登録した mdmark のクローンのページで、プラグインはガイドを持たない。
dev-docs が無い、または配信元 `mdmark` が登録されていないときは、ガイドは参照できない。

## 動線を instructions に配置する

MCP サーバーは、接続したときの `instructions` に、記載する前にガイドを参照し、記載した後に `check` で点検する順序を記載する。
`instructions` は事実の文で記載し、Claude Code の文字数の上限に収める。
mdmark の記法で記載する文書の拡張子は `.mark.md` で、`instructions` は利用者の指示が無い限り純粋な `.md` には記法を使用しないことも伝える。

## 記載するときに 1 回だけ案内する

プラグインのフックは、`.mark.md` のファイルへの Write・Edit（PreToolUse）と、語 mdmark を含む利用者の発言（UserPromptSubmit）で、ガイドを参照してから記載し、記載した後に `check` で点検するよう Claude Code に案内する。
案内したセッションは `session_id` で記録し、同じセッションでは 2 回目から案内しない。
会話を圧縮する前（PreCompact）に記録を削除し、圧縮の後の最初の記載でもう一度案内する。
案内はツールの呼び出しと発言を止めない。

## CLI と同じ処理をツールで呼ぶ

`export_html`・`build_site`・`check` は、CLI の `mdmark export`・`build`・`check` と同じ処理を呼ぶ。
同じ文書・設定・索引では、CLI と同じ結果になる。

作業のフォルダを使用するツールは、作業のフォルダの絶対パスを引数 `project_dir` で受ける。
常駐サーバーにはセッションの作業のフォルダが環境変数で渡らないため、プラグインの PreToolUse のフックが、ツールの呼び出しのたびにセッションのフォルダを `project_dir` に入れる。
設定は、端末の設定と、そのフォルダから上のフォルダの設定ファイルを重ねて読み込む（[設定を重ねて読み込む仕組み](./コアコンセプト-設定を重ねて読み込む仕組み.md)）。
ツールの `config` に別のパスを指定すると、そのファイルと端末の設定だけを重ねる。

## 常駐サーバーで動かす

MCP サーバーは、文書の作成者が `mdmark serve` で起動する常駐のサーバー。
127.0.0.1 の Streamable HTTP で待ち受け、プラグインの `.mcp.json` がその URL へつなぐ。
並行して開いたセッションが同じプロセスを共有するため、サーバーはセッションごとの状態を持たず、呼び出しごとに処理する。
起動の手順は [MCPサーバーを起動する](./ClaudeCodeで使用する-MCPサーバーを起動する.md)。
プラグインのスキル `global-setup` は、systemd --user が使える端末では unit、使えない端末では tmux のセッションの中で `mdmark serve` を起動する（[セットアップする](./ClaudeCodeで使用する-セットアップする.md)）。

サーバーが起動していないと、そのセッションでは MCP サーバーだけが接続に失敗する。
起動してから `/mcp` でもう一度接続すると、セッションをもう一度開かずにツールを呼べる。
セッションの開始では、待ち受けていないときだけ SessionStart のフックが 1 行で伝え、待ち受けているときは何も入れない。
待ち受けているときに動いている unit か tmux のセッションは、`instructions` が伝える。

フックは、まとめた JavaScript で、`node` が起動する。
プラグインはまとめたフックだけを持ち、依存を入れない。

## ガイドの索引が正

ガイドのページの一覧は、リポジトリの `guide/index.yaml` が正。
ビルドが索引の検査にかけ、無いページを指す行があるときは止まる。
