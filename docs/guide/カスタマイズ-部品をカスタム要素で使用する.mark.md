# 部品をカスタム要素で使用する

アプリの画面にビュー・コメント・グラフ・操作できる部品・map の図のカスタム要素を配置し、JavaScript のプロパティでデータを指定して描き、操作をイベントで受け取る手順

アプリの画面の一部を、Markdown の記法で描いたときと同じ外観と操作で表示するときに実行する。
一覧を表で表示するときは [表をカスタム要素で使用する](./カスタマイズ-表をカスタム要素で使用する.mark.md) の `<mdmark-table>` を使用する。

## 前提

- [配布物を読み込む](./導入-配布物を読み込む.md) で、ページが `dist/index.js` と `dist/index.css` を読み込んでいる
- TypeScript で記載するときは、配布物を読み込んだ参照と同じ参照の `dist/` にある型定義（`index.d.ts` と、それが読み込む `.d.ts`）を配置する
  - 型 `MdmarkViewElement`・`MdmarkViewItem`・`MdmarkViewItemClickDetail`・`MdmarkCommentsElement`・`MdmarkCommentEditDetail`・`MdmarkCommentRemoveDetail`・`MdmarkGraphElement`・`MdmarkParamGraphElement`・`MdmarkParamChangeDetail`・`MdmarkMapElement`・`MdmarkNodeClickDetail` を持つ。構造は [API](./API.mark.md#部品をカスタム要素で描く) を参照する

## 手順

### 要素を配置する

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/shuhei1101/mdmark@0/dist/index.css">
<script type="module" src="https://cdn.jsdelivr.net/gh/shuhei1101/mdmark@0/dist/index.js"></script>

<mdmark-view id="tasks"></mdmark-view>
<mdmark-comments id="notes"><p>導入の手順を整える。</p></mdmark-comments>
<mdmark-graph id="trend"></mdmark-graph>
<mdmark-param-graph id="rate"></mdmark-param-graph>
<mdmark-map id="system"></mdmark-map>
```

`dist/index.js` を読み込むと、次の要素を登録する。
別の参照の配布物が先に登録していれば、登録しない。

<!-- table: {"kind": "data"} -->

| 要素 | 描くもの | 記法で描くとき |
| --- | --- | --- |
| `<mdmark-view>` | ボード表示と表形式のビュー | `view` のマーカー |
| `<mdmark-comments>` | 要素の中の本文に付けるコメント | 機能 `comments` |
| `<mdmark-graph>` | 図の枠とグラフ | `chart` のマーカー |
| `<mdmark-param-graph>` | スライダーとグラフ | `param` のマーカー |
| `<mdmark-map>` | map の図 | `map` のマーカー |

<!-- /table -->

要素は Shadow DOM を使用しないので、ページが読み込んだ `dist/index.css` とページの CSS がそのまま適用される。
`<mdmark-comments>` のほかの要素は、中に class `mdmark` の要素を 1 つ配置して描く。
`<mdmark-comments>` は、アプリが要素の中に記載した本文をそのまま残す。

プロパティを指定すると、次のマイクロタスクで描く。
同じマイクロタスクの中の代入は、まとめて 1 回だけ描く。
要素を登録する前に代入したプロパティも、登録した後に読み取る。
ビュー・コメント・map の図は、初めて描くときに部品のモジュール（`dist/view.js`・`dist/comments.js`・`dist/map.js`）を `dist/index.js` の隣から読み込む（[部品のモジュールを指定する](./API.mark.md#部品のモジュールを指定する) で指定したときは、その関数で読み込む）。

### ビューを描く

```js
const view = document.querySelector("#tasks");

view.columns = ["タイトル", "状態", "担当"];
view.items = [
  { key: "T-1", values: { タイトル: "設計", 状態: "対応中", 担当: "佐藤" } },
  { key: "T-2", values: { タイトル: "実装", 状態: "未着手", 担当: "鈴木" } },
];
view.group = "状態";
view.filter = { 担当: "select" };

view.addEventListener("mdmark-item-click", (event) => {
  openDetail(event.detail.key);
});
```

<!-- table: {"kind": "data"} -->

| プロパティ | 必須 / 任意 | 説明 |
| --- | --- | --- |
| `columns` | 必須 | 列名の配列。表形式の列の並びと、ボードの項目に出す値の並び |
| `items` | 必須 | 項目の配列。並びが表形式の行の順。空の配列は項目の無いビューを描く |
| `items[].key` | 必須 | 項目のキー。項目の並びの中で重ならない |
| `items[].values` | 必須 | 列名をキーにした値の組 |
| `group` | 任意 | ボードで列に分ける列名 |
| `default` | 任意 | 描いた直後に出すビュー。`board`・`table` |
| `filter` | 任意 | 表形式で絞り込みを付ける列と種類（`select`・`text`・`date`） |
| `icons` | 任意 | ボードの列の見出しの値からアイコンの名前を参照する対応 |

<!-- /table -->

`columns` と `items` の両方を指定すると描く。
`columns` のほかのプロパティの意味は、[ビューを描く](./API.mark.md#ビューを描く) の `mountView` の同じ名前の引数と同じ。
ボードの項目か表形式の行を押すか、フォーカスして Enter を押すと、`mdmark-item-click` を送信する。
ビューの切り替え・並べ替え・絞り込みのボタンを押しても送信しない。
プロパティを代入し直すと描き直し、表示しているビュー・並べ替え・絞り込みは同じ列名について保つ。

### コメントを付ける

```js
const notes = document.querySelector("#notes");

notes.comments = await loadComments();
notes.editable = true;
notes.removable = true;

notes.addEventListener("mdmark-comment-save", async (event) => {
  await saveComment({ id: crypto.randomUUID(), ...event.detail });
  notes.comments = await loadComments();
});
notes.addEventListener("mdmark-comment-edit", async (event) => {
  await updateComment(event.detail.id, event.detail.body);
  notes.comments = await loadComments();
});
notes.addEventListener("mdmark-comment-remove", async (event) => {
  await removeComment(event.detail.id);
  notes.comments = await loadComments();
});
```

<!-- table: {"kind": "data"} -->

| プロパティ | 必須 / 任意 | 説明 |
| --- | --- | --- |
| `comments` | 必須 | 付いたコメントの配列。要素の構造は [コメントを付ける](./API.mark.md#コメントを付ける) の `load` が返却するコメントと同じ。`id` は重ならない |
| `editable` | 任意 | `true` で吹き出しに「編集」を出す。既定は `false` |
| `removable` | 任意 | `true` で吹き出しに「削除」を出す。既定は `false` |

<!-- /table -->

`comments` を指定すると、要素の中の本文にコメントの操作を付ける。
要素の外の文字を選んでも、コメントのボタンは出ない。
mdmark はコメントを保存しない。
保存・編集・削除の操作はイベントで送信し、送信した後は入力欄・編集欄・削除の確認を閉じる。
マーカーと吹き出しは、アプリが `comments` を指定し直すまで変えない。
保存に失敗したときは、アプリが自分の画面で伝える。
アプリが要素の中の本文を入れ替えたときは、次に `comments` を代入したときに箇所を探し直す。

### グラフを描く

```js
document.querySelector("#trend").definition = {
  type: "line",
  title: "見積もりの推移",
  scope: "Sprint 1〜3",
  updated: "2026-11-24",
  x: { label: "Sprint", ticks: ["1", "2", "3"] },
  y: { label: "pt" },
  series: [{ name: "pt", points: [3, 5, 8] }],
};
```

`definition` に、`chart` のマーカーの範囲に記載する JSON と同じ定義を指定する。
キーは [図を描く](./図を描く-図を描く.md) と同じ。
`definition` を代入し直すと描き直し、図の枠の高さと拡大の倍率は保つ。

### 操作できる部品を描く

```js
const rate = document.querySelector("#rate");

rate.definition = paramDefinition;
rate.addEventListener("mdmark-param-change", (event) => {
  saveRate(event.detail.key, event.detail.value);
});
```

`definition` に、`param` のマーカーの範囲に記載する JSON と同じ定義を指定する。
キーは [操作できる部品を作る](./図を描く-操作できる部品を作る.md) と同じ。
スライダーを動かすたびに `mdmark-param-change` を送信する。
`definition` を代入したときは送信しない。
`definition` を代入し直すと描き直し、スライダーは定義の初期値に戻す。

### map の図を描く

```js
const system = document.querySelector("#system");

system.source = "flowchart LR\n  ui[画面] --> api[API]\n  api --> db[(DB)]";
system.data = { version: 1, notes: { api: { text: "認証してから DB を参照する" } } };
system.options = { title: "全体の構成" };

system.addEventListener("mdmark-node-click", (event) => {
  openNode(event.detail.id);
});
```

<!-- table: {"kind": "data"} -->

| プロパティ | 必須 / 任意 | 説明 |
| --- | --- | --- |
| `source` | 必須 | Mermaid。map の範囲で描ける種類 |
| `data` | 任意 | 補足。map の範囲の `map-data` と同じキー |
| `options` | 任意 | map の設定。`title`・`focus` だけを受け付ける |

<!-- /table -->

`source` を指定すると描く。
`source` と `data` の文字は、`-->` や ``` を持っていてもそのまま図に出る。
ノードを押すか、フォーカスして Enter を押すと、ノードの Mermaid の ID を持つ `mdmark-node-click` を送信する。
グループのタイトル・線・図の枠のボタンを押しても送信しない。
プロパティを代入し直すと描き直し、中へ入ったグループと開閉は同じ ID について保つ。

### 操作のイベントを受け取る

<!-- table: {"kind": "data"} -->

| 要素 | イベント | 発生する操作 | `detail` |
| --- | --- | --- | --- |
| `<mdmark-view>` | `mdmark-item-click` | 項目を押す・フォーカスして Enter を押す | `key`（項目のキー） |
| `<mdmark-comments>` | `mdmark-comment-save` | コメントを記載して保存を押す | `quote`・`prefix`・`suffix`・`body` |
| `<mdmark-comments>` | `mdmark-comment-edit` | 吹き出しで本文を編集して確定する | `id`・`body`（確定した本文） |
| `<mdmark-comments>` | `mdmark-comment-remove` | 吹き出しの削除を確定する | `id` |
| `<mdmark-param-graph>` | `mdmark-param-change` | スライダーを動かす | `key`（スライダーのキー）・`value`（今の値） |
| `<mdmark-map>` | `mdmark-node-click` | ノードを押す・フォーカスして Enter を押す | `id`（ノードの Mermaid の ID） |

<!-- /table -->

どのイベントも `bubbles` と `composed` を持ち、要素を囲む要素でも受け取れる。
`<mdmark-graph>` はイベントを送信しない。

### 指定の誤りを知る

指定に誤りがあると、プロパティの代入は例外を投げずに、要素の中に [通知ブロック](./用語集.mark.md) を出す。
本文に、最初に見つけた誤りの指定の名前（`items[1].key`・`comments`・`options.collapse` など）と修正方法が入る。

<!-- table: {"kind": "data"} -->

| 要素 | 通知ブロックのタイトル | 本文の扱い |
| --- | --- | --- |
| `<mdmark-view>` | `この箇所を表示できません` | 要素の中を通知ブロックにする |
| `<mdmark-comments>` | `この箇所を表示できません` | 要素の中の本文は残し、先頭に通知ブロックを配置する。コメントの操作は付けない |
| `<mdmark-graph>`・`<mdmark-param-graph>`・`<mdmark-map>` | `この図を表示できません` | 要素の中を通知ブロックにする |

<!-- /table -->

ページのほかの要素は動く。
正しい指定を代入し直すと、通知ブロックが消えて部品を描く。

### 要素を取り除く

要素をページから取り除くと、`document` の受け取りを解除する。
`<mdmark-comments>` はマーカーを削除して本文の文字を元に戻す。
ページへ戻すと、保持しているプロパティで描き直す。

## 反映

即時。
代入した次のマイクロタスクで描く。

## 確認

#### 部品が描かれている

```js
document.querySelector("#tasks .mdmark") !== null
```

`true` になる。
グラフ・操作できる部品・map の図は、要素の中に `figure.mdmark-diagram` がある。

#### イベントが届く

ビューの項目か map の図のノードを押すと、`mdmark-item-click`・`mdmark-node-click` の受け取りが項目のキー・ノードの ID で呼ばれる。

#### 誤りの通知が出ていない

要素の中に class `mdmark-notice` の要素が無い。
あれば、通知の本文の指定の名前を確認して修正する。

## 元に戻す

要素を画面から取り除く。
mdmark はデータとコメントを保存しないため、残るものはない。
