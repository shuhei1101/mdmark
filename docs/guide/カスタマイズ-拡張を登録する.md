# 拡張を登録する

`registerExtension` でマーカーを追加する手順。TypeScript を推奨し、配る前に JavaScript へ変換する

利用側のアプリが自分のマーカーを文書に記載できるようにするとき、そのマーカーを描くモジュールを追加するときに実行する。

## 前提

- [文書を描く](./導入-文書を描く.md)
- TypeScript で記載するときは、配布物を読み込んだタグと同じタグの `dist/` にある型定義（`index.d.ts` と、それが読み込む `.d.ts`）を、拡張を書き込むプロジェクトに配置する

## 手順

### 拡張のモジュールを記載する

#### `draw` を記載する

```ts
import type { MdmarkMarkArgs } from "./mdmark/index.js";

export function draw(slot: HTMLElement, value: MdmarkMarkArgs): void {
  slot.textContent = `こんにちは、${String(value.options.target ?? "")}`;
}
```

拡張は TypeScript と JavaScript のどちらでも記載できる。
TypeScript で記載することを推奨する。
`draw` の引数に配布物の型が付き、記載し間違いを配る前に型検査で見つけられる。
`slot` はマーカーの場所の要素、`value.options` はマーカーに記載した JSON のオブジェクト（引数の無いマーカーは `{}`）。
`draw` は Promise を返却する非同期でもよい。
`draw` が例外を投げると、そのマーカーの場所だけが通知ブロックに替わる。

#### JavaScript で記載するときは型を付けて点検する

```js
// @ts-check
/** @type {import("../mdmark/index.js").MdmarkExtension} */
const extension = {
  name: "greet",
  directive: "greet",
  load: async () => ({
    draw(slot, value) {
      slot.textContent = `こんにちは、${String(value.options.target ?? "")}`;
    },
  }),
};

export default extension;
```

JavaScript は変換を挟まずに、先頭の `// @ts-check` と JSDoc で型を付けて記載する。
型は TypeScript と同じ配布物の型定義を読み込む。
`npx tsc --noEmit` で点検すると、型を誤った行がファイルと行つきで出る。
`mdmark init --js` が、この構造の雛形と JavaScript も点検する `tsconfig.json` を配置する（[雛形を配置する](./書き出す-雛形を配置する.md)）。
固有の部品と CSS を文書に適用する手順は [固有の部品とCSSを適用する](./図を描く-固有の部品とCSSを適用する.md)。

#### linter で点検する

```bash
npx @biomejs/biome check extensions
```

拡張を記載するときは、TypeScript と JavaScript のどちらでも linter を使用する。
型検査で見つからない、使用していない変数や記載方法の誤りを、配る前に見つけられる。
linter は Biome を推奨する。
1 つのコマンドで linter と整形の点検ができる。

### 配る

#### JavaScript に変換する

```bash
npx esbuild extensions/greet.ts --format=esm --outfile=public/extensions/greet.js
```

`load` が `import()` で読み込むのはブラウザなので、配るのは JavaScript にしたファイルだけ。
TypeScript のファイルは配らない。
`mdmark export`・`mdmark build` で書き出す拡張は、`load` の中の `import()` の読み込む先を文字列のリテラルで記載する。変数を指定すると、書き出しが警告を出し、書き出した HTML を `blob:` と動的 `import()` を許さない環境で開いたときにその拡張を読み込めない。
変換の道具は利用側で選ぶ。
上は esbuild の例。

### 登録する

#### `registerExtension` を呼ぶ

```js
import { registerExtension } from "https://cdn.jsdelivr.net/gh/shuhei1101/mdmark@{タグ}/dist/index.js";

registerExtension({
  name: "greet",
  directive: "greet",
  load: () => import("/extensions/greet.js"),
});
```

`{タグ}` は CSS を読み込んだタグに置き換える。
`mount` や `update` で描く前に呼ぶ。
描いた後に登録したマーカーは、次の `mount`・`update` から有効になる。
`name` は通知ブロック・記載の警告・`console.error` に出す名前、`directive` はマーカーの名前。
`directive` は英小文字で始まり、英小文字・数字・`-` だけを持つ。
`features` と記法のマーカー（`table`・`tabs`・`steps`・`section`・`row-detail`・`fig`・`toc`・`glossary`・`view`）と、登録済みの拡張の `directive` は使用できず、`Error` を投げて登録しない。
書式に合わない項目があると `TypeError` を投げて登録しない。
設定の `libraries` や図の部品のマーカー（`chart`・`param`・`er`）、廃止した `flow`・`sequence` に同じ名前があるときは、拡張を優先する。廃止した名前の範囲も、図の記載方法を廃止した警告にせず拡張に描かせる。

#### 引数を検査する

```ts
import * as v from "valibot";

registerExtension({
  name: "greet",
  directive: "greet",
  load: () => import("/extensions/greet.js"),
  schema: v.object({
    options: v.strictObject({
      target: v.pipe(v.string(), v.regex(/^[a-z]+$/)),
      lang: v.optional(v.string()),
    }),
  }),
});
```

マーカーの引数を検査するときだけ `schema` を指定する。
`schema` は Standard Schema で、zod・valibot など `~standard` を持つ検査ライブラリの schema をそのまま指定できる。
mdmark は検査ライブラリをまとめない。
検査する値は `{ options: Record<string, unknown>; definition?: unknown }`。
valibot の `object` は知らないキーを許すため、キーを限るときは `strictObject` を使用する。
引数が合わないマーカーの場所は、モジュールを読み込まずに記載の警告に替わる。

### 文書にマーカーを記載する

#### 拡張のマーカーを記載する

```markdown
<!-- greet: {"target": "world", "lang": "ja"} -->
```

`draw` は `{ options: { target: "world", lang: "ja" } }` を受け取る。
前の書き方（`<!-- greet: world lang=ja -->`）のマーカーは、モジュールを読み込まずに記載の警告に替わる。拡張のマーカーは `mdmark upgrade` が書き換えずに移行の報告に出すので、手で書き換える。
文書にそのマーカーがあるときだけ、`mount` と `update` が `load` を呼ぶ。
同じ文書の同じ拡張のマーカーは、`load` を 1 回だけ呼ぶ。
`render` は拡張のマーカーを読み込み中のブロックに置き換えるだけで、`load` も検査も呼ばない。

#### 部品の定義を指定する

````markdown
<!-- greet -->

```json
{ "title": "段取り", "items": ["a", "b", "c"] }
```

<!-- /greet -->
````

マーカーを範囲（`<!-- greet -->` 〜 `<!-- /greet -->`）で記載し、範囲に言語 `json` のコードブロックを 1 つ配置すると、その JSON を読み込んだ値が `value.definition` に入る。
`schema` の検査と `draw` は同じ値を受け取る。
定義の中身の構造は `schema` が確認する。
コードブロックが 2 つ以上あるか、JSON として読み込めないときは、`schema` も `load` も呼ばず、マーカーの場所が記載の警告に替わる。

#### 部品を描く関数を呼ぶ

```js
import { mountView } from "https://cdn.jsdelivr.net/gh/shuhei1101/mdmark@{タグ}/dist/index.js";

export async function draw(slot, value) {
  await mountView(slot, value.definition);
}
```

`draw` の中で、配布物が出すビューを描く関数 `mountView` とコメントを付ける関数 `mountComments` を、`slot` に対して呼べる。
`draw` が部品の `Promise` を待つと、`mount` はその後にマーカーの場所を描き終えたものとして扱う。
`update` と `destroy` でマーカーの場所を片付けるとき、その中の部品の `destroy` も行う。
引数と動きは [部品をJavaScriptから使用する](./カスタマイズ-部品をJavaScriptから使用する.md)。

## 反映

即時。登録は同期で終わり、次に `mount` か `update` で描く文書から有効になる。

## 確認

#### マーカーの場所に描かれている

拡張のマーカーを記載した文書を描く。
マーカーの場所の要素に、`draw` が記載した内容が出る。
ブラウザの開発者ツールのネットワークで、拡張のモジュールへの要求が 1 件ある。

#### マーカーの無い文書で読み込まれていない

拡張のマーカーを記載していない文書を描く。
拡張のモジュールへの要求が 0 件になる。

#### 引数が合わないとき

`schema` に合わない引数のマーカーを記載して描く。
マーカーの場所にタイトル `記載の警告` の枠が出て、本文にマーカーの文字と拡張の名前（`greet`）がある。
拡張のモジュールへの要求は 0 件になる。

#### モジュールを読み込めないとき

`load` が指す先を存在しない URL に変えて描く。
マーカーの場所に通知ブロックが出て、タイトルが `この図を表示できません`、本文が `表示に使用する拡張（greet）を読み込めませんでした。` で始まる。
`console.error` に拡張の名前と元のエラーが出て、ほかの箇所は描かれる。

#### 型検査が通る

TypeScript か、`// @ts-check` を付けた JavaScript で記載したとき、型検査を実行する。

```bash
npx tsc --noEmit
```

型エラーが 0 件になる。

#### linter が通る

```bash
npx @biomejs/biome check extensions
```

違反が 0 件になる。

## 元に戻す

`registerExtension` の呼び出しを削除する。
登録は同じページの間だけ有効になり、削除すると文書の拡張のマーカーは未知のマーカーとして取り除かれる。
配った JavaScript のファイルは別に削除する。
