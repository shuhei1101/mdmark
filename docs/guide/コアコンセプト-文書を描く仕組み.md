# 文書を描く仕組み

Markdown と設定を指定してから描かれるまでの流れと、テーマの層・機能のオン・オフの優先順

利用側のページが `mount` か `render` に Markdown と設定を指定してから、文書が描かれるまでの流れ。
外観と機能が、何で決まるかを合わせて示す。

## 描かれるまでの流れ

1. 設定に既定を適用する。省いたキーは既定になり、型の合わない値は無視する
2. 文書の先頭の [フロントマター](./記法.md#フロントマター) を、行の数を変えずに空白にしてから、Markdown を解析し、GitHub Flavored Markdown の記法（表・タスクリスト・取り消し線・`www` の自動リンク）を HTML にする
3. [取り込み](./記法.md#取り込み) のマーカーの場所に、利用側が `includes` で指定した取り込む文書の中身を差し込む。取り込んだ中身の見出しの ID と図表の番号は、文書全体で振る
4. 文書の [マーカー](./用語集.md) を取得する。引数は JSON のオブジェクトとして読み、記法・`features`・`page` のマーカーはマーカーごとの JSON Schema（`schemas/marks/`）で検査する。読めない引数と型の合わない値はその場所の記載の警告にして当てず、知らないキーは無視する。前の書き方の引数は JSON に変換して読む。`features` のマーカーは機能のオン・オフに使用し、記法のマーカーはその記法の機能がオンなら記法にし、オフなら取り除いて普通の Markdown として描く。対応表にある名前のマーカーと登録した拡張のマーカーはマーカーの場所に置き換え、それ以外のマーカーは取り除く。機能 `frontmatter` がオンなら、本文の先頭にフロントマターの折りたたみを配置する
5. [記法](./記法.md) を HTML にする。表・注意書き・タブ・ステップ・ファイルツリー・バッジ・目次・セクション・行の詳細・図表の番号を、中身を読み込める HTML にし、見出しに ID を付ける。読み込めない指定は、その箇所に記載の警告を配置し、読み込めた指定で描く
6. 許可していない要素・属性・URL を落とす。`script` 要素・`on` で始まる属性・`style` 属性・`javascript:` の URL は残らず、スクリプトは実行されない。`href` と `src` は `http`・`https`・`mailto` と相対 URL だけ残り、画像の `src` は画像の種類と base64 の構造の `data:` URL も残る。記法の class・`data-*`・`id` は、mdmark が記法から出した要素にだけ残る
7. `render` は、ここで本文の HTML 文字列を返却する。各記法の中身は、スクリプトを動かさなくても読み込める
8. `mount` は、要素の中に本文を描いて class `mdmark` を付け、記法の操作（表の並べ替え・ピン止め・絞り込み・件数・テーブル設定・集計の行・コピー・行へ移る処理・見出し行と集計の行を留める処理、階層の表の開閉・パスのコピー・行の選択と YAML の見本の切り替え、コードブロックのコピー、タブの切り替え、セクションと行の詳細の開閉）を付ける。マーカーの場所があれば外部ライブラリと拡張のモジュールを、配布物に入っていない名前の `icon:` があれば Lucide のアイコンを jsDelivr から読み込み、印刷と `hashchange` の受け取りを付ける。`update` は本文を差し替えて操作をもう一度付け、`destroy` は操作と受け取りを解除する
   URL の `#ID` が選ばれていないタブの中の要素（入れ子のタブの中を含む）を指すときは、描いたときと `hashchange` で、外側のタブから順にそのタブを選び、外側の閉じたセクションを開いてから要素へ移る。
   描いたときは、覚えたタブ名より URL の `#ID` が指すタブを優先する。
   URL の `#ID` で選んだタブは覚えず、同じ組のほかのタブ群も切り替えない

## 索引を指定したときの流れ

`opts.index`・`opts.docId`・`opts.references` を指定すると、上の流れに次が加わる（考え方は [索引と被参照](./コアコンセプト-索引と被参照.md)）。

1. 索引の構造を確認し、Schema に合わない文書・用語の項目は除く
2. 文書の `glossary` のマーカーで囲んだ表から用語を読み込む。`glossary` がオフなら読み込まず、表を普通の表として描く
3. 索引の `terms`・描く文書の表・ほかの文書の表（`references.glossary`）・文書の `aliases` から、照合する単語の辞書を作る。同じ単語は、索引の `terms`、描く文書の表、ほかの文書の表の順に優先する。文書の別名は `backlinks` がオンのときだけ入れ、描く文書自身の別名は入れない
   辞書の単語と本文の文字は、照合の前に NFKC・英字の小文字化・前後の空白の除去で正規化する。
   正規化した後に同じになる単語は 1 つの単語として、この優先の順で先の用語を使用する。
4. 本文の文字を、単語の区切りに一致するところだけ、長い単語を先に辞書と照合する。用語は用語の `id`、文書の別名は文書の `id` ごとに、セクションごとに最初に出たところだけに下線とツールチップを付ける。コード・リンク・見出し・用語集の表の中は照合しない
   下線は、正規化する前の本文に記載したままの文字に付ける。
   索引の用語の `avoid` と用語集の表の `avoid.column` の列のやめた言い方も、辞書の単語として同じ規則で照合する。
   同じ位置で用語の単語・別名にも該当するときは用語を選び、文書の別名にも該当するときはやめた言い方を選ぶ。
   やめた言い方は、セクションごとに言い方ごとの最初に出たところだけ、用語の下線とは別に数えて、波線のマーカーと代わりの用語のツールチップを付ける。
   `glossary` がオフのときは、やめた言い方を照合しない。
5. 描く文書を参照している文書を、`opts.references.backlinks[opts.docId]`（無ければ索引の `related` に描く文書を持つ文書）から引き、本文の末尾に被参照の一覧を配置する。`backlinks` がオフなら配置しない
6. 索引のタイトル・意味・概要は Markdown として解析せず、文字として出す。リンクの `href` は、本文のリンクと同じ許可の検査にかける

`render` はここまでの HTML 文字列を返却する。
意味と関連文書は、スクリプトを動かさなくても読み込める。
`mount` は、ツールチップを開閉する操作を付ける。
`update` でもう一度付け、`destroy` で削除する。

## 埋め込んだ HTML を描くときの流れ

`<!-- html -->` の範囲に `html` のコードブロックがあり、`html` の機能がオンのとき、描かれるまでの流れに次が加わる（記載方法は [記法](./記法.md#埋め込んだ-html)）。

1. 範囲の `html` のコードブロックの中身を、コードでなく生の HTML として読み込む。範囲のコードブロックが 1 つでないときは、記載の警告を配置し、コードのまま描く
2. 中身に、上の許可の検査にかける。`script` 要素・`on` で始まる属性・`javascript:` の URL は残らない。`button` は `type="button"` に固定して残し、`style` はレイアウト・余白・枠・色・文字の宣言だけを残す
3. 中の `<mdmark-chart>` などの custom element の中身を、図の部品のマーカーの範囲と同じ定義として読み込み、図に置き換える。`hints` がオンなら、`data-hint` を持つ要素と図のノードの `hint` に、ツールチップの中身とマーカーを配置する
4. 中の文字を、本文と同じ用語の辞書と照合する

`render` はここまでの HTML 文字列を返却する。
`mount` は、中の図の部品に拡大・縮小・移動の操作を、ヒントに開閉の操作を付け、本文の列より広い HTML を中で横にスクロールさせる。
範囲の `html` に記載したスクリプトは動かず、動くのは mdmark が付ける操作と、次の流れで適用する範囲の `ts`・`js` だけになる。

## 範囲の CSS と TypeScript を適用するときの流れ

`html` に加えて `html-scripts` の機能がオン（既定はオフ）のとき、範囲に配置した `css`・`ts`・`js` のコードブロックに、上の流れに次が加わる（記載方法は [コードブロックのHTMLを描く](./図を描く-コードブロックのHTMLを描く.md)）。

1. 範囲の根の要素に、文書の中の範囲の通し番号を付ける
2. `css` の各規則のセレクタの前に範囲の根の要素を付け、範囲の HTML の中だけに該当する `style` にして根の要素の先頭に配置する。`@import` など、範囲の外へ該当しうる `@` の規則は落とす
3. `ts`・`js` のコードを文字として `template` に入れて根の要素の末尾に配置する。`render` はここまでを返却し、コードは実行しない
4. `mount` は、描いた後に `html-scripts.url` の変換のライブラリを読み込み、`ts` の型を削除して CommonJS に変え、ページの `script` の `nonce` を付けた `script` 要素で動かす。既定のエクスポートの関数を、範囲の根の要素を引数に文書の順に 1 回ずつ呼ぶ
5. 関数が返却した関数を、`update`・`destroy` と同じ要素への 2 回目の `mount` で再描画する前に 1 回呼ぶ

`mdmark export`・`mdmark build` は、CLI が esbuild で変換したコードを書き出す HTML の 1 つの `script` にまとめ、変換のライブラリを読み込まずに同じ関数を呼ぶ。
変換のライブラリを読み込めないときは範囲の前に通知ブロックを、コードが動かせないときは記載の警告を配置し、範囲の `html`・`css` は描く。
差分の中の範囲は動かさない。

## 機能のオン・オフの優先順

機能のオン・オフは、次の順に重ねて決まる。
後に挙げたものが、前に挙げたものを上書きする。

| 順 | 決めるもの | 記載する場所 |
| --- | --- | --- |
| 1 | mdmark の既定 | [機能の既定](./設定.md#機能の既定) |
| 2 | 設定の `features` | `opts.config.features` |
| 3 | 文書のマーカー | 文書の `<!-- features: {"機能": false} -->` |

文書のマーカーは、記載した順に重ねる。
同じ名前が何度も出たら、後に記載したものが勝つ。
知らない機能名は無視する。
`update` で本文を差し替えると、差し替えた本文のマーカーでもう一度決める。

## テーマの層

mdmark の CSS は `@layer mdmark` に入る。
利用側が層の外に記載した CSS は、詳細度によらず mdmark の CSS に勝つ。
配色は、mdmark に入れたテーマから設定の `colorTheme` で選べる（[選ぶテーマ](./設定.md#選ぶテーマ)）。
選んだテーマの配色の値は、層の中の `:root` に該当する。
外観は、次の 2 つで変えられる。

- `--mdmark-` で始まる CSS 変数の値を変える（一覧は [テーマの CSS 変数](./API.md#テーマの-css-変数)）
- 層の外の CSS で、本文の規則を上書きする

利用側の `theme.css` は、利用側のページが `<link>` で層の外に読み込む。
mdmark は `theme.css` を読み込まない。
CLI の書き出しと VS Code のプレビューは、重ねた設定の `theme` を同じく層の外に適用する（[設定を重ねて読み込む仕組み](./コアコンセプト-設定を重ねて読み込む仕組み.md)）。
画面で OS の設定がダークのときは、色の変数がダークの値になる。
描く先の要素かその祖先の class があるときは、OS の設定より先に class が配色を決める（[配色を切り替える class](./API.md#配色を切り替える-class)）。
印刷では明るい配色に戻る。

配色の値は、次の順に重ねて決まる。
後に挙げたものが、前に挙げたものを上書きする。

| 順 | 決めるもの | 記載する場所 |
| --- | --- | --- |
| 1 | 既定のテーマ（`dev-swiss`）の値 | 層の中の `:root` |
| 2 | 選んだテーマの値 | 文書の [ページの設定](./記法.md#ページの設定) の `theme`、無ければ設定の `colorTheme`（[選べるテーマ](./API.md#選べるテーマ)） |
| 3 | 利用側の CSS | 層の外の `:root`・`.mdmark` に記載した変数と規則（`theme.css` を含む） |

明るい配色とダークの配色は、次の順に先にあるもので決まる。

| 順 | 決めるもの | 記載する場所 |
| --- | --- | --- |
| 1 | 文書の明暗 | 文書の先頭の `<!-- page: {"scheme": …} -->`（[ページの設定](./記法.md#ページの設定)） |
| 2 | 設定の明暗 | 設定の `colorScheme`（[配色の明暗](./設定.md#配色の明暗)） |
| 3 | 描く先の祖先の class | `mdmark-theme-dark`・`mdmark-theme-light`・`vscode-*`（[配色を切り替える class](./API.md#配色を切り替える-class)） |
| 4 | OS の設定 | `prefers-color-scheme` |

`auto` を記載した順は、飛ばして次の順で決める。
印刷では、選んだテーマの明るい配色になる。

## 外部ライブラリを読み込むタイミング

外部ライブラリのモジュールは、文書に対応表にあるマーカーがあるときだけ、`import()` で読み込む。
マーカーの無い文書では、外部ライブラリへの要求は 0 件になる。
同じ文書の同じ名前のマーカーは、モジュールを 1 回だけ読み込む。
`registerExtension` で登録した拡張のモジュールも、文書にそのマーカーがあるときだけ、`load` で読み込む。
`schema` を指定した拡張は、読み込む前にマーカーの引数を検査し、合わなければ読み込まずに、そのマーカーの場所だけを記載の警告に替える。
import map は使用しない。

読み込みの間、マーカーの場所には読み込み中のブロックが出る。
モジュールを読み込めないとき、またはモジュールの `draw` が例外を投げたときは、そのマーカーの場所だけが通知ブロックに替わり、ほかの箇所は描かれる。
拡張のモジュールも同じ。
