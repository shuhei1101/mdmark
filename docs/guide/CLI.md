# CLI

コマンド・引数・出力・終了コードの一覧

どのコマンドも `npx github:shuhei1101/mdmark#v{バージョン} {コマンド}` で呼ぶ。
`{バージョン}` は使用するバージョンの `{MAJOR}.{MINOR}.{PATCH}`。
npm のレジストリには公開しない。
Node 24 以降で動く。
`export`・`build`・`check` は、端末の設定と、`--config` で指した設定ファイルか今のフォルダから上のフォルダの `mdmark.config.yaml` を重ねて読み込む（[設定を重ねて読み込む仕組み](./コアコンセプト-設定を重ねて読み込む仕組み.md)）。
`upgrade` は、`--config` で指した設定ファイルか、今のフォルダから上へ最初に見つかった `mdmark.config.yaml` だけを書き換える。`--settings` を指定すると端末の設定だけを書き換える。
設定のキーは [設定](./設定.md)。

## 雛形を配置する

設定・利用側の CSS・索引・拡張の雛形をフォルダに配置する。
既にあるファイルは上書きしない。
手順は [雛形を配置する](./書き出す-雛形を配置する.md)。

配置したファイルの行（`配置した: {パス}`）と、既にあって配置しなかったファイルの行（`配置しなかった（既にある）: {パス}`）を、雛形の並びで 1 行ずつ標準出力に出す。
パスは配置先のフォルダからの相対パス。

```text
配置しなかった（既にある）: mdmark.config.yaml
配置した: theme.css
配置した: index.yaml
配置した: extensions/example.ts
配置した: tsconfig.json
配置した: package.json
```

### 使用方法

```bash
npx github:shuhei1101/mdmark#v{バージョン} init [{配置先のフォルダ}] [--js]
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `{配置先のフォルダ}` | 任意 | 雛形を配置するフォルダ。省くと今のフォルダ。無ければ作る | `docs` |
| `--js` | 任意 | 拡張の雛形を JavaScript で配置する。`extensions/example.js` を配置し、`tsconfig.json` と `package.json` は配置しない | `--js` |

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | 配置できた（配置しなかったファイルがあっても） |
| `1` | 配置先のフォルダを作れない、またはファイルを書き込めない。標準エラーに書き込めなかったパスと修正方法を出す。記載できたファイルは残る |

## 文書を HTML に書き出す

Markdown を 1 つ、CDN を読み込まない 1 枚の HTML に書き出す。
配布物・利用側の CSS・外部ライブラリのモジュール・拡張・画像を埋める。
動画・音声は、出力の HTML と同じフォルダの `{出力のファイル名から拡張子を除いた名前}_files/` へコピーし、HTML からそのコピーへの相対パスにする。
開いた HTML は `mount` で文書を描き、開いてから描き終えるまで、ページ自身・`_files/` の下にコピーした動画と音声と画像の `data:` のほかへ要求しない。
手順は [文書を書き出す](./書き出す-文書を書き出す.md)。

標準出力に `書き出した: {出力のパス}` の 1 行を出す。
警告は、標準エラーに 1 つ 1 行（`警告: {ファイル}: {内容}`）で出す。
警告の対象は、読み込めない画像・動画・音声・外部ライブラリのモジュール・拡張・`theme` の CSS と、埋めずに残した絶対 URL の画像・動画・音声と、まとめた後も動的 `import()` が残る外部ライブラリ・拡張（埋めたうえで出す）。
文書間のリンクは記載したままの `href` で残し、警告に出さない。

文書の include のマーカーの取り込み先を、設定ファイルのフォルダ（無ければ文書のフォルダ）の中から読み込んで埋める。
そのフォルダの外を指すパスと読み込めないファイルは埋めず、警告に出す（開いたときは、その場所に記載の警告が出る）。
文書が使用する、配布物に入っていない名前の Lucide のアイコンの形状も埋め、開いたときに jsDelivr を読み込まない。
Lucide に無い名前は埋めず、警告に出す。

文書が相対パスで指す画像・動画・音声・動画の `poster` は、文書のフォルダを基準に探し、無ければ設定の [アセットのルート](./設定.md#アセットのルート) を基準に同じ相対パスで探す。
`src` のクエリとフラグメント（`#only-dark` など）は、書き出す値に残す。
コピー先の中のパスは、設定ファイルのフォルダ（設定ファイルが無ければ文書のフォルダ）からの相対パスにする。
そのフォルダの外にあるファイルは `_files/external/{ファイル名}` にし、名前が重なれば `-1`・`-2` を付ける。
前の書き出しが残した `_files/` の中のファイルは削除しない。
添付のファイル（PDF など）はコピーせず、記載したままのリンクで残す。
`features` で `images`・`media` をオフにしていても、画像の埋め込みと動画・音声のコピーはする。

設定の `colorTheme` が選べるテーマの名前に無いときは、書き出しを止めず、既定の `dev-swiss` で描く。
警告は `警告: {設定ファイル}: 不明なテーマ名 {名前} です。既定の dev-swiss で描画します。` で出す。
選べるテーマは [選ぶテーマ](./設定.md#選ぶテーマ)。

設定に `aliases` があるときは、行の `paths` の YAML を読み込み、[`buildAliases`](./API.md#エイリアスを作る) で作ったエイリアスから `env` を除いて、書き出す HTML に埋める。
該当するファイルが無い行・読み込めない YAML・使用できない行とレコードは、書き出しを止めず、警告（`警告: {ファイル}:{場所}: {種類}: {内容}`。場所が空のときは `警告: {ファイル}: {種類}: {内容}`）に出す。
種類と意味は [設定と索引を点検する](#設定と索引を点検する) と同じ。

```text
書き出した: docs/使用方法/guide.html
```

```text
警告: docs/使用方法/guide.md: 画像 `img/missing.png` を読み込めません。パスを修正するか画像を配置してください。
警告: aliases/terms.yaml:terms[2].description: alias_required_empty: `aliases/terms.yaml` の `terms[2]` の `description` が空です。説明を記載してください。
```

### 使用方法

```bash
npx github:shuhei1101/mdmark#v{バージョン} export {文書} [--out {出力}] [--config {設定ファイル}]
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `{文書}` | 必須 | 書き出す Markdown のパス | `docs/使用方法/guide.md` |
| `--out` | 任意 | 書き出す HTML のパス。省くと文書と同じフォルダの、拡張子を `.html` に替えたパス。親のフォルダが無ければ作り、既にあれば上書きする | `--out dist/guide.html` |
| `--config` | 任意 | 使用する設定ファイルのパス。指定するとこのファイルと端末の設定だけを重ねる。省くと今のフォルダから上のフォルダへ `mdmark.config.yaml` を探して重ねる | `--config docs/mdmark.config.yaml` |

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | 書き出した（警告があっても） |
| `1` | 設定ファイルが無い・読み込めない・Schema に合わない（空の設定ファイルを含む。重ねた設定ファイルと端末の設定のどれかでも同じ）。標準エラーに原因と修正方法を出す。Schema に合わないときは `mdmark check` で確認できることも出す |
| `1` | `{文書}` のファイルが無い・読み込めない。標準エラーにパスと修正方法を出す |
| `1` | 出力のパスか、動画・音声のコピー先の `_files/` へ書き込めない。標準エラーに書き込めなかったパスと修正方法を出す。HTML はどこにも記載しない |

## 複数の文書を 1 枚の HTML にまとめる

設定の `build` で決めた文書を、文書を行き来できる 1 枚の HTML にまとめる。
参照・被参照・用語のツールチップが有効になる。
埋めるものと外へ要求しないことは、[文書を HTML に書き出す](#文書を-html-に書き出す) と同じ。
画像・動画・音声はそれぞれの文書のフォルダを基準に探す。
include の取り込み先は文書ごとにその文書のフォルダから数え、`build` の対象外のファイルでも設定ファイルのフォルダの中なら埋める（文書の一覧には出さない）。
複数の文書が指す同じ画像は 1 回だけ埋め、同じ動画・音声は `{build.out のファイル名から拡張子を除いた名前}_files/` へ 1 回だけコピーする。
手順は [文書を1枚にまとめる](./書き出す-文書を1枚にまとめる.md)。

標準出力に `書き出した: {build.out}（文書 {件数} 件）` の 1 行を出す。
警告は、[文書を HTML に書き出す](#文書を-html-に書き出す) の警告（設定の `aliases` の警告を含む。エイリアスはまとめた全ての文書で有効になる）に、まとめた HTML に含まれない文書へのリンクと、`build.glossary` と `build.entry` がまとめる文書に該当しないことを追加して出す。

```text
書き出した: dist/docs.html（文書 3 件）
```

```text
警告: README.md: `下書き/メモ.md` へのリンクはまとめた HTML に含まれません。記載したままのリンクで残します。まとめるなら `build.include` に追加してください。
```

### 使用方法

```bash
npx github:shuhei1101/mdmark#v{バージョン} build [--config {設定ファイル}]
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `--config` | 任意 | 使用する設定ファイルのパス。指定するとこのファイルと端末の設定だけを重ねる。省くと今のフォルダから上のフォルダへ `mdmark.config.yaml` を探して重ねる。まとめる文書と書き出す先は、重ねた設定の `build` が持つ | `--config docs/mdmark.config.yaml` |

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | `build.out` に記載した（警告があっても） |
| `1` | 設定ファイルが無い・読み込めない・Schema に合わない（空の設定ファイルを含む）、または `build` が無い。標準エラーに原因と修正方法を出す |
| `1` | `build.include` に該当し `build.exclude` に該当しない文書が 0 件。標準エラーに、対象が 0 件であることと `build.include` を修正することを出す。HTML は記載しない |
| `1` | `build.out` か、動画・音声のコピー先の `_files/` へ書き込めない。標準エラーに書き込めなかったパスと修正方法を出す。HTML は記載しない |

## 設定と索引を点検する

設定の構造・索引と文書のずれ・`build` の対象の有無・設定の `aliases` のずれ・文書の本文にある知らないマーカー・文書が指す見つからないファイル・include のマーカーの取り込み先・図の部品の定義を点検する。
ずれの一覧を標準出力に出し、設定・索引・文書・エイリアスの YAML は書き換えない。
手順は [点検する](./書き出す-点検する.md)。

ずれ 1 つを 1 行（`{ファイル}:{場所}: {種類}: {内容}`。場所が空のときは `{ファイル}: {種類}: {内容}`）で並べ、最後に `ずれ {件数} 件` の行を出す。
ファイルは設定ファイルのあるフォルダからの相対パス。
並びは `schema` → `unknown_color_theme` → `no_documents` → `checkIndex` が返却した並び → エイリアスのずれ（[`buildAliases`](./API.md#エイリアスを作る) が返却した並び。`alias_no_files`・`alias_unreadable` は読み込んだ行の順にその場所へ配置する） → `missing_file` → `include_target_missing`・`include_circular` → `unknown_mark` → `diagram_` で始まる種類（いずれも文書のパスの順、同じ文書の中は行の順） → `plain_md_with_marks`（文書のパスの順）。
内容は、何が合わないかと修正方法の日本語の 1 文。

```text
docs/index.yaml:docs[1].path: missing_doc: `old.md` が見つかりません。文書を戻すか、索引の `docs[1]` を削除してください。
mdmark.config.yaml:build: schema: `build.out` がありません。書き出す HTML のパスを記載してください。
ずれ 2 件
```

種類は次のとおり。

<!-- table: {"kind": "data"} -->

| 種類 | 意味 |
| --- | --- |
| `schema` | 設定か索引が Schema に合わない。`build.glossary`・`build.entry` が `build.include` に該当しないもの、`theme`・`extensions` のファイルと `assets.root` のフォルダが無いもの、`extensions` の拡張を読み込めないもの、`aliases` の行が取り込んだ Schema に合わないもの（場所は `aliases[1].alias_type` の構造）を含む |
| `unknown_color_theme` | 設定の `colorTheme` が選べるテーマの名前に無い。場所は `colorTheme`。内容は `不明なテーマ名 {名前} です。dev-swiss・theme-paper・theme-slate・theme-contrast のいずれかに修正してください。` |
| `no_documents` | `build.include` に該当し `build.exclude` に該当しない文書が 0 件 |
| `missing_doc` | 索引にあって、文書が見つからない |
| `orphan_doc` | 文書があって、索引に無い |
| `broken_ref` | `related` の `id`（オブジェクトの要素は `to`）が索引に無い |
| `untyped_related` | `related` の要素が `type` と `when` を持たない文字列。オブジェクトへの書き換えを求める |
| `one_sided_change_together` | `change_together` の相手が、自分への `change_together` を記載していない |
| `related_link_overlap` | `change_together` でない `related` の相手を、本文でもリンクしている |
| `missed_change_together` | `--base` を指定したとき、`change_together` の組のうち片方の文書だけが変わっている。場所は空で、ファイルは変わっていない側の文書のパス |
| `duplicate_term` | 用語の単語か別名が、NFKC・英字の小文字化・前後の空白の除去で正規化した後に重なっている |
| `avoided_term` | 索引の文書の本文に、用語のやめた言い方が出ている |
| `alias_no_files` | `aliases` の行の `paths` に該当するファイルが 0 件。場所は `aliases[1].paths` |
| `alias_unreadable` | `paths` に該当したファイルを YAML として読み込めない |
| `duplicate_alias_row_id` | `aliases` の行の `id` が、前の行と重なっている。重なった後の行は読み込まない |
| `alias_records_missing` | 行の `records` のキーの配列が、ファイルに無い |
| `alias_field_missing` | `metadata` に記載した列が、レコードに無い |
| `alias_unknown_type` | 行の `alias_type` が、9 つの種類に無い（`buildAliases` に直接渡した行だけ。`mdmark check` は `schema` のずれにする） |
| `alias_required_empty` | 種類の必須のキーが空。`env` は `url` と `port` が両方空のとき |
| `duplicate_alias_id` | エイリアスの `id` が、前のエイリアス（`env` を含む）と重なっている |
| `unknown_mark` | 文書の本文に、記法のマーカー・`features`・`libraries` の対応表・`extensions` の拡張のマーカー・`check.ignore` の名前のどれにも該当しないマーカーがある。場所はマーカーのある行の番号 |
| `missing_file` | 文書が相対パスで指す画像（動画の `poster` を含む）・動画・音声・添付のカードにするファイルが、文書のフォルダにもアセットのルートにも無い。場所は記載した行の番号。内容は記載したパスと種類（画像・動画・音声・添付）と修正方法。コードブロックと行内のコードの中・絶対 URL・`#` で始まるリンクは点検しない |
| `include_target_missing` | include のマーカーが指すファイル・見出し・行の範囲が無いか、設定ファイルのフォルダ（無ければ文書のフォルダ）の外を指す。場所はマーカーの行の番号。内容は取り込み先と、無いもの（行の範囲はファイルの行の数も）と修正方法 |
| `include_circular` | include の取り込みが循環する。場所はマーカーの行の番号。内容は循環の順（`a.md → b.md → a.md`）と修正方法 |
| `diagram_invalid` | `chart`・`param`・`er` のマーカーの中の `json` のコードブロックの部品の定義を読み込めないか、部品の構造に合わない。内容は描いたときに出す記載の警告と同じ文 |
| `retired_diagram` | 文書に、廃止した `flow`・`sequence` の範囲がある（同じ名前の拡張を `extensions` に記載しているときは出ない）。場所は範囲の開きのマーカーの行。内容は map の範囲で記載することと、`mdmark upgrade` で書き換えられること |
| `syntax_warning` | `--text`・`--file` で指定した Markdown を描いたときに出る記載の警告のうち、`unknown_mark`・`diagram_invalid`・`retired_diagram` に該当しないもの。include の取り込み先が無い警告は、取り込み先を読み込まないため出さない（取り込み先は設定の文書の点検の `include_target_missing`・`include_circular` で確認する）。内容は記載の警告の文と同じ。場所は警告の元のマーカーの行 |
| `unknown_mark_arg` | 設定の文書と `--text`・`--file` で指定した Markdown の記法のマーカーに、描くときに警告を出さずに無視する知らないキーがある。1 つにつき 1 件で、内容は無視したキー・その場所で使用できるキー・修正方法。場所はマーカーの行 |
| `legacy_mark` | 記法・拡張・`libraries` のマーカーの引数が、JSON でない前の書き方（`キー=値`・`+機能` など）。内容は JSON での記載方法と、`mdmark upgrade` で書き換えられるか。場所はマーカーの行 |
| `mark_option_invalid` | マーカーの引数を JSON のオブジェクトとして読めないか、値の型・選べる値・必須のキーが合わない。内容は描いたときに出す記載の警告と同じ文。場所はマーカーの行 |
| `mark_option_unapplied` | マーカーに記載した設定が当たらない（`{"enabled": false}` にした機能の列の設定、`column` と `value` の片方だけの `rows.colors` の要素など）。場所はマーカーの行 |
| `map_invalid` | map の範囲の Mermaid に読めない行・閉じの無い `subgraph` かブロックがあるか、範囲の中の mermaid のブロックが 0 か 2 つ以上・補足が 2 つ以上・描けない図の種類（`flowchart`・`sequenceDiagram` 以外）。場所は Mermaid の行（範囲の全体なら範囲の開きのマーカーの行） |
| `map_unknown_ref` | map の補足（`notes`・`walkthroughs`・`layout`・`plays_over`）が、Mermaid に無いノード・線・グループの ID を指している |
| `map_unknown_key` | map の補足か、マーカーの JSON のオブジェクトに知らないキーがある。内容に使用できるキーの一覧を含む。マーカーの知らないキーは、描くときは警告を出さずに無視する |
| `map_invalid_value` | map の補足の値がスキーマに合わないか `--` を含む、またはマーカーの引数が JSON のオブジェクトとして読めないか、値の型が合わない |
| `map_unknown_icon` | 設定の `map.kinds` の `icon` が Lucide に無い名前。場所はキーのパス（`map.kinds.store.icon`） |
| `map_unknown_class` | map の範囲のノードのクラスが、設定の `map.kinds` に無い |
| `map_unknown_line` | map の補足の `layout` の `line` の名前が、設定の `map.lines` に無い |
| `plain_md_with_marks` | 拡張子が `.md` で `.mark.md` でない文書が、mdmark のマーカー（記法・`features`・`libraries` の対応表・`extensions` の拡張のマーカー。`check.ignore` の名前を除く）を含む。1 文書に 1 件で、場所は最初のマーカーの行。内容は改名先のファイル名と、設定の `check.suggestMarkExtension` で提案を止められること。設定の `check.suggestMarkExtension` が `false` のときと、`--text`・`--file` のときは出さない |

<!-- /table -->

`missing_doc` から `avoided_term` までは、`checkIndex` が返却する `kind` と同じ（[点検が返却するずれ](./索引.md#点検が返却するずれ)）。
`duplicate_alias_row_id` から `duplicate_alias_id` までは、`buildAliases` が返却する `kind` と同じ（[エイリアスを作る](./API.md#エイリアスを作る)）。
`diagram_invalid` の場所は図の開くマーカーの行の番号。
図の点検はブラウザを使用しない。埋め込んだ HTML の custom element は点検しない。
`missed_change_together` は、`--base` を指定したときだけ出る。
エイリアスのずれは、設定に `aliases` があるときだけ出る。`enabled` が `false` の行は読み込まない。`env` のレコードも種類と必須のキーを確認し、ずれがあれば出す。

### 使用方法

```bash
npx github:shuhei1101/mdmark#v{バージョン} check [--config {設定ファイル}] [--base {git の ref} | --text {Markdown} | --file {ファイル} --key {YAML のキー}]
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `--config` | 任意 | 使用する設定ファイルのパス。指定するとこのファイルと端末の設定だけを重ねる。省くと今のフォルダから上のフォルダへ `mdmark.config.yaml` を探して重ね、重ねた設定ファイルと端末の設定のそれぞれの構造を点検する | `--config docs/mdmark.config.yaml` |
| `--base` | 任意 | 修正漏れの検査に比べる基準の git の ref。指定すると、基準と HEAD の merge-base から作業ツリーまでに変わった文書を比べ、`change_together` の組のうち片方だけが変わった組を `missed_change_together` で出す。省くと修正漏れを検査しない。設定に `index` が無いときは使用しない | `--base origin/develop` |
| `--text` | 任意 | 点検する Markdown の文字列。`-` を指定すると標準入力から読み込む。指定すると設定と索引を点検せず、描いたときの記載の警告・描くときに無視するマーカーの知らない引数・知らないマーカー・図の配置のずれだけを、ファイル `-`・文字列の行で出す。設定ファイルが無ければ既定の設定で点検する。`--base`・`--file`・`--key` と一緒に指定できない | `--text -` |
| `--file` | 任意 | Markdown をキーの値に持つ YAML のファイル。`--key` と一緒に指定し、そのキーの値を `--text` と同じく点検する。場所は YAML のファイルの行（ブロックスカラーは値の中の行をファイルの行に置き換え、それ以外の値はキーの行） | `--file records.yaml` |
| `--key` | `--file` と一緒に必須 | `--file` の YAML の中の、点検する文字列の値のキー。`.` でキーを、`[位置]` で配列の要素をたどる | `--key items[0].body` |

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | ずれが 0 件 |
| `1` | ずれが 1 件以上ある。全てのずれを出してから終わる |
| `1` | `--config` のファイルが無い、または今のフォルダと上のフォルダに `mdmark.config.yaml` が無い（`--text`・`--file` を指定し、`--config` を指定しないときを除く）。標準エラーに、探した場所と `mdmark init` で配置できることを出す |
| `1` | 一緒に指定できない引数を指定した、`--file` と `--key` の片方だけを指定した、`--file` のファイルが無いか YAML として読み込めない、`--key` のキーが無いか値が文字列でない。標準エラーに原因と修正方法を出し、点検はしない |
| `1` | 設定ファイルを YAML として読み込めない。標準エラーに、ファイルと読み込めない行と修正方法を出す |
| `1` | `--base` を指定し、git が無い・設定ファイルのフォルダが git のリポジトリの中に無い・ref と HEAD の merge-base を参照できない。標準エラーに、指定した ref と参照できない理由と、ref を修正するか履歴を取得する修正方法（CI の checkout の `fetch-depth`）を出す。ずれの点検はしない |

## バージョンを上げる

設定の手元のバージョンから、呼んだ CLI のバージョン（目標のバージョン）までの移行の手順を、設定・索引・文書へバージョンの順に適用する。
適用した範囲の変更履歴の行を出す。
手順は [バージョンを上げる](./導入-バージョンを上げる.md)。仕組みは [バージョンを上げる仕組み](./コアコンセプト-バージョンを上げる仕組み.md)。

手元のバージョンより新しく目標のバージョン以下のバージョンの手順を適用する前に、設定ファイルと、手順が書き換えうる全てのファイルのコピーを、設定ファイルのあるフォルダの `.mdmark/backup/{yyyymmddHHMMSS}/` へ、そのフォルダからの相対パスを保って取る。
`.mdmark/` は中身が `*` の `.gitignore` を持ち、コピーは適用した後も削除しない。
全ての手順を適用した後に `mdmark check` と同じ点検を実行し、ずれが 0 件のときだけ設定の `version` を目標のバージョンに書き換える（無ければ最上位の先頭に追加する）。
手順の失敗と点検のずれは、コピーから戻して `version` を変えない。

標準出力に、`手元のバージョン: {バージョン}`・`目標のバージョン: {バージョン}` の後、適用するバージョンごとに `{バージョン}:` の行と手順 1 つ 1 行（`  {種類}: {説明}`。壊す手順は種類の後ろに `（壊す手順）`）、`変更履歴:` の行と変更履歴の行 1 つ 1 行（`  {バージョン} {PR} {変更}`）を出す。
最後に、適用したときは `コピー: {パス}` と `バージョンを {目標のバージョン} にしました`、`--plan` のときは `--plan のため書き換えていません`、適用する手順が無いときは `手元のバージョンが目標のバージョンと同じです。適用する手順はありません` を出す。
コピーのパスは設定ファイルのあるフォルダからの相対パス。
手順を持たないバージョンは行を出さない。

```text
手元のバージョン: v0.3.0
目標のバージョン: v0.5.0
v0.4.0:
  rename_key: `build.out` を `build.output` に改める
v0.5.0:
  replace_mark（壊す手順）: マーカー `<!-- note -->` を `<!-- callout -->` に書き換える
変更履歴:
  v0.4.0 #40 バージョンを上げるときに移行の手順を適用する mdmark upgrade を作る
  v0.5.0 #45 注意書きのマーカーの名前を統一する
コピー: .mdmark/backup/20261017120000
バージョンを v0.5.0 にしました
```

### 使用方法

```bash
npx github:shuhei1101/mdmark#v{目標のバージョン} upgrade [--plan] [--yes] [--config {設定ファイル} | --settings]
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `--plan` | 任意 | 何も書き換えず、適用するバージョンごとの手順・変更履歴の行・壊す手順の有無を出す。コピーは取らない | `--plan` |
| `--yes` | 任意 | 壊す手順を、確認せずに適用する。手元のバージョンと、値を聞く手順の質問は飛ばさない | `--yes` |
| `--config` | 任意 | 書き換える設定ファイルのパス。省くと今のフォルダから上のフォルダへ順に `mdmark.config.yaml` を探し、最初に見つかったものを使用する。上のフォルダの設定と端末の設定は書き換えない | `--config docs/mdmark.config.yaml` |
| `--settings` | 任意 | 端末の設定（`MDMARK_CONFIG`、無ければ `${XDG_CONFIG_HOME:-~/.config}/mdmark/settings.yaml`）を書き換える。設定ファイルの手順だけを当て、索引と文書の手順は飛ばす。`--config` と一緒には指定できない | `--settings` |

目標のバージョンは引数で受けず、呼んだ CLI のバージョンにする。
手元のバージョンは設定の `version` で、無ければ標準エラーに `手元のバージョン（v{MAJOR}.{MINOR}.{PATCH}）を入れてください:` を出して聞く（`--plan` のときも聞く）。

### 標準入力

質問への回答を、質問 1 つにつき 1 行で読み込む。
質問は次の順に出し、全て書き換えの前に聞く。

1. 手元のバージョン（設定に `version` が無いとき）
2. 値を聞く手順の質問（適用する順。追加するキーが設定・索引に既にあるときは聞かない）
3. 壊す手順の確認（`--yes` が無く、壊す手順が 1 つ以上あるとき 1 回だけ）。承諾は `y` だけ

`--plan` は手元のバージョンだけを聞く。

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | 手順を適用して点検が通り、`version` を書き換えた。`--plan` で示した。手元のバージョンが目標のバージョンと同じで適用する手順が無い |
| `1` | 壊す手順の確認に `y` 以外を回答した。何も書き換えず、コピーも取らない。標準エラーに、`--yes` で確認せずに適用できることを出す |
| `1` | 手順の途中で、`call` のスクリプトが 0 以外で終わったか、ファイルを書き込めなかった。コピーから戻し、標準エラーに失敗したバージョン・手順の説明・理由を出す |
| `1` | 適用した後の点検にずれが 1 件以上ある。コピーから戻し、標準エラーに `mdmark check` と同じ構造のずれの行を出す |
| `1` | 手元のバージョンが目標のバージョンより新しい。標準エラーに、手元のバージョン・目標のバージョンと、`npx github:shuhei1101/mdmark#{手元のバージョン} upgrade` など手元のバージョン以上の CLI でもう一度呼ぶことを出す。何も書き換えない |
| `1` | 設定の `version` か質問への回答が `v{MAJOR}.{MINOR}.{PATCH}` に合わない。標準エラーに書式を出す |
| `1` | 質問に回答する前に標準入力が終わった。標準エラーに回答する質問を出し、何も書き換えない |
| `1` | 適用するバージョンの `steps.yaml` が読み込めない・構造に合わない、または `call` のスクリプトが無い。標準エラーにバージョンと合わないところと、mdmark をもう一度入れることを出す。何も書き換えない |
| `1` | `--config` のファイルが無い、今のフォルダと上のフォルダに `mdmark.config.yaml` が無い、または YAML として読み込めない。`mdmark check` と同じ文を標準エラーに出す |
| `1` | `--config` と `--settings` を一緒に指定した |

## MCP サーバーを起動する

Claude Code のプラグインがつなぐ MCP の常駐サーバーを、127.0.0.1 の Streamable HTTP で起動する。
手順は [MCPサーバーを起動する](./ClaudeCodeで使用する-MCPサーバーを起動する.md)。ツールは [MCP](./MCP.md)。

`127.0.0.1` の `/mcp` だけを待ち受ける。
待ち受けたら、接続先の URL を標準出力に 1 行出し、止める合図を受けるまで動き続ける。
`Ctrl+C`（SIGINT）か SIGTERM を受けると待ち受けを閉じる。

```text
MCP サーバーを起動しました: http://127.0.0.1:8782/mcp
```

### 使用方法

```bash
npx github:shuhei1101/mdmark#v{バージョン} serve
```

### 引数

引数は無い。
待ち受けるポートは環境変数 `MDMARK_PORT` で決め、無ければ 8782 にする（[設定](./設定.md#mcp-サーバーのポート)）。

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | `Ctrl+C`（SIGINT）か SIGTERM を受けて、待ち受けを閉じた |
| `1` | ポートを別のプロセスが使用している。標準エラーに、ポートの番号と、`~/.claude/settings.json` の `env` と `serve` を起動する環境の両方に同じ `MDMARK_PORT` を設定すれば別のポートで動かせること、`serve` が既に起動しているならそのまま使用できることを出す |
| `1` | `MDMARK_PORT` が 1〜65535 の整数でない。標準エラーに、受け取った値と、1〜65535 の整数を設定することを出す |
