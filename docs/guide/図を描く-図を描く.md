# 図を描く

HTML の用途と、文書に部品の定義を記載してグラフ・操作できる部品・ER 図を描く手順

文書に数値の変化・テーブルの関係を図で入れるときに実行する。構成図・処理の順番・時刻の流れは [Mermaidと補足で図を描く](./図を描く-Mermaidと補足で図を描く.md) の map で描く。

## 前提

- [文書を描く](./導入-文書を描く.md)
- 設定の `features.diagrams` がオン（既定）。オフにする手順は [機能をオン・オフする](./カスタマイズ-機能をオン・オフする.md)

## 手順

### HTML を使用するか決める

#### 図とチャートだけ HTML にする

文章・表・手順・リストは Markdown で記載する。
HTML は、図・チャートなど外観のあるものを描くときだけ使用する。
構成図とシーケンス図は map、グラフ・ER 図・操作できる部品は部品の定義で記載し、HTML を書き込まない。
部品で描けない外観だけ HTML で記載する。記載方法は [HTML の記載方法](./HTMLの記載方法.md)。
HTML を文書に描かせる手順と、HTML の中にチャートを配置する手順は [コードブロックのHTMLを描く](./図を描く-コードブロックのHTMLを描く.md)。

文書に記載した `<script>` は動かない。
動きは部品が持つ。

### 構成図とシーケンス図は map で記載する

#### Mermaid で記載して自動で配置させる

構成図とシーケンス図は、[map](./記法.md#map) のマーカーで Mermaid のブロックを囲んで記載する。
mdmark が入れ子のグループを自動で配置し、mdmark の無い表示でも Mermaid の図として読める。
座標で記載していた `flow`・`sequence` の範囲は廃止した。描かずに記載の警告を出すため、`mdmark upgrade` で map の範囲へ書き換える（[バージョンを上げる](./導入-バージョンを上げる.md)）。
ノードの名前に `※1` を付けて図の下の表に注意書きを並べる代わりに、[注記](./記法.md#注記) を定義し、補足の `notes` の `annotations` で参照する（[Mermaidと補足で図を描く](./図を描く-Mermaidと補足で図を描く.md)）。

### 部品の定義を記載する

#### マーカーで囲んで `json` のコードブロックを 1 つ配置する

````markdown
<!-- er -->

```json
{
  "title": "問い合わせのデータ",
  "scope": "問い合わせの DB",
  "updated": "2026-10-18",
  "width": 320,
  "tables": [
    { "id": "inquiries", "name": "inquiries", "label": "問い合わせ", "x": 24, "y": 24, "w": 240, "columns": [{ "name": "id", "type": "bigint", "pk": true }] }
  ],
  "relations": []
}
```

<!-- /er -->
````

マーカーは `chart`（グラフ）・`param`（[操作できる部品](./図を描く-操作できる部品を作る.md)）・`er`（ER 図）。
範囲に配置する `json` のコードブロックは 1 つだけ。
範囲のコードブロック以外の Markdown と定義の JSON は、描いた文書に残らない。

#### タイトルと更新日を記載する

どの定義も `title`（タイトル）・`scope`（範囲）・`updated`（更新日。`YYYY-MM-DD`）を持つ。
図の上にタイトル・範囲・更新日が出る。
凡例は記載しない。グラフは系列から、ER 図はテーブルの種類・列のマーカー・多重度から作られる。記載する項目が無い図は凡例を出さない。

### グラフを記載する

#### 軸と系列を記載する

````markdown
<!-- chart -->

```json
{
  "title": "返信までの時間",
  "scope": "10 月の第 2 週",
  "updated": "2026-10-18",
  "x": { "label": "曜日", "ticks": ["月", "火", "水", "木", "金"] },
  "y": { "label": "分", "min": 0, "max": 60, "step": 15 },
  "series": [
    { "name": "自動返信", "points": [12, 9, 14, 8, 10] },
    { "name": "担当者", "points": [42, 38, 51, 35, 44] }
  ]
}
```

<!-- /chart -->
````

系列は 1〜6 つ。
`points` の数は `x.ticks` の数と同じにする。
系列は色と線の模様と点の形状状と塗りの模様の組で分かれ、ライトとダークのどちらでも色だけで見分けなくてよい。

#### グラフの種類を選ぶ

`type` で種類を選ぶ。省くと折れ線（`line`）になる。

| `type` | 描くもの | 系列の記載方法 |
| --- | --- | --- |
| `line` | 折れ線 | `x.ticks` と `series` |
| `area` | 面。折れ線の下を系列の塗りで塗る | `x.ticks` と `series` |
| `bar` | 棒。系列を色と塗りの模様の組で分ける | `x.ticks` と `series` |
| `stacked-bar` | 積み上げの棒。棒の上に合計を出す。負の値は 0 から下へ追加する | `x.ticks` と `series` |
| `stacked-area` | 積み上げの面 | `x.ticks` と `series` |
| `horizontal-bar` | 横棒。項目を縦に並べ、値を横の長さにする | `x.ticks`（縦に並ぶ項目）と `series` |
| `pie` | 円。扇形の外に割合（整数の %）、凡例に項目の名前と値を出す | `series` と `x`・`y` の代わりに `items`（`name`・`value`）を 1〜6 つ。凡例の値の単位は `unit` |
| `donut` | ドーナツ。円の中を空け、中央に合計と `合計{unit}` を出す | `pie` と同じ |
| `radar` | レーダー。`x.ticks` の軸を放射状に並べ、系列を多角形にする | `x.ticks`（軸の名前）と `series` |
| `scatter` | 散布図。系列を色と点の形状状の組で分ける | `points` を `[x, y]` の組にする。`x` は数値の軸で `ticks` を記載しない |
| `bubble` | バブル。3 つ目の値を円の面積にし、凡例に `円の面積: {size.label}` を出す | `points` を `[x, y, size]` の組にし、`size`（`label`）を記載する。`x` は数値の軸で `ticks` を記載しない |
| `combo` | 折れ線と棒の組み合わせ。右の縦の軸を持つと、凡例の系列の名前に `（左の軸）`・`（右の軸）` を添える | `x.ticks` と `series`。系列ごとに `as`（`line`・`bar`。省くと `line`）と `axis`（`y`・`y2`。省くと `y`）を記載し、`y2` に右の縦の軸を記載する |

系列か項目を 7 つ以上書くと、その図の場所に記載の警告を出す。

縦の軸の `min`・`max`・`step` は 3 つとも記載するか、3 つとも省く。
省くと、データの最小と最大を含む 1・2・5×10 のべき乗の刻みで切る。

### ER 図を記載する

#### テーブルと関係を記載する

````markdown
<!-- er -->

```json
{
  "title": "注文のデータ",
  "scope": "注文の DB",
  "updated": "2026-10-31",
  "width": 640,
  "tables": [
    {
      "id": "customers", "name": "customers", "label": "顧客", "kind": "master", "desc": "注文する人",
      "x": 24, "y": 24, "w": 230,
      "columns": [
        { "name": "id", "type": "bigint", "pk": true, "nn": true },
        { "name": "email", "type": "varchar(255)", "nn": true, "desc": "ログインに使用する" }
      ]
    },
    {
      "id": "orders", "name": "orders", "label": "注文", "kind": "transaction",
      "x": 344, "y": 24, "w": 250,
      "columns": [
        { "name": "id", "type": "bigint", "pk": true, "nn": true },
        { "name": "customer_id", "type": "bigint", "fk": true, "nn": true },
        { "name": "note", "type": "text" }
      ]
    }
  ],
  "relations": [
    { "from": "customers", "fromColumn": "id", "fromCard": "1", "to": "orders", "toColumn": "customer_id", "toCard": "0..n", "label": "注文する" }
  ]
}
```

<!-- /er -->
````

テーブルは定義の座標（`x`・`y`・`w`）に配置し、自動では並べない。
見出しに物理名（`name`）と論理名（`label`）、列の行に `PK`・`FK`・`NN` のマーカーと名前と型が出る。
`kind` は `master`（マスター。既定の色は青）か `transaction`（トランザクション。既定の色はオレンジ）で、見出しに種類の札が出る。
`color` に [色の名前](./記法.md#色の名前) を記載すると、種類の既定の色より優先する。

関係は、元の列（`from`・`fromColumn`）の行から先の列（`to`・`toColumn`）の行へ、横・縦・横の線で結ぶ。
縦の線の位置は `midX` で決め、省くと両端の中間になる。
両端の多重度（`fromCard`・`toCard`）は `1`・`0..1`・`1..n`・`0..n` で、記号が線の端に出る。

列の多いテーブルに `"folded": true` を記載すると、主キーと外部キーの列だけを出した状態で開く。
関係が無いテーブルや列を指す、テーブルの `id` か同じテーブルの列の名前が重なる、`kind`・`color`・多重度に使用できない値を記載すると、その図の場所に記載の警告を出す。

### 読者ができること

図は全体が収まる倍率で開く。
右上のボタンと、図にフォーカスしているときのキー `+`・`-`・`0` で拡大・縮小する。
縮小と拡大の間の倍率のボタン（`125%` の書式）か `0` で、開いたときの倍率と位置に戻る。
ドラッグ・矢印キー・移動のボタンで動かし、全画面のボタンでモーダルに開く。
タッチの端末では、図の余白をタップするまでは指の横のドラッグで図を動かし、縦のドラッグは文書のスクロールになる。
余白をタップすると枠線がリンクの色の太い線になり、図の外をタップするまで、指で縦にも横にも図を動かせる。
右下のリサイズハンドルのドラッグか `↑`・`↓` で表示する枠の高さを変え、ダブルクリックで元の高さに戻す。
ホイールは文書のスクロールに使用する（Shift を押しながらで横）。
文字の上では文字を選べる。

グラフの点・棒・扇形と、ER 図のテーブルの説明のボタンは、ポインターを乗せるかフォーカスするとツールチップが出る。
ツールチップは持ち主の下に出る（設定の `tooltips.diagramPlacement` で上にできる）。
Esc で閉じ、ツールチップの上に乗っても閉じない。
タッチの端末では、タップで開き、ツールチップと持ち主の外のタップか、同じ持ち主のもう一度のタップで閉じる。
ER 図は、テーブルか列に `desc` を記載したテーブルの見出しの説明のボタンで、論理名と物理名・概要・列の説明が出る。
主キーでも外部キーでもない列を持つテーブルは、見出しの開閉のボタンでその列を畳む・開く。印刷では全ての列を出す。
ツールチップを出したくないときは、設定の `features.hints` をオフにする（[機能をオン・オフする](./カスタマイズ-機能をオン・オフする.md)）。

## 反映

即時。`mount` と `update` で描くたびに、文書の定義から図を再描画する。

## 確認

#### 図が描かれている

```js
[...document.querySelectorAll(".mdmark figure.mdmark-diagram")].map((f) => f.dataset.diagram)
```

記載した順に `chart`・`er` が出る。
タイトル・範囲・更新日と凡例が図に付いている。

#### 定義の JSON が出ていない

文書に定義の JSON の文字（`"series"` など）が出ていない。

#### 外観と操作を確認する

[描いた図を確認する](./図を描く-描いた図を確認する.md) の手順で、操作を経由し、スクリーンショットを撮って確認する。

#### 定義を読み込めないとき

定義の閉じの `}` を削除して描く。
その図の場所にタイトル `記載の警告` の枠が出て、`グラフの部品の定義を JSON として読み込めません（` で始まる本文に、読み込めなかった行と足りない記号が記載される。
ほかの図と本文は描かれる。

定義の構造が合わないときも、その図だけが警告になる。
本文に読み込めない箇所と修正の仕方が記載される（`系列「担当者」の点が 4 つで、横の目盛り（x.ticks）の 5 つと合いません` など）。
ER 図の関係の端が無いテーブルか列を指す・テーブルの `id` が重なるのも、構造の誤りになる。

## 元に戻す

マーカーと定義を削除する。
図を描く機能ごと止めるときは、`features.diagrams` をオフにする。
オフにするとマーカーを取り除き、定義を JSON のコードブロックのまま描く。
