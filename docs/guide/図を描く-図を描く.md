# 図を描く

HTML の用途と、文書に部品の定義を記載してフロー図・シーケンス図・グラフ・ER 図を描く手順

文書に構成図・処理の順番・時刻の流れ・数値の変化を図で入れるときに実行する。

## 前提

- [文書を描く](./導入-文書を描く.md)
- 設定の `features.diagrams` がオン（既定）。オフにする手順は [機能をオン・オフする](./カスタマイズ-機能をオン・オフする.md)

## 手順

### HTML を使用するか決める

#### 図とチャートだけ HTML にする

文章・表・手順・リストは Markdown で記載する。
HTML は、図・チャートなど外観のあるものを描くときだけ使用する。
フロー図・シーケンス図・グラフ・ER 図・操作できる部品は、HTML を書き込まずに部品の定義を記載する。
部品で描けない外観だけ HTML で記載する。記載方法は [HTML の記載方法](./HTMLの記載方法.md)。
HTML を文書に描かせる手順と、HTML の中にチャートを配置する手順は [コードブロックのHTMLを描く](./図を描く-コードブロックのHTMLを描く.md)。

文書に記載した `<script>` は動かない。
動きは部品が持つ。

### 新しく構成図を記載するときは map を使用する

#### Mermaid で記載して自動で配置させる

新しく構成図とシーケンス図を記載するときは、座標を記載する部品の定義ではなく、[map](./記法.md#map) のマーカーで Mermaid のブロックを囲む。
mdmark が入れ子のグループを自動で配置し、mdmark の無い表示でも Mermaid の図として読める。
`flow`・`sequence` の部品の定義は、座標を決めて描きたい図と、今の文書のために残す。

### 部品の定義を記載する

#### マーカーで囲んで `json` のコードブロックを 1 つ配置する

````markdown
<!-- flow -->

```json
{
  "title": "問い合わせの受け取り",
  "scope": "受け取りから分類まで",
  "updated": "2026-10-18",
  "width": 520,
  "height": 160,
  "nodes": [
    { "id": "recv", "kind": "script", "x": 20, "y": 48, "w": 140, "h": 64, "name": "受け取り", "sub": "1 通ずつ読み込む" },
    {
      "id": "classify", "kind": "dm", "x": 300, "y": 48, "w": 140, "h": 64, "name": "分類", "sub": "返信の種類を選ぶ",
      "io": { "in": "問い合わせの本文", "do": "返信の種類から 1 つ選ぶ", "out": "返信の種類" }
    }
  ],
  "wires": [
    { "id": "w-body", "from": "recv", "to": "classify", "line": "flow", "points": [[160, 80], [300, 80]], "label": "本文", "labelAt": [230, 80], "tip": "件名を除いた本文" }
  ]
}
```

<!-- /flow -->
````

マーカーは `flow`（フロー図）・`sequence`（シーケンス図）・`chart`（グラフ）・`param`（[操作できる部品](./図を描く-操作できる部品を作る.md)）・`er`（ER 図）。
範囲に配置する `json` のコードブロックは 1 つだけ。
範囲のコードブロック以外の Markdown と定義の JSON は、描いた文書に残らない。

#### タイトルと更新日を記載する

どの定義も `title`（タイトル）・`scope`（範囲）・`updated`（更新日。`YYYY-MM-DD`）を持つ。
図の上にタイトル・範囲・更新日が出る。
凡例は記載しない。フロー図とシーケンス図は、図に 2 種類以上あるノードの種類と線の種類から作られ、グラフは系列から作られる。記載する項目が無い図は凡例を出さない。

### フロー図を記載する

#### ノードを記載する

`nodes` の 1 つがノード 1 つ。

<!-- table: {"kind": "data"} -->

| 項目 | 説明 |
| --- | --- |
| `id` | 線の端に指す名前。図の中で重ねない |
| `kind` | ノードの種類。下の表から選ぶ |
| `x`・`y`・`w`・`h` | ノードの左上の位置と大きさ。図の中の px |
| `name` | ノードの名前 |
| `tag`・`sub` | 名前の上の札と、名前の下の補足。省ける |
| `io` | `in`（入力）・`do`（処理）・`out`（出力）。ツールチップに出す。LLM・意思決定モデル・スクリプトなど、入力と出力を説明したいノードに付ける |
| `hint` | ノードの説明の文。ツールチップに出す。`io` と一緒に記載すると、入力・処理・出力の後に出る。省ける |
| `href` | ノードのリンク先。`http`・`https`・`mailto` の URL か相対パス。省ける |

<!-- /table -->

<!-- table: {"kind": "data"} -->

| `kind` | 表すもの |
| --- | --- |
| `llm` | LLM |
| `dm` | 意思決定モデル |
| `script` | スクリプト |
| `mcp` | MCP |
| `data` | データ |
| `external` | 外部のシステム |
| `start` | 判定フローチャートの開始（円） |
| `question` | 判定フローチャートの質問（菱形） |
| `action` | 判定フローチャートのアクション（角の丸くない四角） |
| `result` | 判定フローチャートの結果（両端の丸い形状） |

<!-- /table -->

`tag`・`name`・`sub` の `{{単語}}` は、索引か用語集の表にある用語なら、本文の用語と同じ破線の下線とツールチップになる。
記載方法は [索引と用語集を記載する](./記載する-索引と用語集を記載する.md)。

#### 線を記載する

`wires` の 1 つが線 1 本。

<!-- table: {"kind": "data"} -->

| 項目 | 説明 |
| --- | --- |
| `id` | 線の名前。図の中で重ねない |
| `from`・`to` | 端のノードの `id`。矢じりは `to` の側に付く |
| `line` | 線の種類。`flow`（処理の流れ）・`read`（読み込む）・`write`（書き込む）・`reply`（返却する）・`loop`（戻る） |
| `points` | 線が通る点。縦と横だけの折れ線で、ノードの縁から縁へ参照する |
| `label`・`labelAt` | 線に記載する入力の要約と、その位置。省ける |
| `tip` | 入力の詳細。ツールチップに出す。省ける |

<!-- /table -->

横の線が縦の線と交わる点は、mdmark が横の線に飛び越えの弧を入れる。
同じ向きで重なる線はずらす。
`x`・`y`・`points` は自分で配置する。
判定フローチャートだけは、座標を全て省いて mdmark に配置させられる（[座標を省いて判定フローチャートを記載する](#座標を省いて判定フローチャートを記載する)）。

#### システムの枠とレイヤーを記載する

内側のシステムを大きな枠で囲むときは `frame`（`title`・`x`・`y`・`w`・`h`）を記載する。
枠の内側を上から LLM・処理・データの 3 レイヤーに分けるときは `lanes`（`label`・`kind`・`y`・`h`）を記載する。
`frame` と `lanes` の要素に `hint` を記載すると、タイトルの右にマーカーが付き、説明の文がツールチップに出る。
拡大して動かしている間、見えている枠とレイヤーのタイトルは表示する枠の上端に留まる。留めたくない図は、定義に `"stickyTitles": false` を記載する。
`kind` は `llm`・`mcp`・`data` で、レイヤーのノードの色がうっすら背景に敷かれる。
外部のシステムのノードは枠の外に配置する。
決まりは [構成図の決まり](./構成図の決まり.md)。

#### 判定フローチャートを記載する

質問の YES / NO で結果を決める図は、ノードの `kind` を `start`・`question`・`action`・`result` にし、`frame`・`lanes` を記載しない。
凡例の種類は、図に出る開始・質問・アクション・結果だけになる。

````markdown
<!-- flow -->

```json
{
  "title": "外観をどこで変えるかの判定",
  "scope": "描いた文書の外観を変えたいとき",
  "updated": "2026-11-02",
  "width": 760,
  "height": 600,
  "nodes": [
    { "id": "start", "kind": "start", "x": 310, "y": 16, "w": 100, "h": 100, "name": "外観を変える" },
    { "id": "q0", "kind": "question", "x": 220, "y": 156, "w": 280, "h": 136, "name": "全ての利用側の既定を変える外観か" },
    { "id": "q1", "kind": "question", "x": 220, "y": 340, "w": 280, "h": 136, "name": "テーマの CSS 変数で表せるか" },
    { "id": "a1", "kind": "action", "x": 560, "y": 188, "w": 180, "h": 72, "name": "既定の変更を Issue で頼む" },
    { "id": "r1", "kind": "result", "x": 250, "y": 524, "w": 220, "h": 60, "name": "CSS 変数を上書きする" },
    { "id": "r2", "kind": "result", "x": 560, "y": 378, "w": 180, "h": 60, "name": "層の外の CSS を追加する" }
  ],
  "wires": [
    { "id": "j-start", "from": "start", "to": "q0", "line": "flow", "points": [[360, 116], [360, 156]] },
    { "id": "j-q0-yes", "from": "q0", "to": "a1", "line": "flow", "points": [[500, 224], [560, 224]], "label": "YES", "labelAt": [530, 224] },
    { "id": "j-q0-no", "from": "q0", "to": "q1", "line": "flow", "points": [[360, 292], [360, 340]], "label": "NO", "labelAt": [360, 316] },
    { "id": "j-q1-yes", "from": "q1", "to": "r1", "line": "flow", "points": [[360, 476], [360, 524]], "label": "YES", "labelAt": [360, 500] },
    { "id": "j-q1-no", "from": "q1", "to": "r2", "line": "flow", "points": [[500, 408], [560, 408]], "label": "NO", "labelAt": [530, 408] }
  ]
}
```

<!-- /flow -->
````

開始の `w` と `h` は同じ値にして円にする。
名前は構造の中に収まるよう、質問は菱形の中央の四角に、開始は円の中の四角に折り返す。
決まりは [フローチャートの決まり](./フローチャートの決まり.md#判定フローチャート)。

#### 座標を省いて判定フローチャートを記載する

ノードの種類が全て `start`・`question`・`action`・`result` の図は、ノードの `x`・`y`・`w`・`h`、線の `points`・`labelAt`、図の `width`・`height` を全て省ける。
mdmark が、開始を一番上に、質問を左の列に上から下へ並べ、アクションと結果を右と下に配置する。

````markdown
<!-- flow -->

```json
{
  "title": "外観をどこで変えるかの判定",
  "scope": "描いた文書の外観を変えたいとき",
  "updated": "2026-11-05",
  "nodes": [
    { "id": "start", "kind": "start", "name": "外観を変える" },
    { "id": "q0", "kind": "question", "name": "全ての利用側の既定を変える外観か" },
    { "id": "q1", "kind": "question", "name": "テーマの CSS 変数で表せるか" },
    { "id": "a1", "kind": "action", "name": "既定の変更を Issue で頼む" },
    { "id": "r1", "kind": "result", "name": "CSS 変数を上書きする" },
    { "id": "r2", "kind": "result", "name": "層の外の CSS を追加する" }
  ],
  "wires": [
    { "id": "j-start", "from": "start", "to": "q0", "line": "flow" },
    { "id": "j-q0-yes", "from": "q0", "to": "a1", "line": "flow", "label": "YES" },
    { "id": "j-q0-no", "from": "q0", "to": "q1", "line": "flow", "label": "NO" },
    { "id": "j-q1-yes", "from": "q1", "to": "r1", "line": "flow", "label": "YES" },
    { "id": "j-q1-no", "from": "q1", "to": "r2", "line": "flow", "label": "NO" }
  ]
}
```

<!-- /flow -->
````

座標は、全て記載するか全て省く。
一部のノードにだけ座標を記載した定義と、判定フローチャート以外の種類のノードで座標を省いた定義は、記載の警告になり図を描かない。
配置の結果も `mdmark check` が重なり・はみ出し・線の横切り・ラベルの長さを点検する（[描いた図を確認する](./図を描く-描いた図を確認する.md)）。

#### ノードにリンク先を持たせる

ノードに `href` を記載すると、ノードの全体がリンクになり、名前が本文のリンクと同じ色と下線になる。
読者は、ノードを押すか、フォーカスして Enter を押してリンク先を開く。
図を動かすためにノードの上からドラッグしたときと、右上のマーカーでツールチップを開いたときは、リンク先を開かない。

```json
{ "id": "recv", "kind": "script", "x": 40, "y": 60, "w": 160, "h": 64, "name": "受け取る", "href": "https://example.com/spec" }
```

使用できるリンク先は、本文のリンクと同じ `http`・`https`・`mailto` の URL と相対パス。
まとめた HTML では、まとめた文書を指す相対パスで 1 枚の中のその文書へ移る。
`javascript:` や、`id:spec#items` のような URL でない参照は使用できず、そのノードはリンクにならずに記載の警告が出る。
文書の ID などで指したいときは、書き込む側で URL に変換してから定義に記載する。

### シーケンス図を記載する

#### 相手とメッセージを記載する

````markdown
<!-- sequence -->

```json
{
  "title": "問い合わせ 1 通の流れ",
  "scope": "受け取りから分類まで",
  "updated": "2026-10-18",
  "participants": [
    { "id": "mail", "kind": "external", "tag": "外部", "name": "メールサーバー" },
    { "id": "recv", "kind": "script", "name": "受け取り" },
    { "id": "classify", "kind": "dm", "name": "分類" }
  ],
  "steps": [
    { "from": "mail", "to": "recv", "label": "問い合わせのメール", "tip": "件名・本文・送信者のアドレス" },
    { "from": "recv", "to": "classify", "label": "本文" },
    { "from": "classify", "to": "recv", "label": "返信の種類", "reply": true }
  ],
  "loop": { "label": "1 へ戻る（次の問い合わせ）" }
}
```

<!-- /sequence -->
````

`participants` は左から右へ並べる順、`steps` は上から下へ時刻の順。
`reply` を `true` にしたメッセージは、破線と開いた矢じりの応答の線になる。
`loop` は最後のメッセージから最初へ戻る繰り返しで、右の帯を通る破線と戻り先のラベルになる。
`kind` はノードの種類と同じ。

### グラフを記載する

#### 軸と系列を記載する

````markdown
<!-- chart -->

```json
{
  "title": "返信までの時間",
  "scope": "10 月の第 2 週",
  "updated": "2026-10-18",
  "x": { "label": "曜日", "ticks": ["月", "火", "水", "木", "金"] },
  "y": { "label": "分", "min": 0, "max": 60, "step": 15 },
  "series": [
    { "name": "自動返信", "points": [12, 9, 14, 8, 10] },
    { "name": "担当者", "points": [42, 38, 51, 35, 44] }
  ]
}
```

<!-- /chart -->
````

系列は 1〜6 つ。
`points` の数は `x.ticks` の数と同じにする。
系列は色と線の模様と点の形状状と塗りの模様の組で分かれ、ライトとダークのどちらでも色だけで見分けなくてよい。

#### グラフの種類を選ぶ

`type` で種類を選ぶ。省くと折れ線（`line`）になる。

| `type` | 描くもの | 系列の記載方法 |
| --- | --- | --- |
| `line` | 折れ線 | `x.ticks` と `series` |
| `area` | 面。折れ線の下を系列の塗りで塗る | `x.ticks` と `series` |
| `bar` | 棒。系列を色と塗りの模様の組で分ける | `x.ticks` と `series` |
| `stacked-bar` | 積み上げの棒。棒の上に合計を出す。負の値は 0 から下へ追加する | `x.ticks` と `series` |
| `stacked-area` | 積み上げの面 | `x.ticks` と `series` |
| `horizontal-bar` | 横棒。項目を縦に並べ、値を横の長さにする | `x.ticks`（縦に並ぶ項目）と `series` |
| `pie` | 円。扇形の外に割合（整数の %）、凡例に項目の名前と値を出す | `series` と `x`・`y` の代わりに `items`（`name`・`value`）を 1〜6 つ。凡例の値の単位は `unit` |
| `donut` | ドーナツ。円の中を空け、中央に合計と `合計{unit}` を出す | `pie` と同じ |
| `radar` | レーダー。`x.ticks` の軸を放射状に並べ、系列を多角形にする | `x.ticks`（軸の名前）と `series` |
| `scatter` | 散布図。系列を色と点の形状状の組で分ける | `points` を `[x, y]` の組にする。`x` は数値の軸で `ticks` を記載しない |
| `bubble` | バブル。3 つ目の値を円の面積にし、凡例に `円の面積: {size.label}` を出す | `points` を `[x, y, size]` の組にし、`size`（`label`）を記載する。`x` は数値の軸で `ticks` を記載しない |
| `combo` | 折れ線と棒の組み合わせ。右の縦の軸を持つと、凡例の系列の名前に `（左の軸）`・`（右の軸）` を添える | `x.ticks` と `series`。系列ごとに `as`（`line`・`bar`。省くと `line`）と `axis`（`y`・`y2`。省くと `y`）を記載し、`y2` に右の縦の軸を記載する |

系列か項目を 7 つ以上書くと、その図の場所に記載の警告を出す。

縦の軸の `min`・`max`・`step` は 3 つとも記載するか、3 つとも省く。
省くと、データの最小と最大を含む 1・2・5×10 のべき乗の刻みで切る。

### ER 図を記載する

#### テーブルと関係を記載する

````markdown
<!-- er -->

```json
{
  "title": "注文のデータ",
  "scope": "注文の DB",
  "updated": "2026-10-31",
  "width": 640,
  "tables": [
    {
      "id": "customers", "name": "customers", "label": "顧客", "kind": "master", "desc": "注文する人",
      "x": 24, "y": 24, "w": 230,
      "columns": [
        { "name": "id", "type": "bigint", "pk": true, "nn": true },
        { "name": "email", "type": "varchar(255)", "nn": true, "desc": "ログインに使用する" }
      ]
    },
    {
      "id": "orders", "name": "orders", "label": "注文", "kind": "transaction",
      "x": 344, "y": 24, "w": 250,
      "columns": [
        { "name": "id", "type": "bigint", "pk": true, "nn": true },
        { "name": "customer_id", "type": "bigint", "fk": true, "nn": true },
        { "name": "note", "type": "text" }
      ]
    }
  ],
  "relations": [
    { "from": "customers", "fromColumn": "id", "fromCard": "1", "to": "orders", "toColumn": "customer_id", "toCard": "0..n", "label": "注文する" }
  ]
}
```

<!-- /er -->
````

テーブルは定義の座標（`x`・`y`・`w`）に配置し、自動では並べない。
見出しに物理名（`name`）と論理名（`label`）、列の行に `PK`・`FK`・`NN` のマーカーと名前と型が出る。
`kind` は `master`（マスター。既定の色は青）か `transaction`（トランザクション。既定の色はオレンジ）で、見出しに種類の札が出る。
`color` に [色の名前](./記法.md#色の名前) を記載すると、種類の既定の色より優先する。

関係は、元の列（`from`・`fromColumn`）の行から先の列（`to`・`toColumn`）の行へ、横・縦・横の線で結ぶ。
縦の線の位置は `midX` で決め、省くと両端の中間になる。
両端の多重度（`fromCard`・`toCard`）は `1`・`0..1`・`1..n`・`0..n` で、記号が線の端に出る。

列の多いテーブルに `"folded": true` を記載すると、主キーと外部キーの列だけを出した状態で開く。
関係が無いテーブルや列を指す、テーブルの `id` か同じテーブルの列の名前が重なる、`kind`・`color`・多重度に使用できない値を記載すると、その図の場所に記載の警告を出す。

### 読者ができること

図は全体が収まる倍率で開く。
右上のボタンと、図にフォーカスしているときのキー `+`・`-`・`0` で拡大・縮小する。
縮小と拡大の間の倍率のボタン（`125%` の書式）か `0` で、開いたときの倍率と位置に戻る。
ドラッグ・矢印キー・移動のボタンで動かし、全画面のボタンでモーダルに開く。
タッチの端末では、図の余白をタップするまでは指の横のドラッグで図を動かし、縦のドラッグは文書のスクロールになる。
余白をタップすると枠線がリンクの色の太い線になり、図の外をタップするまで、指で縦にも横にも図を動かせる。
右下のリサイズハンドルのドラッグか `↑`・`↓` で表示する枠の高さを変え、ダブルクリックで元の高さに戻す。
ホイールは文書のスクロールに使用する（Shift を押しながらで横）。
文字の上では文字を選べる。

矢印のラベル、`io` か `hint` を持つノードの右上のマーカー、`hint` を持つ枠とレイヤーのタイトルのマーカー、グラフの点・棒・扇形は、ポインターを乗せるかフォーカスするとツールチップが出る。
ツールチップは持ち主の下に出る（設定の `tooltips.diagramPlacement` で上にできる）。
ノードは右上のマーカーの上でだけ開き、ノードの上では開かない。ポインターの形状状は変わらない。
Esc で閉じ、ツールチップの上に乗っても閉じない。
タッチの端末では、タップで開き、ツールチップと持ち主の外のタップか、同じ持ち主のもう一度のタップで閉じる。
理解に必須のことはツールチップに入れず、ノードと線の要約だけで図が読み込めるようにする。
ER 図は、テーブルか列に `desc` を記載したテーブルの見出しの説明のボタンで、論理名と物理名・概要・列の説明が出る。
主キーでも外部キーでもない列を持つテーブルは、見出しの開閉のボタンでその列を畳む・開く。印刷では全ての列を出す。
ツールチップを出したくないときは、設定の `features.hints` をオフにする（[機能をオン・オフする](./カスタマイズ-機能をオン・オフする.md)）。

## 反映

即時。`mount` と `update` で描くたびに、文書の定義から図を再描画する。

## 確認

#### 図が描かれている

```js
[...document.querySelectorAll(".mdmark figure.mdmark-diagram")].map((f) => f.dataset.diagram)
```

記載した順に `flow`・`sequence`・`chart` が出る。
タイトル・範囲・更新日と凡例が図に付いている。

#### 定義の JSON が出ていない

文書に定義の JSON の文字（`"nodes"` など）が出ていない。

#### 外観と操作を確認する

[描いた図を確認する](./図を描く-描いた図を確認する.md) の手順で、操作を経由し、スクリーンショットを撮って確認する。

#### 定義を読み込めないとき

定義の閉じの `}` を削除して描く。
その図の場所にタイトル `記載の警告` の枠が出て、`フロー図の部品の定義を JSON として読み込めません（` で始まる本文に、読み込めなかった行と足りない記号が記載される。
ほかの図と本文は描かれる。

定義の構造が合わないときも、その図だけが警告になる。
本文に読み込めない箇所と修正の仕方が記載される（`ノード「分類」の種類 robot は使用できません。使用できる種類は llm・dm・script・mcp・data・external・start・question・action・result です` など）。
線の端が無いノードの `id` を指す・`id` が重なる・系列の点の数が目盛りの数と合わないのも、構造の誤りになる。

## 元に戻す

マーカーと定義を削除する。
図を描く機能ごと止めるときは、`features.diagrams` をオフにする。
オフにするとマーカーを取り除き、定義を JSON のコードブロックのまま描く。
