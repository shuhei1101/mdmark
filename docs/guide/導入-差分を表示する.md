# 差分を表示する

`mount` の `diffSource` に取り出し元を指定し、文書の 2 つのリビジョンの差分を出す

読者が文書の変更を、削除した行は赤・追加した行は緑・行の中で変わった文字は濃い色で読み込めるようにするときに実行する。
仕組みは [差分を表示する仕組み](./コアコンセプト-差分を表示する仕組み.md)。

## 前提

- [文書を描く](./導入-文書を描く.md)（`mount` で文書を描いている）
- 描く文書の索引の `id` を `docId` として指定できる
- 文書のリビジョンの一覧と、リビジョンごとの Markdown を返却できるサーバーかファイルがある

mdmark は Git や YAML の読み込み方を持たない。
リビジョンの一覧と本文を返却する取り出し元（`DiffSource`）を、利用側が記載する。

## 手順

### 取り出し元を指定する

#### 取り出し元を記載する

`revisions` と `content` の 2 つを持つオブジェクトを記載する。

```js
const diffSource = {
  async revisions(docId) {
    // 新しい順の { id, at, label?, author? } の配列を返却する
  },
  async content({ docId, revisionId }) {
    // そのリビジョンの Markdown の文字列を返却する
  },
};
```

| 関数 | 返却する値 |
| --- | --- |
| `revisions(docId)` | リビジョンの配列を、新しい順に返却する `Promise`。mdmark は並べ替えない |
| `content({ docId, revisionId })` | そのリビジョンの Markdown を返却する `Promise` |

リビジョンは次の項目を持つ。

| 項目 | 必須 / 任意 | 説明 |
| --- | --- | --- |
| `id` | 必須 | リビジョンの識別子。空にできず、一覧の中で重ならない |
| `at` | 必須 | ISO 8601 の日時の文字列 |
| `label` | 任意 | 一言の説明。リビジョンを選ぶ欄に出る |
| `author` | 任意 | 記載した人。リビジョンを選ぶ欄に出る |

取り出せないときは reject する。
構造は [API](./API.md#文書を描く) の `opts.diffSource`。

#### `mount` に指定する

```js
mount(document.querySelector("#doc"), { markdown, docId: "guide", diffSource });
```

`docId` は取り出し元の関数に渡る文書の識別子で、`diffSource` と一緒に指定する。
`docId` を指定しないと、`mount` は何も描かずに `TypeError` を投げる。
`diffSource` を指定しない `mount` は、差分の UI を付けずに今までどおり描く。

文書のタイトル（先頭の `h1`）の後ろに「変更表示」のボタンが付く。
押すと、タイトルを残して本文を隠し、一番新しいリビジョンとその 1 つ前の差分を出す。
前と後のリビジョンは、差分の上の 2 つの欄でもう一度選べる。
もう一度押すと、差分を片付けて本文に戻る。

### Git の取り出し元を記載する

コミットごとの文書のファイルを、リビジョンにする例。
ブラウザは Git を読み込めないため、利用側のサーバーが Git を呼んで返却する。

#### サーバーを記載する

```js
import { createServer } from "node:http";
import { execFile } from "node:child_process";
import { promisify } from "node:util";

const run = promisify(execFile);
const repo = "/path/to/repo";
// 文書の識別子から、リポジトリの中のファイルを参照する。表に無い識別子は受け付けない
const files = { guide: "docs/guide.md" };

createServer(async (req, res) => {
  const url = new URL(req.url, "http://localhost");
  const file = files[url.searchParams.get("doc")];
  if (!file) return res.writeHead(404).end();
  try {
    if (url.pathname === "/api/history") {
      const { stdout } = await run("git", ["log", "--format=%H%x1f%aI%x1f%an%x1f%s", "--", file], { cwd: repo });
      const revisions = stdout.split("\n").filter(Boolean).map((line) => {
        const [id, at, author, label] = line.split("\x1f");
        return { id, at, author, label };
      });
      return res.writeHead(200, { "content-type": "application/json" }).end(JSON.stringify(revisions));
    }
    if (url.pathname === "/api/file") {
      const rev = url.searchParams.get("rev");
      if (!/^[0-9a-f]{40,64}$/.test(rev)) return res.writeHead(400).end();
      const { stdout } = await run("git", ["show", `${rev}:${file}`], { cwd: repo, maxBuffer: 16 * 1024 * 1024 });
      return res.writeHead(200, { "content-type": "text/markdown; charset=utf-8" }).end(stdout);
    }
    res.writeHead(404).end();
  } catch (error) {
    console.error(error);
    res.writeHead(500).end();
  }
}).listen(8080);
```

`git log` は新しいコミットから返却するため、並べ替えずにそのまま指定できる。
コミットの ID を `id`、日時を `at`、件名を `label`、記載した人を `author` にする。

#### 取り出し元を記載する

```js
const gitSource = {
  async revisions(docId) {
    const res = await fetch(`/api/history?doc=${encodeURIComponent(docId)}`);
    if (!res.ok) throw new Error(`履歴を取り出せません (${res.status})`);
    return res.json();
  },
  async content({ docId, revisionId }) {
    const res = await fetch(`/api/file?doc=${encodeURIComponent(docId)}&rev=${revisionId}`);
    if (!res.ok) throw new Error(`本文を取り出せません (${res.status})`);
    return res.text();
  },
};
```

### YAML の取り出し元を記載する

Git の管理外の、項目ごとの変更履歴を YAML に持つ例。
文書の識別子ごとに、リビジョンを `content`（その時点の Markdown）つきで並べる。

#### 変更履歴を記載する

```yaml
guide:
  - id: r2
    at: "2026-10-20T11:05:00+09:00"
    author: 田中
    label: 見出しを書き換える
    content: |
      # ガイド

      変更を色分けして読み込む。
  - id: r1
    at: "2026-10-18T09:12:00+09:00"
    author: 佐藤
    label: 初版
    content: |
      # ガイド

      差分を色分けして読み込む。
```

#### 取り出し元を記載する

```js
import { parse } from "https://cdn.jsdelivr.net/npm/yaml@2.9.1/+esm";

async function history(docId) {
  const res = await fetch("/history.yaml");
  if (!res.ok) throw new Error(`変更履歴を取り出せません (${res.status})`);
  const items = parse(await res.text())[docId];
  if (!items) throw new Error(`${docId} の変更履歴がありません`);
  return items;
}

const yamlSource = {
  async revisions(docId) {
    return (await history(docId))
      .map(({ id, at, label, author }) => ({ id, at, label, author }))
      .sort((a, b) => Date.parse(b.at) - Date.parse(a.at));
  },
  async content({ docId, revisionId }) {
    const item = (await history(docId)).find((r) => r.id === revisionId);
    if (!item) throw new Error(`${revisionId} がありません`);
    return item.content;
  },
};
```

mdmark は一覧を並べ替えないため、日時の新しい順に並べて返却する。

### 差分の出し方を選ぶ

#### `diffMode` を指定する

```js
mount(document.querySelector("#doc"), { markdown, docId: "guide", diffSource, diffMode: "blocks" });
```

| `diffMode` | 出し方 |
| --- | --- |
| `button`（既定） | 読者が「変更表示」を押してから、差分の行を出す |
| `open` | 描いた時点で「変更表示」を押した状態にして、差分の行を出す。押さずに取り出し元が呼ばれ、もう一度押すと閉じる |
| `blocks` | 「変更表示」と差分の場所を配置せず、描いた文書のブロックを追加と削除の色で塗り分ける |

`open` は差分を最初から読み込ませたいとき、`blocks` は見出し・表・図の変更を描いた外観のまま読み込ませたいときに選ぶ。
`diffMode` は `diffSource` と一緒に指定する。
知らない値は `button` として描く。

#### `blocks` で色分けを出す

`blocks` は、`markdown` に指定した変更後の文書を描き、変更前と比べたブロックに色を適用する。
本文を描いた後に `revisions` を 1 回呼び、2 つ以上あれば 2 番目を前、1 番目を後として `content` を 1 回ずつ呼ぶ。

| 見え方 | 意味 |
| --- | --- |
| 追加の色の面と、左の余白の `+` | 追加・変更したブロック |
| 削除の色の面と、左の余白の `−` | 削除したブロック。変更前の文書での位置に出る |
| 色も余白の記号も無い | 変えていないブロック |

リビジョンが 1 つのとき、2 つの本文が同じとき、取り出し元を待つ間は、`markdown` を色を当てずに描いたままにする。
色は `--mdmark-color-diff-*` の CSS 変数で決まり、利用側が上書きできる（[テーマを上書きする](./カスタマイズ-テーマを上書きする.md)）。
ブロックの分け方と、書き換えと入れ替えの見分け方は [差分を表示する仕組み](./コアコンセプト-差分を表示する仕組み.md#描いた文書のブロックを色分けする)。

#### 対応するバージョンを確認する

`diffMode` を知らない古いバージョンの配布物は、指定を黙って無視する。
配布物が公開する `diffModes` で、描く前に対応を確認する。

```js
import * as mdmark from "https://cdn.jsdelivr.net/gh/shuhei1101/mdmark@{タグ}/dist/index.js";

if (!mdmark.diffModes?.includes("blocks")) {
  // blocks に対応しないバージョン。利用側が理由を出す
}
```

構造は [API](./API.md#差分の出し方を読み込む) の `diffModes`。

### 比較元の Markdown で色分けする

リビジョンの一覧を持たず、比べる前の Markdown を手元に持っているときは、`diffSource` の代わりに `baseMarkdown` を指定する。
`baseMarkdown` を前、`markdown` を後として、`blocks` と同じ色で本文のブロックを塗り分ける。
`docId` と `diffSource` は要らない。

```js
const handle = mount(document.querySelector("#doc"), { markdown, baseMarkdown: savedMarkdown });

// 本文と比較元を差し替える
handle.update(nextMarkdown, { baseMarkdown: savedMarkdown });

// 比較元を解除する
handle.update(nextMarkdown, { baseMarkdown: null });
```

`update` の第 2 引数を省くと、前の比較元のまま再描画する。
`baseMarkdown` と `markdown` が同じときは色を適用しない。
`diffSource` も指定したときは、本文の色分けに `baseMarkdown` を使用し、取り出し元は「変更表示」の差分にだけ使用する。
`diffMode` が `blocks` のときは取り出し元を呼ばない。

比較元か `diffMode: "blocks"` で本文を色分けしているときは、右側の目次で、色分けしたブロックを持つセクション（子のセクションを含む）の項目の右端に橙の円を出し、読み上げでは項目の名前に続けて `（変更）` と伝える。
`hover` では右端の線もその見出しの線を橙にする。
`baseMarkdown` を `null` にして色分けを解除すると、円も消える。

## 反映

即時。`mount` を呼ぶと「変更表示」のボタンが付き、押すと取り出し元が呼ばれる。
`diffMode` が `open` なら、ボタンを押した状態で描いた時点に取り出し元が呼ばれる。
`blocks` なら、ボタンを付けず、本文を描いた後に取り出し元が呼ばれる。
`update` は開いている差分を閉じて本文を再描画する。

## 確認

#### 差分が開く

```js
document.querySelector("#doc button[aria-expanded]").click()
```

差分の上に、前と後のリビジョンを選ぶ 2 つの欄が並び、一番新しいリビジョンとその 1 つ前の差分が出る。
削除した行は赤の背景と行頭の `-`、追加した行は緑の背景と行頭の `+` で出る。
書き換えた行の対では、変わった単語だけが濃い色になる。

#### 取り出せないときの表示

`revisions` を reject させて開くと、差分の場所に「変更の履歴を表示できません」の通知ブロックが出て、文書の本文は残る。
`content` が reject したときは、選ぶ欄を残して「このリビジョンの本文を表示できません」の通知ブロックが出る。
別のリビジョンをもう一度選ぶと、差分が出る。

#### 開いた状態で描かれる

`diffMode: "open"` で `mount` を呼ぶと、ボタンを押さなくても差分の行が出る。
ボタンは押した状態（`aria-expanded="true"`）で、もう一度押すと本文に戻る。

#### ブロックが色分けされる

`diffMode: "blocks"` で `mount` を呼ぶと、「変更表示」のボタンと差分の場所は付かない。
追加・変更したブロックが追加の色と `+`、削除したブロックが変更前の位置に削除の色と `−` で出る。
変えていないブロックは、色を当てずに出る。

#### 比較元で色分けされる

`baseMarkdown` に段落を 1 つ削除した Markdown を指定して `mount` を呼ぶと、取り出し元を指定しなくても、その段落が追加の色と `+` で出る。
`update(markdown, { baseMarkdown: null })` を呼ぶと、色が消える。

## 元に戻す

`mount` の呼び出しから `docId` と `diffSource` を削除する。
「変更表示」のボタンが付かず、文書は今までどおり描かれる。
`diffMode` だけを削除すると、`button` の出し方に戻る。
`destroy` を呼ぶと、差分と取り出し元の待ちも片付く。
