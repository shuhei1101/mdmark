# 1枚にまとめる仕組み

文書を集めて参照の表を作り、配布物・CSS・外部ライブラリ・画像と一緒に 1 枚に埋める流れ

`mdmark export` と `mdmark build` が、Markdown から CDN を読み込まない 1 枚の HTML を書き出し、その HTML が開かれて文書が描かれるまでの考え方。
手順は [書き出す](./使用方法.md)。

## 書き出すまでの流れ

1. 設定ファイル `mdmark.config.yaml` を読み込み、Schema に合うかを確認する。`mdmark build` は、設定の `build` の `include`・`exclude` でまとめる文書を決める
2. 設定の `index` があるとき、索引と、索引の `docs` の文書を読み込み、`collectReferences` で参照の表を作る
3. 文書のマーカーにある外部ライブラリを、設定の `libraries` の URL から読み込み、モジュールが import する先も含めて URL ごとに 1 つの ES モジュールにまとめる。設定の `extensions` の拡張のモジュールも、1 つずつまとめる
   - 文書に色分けする言語のコードブロックがあるときは、設定の `syntax.url` から色分けのライブラリの本体と、文書が使用する言語のモジュールだけを、1 つずつまとめる
   - 文書に mermaid のコードブロックがあるときは、設定の `mermaid.url` から mermaid を、中で読み込む全ての図の種類の部品ごとまとめる。mermaid のコードブロックが無い文書には埋めない
4. 文書の include のマーカーの取り込み先を、設定ファイルのフォルダ（無ければ文書のフォルダ）の中から読み込み、取り込む文書の表にする。文書が使用する、配布物に入っていない名前の Lucide のアイコンの形状を、依存の lucide から取り出す
5. 文書が相対パスで指す画像・動画・音声を、文書のフォルダで探し、無ければ設定の `assets.root` のフォルダで同じ相対パスを探す
6. 画像を読み込み、`data:` URL に替える。`mdmark build` は、複数の文書が指す同じ画像を 1 回だけ埋める
7. 動画・音声を、出力の HTML の隣の `{出力のファイル名から拡張子を除いた名前}_files/` へ 1 つずつコピーし、文書の動画・音声のパスをそのコピーへの相対パスに替える。コピーは HTML を書き込む前に行う
8. 起動の処理・部品・色分け・mermaid・外部ライブラリのモジュール・拡張を esbuild で 1 つのスクリプトにまとめる。外部ライブラリと拡張は、呼んだときに初めて評価する関数としてまとめる
9. 配布物の CSS、設定の `theme` の CSS、設定・索引・参照の表・文書の Markdown・取り込む文書の表・アイコンの形状、まとめたスクリプトを、1 枚の HTML に埋めて記載する
10. `--keep-traces` が無ければ、記載する前に、HTML・CSS・まとめたスクリプト・設定の `mdmark` の名前を別名へ置き換え、HTML のコメントと mdmark のバージョンを削除する。文書の Markdown は、部品の要素名・CSS 変数・`class` の値の名前だけを置き換え、マーカーでない HTML のコメントを削除する。文書のタイトル・パス・索引・地の文は置き換えない

文書に記載したスクリプトは、`render` と同じサニタイズで落とし、書き出した HTML でも実行しない。
読み込めない画像・動画・音声・モジュール・拡張・CSS は、書き出しを止めず警告に出す。
動画・音声は大きく、`data:` URL にすると HTML が重くなるため、埋めずに隣のフォルダへ配置する。
名前の置き換えは書き出した HTML の全体に同じ規則で当てるため、`theme` の上書きと拡張は、置き換えた名前のまま隠さない書き出しと同じに効く。

## 開いたときの流れ

1. 起動の処理が、埋めた中身を読み込む
2. まとめた部品・色分け・mermaid・外部ライブラリを `mount` の読み込み先に指定する。まとめた拡張を 1 つずつ評価し、描く前に `registerExtension` で登録する。評価で例外を投げた拡張は飛ばす
3. 文書を `mount` で描く。描かれる本文は `render` と同じで、記法の操作・用語のツールチップ・被参照も `mount` で付く

ページ自身・隣の `_files/` の動画と音声と画像の `data:` のほかへ要求しないため、file:// で開いても、CDN を読み込めない環境でも、HTML と `_files/` だけで描き終える。
まとめたスクリプトは `blob:` URL と動的 `import()` を使用しないため、それらを許さない環境（`script-src 'unsafe-inline'` の CSP 等）でも動く。
色分けも、`mount` が描いた後に、埋めた本体と言語のモジュールから色を付ける。
埋めなかった言語のコードブロックは、読み込みに行かずに色分けせず残す。
mermaid も、`mount` が描いた後に埋めたモジュールで図にする。mermaid を埋めた HTML は 5 MB ほど大きくなる。

## まとめた HTML の文書の行き来

`mdmark build` の HTML は、まとめた全ての文書をパスで参照できる構造で埋め、文書の一覧と、開いている文書を並べる。
開く文書と見出しは URL の `#` が `#/{文書のパス}#{見出しの ID}` の構造で指し、指していないときは `build.entry` の文書を出す。

- 文書の一覧で選ぶ、まとめた文書へのリンクと関連文書のリンクを押すと、URL の `#` を替えて 1 枚の中の文書へ移り、履歴に追加する
- ブラウザの戻る・進むで、移った文書を行き来する。戻った文書は、離れたときのスクロール位置・セクションなどの開閉・選んだタブのまま出す。再読み込みしても同じ
- 文書の一覧とリンクで移った文書は、見出しを指していればその見出しから、指していなければ頭から出す
- 見出しのアンカーと目次のリンクは、移った先の文書の中の見出しへ移る
- まとめた文書に含まれない文書へのリンクは、記載したままの `href` で残る。`mdmark build` が警告に出す

`mdmark export` の HTML は文書を 1 つだけ持つため、文書間のリンクは全て記載したままの `href` で残る。
文書を行き来させたいときは `mdmark build` でまとめる。
