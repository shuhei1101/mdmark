# 要件

## 要望

廃止した `flow`・`sequence` の範囲の文字（ノードの `sub` など）に `--` があっても、`mdmark upgrade` が map の範囲へ書き換えた文書が点検に合格し、点検のずれで全ての変更をコピーから戻さない。

- 終了の条件: Issue の事象の文書（flow のノードの `sub` が `コンテナの中・--mcp-config`）を含む文書のフォルダへ `mdmark upgrade --yes` を適用すると、終了コード 0 で全ての範囲が map の範囲になり、補足の文字は元の `--` のまま描かれる
- 出したバージョン（v0.13.0・v0.14.0）の `migrations/` の配布物は書き換えない

`未確定`: 修正方法（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 点検（`src/map/data.ts`）が、HTML コメントの中にそのまま記載した `--` だけをずれにし、JSON の Unicode エスケープで記載した `--` は合格させる。変換は今のまま | 出した移行の手順の配布物を書き換えずに、upgrade を実行する CLI の点検の修正で解消する。元の文字（`--mcp-config`）が変わらない | 補足の文字の `--` の決まりを記載したガイドと設計書を書き換える |
| B | 変換（`src/map/convert.ts`）が `--` を記載できる別の文字に置き換えて書き出し、置き換えた範囲を移行の報告に挙げる | 点検の決まりが変わらない | 元の文字が変わる。修正するには出した `migrations/v0.13.0/` の配布物を書き換えるか、新規のバージョンに手順を追加する |
| C | 変換が `--` を含む範囲を書き換えずに残し、移行の報告に挙げる | 点検の決まりが変わらない | 残した範囲を作成者が手で記載し直す。B と同じく出した配布物の書き換えか新規の手順が要る |

推奨: A

変換は既に `--` を JSON のエスケープで書き出しており、HTML コメントを閉じない表記になっている。食い違っているのは点検の側だけで、点検は upgrade を実行する CLI が持つため、出したバージョンの配布物を変えずに解消する。
