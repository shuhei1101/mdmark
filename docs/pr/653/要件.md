### 要件

- map の範囲の Mermaid の 1 行目が `gantt`・`timeline`・`gitGraph`・`journey`・`block-beta` のとき、コードブロックのまま表示せず map の図にする
- map の範囲の外のこの 5 種類のコードブロックも、ほかの map が描ける種類と同じく、補足の無い map の図にする
- マーカー（`map`）・Mermaid のブロック・補足（`notes`・`layout`・巡回）の記載方法と、拡大と縮小・凡例・ツールチップの操作は、既存の種類と同じにする。
  種類ごとに追加するのは、読み取り・配置・種類に固有の機能だけにする
- gantt は日付の軸、timeline・gitGraph・journey は記載順の軸に沿って配置する。入れ子の自動配置（`src/map/layout.ts`）・木の配置（`src/map/mindmap-layout.ts`）とは別の配置の処理にする
- gantt・timeline・journey の section は開閉と中へ入るができ、gitGraph のブランチは選択で強調できる
- 4 種類は、案内の帯（シーケンス図・状態遷移図の再生と同じ帯）で記載順に 1 歩ずつ再生できる
- block-beta は `columns` の列の数の格子に記載の順で配置し、幅 `:{数}`・`space`・入れ子の `block … end`（入れ子の中の `columns` を含む）を読む。入れ子のブロックは開閉と中へ入るができる
- 項目を選ぶと、その項目と、種類ごとに決めたつながり（gantt の依存 `after`・gitGraph の親の commit・block-beta の矢印）だけを強調する
- 読めない行は、ほかの種類と同じく描画を止めずに書き方の警告にし、補足が指す無い項目は点検のずれにする
- 描けない種類の案内の文言（描ける種類の一覧）に 5 種類を加える
- map の flowchart の `click {ノード} "id:{ID}#{項目のパス}"`（`href` を挟む書き方を含む）を、下の `未確定` で決めた方法でノードのリンクにし、点検の `map_invalid_value`・書き方の警告・ガイドの「ノードにリンク先を持たせる」を決めた方法に合わせる
- 既存の種類と、map の範囲の外の mermaid のコードブロック（5 種類以外）の記載方法と描画は変えない

`未確定`: 補足の `layout` とドラッグを、軸に沿った配置と格子の配置でどこまで適用するか（決める段: 単一ユースケース設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | マインドマップと同じく色と閉じた状態（`collapsed`）だけを適用し、座標・並び順は書き方の警告にする。ドラッグしない | 配置が軸と格子で決まる種類の位置の意味を壊さない。既存の決め方と統一できる | 項目の位置を作成者が微調整できない |
| B | 座標を適用し、ドラッグで動かせるようにする | 作成者が自由に位置を変えられる | 動かした項目が日付・記載順・列の位置と合わなくなる |

推奨: A

軸と格子の位置そのものが日付・記載順・列を表すため、動かすと図の意味が変わる。

`未確定`: ID の書き方を持たない項目（`id:` の無い gitGraph の commit・timeline の出来事・journey のタスク）を、補足の `notes` のキーと再生の帯でどう指すか（決める段: 単一ユースケース設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | マインドマップと同じく、ID を書いた項目は ID、書かない項目は表示する文字（commit の `msg`・出来事の文・タスク名）をキーにし、同じ文字の項目を指すキーは `map_ambiguous_ref` にする。`id:` も `msg` も無い commit は記載順の番号をキーにする | 既存の決め方と統一でき、作成者が新しい書き方を覚えなくてよい | 表示する文字を変えると補足のキーも修正する |
| B | 全ての項目を記載順の番号で指す | キーが必ず 1 つに決まる | 項目を挿入すると後ろの番号が全てずれる |

推奨: A

Mermaid が `id:` の無い commit に振る ID は乱数を含み、キーに使えない。既存のマインドマップの決め方に統一すると、点検のずれの種類も増えない。

`未確定`: 閉じた section と中へ入った section の見え方（決める段: モック作成）

| 案 | 内容 |
| --- | --- |
| A | gantt の閉じた section は、section の名前とタスクの数を持つ 1 行に、最初の開始日から最後の終了日までの 1 本の棒で描き、日付の軸は変えない。journey の閉じた section は、点数の平均の高さの印 1 つで描く。timeline の中へ入った section は、その section の期間と出来事だけを配置し直し、ほかの期間を薄く残す |
| B | 閉じた section も中へ入った section も、軸の幅は変えずにほかの section を薄くする |

推奨: A

中へ入る操作は、ほかの種類でも中だけを描き直す操作で、B は選択の強調と見分けが付かない。閉じた section は、日付の軸・点数の高さの意味を保ったまま 1 つにまとめる。

`未確定`: gantt の今日の線（決める段: 単一ユースケース設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | Mermaid の `todayMarker` の指定に従い、指定が無ければ読者の端末の今日の日付に線を描き、`todayMarker off` で描かない | Mermaid で書いた図と同じ見え方になる | 開く日によって図が変わる |
| B | 今日の線を描かない | 開く日に依らず同じ図になる | Mermaid の指定を書いても効かない |

推奨: A

Mermaid の記載方法の意味を変えない方針（既存の種類と同じ）に統一する。

`未確定`: block-beta の閉じた入れ子のブロックの大きさと、ほかのブロックの列の位置（決める段: モック作成）

| 案 | 内容 |
| --- | --- |
| A | 閉じた入れ子のブロックは、記載した幅（`:{数}`）の 1 行の高さに縮め、中のブロックの数を出す。ほかのブロックの列の位置は変えない |
| B | 閉じた入れ子のブロックを 1 列の幅に縮め、後ろのブロックを左へ詰める |

推奨: A

列の位置が変わると、`columns` で並べた位置が崩れて別の図に見える。

`未確定`: map の flowchart の `click` の `id:` を、どこで URL に変えるか（決める段: 単一ユースケース設計。今の決定は PR [#534](https://github.com/shuhei1101/mdmark/pull/534) の確認ログ『map のノードのリンクをこの PR の要件に追加するか』で、覆す案はユーザーに確認する）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 決定を覆さず、利用側が `id:` を URL に変えてから記載する。書き方の警告の文と、ガイドの「ノードにリンク先を持たせる」に変え方を記載する | mdmark の変更が文言だけで済む | 設計書の `click` の 151 件を、利用側が描く前に毎回書き換える。`mdmark check` は設計書を点検するたびにずれを出す |
| B | 決定を覆し、`mount` の設定で利用側が `id:` を URL に変える関数を渡せるようにする。map のノードのリンクと本文の `[名前](id:...)` の両方に適用し、関数を渡さないときは今の警告のまま。`mdmark check` は `id:` のリンク先をずれにしない | 利用側（dev-docs など）が索引を持ったまま変えられ、本文のリンクと扱いを統一できる | 公開関数の設定を追加する |
| C | 決定を覆し、mdmark が索引（`mdmark.index.yaml`）から `id:` を解いて URL にする | 利用側の実装が要らない | 設計書の ID は mdmark の索引が持たない値で、索引の構造から作り直しになる |

推奨: B

`id:` を URL に解ける対応表を持つのは利用側で、mdmark は解き方を受け取るだけにすると、本文のリンクとノードのリンクを 1 つの方法で扱える。
