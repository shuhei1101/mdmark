## 変更方針

<!-- table: {"kind": "data"} -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| サイトのレイアウト | AI Monitor の develop の worktree で `import-site --version v0.4.0` を mdmark の worktree に実行する | 控えの `version` も書き換わる |
| 配信設定 | 配布元の v0.4.0 の `exclude` で増えた行のうち、mdmark の `docs/` にあるもの（`data/`・`layout/`）を追加する | `rules.yaml` の行は、ルール索引を直下へ移すと `docs/` の外になるため削除する |
| ルール索引 | 配布元の v0.4.0 の `rules.yaml` で増えた行のうち、mdmark のファイルに該当する行を追加する | 反映作業『プロジェクトの索引の移動』の後 |
| 反映作業のスクリプト | コピーしたスクリプトの `dev-docs.yaml` の参照を `project-index.yaml` に合わせる | 3 件が dry-run で止まった |
| 反映作業の実行 | `index.yaml` の順に、`疎通確認` → `実行` → `確認` を実行し、出力を作業のフォルダに残す | 『各プロジェクトのスキーマの参照への移行』を『配布先のデータの設計書の作成』より先に実行する |
| 端末の設定に触れる反映作業 | 『配布先のエージェント統合への追従』『プロジェクトの索引の設定ファイルへの移行』『配布先の dev-docs への移行』は、dry-run で書き換える対象が無い（`skipped`）か、確認だけになる | 実行の前に、書き換えるファイルのバックアップを取る |
| Schema のコピー | `schemas/` の 4 ファイルを削除し、`schemas/files.yaml` の行を除外する | 反映作業『各プロジェクトのスキーマの参照への移行』の実行で削除しなかった分は手で削除する |
| 管理用の YAML の 1 行目 | `$schema` を knowledge の `knowledge-files.schema.yaml` のリビジョンつきの URL にする | `project-index.yaml` の `schema` の `ref` に統一する |
| フォルダ構成の設計書・アーキテクチャ図 | `generated_from.source` のバージョン・`schemas/` のエントリ・`rules.yaml` と `docs/data/` のエントリ・管理用の YAML のスキーマの記載を修正する | `write_docs` で記載する |
| 規約・テンプレート・判定の参照し直し | `git diff v0.3.0 v0.4.0` で変わった規約・テンプレート・判定フローチャート・チェックシート・フェーズ手順を参照し、従っていない成果物を修正する | 修正した成果物は更新ドキュメントに行を追加する |
| プラグイン・設定スキーマ・MCP ツール | `update_plugins` を呼び、AI Monitor の `settings.yaml` の mdmark の行のキーとツールを配布元の `settings.yaml.example` と比べる | `settings.yaml` はリポジトリの外部のファイルのため、書き換える前にバックアップを取る |
