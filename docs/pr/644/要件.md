# 要件

## 要望

AI Monitor の配布物を v0.4.0 に統一し、準拠バージョンを v0.4.0 にする。
起点 Issue の「影響のある分類」の行と、配布先の反映作業ごとに、次を完了の条件にする。

<!-- table: {"kind": "data"} -->

| 分類 | 完了の条件 |
| --- | --- |
| サイトのレイアウト | `python -m ai_monitor.distribution import-site --version v0.4.0` を worktree に実行して終了コード 0 で終了し、`docs/_theme/` が v0.4.0 の配布元の `docs/_theme/` と一致する（配布物リストの `excludes` のファイルは mdmark の内容のまま）。控えの `ai-monitor-theme.yaml` の `version` が `v0.4.0` |
| 配信設定 | `docs/_config.yml` の `exclude` に、配布元の v0.4.0 で増えた行のうち mdmark の `docs/` にあるフォルダ・ファイルの行がある。`rules.yaml` の行は、ルール索引の移動の後の配置場所に合う |
| テンプレート・規約・フェーズ手順・判定・観点 | v0.3.0..v0.4.0 で変わったページを参照し直し、従っていない mdmark の成果物を修正する。修正が 1 ファイルの書式の修正を超える（設計書の作り替え・実装の変更を伴う）ものはスコープ外へ回して起票する |
| ルール索引 | 配布元のルール索引で v0.3.0..v0.4.0 に増えた行のうち、mdmark のファイルに該当する行が、直下の `rules.yaml` にある |
| プラグイン | MCP `update_plugins` でプラグインを取得し直し、結果を計画書に記録する |
| 設定スキーマ・MCP ツール | AI Monitor の `settings.yaml` の mdmark の行に、配布元で増えたキーと、`agents[].mcp_tools` に増えたツールがある |
| 反映作業 | [反映作業](./反映作業/index.yaml) の 8 件を `疎通確認` → `実行` → `確認` の順に実行し、`確認` が全て成功で終了する |
| #584・#586 から移した範囲 | フォルダ構成の設計書 [LAY-472-1](https://github.com/shuhei1101/mdmark/blob/develop/docs/layout/LAY-472-1.yaml) の `docs/_theme/` の `generated_from.source` が `shuhei1101/ai-monitor@v0.4.0` で、`schemas/` のエントリに削除した Schema のコピーが無い。`schemas/` に `files.schema.yaml`・`index.schema.yaml`・`er.schema.yaml`・`common.schema.yaml` が無く、それを参照する箇所（各フォルダの管理用の YAML の 1 行目・[ARCH-472-1](https://github.com/shuhei1101/mdmark/blob/develop/docs/architecture/ARCH-472-1.yaml)・[project-index.yaml](https://github.com/shuhei1101/mdmark/blob/develop/project-index.yaml)）が knowledge の Schema の参照を指す |
| 準拠バージョン | `ai-monitor-version.ini` が `v0.4.0` |

反映作業のスクリプトは、配信元の定義を直下の `dev-docs.yaml` として参照する。
mdmark は配信元の定義を `project-index.yaml` に改名しているため、そのまま実行すると『配布先の dev-docs への移行』『各プロジェクトのスキーマの参照への移行』『配布先のデータの設計書の作成』の 3 件が `dev-docs.yaml` が無いことで止まる（各作業のフォルダの `dry-run.log`）。
『実装』で、コピーしたスクリプトが参照するファイルを `project-index.yaml` に合わせてから実行する。
