# 要件

## 要望

| 対象 | 要件 | 確認の基準 |
| --- | --- | --- |
| プラグインの定義 | `plugin/.claude-plugin/plugin.json` に `version` を持たせない | develop の `plugin.json` に `version` のキーが無い |
| ビルド | `scripts/build-plugin.ts` の `writePluginManifest` が `version` を記載しない（`npm run build -- --version v{バージョン}` の後も `plugin.json` が変わらない） | ビルドの後の `git status --porcelain plugin/.claude-plugin` が空 |
| バージョンを参照する処理 | 端末の設定の移行の目標（`target_version`）・常駐サーバーの起動コマンドのバージョンは、`plugin.json` ではなくビルドで埋めた mdmark のバージョン（`version.ini`）を参照する。設計書の「プラグインのバージョン（`plugin.json` の `version`）」の記述を合わせる | 設計書に `plugin.json` の `version` を出所にする記述が残らない |
| プラグインの届き方 | develop に入った commit が、プラグインの更新で配布先に届く | PoC で、`version` の無いプラグインがマーケットプレイスの更新で新しい commit に上がることを実機で確認する |
| jsDelivr の配布物 | スプリントの区切りに develop の commit へ `v{X}.{Y}.{Z}` のタグを打ち、`https://cdn.jsdelivr.net/gh/shuhei1101/mdmark@{タグ}/` で配る（E2E は回さない） | 開発コマンドの管理作業が develop で配布物を入れてタグを打つ手順になっている |
| VS Code 拡張機能 | develop の commit に打ったタグで .vsix を作り GitHub Release に添える | シナリオ・開発コマンド・アーキテクチャ図のタグを打つ commit が develop になっている |
| master を指す参照 | 文書・設計書が master のブランチを指す参照を develop に修正する | `git grep` で `blob/master`・`@master`・`/master/` の参照が残らない（外部ライブラリのコピーを除く） |
| 規約への準拠 | knowledge の規約『Claude プラグインルール』の「version を置かない」に合わせる | - |

`未確定`: VS Code 拡張機能のタグの名前（決める段: 単一ユースケース設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 今の `vscode-v{X}.{Y}.{Z}` のタグを、develop の commit に打つ | 拡張機能のバージョンを mdmark と別に上げられ、タグの一覧から mdmark のバージョンを選ぶ処理も変わらない | スプリントの区切りに 2 種類のタグを打つ |
| B | 拡張機能を mdmark の `v{X}.{Y}.{Z}` のタグで作る | 打つタグが 1 種類になる | 拡張機能の `package.json` の `version` を mdmark に合わせる変更と、タグの照合・ワークフローの契機の作り直しが要る |

推奨: A

Issue の決定は「タグを打つブランチを develop にする」ことで、タグの名前を変える要望は無い。

`未確定`: `plugin/` の生成物（`plugin/scripts/`・`plugin/bin/`・`plugin/THIRD_PARTY_LICENSES.txt`）を develop にいつ入れるか（決める段: 単一ユースケース設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 今と同じく、スプリントの区切りの管理作業でだけビルドして入れる | 作業 PR の差分に生成物が入らない | `src/plugin/` の変更は、次のタグまでプラグインの更新で届かない |
| B | `src/plugin/` を変える作業 PR が、生成物もビルドして commit する | develop に入った変更がすぐ届く | 作業 PR どうしで生成物が競合する |

推奨: A

ビルドの要らない配布物だけを develop の最新で届ける決定（D-295）に合い、スキル・フックの定義・テンプレートは develop に入るたびに届く。
