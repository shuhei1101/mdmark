# 要件

## 要望

資料 A-35 の No 13〜17 を、map に追加するかを項目ごとに決め、追加する項目を設計して実装する。

- 終わりの条件 1: 5 つの項目ごとに、追加するかをユーザーが決め、決めた内容と理由が確認ログに残っている
- 終わりの条件 2: 追加する項目は、map の範囲に記載した図（補足の新規のキーか、図の枠の操作）で使用でき、その項目を使用しない図は今の描き方のまま描かれる
- 終わりの条件 3: 追加する項目に補足のキーを追加する場合、値の誤りと無い ID は、今の `map_invalid_value`・`map_unknown_ref` と同じく書き方の警告と点検のずれになる

| No | 項目 | A-35 の内容 |
| --- | --- | --- |
| 13 | 確信度のマーカー | 箱と線ごとに、確認済み・推測・仮説・出典なしを示す |
| 14 | 変更の表示 | 計画した変更（追加・変更・削除）、前に見た後の変更、変更前と変更後の重ね表示 |
| 15 | 環境とシナリオ | 動く環境ごとの配置、失敗のシナリオ |
| 16 | 書き出し | 図を SVG・PNG に書き出す |
| 17 | 一覧の表示 | 同じ図を見出しの一覧として、キーボードと読み上げで読む |

`未確定`: 項目ごとに追加するか（決める段: 単一ユースケース設計。最初にユーザーへ確認する）

| 案 | 内容 |
| --- | --- |
| A | No 13・16・17 を追加し、No 14 は計画した変更（補足で追加・変更・削除を示す）だけを追加する。No 15 は追加しない |
| B | 5 つの項目を全て A-35 の内容のとおり追加する |
| C | どれも追加しない |

推奨: A

No 13・14 の計画した変更は、補足の新規のキーで追加でき、既存の記載方法を変えない。
No 14 の前に見た後の変更と重ね表示は、文書の差分（`diffSource`）と、「前に見た」を記録する場所の決定を要する。
No 15 の環境ごとの配置は今の `C4Deployment`・`architecture-beta` で、失敗のシナリオは補足の `walkthroughs` で描ける。
No 16・17 は図の枠の操作で、どの種類の図にも同じ操作で付けられる。
