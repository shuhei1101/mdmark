## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 移行の手順の配布物の書き込み先 | `buildLegacyMarks`・`buildRetiredDiagrams` は、`v{X}.{Y}.{Z}` のタグがあるバージョンのフォルダへ書き込まない | 出したかは、フォルダの名前と同じ `v{X}.{Y}.{Z}` のタグが `git tag` にあるかで判定する（IF-472-41 の制約『移行の手順の配布物の書き込み先』） |
| develop の配布物の作り直しの commit の対象 | 出したバージョンのフォルダを commit しない | ビルドが書き換えなくなれば今の `git add --all dist plugin migrations` のままでも出したバージョンの差分は出ないため、`develop-dist.yml` は変えない（`migrations/next/` の配布物の commit に今の `git add` が要る） |
| タグを打つ手順の commit の対象 | `管理作業` の手順 4・5 の対象へ `migrations` を追加し（`git status --porcelain dist plugin migrations`・`git add dist plugin migrations`）、手順 3 のビルドが `migrations/v{バージョン}/` へ書き込んだ配布物をタグの commit に含める | タグの後は出したバージョンへ書き込まなくなるため、タグの commit がそのフォルダを更新する最後の機会になる。手順の文面は CMD-472-1 の `管理作業` の手順 4・5 に記載した |
| 出したバージョンを意図して作り直すとき | 指定を設けるかを設計で決める | [#623](https://github.com/shuhei1101/mdmark/issues/623)（[#654](https://github.com/shuhei1101/mdmark/pull/654)）は出したバージョンの配布物を変えずに解消したため、今は要る場面が無い |
| 書き換わったファイル | 出したときの内容に戻す | 4 ファイルとも v0.14.0 のタグの内容に戻す（`要件.md`） |
