## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 移行の手順の配布物の書き込み先 | `buildLegacyMarks`・`buildRetiredDiagrams` は、`v{X}.{Y}.{Z}` のタグがあるバージョンのフォルダへ書き込まない | 出したかの判定の方法（git のタグ一覧・`migrations/no-steps.yaml` など）は設計で決める |
| develop の配布物の作り直しの commit の対象 | 出したバージョンのフォルダを commit しない | ビルドが書き換えなくなれば今の `git add` のままでも差分は出ないため、workflow を変えるかは設計で決める |
| タグを打つ手順の commit の対象 | `管理作業` の手順 4・5 の対象へ `migrations` を追加し（`git status --porcelain dist plugin migrations`・`git add dist plugin migrations`）、手順 3 のビルドが `migrations/v{バージョン}/` へ書き込んだ配布物をタグの commit に含める | タグの後は出したバージョンへ書き込まなくなるため、タグの commit がそのフォルダを更新する最後の機会になる。手順の文面はインターフェース定義設計以降で決める |
| 出したバージョンを意図して作り直すとき | 指定を設けるかを設計で決める | [#623](https://github.com/shuhei1101/mdmark/issues/623)（[#654](https://github.com/shuhei1101/mdmark/pull/654)）は出したバージョンの配布物を変えずに解消したため、今は要る場面が無い |
| 書き換わったファイル | 出したときの内容に戻す | 戻し先は `要件.md` の `未確定` |
