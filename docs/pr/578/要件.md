# 要件

## 要望

mdmark のリポジトリの文書の今の書き方（`キー=値`・`+機能`・位置の値）のマーカーを、JSON のオブジェクトの記載へ書き換える。

- 終わりの条件: 対象の文書の全てで、`mdmark check` が `legacy_mark` を 0 件にする
- 対象: `docs/mock/`・`docs/pr/`・`docs/design-policy.md`
- 対象外（`要件.yaml` のスコープ外）
  - AI Monitor の設計書の Markdown の生成が出力する `docs/README.md` と設計書のフォルダの `README.md`
  - #80 の当時の版に固定した配布物で描く `docs/mock/pages/ui-canvas/80/side-by-side/index.html`

### 対象の文書

[develop の 8659c279](https://github.com/shuhei1101/mdmark/tree/8659c279f0e8855898c74287b36067b68b4aaf8f) の Markdown と HTML を、1 ファイルずつ `mdmark check --text -` に指定して数えた（対象外のファイルを除く）。

| 場所 | ファイル | `legacy_mark` | 書き換え方 |
| --- | --- | --- | --- |
| `docs/mock/` の Markdown | 6 | 6 | `mdmark upgrade` |
| `docs/mock/` の HTML | 3 | 7 | 手で書き換える（HTML の中の Markdown は移行の手順の対象外） |
| `docs/pr/` | 107 | 233 | `mdmark upgrade` |

### 書き換えと確認方法

- リポジトリは `mdmark.config.yaml` を持たないため、対象の文書を `documents` に指定した設定を一時に配置して `mdmark upgrade` を当て、設定は commit しない
- 移行の報告に挙がった記載（書き出さない記載・拡張と `libraries` のマーカー）は、[記法](../../guide/記法.md) のとおりに JSON のキーで記載し直す
- 書き換えた後に、対象の文書の全てを 1 ファイルずつ `mdmark check --text -` に指定し、`legacy_mark` が 0 件であることを確認する

### docs/pr を対象に含める判断

[#477](https://github.com/shuhei1101/mdmark/pull/477) の `要件.yaml` は、過去の PR ドキュメントの書き換えを「当時の記載と食い違う」理由で対応しない（`none`）とした。
[#481](https://github.com/shuhei1101/mdmark/issues/481) の扱いの判断で、終わりの条件の範囲に `docs/pr/` を含めることが合格したため、対象に含める。
書き換えるのはマーカーの引数の記載だけで、描いた結果と本文の文言は変わらない。
