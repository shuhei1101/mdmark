### 罫線のコードブロック（[#739](https://github.com/shuhei1101/mdmark/issues/739)）

- 罫線の行の数が今の警告と同じ基準（`TREE_WARNING_MIN_LINES`）以上のコードブロックを、ファイルツリーで描く
- ファイルツリーの帯は、コードブロックの帯と同じ高さ・余白・色・言語のラベル・コピーのボタンの位置で描く
- 罫線を読み取れない行を持つコードブロックは、今の言語 `tree` のコードブロックと同じ扱い（記載の警告を出してコードブロックのまま描く）にする

ファイルツリーにする言語の範囲は、今の警告の対象と同じく、言語が `tree` でない全てのコードブロック（言語なしを含む）にする（単一ユースケース設計で推奨案 A に決定）。罫線のまま見せたいブロックは `tree_warning: false` で止める。

`未確定`: 罫線のまま見せる指定 `tree_warning: false` の扱い（決める工程: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | キーの名前を変えず、`false` のときはファイルツリーにせずコードブロックのまま描く | Schema と移行の手順を変えない | キーの名前が `warning` のまま意味が変わる |
| B | 新規のキーに改名し、`tree_warning` を移行の手順で書き換える | 名前と意味が一致する | Schema・移行の手順・破壊的変更が増える |

推奨: A

`false` が「罫線をフォルダ構成として扱わない」指定である点は今と変わらないため。

`未確定`: 帯をコードブロックとファイルツリーで同じ部品にするか（決める工程: 部品設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 帯の HTML と CSS をコードブロックとファイルツリーで共通の部品にする | 片方の帯を修正するともう片方にも反映される | ファイルツリー固有のボタン（開閉）を共通の部品へ配置するインターフェースが要る |
| B | 別の部品のまま、CSS の値だけを共通の変数にする | 変更が CSS に閉じる | 構造の違いで見た目がずれ続ける |

推奨: A

Issue の困りごとが「コードブロックの帯を修正したときにファイルツリーの帯が修正されない」ことのため。

### mermaid のコードブロック（[#738](https://github.com/shuhei1101/mdmark/issues/738)）

- ビュワーで更新前の見た目が出た原因: [#630](https://github.com/shuhei1101/mdmark/issues/630) の commit [4d38ecc2](https://github.com/shuhei1101/mdmark/commit/4d38ecc2) はどのタグにも入っておらず（最新のタグ v0.14.0 は 2026-11-17T02:35Z で、4d38ecc2 より前）、タグの版を読み込むビュワーは #630 の前の描き方で描く。版の差だけで解消する文書もあるが、下の戻す場合は develop でも残るため対応する
- front matter の `config`・`%%{` の行を持つ map が描ける種類のコードブロックを、map の図で描く
- mermaid が読み取れる行（`A --o B` など）・見た目を指定する行（`classDef`・`style`・`linkStyle`・`cssClass`・`:::`・`::icon(...)`）を持つ map が描ける種類のコードブロックを、map の図で描く
- GitHub の Mermaid でも読み取れない行は、map の範囲の中と同じく記載の警告にし、読み取れた部分を map の図で描く

map が描けない種類（pie など）は、mermaid のライブラリの経路をその種類のためだけに残す（単一ユースケース設計で推奨案 A に決定）。map が描けない種類には合わせる先の処理が無く、設定 `mermaid`・公開関数を削除しないため、破壊的変更にならない。

`未確定`: 見た目を指定する行・`%%{` の行・front matter の `config` の値を map の図に適用するか（決める工程: モック作成）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 値を適用せず、map の配色で描く | map の図の見た目が文書の中で統一される | 作成者が指定した色が出ない |
| B | `style`・`classDef` の塗りと線の色を map のノードに適用し、テーマの指定（`%%{init}`・`config`）は適用しない | 作成者が色で示した区別を残せる | map の読み取りと描画に色の上書きを追加する |

推奨: B

色で区別を示した図は、色を落とすと意味が変わるため。
単一ユースケース設計（SC-472-11 の正常シナリオ（設定の行・外観を指定する行を持つ））は推奨案 B で記載し、モック作成で案 A に決まったら期待値を修正する。
