# 要件

## 要望

クローンした直後の作業ツリーで、直下の `npm ci` だけを流した状態から `npm run typecheck` が型エラー 0 件・終了コード 0 で終わるようにする。
直下の型検査（`tsconfig.json` の `include`）が、`vscode/package.json` にだけある依存（`@vscode/test-electron`）の型を引かないようにする。
直下の `package.json` の依存は増やさない。

E2E の VS Code のシナリオが使う代役の配信（`createStubServer`）と、VS Code 拡張機能の結合テストの入口（`vscode/tests/integration/run.ts` の `runIntegrationTests`）の振る舞いは変えない。

完了の基準は次の 2 つ。

- release の追跡しているファイルだけを写した一時フォルダで、直下の `npm ci` → `npm run typecheck` が終了コード 0 で終わる
- 単一『配布物をビルドして検査する』の spec（8 件）と、VS Code を起動する 8 つの spec（複合 1・単一 7）が全て pass する

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| E2E の `globalSetup`（`tests/e2e/vscode-binary.ts`）が実行時に `vscode/` の `@vscode/test-electron` を読む | 実行時に `createRequire` で読み、型検査では引かない。E2E の前提に `npm --prefix vscode ci` が既に書かれている | 予定なし |
| 直下の `package.json` に `@vscode/test-electron` を加える案 | 直下の依存を増やさずに直せるため選ばない | 予定なし |
