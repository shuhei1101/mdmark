## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 指 1 本の移動 | 開いたときの倍率より拡大している図では、表示する枠の上の指 1 本の縦横のドラッグを図の移動にし、ページをスクロールしない。開いたときの倍率の図では、縦のドラッグをページのスクロールにし、横のドラッグは枠に収まらない分だけ図の移動にする。指の移動はポインターのイベントで動かさず、表示する枠を縦横にスクロールできる枠（`touch-action: pan-x pan-y`）にしてブラウザのスクロールに任せ、開いたときの倍率では縦のスクロールを止める | iPhone の Safari ではポインターのイベントが途中で打ち切られて動かないため（モックで確かめた）。指を離さずに図の端を越えて続けたドラッグは、ブラウザのスクロールの連鎖で文書のスクロールになる。拡大して縦にスクロールできる間のホイールは取り消し、表示する枠の祖先のスクロールへ渡す（インターフェース定義で決めた） |
| ピンチ | 図の上の 2 本の指の間隔の変化を、2 本の指の中点を保った倍率の変更にする。倍率はボタン・キーと同じ、開いたときの倍率の 0.25 倍〜5 倍の間に収め、図の上だけブラウザのページの拡大を止める | 図の外の段落の上のピンチではページ全体を拡大できるように残す（viewport の `user-scalable=no` は使用しない） |
| 操作中のマーカー | 余白のタップで縦に動かせるようにする `data-touch-active` と `diagram-touch.interact.ts` を削除し、表示する枠の `data-at-fit`（開いたときの倍率以下で縦のスクロールを止める）に置き換える | モジュール構成設計で決めた |
| ボタンのパネル | 拡大・縮小・倍率・全画面のボタンを、表示する枠の上の別の行から、表示する枠の右上に重ねる角の丸い小さいパネルへ移す。パネルは倍率の表示と開くボタン（`aria-expanded`）だけに畳んで開き、開くと残りのボタンを並べる。移動のボタン（`data-group="pan"`）は削除し、倍率の範囲（今の `ZOOM.max` と開いたときの倍率の下限）を開いたときの倍率の 0.25 倍〜5 倍に変える | モックの案 C（[確認ログ](./確認ログ.yaml)）。map の図のボタンのまとまり（`data-group="map"`）も同じパネルに含める |
| ライトボックスの移動のボタン | 上のバーの移動のボタン（`data-group="pan"`）を削除し、拡大中の移動はドラッグ（指を含む）と矢印キーで行う。`attachZoom` の移動のボタンのまとまりの処理も削除する | スマホの幅で拡大すると上のバーが 3 行に折り返し、ピンチの中点の下の画像がずれるため（[確認ログ](./確認ログ.yaml)） |
| アクセシビリティ | パネルのボタンは `role="toolbar"` とスクリーンリーダー向けの名前、キーボードの操作を今のまま保つ。指で押せる大きさを守る | - |
| 既存機能への影響 | マウスのドラッグ・ホイール（文書のスクロール）・キー・リサイズハンドル・全画面のモーダル・ツールチップのタップ・map の参加者の箱のドラッグを壊さない | 回帰を結合テストで確認する |
| 公開ドキュメント | 『図を描く』『構成図の決まり』『mermaidの図を描く』『コードブロックのHTMLを描く』『API』『用語集』の記載を、パネルと指の操作に合わせる | 更新ドキュメントの表 |
