## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 原因 | `Fetch.enable` の応答を受けた後も、続く要求の一部が差し替えを通らずに jsDelivr へ出る。`test_normal_when_unbundled_icons` で `sailboat.mjs`・`anchor.mjs` がすり抜けると、本物のアイコンで `svg` が描かれ、記録した要求が 0 件になる | 使い捨てのテストで、`Fetch.enable` の直後の `import()` を 300 回繰り返すと、3 回の実行でそれぞれ 1 回すり抜けた（`テスト結果/20261114072721_25305e7b_Fetch.enableの直後の要求の差し替えの確認.log`）。Vitest もモジュールの代役で同じ事象を扱い、探りの要求で待っている（`@vitest/browser-playwright` の `probeInterception`） |
| `stubLucide` | `Fetch.enable` の後に、差し替えの対象の URL（`https://cdn.jsdelivr.net/npm/lucide@0.0.0/__probe__`）へ `fetch` を送り、`Fetch.requestPaused` で受けるまで送り直してから返却する。受けた探りの要求は記録せず 204 を返却する。200 回送っても受けなければ例外にする | 同じ使い捨てのテストで探りの要求で待つと、300 回 × 3 回の実行ですり抜けは 0 回。確かめる内容（要求が `sailboat.mjs` と `anchor.mjs` の 1 件ずつ・`GET` だけ・アイコンを持たない文書では 0 件）は変えない |
| 実装・設計書 | 変えない | 原因はテストの準備にあり、`src/inline-icons.ts` とインターフェース定義の `expected` に関わらない |
| 対象外 | タッチの代役の後始末（#530）は扱わない | - |
