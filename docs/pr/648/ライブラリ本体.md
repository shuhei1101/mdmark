## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 単体テスト（フロント）の実行場所 | 判定フローチャート『テストの実行場所』で決める。Node と Chromium（`npx playwright install chromium`）だけを使用するため `runner` の見込み | 決めるのは planner『テスト作成』『実装』で全件実行を記載する時点 |
| 結合テスト（フロント）の実行場所 | 同じ判定フローチャートで決める。子プロセスの MCP サーバー・Storybook・Chromium は workflow の中で用意でき、VS Code 拡張機能の結合テストは `xvfb-run` と VS Code の取得が要る | 手元でしか用意できないものを使用するテストがあれば、マーカーを付けてランナーの全件実行から除く |
| lint の実行場所 | `local` | 判定フローチャートの最初の判定 |
| `未確定` の層 | 実行場所を記載しない | 全件実行のコマンドが無い |
| workflow | `runner` の層を入力で選んで回す workflow を 1 つ作り、`workflow_dispatch` だけで起動する | インターフェース定義 `docs/interface/IF-472-44.yaml` |
| `run_runner` | `gh workflow run` で起動し、実行を API で参照できるまで待ってから `gh run watch` で待ち、ログを取得する 1 コマンド | 失敗したときもログを取得してから失敗で終える |
| 手元のコマンド | `run_all`・`run_one` を残す | ランナーで回せないときに使用する |
| skip の照合 | ランナーで回したときと手元で回したときの skip の件数を比べる | `workflow_dispatch` は develop にある workflow だけを起動できるため、作業ブランチへの `push` を一時的に追加してランナーを動かし（規約『Git フックと CI で動かすもの』）、その実行で比べる。作業 PR のテストのログは手元の全件実行で取る |
| 管理用の YAML | `.github/files.yaml` に workflow の行を追加し、インターフェース定義への `implements` を記載する | - |
