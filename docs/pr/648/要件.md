# 要件

## 要望

- テスト実行方法の層ごとに、判定フローチャート『テストの実行場所』で実行場所（`runner` / `local`）を決め、層の `location` に記載する
  - 全件実行のコマンドが `未確定` の層は対象にしない
  - lint の層は判定フローチャートのとおり `local` にする
- `runner` にした層は、層の全件か指定した結合テストを回す GitHub Actions の workflow を、インターフェース定義で設計してレビューに合格してから作る
  - workflow は手動の起動（`workflow_dispatch`）だけで起動する
  - 層の `run_runner` に、workflow を起動して終わるまで待ち、ログを取得する 1 コマンドを記載する
- `runner` にした層も、手元の全件実行（`run_all`）・個別実行（`run_one`）のコマンドを残す
- ランナーで回したときの skip の件数が、手元で回したときと同じことを確認する
- 追加した workflow の行を `.github/files.yaml` に追加する

## 決めたこと

| 論点 | 決定 | 理由 |
| --- | --- | --- |
| Schema の参照のバージョン | `project-index.yaml` の参照（`design-schemas/v8.4.0`）を変えない | v8.4.0 のテスト実行方法の Schema が `location`・`run_runner` を持ち、インターフェース定義の Schema が `trigger` の workflow の `overall_flow`・`exclusivity` の決まりを持つ。v9 系との差分は文言・規則の追加と関連の要素の破壊的変更で、この要望に要るキーは増えない |
| workflow のテスト | テストのファイルを作らず、インターフェース定義の `test_file` を持たない | 対応テストファイルは任意の項目。フローは規約『Git フックと CI で動かすもの』の手順で、作業ブランチのランナーを動かして確認する |
