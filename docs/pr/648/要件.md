# 要件

## 要望

- テスト実行方法の層ごとに、判定フローチャート『テストの実行場所』で実行場所（`runner` / `local`）を決め、層の `location` に記載する
  - 全件実行のコマンドが `未確定` の層は対象にしない
  - lint の層は判定フローチャートのとおり `local` にする
- `runner` にした層は、層の全件か指定した結合テストを回す GitHub Actions の workflow を、インターフェース定義で設計してレビューに合格してから作る
  - workflow は手動の起動（`workflow_dispatch`）だけで起動する
  - 層の `run_runner` に、workflow を起動して終わるまで待ち、ログを取得する 1 コマンドを記載する
- `runner` にした層も、手元の全件実行（`run_all`）・個別実行（`run_one`）のコマンドを残す
- ランナーで回したときの skip の件数が、手元で回したときと同じことを確認する
- 設計書の Schema の参照（`project-index.yaml` の `documents[].schema.ref`）のうち、テスト実行方法とインターフェース定義を、`location`・`run_runner` と workflow のインターフェース定義を持つバージョンにする
- 追加した workflow の行を `.github/files.yaml` に追加する

`未確定`: Schema の参照を上げる範囲（決める工程: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | テスト実行方法とインターフェース定義の種類だけを `design-schemas/v9.2.2` にする | 差分がこの要望の範囲に収まる | 種類ごとに参照のバージョンが分かれる |
| B | 全ての種類を `design-schemas/v9.2.2` にする | バージョンがそろう | v9.0.0 の破壊的変更（関連の要素の変更）への追従で、要望の範囲外の設計書まで書き換える |

推奨: A

要望が求めるのは 2 つの種類の Schema の更新で、全ての種類のバージョン上げは要望の範囲外の設計書の書き換えを伴う。

`未確定`: workflow のテストの要否と置き場所（決める工程: インターフェース定義設計）

インターフェース定義の Schema は、エントリーポイントが `trigger` の workflow の対応テストファイルを `tests/e2e/workflow/` にしている。
このリポジトリには E2E のテストの層が無いため、テストを作るかと置き場所をインターフェース定義設計で決める。
