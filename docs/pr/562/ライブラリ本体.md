## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 注釈の定義 | 文書の中に ID と本文の組で定義する。同じ ID の定義が 2 つあれば後の定義を無視して警告する | 記載方法は `未確定`（[要件](./要件.md)） |
| 本文・表のセルからの参照 | 行内の参照の記法を ID で記載し、定義の本文を参照の場所のツールチップに出す。1 か所に複数の注釈を並べて参照できる | 表のセルは本文と同じ記法で参照する |
| map のノードと線からの参照 | 補足でノード・線の ID ごとに注釈の ID の並びを持ち、図のツールチップでノードの説明の下に注釈の本文を出す | 補足のキーは `未確定`（[要件](./要件.md)） |
| 参照のマーカーとツールチップ | 脚注の参照の番号とツールチップの部品を拡張して使用する。マーカーは脚注の番号と見分けられる見た目にする。ポインター・フォーカスで出し、Esc で閉じ、タッチ・印刷の振る舞いは脚注と同じにする | 見た目はモック作成で決める |
| 末尾の注釈の一覧 | 脚注の閉じた一覧の部品を拡張し、参照された注釈を定義の順に並べる。一覧の項目から参照の場所へ戻れる。印刷では開いて出す | 脚注の一覧と並べるか 1 つにまとめるかはモック作成で決める |
| 脚注への影響 | 脚注の記法・番号・ツールチップ・一覧の今の表示と操作は変えない | 既存の脚注のテストを回帰確認に使用する |
| 点検 | 描画の記載の警告として、定義の無い ID の参照・参照されていない定義・同じ ID の 2 つ目の定義を出し、`mdmark check`・MCP の `check` が同じ警告を返す。map の補足の未定義の参照も同じ警告にする | 警告の種類の名前はインターフェース定義設計で決める |
| 機能のオン・オフ | 設定の `features` に注釈のキーを持つかを決め、持つ場合は脚注と同じ既定にする | インターフェース定義設計で決める。持つ場合は `schemas/` の変更と `migrations/` の行が要る |
| 1 枚にまとめた HTML | `mdmark build`・`export` の HTML でも、マーカー・ツールチップ・一覧が働く | 脚注と同じ経路で埋め込む |
| アクセシビリティ | マーカーはフォーカスでき、ツールチップを `aria-describedby` で結び、一覧への移動を Enter で行える | 脚注と同じ |
