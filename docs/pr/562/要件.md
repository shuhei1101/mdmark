# 要件

## 要望

- 文書の中に注記を ID つきで定義し、本文・表のセル・map の図のノードと線から ID で参照できる
- 機能の名前は「注記」にする（用語集のファイルツリーの用語「注釈」と重ならない名前）
- 参照した場所にマーカーを出し、ポインターを乗せるかフォーカスすると注記の本文をツールチップで出す。キーボードで開け、Esc で閉じる（脚注のツールチップと同じ操作）
- 同じ注記を複数の場所から参照でき、どの場所でも同じ本文を出す
- 注記は map の補足の `notes`（ノードと線の説明）とは別に持ち、ノードの説明と注記を両方出せる
- 参照した場所のマーカーは上付きの「※」と番号（`※1`）にする。番号は文書の中で最初に参照した順に 1 から振り、脚注の番号とは別に数え、同じ注記は同じ番号にする
- 文書の末尾に、参照された注記の一覧を番号の順に閉じた状態で出す。脚注の一覧とは分け、本文 → 脚注 → 注記 → 関連文書の順に並べる。印刷では開いて出す
- 参照のマーカーのツールチップと末尾の閉じた一覧は、脚注の部品を再利用・拡張する。脚注の今の表示と操作は変えない
- `check` で、定義の無い ID の参照と、参照されていない定義を警告する。同じ ID の定義が 2 つあれば、前の定義を使用し、2 つ目の定義を警告する
- 使用方法集の notation・map・diagrams に記載方法を追加する

注記の定義と参照の記載方法（インターフェース定義設計で決めた。脚注の記載方法を広げず、注記専用の記載方法を追加する案）:

- 定義は行頭の `※[ID]: 本文`（ID は英数字・`-`・`_`。4 文字の字下げで続く段落を含む）、参照は行内の `※[ID]`
- 一般的な Markdown では、本文の `※[cond]` と定義の行 `※[cond]: …` がそのまま並んで読め、今の `※n` の注記と同じ読み方になる
- map の補足では、`notes` のノード・線ごとの値に注記の ID の並びを持たせる（`{"text": "…", "annotations": ["cond"]}`。`text` を省いてもよい）
- 機能の名前は `annotations`（設定と文書の `features`）、点検のずれの種類は `annotation_undefined`・`annotation_unused`・`annotation_duplicate`
