# 要件

## 要望

- 文書の中に注釈を ID つきで定義し、本文・表のセル・map の図のノードと線から ID で参照できる
- 参照した場所にマーカーを出し、ポインターを乗せるかフォーカスすると注釈の本文をツールチップで出す。キーボードで開け、Esc で閉じる（脚注のツールチップと同じ操作）
- 同じ注釈を複数の場所から参照でき、どの場所でも同じ本文を出す
- 注釈は map の補足の `notes`（ノードと線の説明）とは別に持ち、ノードの説明と注釈を両方出せる
- 文書の末尾に、参照された注釈の一覧を閉じた状態で出す。印刷では開いて出す
- 参照のマーカーのツールチップと末尾の閉じた一覧は、脚注の部品を再利用・拡張する。脚注の今の表示と操作は変えない
- `check` で、定義の無い ID の参照と、参照されていない定義を警告する。同じ ID の定義が 2 つあれば、前の定義を使用し、2 つ目の定義を警告する
- 使用方法集の notation・map・diagrams に記載方法を追加する

`未確定`: 注釈の定義と参照の記載方法（決める工程: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 脚注の記載方法を広げる（定義は `[^ID]: 本文`、参照は `[^ID]`）。定義にマーカーを付けたものを注釈として扱う | 覚える記載方法が増えない | 番号を振る脚注と同じ本文を参照する注釈を、記載した文字から見分けられない |
| B | 注釈専用の記載方法を新しく追加する（定義はマーカーで囲んだ範囲、参照は行内の記法） | 脚注と記載を分けられ、点検の警告も分けられる | 記載方法が 1 つ増える |

推奨: B

脚注は本文の順に番号を振るもの、注釈は同じ本文を複数の場所から参照するもので、作成者が使い分ける場面が違うため。

`未確定`: map の補足で注釈を参照するキー（決める工程: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 補足の `notes` のノード・線ごとの値に注釈の ID の並びを持たせる（`{"text": "…", "annotations": ["id"]}`） | ノード・線ごとの情報が 1 か所に集まり、`map_unknown_ref` の点検の経路を共用できる | `notes` に `text` の無い値を許す必要がある |
| B | 補足に `notes` と並ぶキーを追加し、ノード・線の ID ごとに注釈の ID の並びを持たせる | `notes` の構造を変えない | 同じノードの ID を 2 か所に記載する |

推奨: A

ノードの説明と注釈を同じ場所で参照・記載でき、点検の経路も 1 つで済むため。
Issue の例 `notes: ["id"]` は、補足の `notes` が既に説明の欄の名前のため、そのまま使用できない。
