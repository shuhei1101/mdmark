# 要件

## 要望

VS Code 拡張機能のタグ一覧の要求（`vscode/src/version.ts` の `fetchLatestVersion`）が、待ちの上限 `TAGS_TIMEOUT_MS`（3000 ms）より前に中断されて見える原因を特定して修正する。

- 原因: 結合テストと代役の配信が経過時間を `Date.now` で測っており、WSL2 の時計の補正で `Date.now` が戻ると、経過時間が実際より短く出る。`AbortSignal.timeout` は単調な時計で測るため、補正では早まらない
  - 戻りの大きさは時間で変わる。30 秒ごとの戻りは 14 時台に 55〜72 ms（[計測のログ](./テスト結果/20261113142206_905ccdba_時計の補正の計測.log)）、21〜23 時台に合計 1.2〜1.4 秒だった（[突き合わせのログ](./テスト結果/20261113230339_0341dfe1_時計の戻りと修正前後のテストの突き合わせ.log)）
  - 戻りが 1.2 秒の間に、修正前のテストは 40 回中 5 回 fail した（`Date.now` で測った要求までが 1770〜2510 ms）。5 回とも、中断の直前 3 秒以内に合計約 1.2 秒の戻りがあった。修正後のテストは同じ間に 40 回とも pass した
  - ループを止めた後に作った `AbortSignal.timeout(3000)` も、`performance.now` で 3000 ms で中断した
  - #504 の +276 ms には約 2.7 秒の戻りが要る。その時刻のジャーナルは残っておらず、確かめられない
- `vscode/tests/integration/preview-open.test.ts` と `vscode/tests/integration/stub-server.ts` の経過時間を、`Date.now` の差から `performance.now` の差へ替える。代役の配信はテストと別のプロセスで動くため、`/tags` を受けてから閉じられるまでの時間は代役の配信の中で測る
- 同じファイルの `Date.now` の差で経過時間を比べる箇所（`test_normal_when_tags_unreachable` の 403 の確認・`test_normal_when_loading_shown`）も同じく替える
- 待ちの上限の値（3000 ms）・期待の範囲（2800 ms 以上 6000 ms 未満）・拡張機能の実装（`vscode/src`）は変えない
- `test_normal_when_tags_unreachable` を、VS Code 1.141.0 と stable のそれぞれで 10 回繰り返して全 pass する。fail したときは `Date.now` と `performance.now` の両方の経過時間をメッセージに出し、実装の中断が単調な時計でも上限より早いかを切り分ける
