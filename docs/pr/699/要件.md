# 要件

## 要望

mdmark のマーケットプレイスに、Claude Code の画面を mdmark の共通スタイルで描く mod の単独のプラグイン `mdmark-style` を配置する。

| 要件 | 終了の条件 |
| --- | --- |
| 返答の描き換え | アシスタントの返答の表は Box の罫線と列の幅、注意書きは左の縦線と色と先頭のラベル、見出しは太字と色、コード・差分は Code 部品で描く。図（mermaid・map）と埋め込んだ HTML は描かない |
| マーカーを画面に出さない | 返答に記載された mdmark のマーカー（`<!-- table: ... -->` など）を描き方に使用し、マーカーの文字は画面に出さない |
| マーカーの記載方法の注入 | SessionStart で、マーカーの記載方法の短い説明を 1 セッションに 1 回だけ注入する |
| 用語のマーカー | 利用者の発言とアシスタントの返答に出た用語・エイリアスに下線を付け、ポインターを乗せると開くカードと、マウスを使えないときのための脚注を出す。用語は設定 `glossary` が指す `mdmark.config.yaml` の索引・aliases・用語集の表から取り、YAML の文書・MCP は参照しない |
| 共通スタイルの共有 | 色・表の型・注意書きの種類の定義を TypeScript のモジュール 1 か所に配置し、Web の描画と mod の両方が参照する。Web の CSS 変数の名前と値は変えない |
| 設定 | `MDMARK_STYLE_CONFIG`（無ければ既定のパス `~/.config/mdmark-style/settings.yaml`、ファイルも無ければ既定値）の `global`・`projects` で、`enabled`・`parts.*`（table・heading・callout・code・terms・hover_card・footnote）・`targets`（assistant・user）・`glossary`・`inject_marker_guide` を変えられる。サンプル `settings.sample.yaml` をプラグインの中に配置する |

`未確定`: hover で開くカードが有効な端末の範囲と、デスクトップ版・VS Code での HTML コメントの描き方（決める工程: PoC 検証）

| 案 | 内容 |
| --- | --- |
| A | ターミナル版で `ui.render` による返答の描き換え・マーカーの削除・hover のカードを PoC で確認し、デスクトップ版・VS Code は確認した範囲を外部ライブラリの設計書に記録する |
| B | ターミナル版・デスクトップ版・VS Code の 3 つを全て PoC で確認してから設計に入る |

推奨: A

手元で自動で起動して画面を読めるのはターミナル版で、描く部品の木は 3 つの画面で共通のため。

`未確定`: mdmark-style をアーキテクチャ図のサブシステム「Claude Code プラグイン」に含めるか、別のサブシステムにするか（決める工程: 単一ユースケース設計）

| 案 | 内容 |
| --- | --- |
| A | サブシステム「Claude Code プラグイン」に含め、プラグインを 2 つ持つ構造にする |
| B | サブシステム「mdmark-style」を新規に追加する |

推奨: A

どちらも Claude Code が読み込むプラグインで、Claude Code のバージョンと仕様に依る部分を分けて確認する理由（今のサブシステムの `reason`）が同じため。
