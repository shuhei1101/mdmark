# 要件

## 要望

`vscode-v{X}.{Y}.{Z}` のタグの push で、`vscode-release.yml` が GitHub Release に .vsix を添えた後、同じ .vsix を Visual Studio Marketplace へ `ShuheiNishikawa.mdmark-vscode` として公開する。

- 認証は Marketplace の trusted publishing（GitHub Actions の OIDC トークン。`vsce publish --oidc`）で行い、PAT をリポジトリのシークレットに配置しない
- ワークフローの `permissions` に `id-token: write` を加える
- タグと `vscode/package.json` の `version` が合わないときは、今と同じく .vsix を作らず、Marketplace へも公開しない
- Marketplace に同じバージョンが公開済みのときは、ワークフローを失敗させる（同じバージョンは上書きできない）
- 公開の流れは規約『VS Code 拡張機能の配布』（自動にできる公開先は CI で公開する）に従う
- ワークフローで拡張機能の .vsix を作る前に、リポジトリの直下の依存も入れる（[#378](https://github.com/shuhei1101/mdmark/pull/378) から拡張機能のビルドがリポジトリの直下の `src/` を読み込み、`npm --prefix vscode ci` だけでは `yaml`・`ajv`・`lucide` を解決できず .vsix を作れない）
- Open VSX へは公開しない（[ユーザーの回答](https://github.com/shuhei1101/mdmark/pull/512#discussion_r4570559008)）

trusted publishing のポリシーは、ユーザーが publisher `ShuheiNishikawa` に登録済み（Owner `shuhei1101`・Repository `mdmark`・Workflow `vscode-release.yml`・Environment なし。状態は Active）。

Marketplace には 0.1.0・0.1.1・0.1.2 が公開済み（0.1.2 はワークフローの外で 2026-11-14 に公開された）で、リポジトリの `vscode/package.json` とタグは 0.1.0 のまま。
この PR で `vscode/package.json` の `version` を `0.1.3` に上げ、マージ後に最初に打つタグを `vscode-v0.1.3` にする（[確認ログ](https://github.com/shuhei1101/mdmark/pull/512#discussion_r4571168056)）。
