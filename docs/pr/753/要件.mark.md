### #742 用語の YAML から用語集の表を描く

- 今の書き方（本文の表を `glossary` のマーカーで囲む）は残し、用語の YAML を表の元として追加する
- 描いた用語集の表の列は、YAML の `name`（用語）・`aliases`（別名）・`avoid`（使用しない言い方）・`description`（意味）・詳細のページ（詳細）から作り、今の `docs/guide/用語集.mark.md` の表と同じ列を出す
- 詳細のページを持つキーは knowledge の用語のスキーマに追加する（[knowledge#525](https://github.com/shuhei1101/knowledge/issues/525)。[確認ログ](./確認ログ.yaml) の案 A）。`docs/guide/用語集.yaml` の各用語への詳細のページの記入と `用語集.mark.md` の表の削除は、knowledge#525 のスキーマのタグが打たれてから行う
- `docs/guide/用語集.mark.md` の表を削除し、`docs/guide/用語集.yaml` を読み込むエイリアスの行を指すマーカーに置き換える。`docs/guide/用語集.yaml` の `items` の概要の「描く表は用語集.mark.md が持つ」も合わせて修正する

用語の YAML は、設定の `aliases` の `alias_type: term` の行で読み込んだエイリアスとして描く処理へ指定し、`glossary` のマーカーの引数でその行を指す（引数の名前は ER 図『用語集の表のマーカーの設定』で決める）。
`export`・`build`・`check`・dev-docs は既に `aliases` を指定しているため、用語の YAML を読み込む経路を増やさずに済む。
エイリアスとして入った用語は、今と同じく本文の下線とツールチップ・点検・本文の参照の取り出しに入るため、表から描いた用語として重ねて入れない。
mdmark の公開ドキュメントは、`mdmark.config.yaml` に `docs/guide/用語集.yaml` を読み込む `aliases` の行を追加する。

### #532 書き出した HTML に元の Markdown を埋め込まない

- 書き出しの中身（`ExportPayload`）の `docs[].markdown` と取り込む文書の本文（`includes`）を埋め込まず、書き出すときに `render` で描いた HTML を埋め込む
- 開いたときは、埋め込んだ HTML を描く先の要素に入れ、`mount` と同じ読者の操作（ツールチップ・表の操作・目次・図の部品・コメント 等）を付ける
- 外部ライブラリと拡張のマーカーは、書き出すときに描けないため、マーカーの場所と引数を HTML に残し、開いたときにモジュールで描く
- 「Markdown でコピー」「Markdown でエクスポート」は、書き出すときに `toPureMarkdown` で作った純粋な Markdown を文書ごとに埋め込んで使用する
- まとめた HTML（`build`）の文書の行き来・リンクの書き換え・表示の状態の保存と復元は、今と同じに動く

描いた HTML に操作を付ける起点は、`mount` に描いた結果（`opts.rendered`。本文の HTML・機能のオン・オフ・ページの設定）と純粋な Markdown（`opts.pureMarkdown`）を受け取る引数を追加する（インターフェース定義『文書を描く』）。
`mount` は描いた後の操作の付与を既に `interact.ts` にまとめており、描く処理を飛ばす分岐だけで足り、1 文書・まとめた HTML とも `mount` の戻り値（`destroy`・`update`）をそのまま使用できる。
