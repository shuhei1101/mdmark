### #742 用語の YAML から用語集の表を描く

- 今の書き方（本文の表を `glossary` のマーカーで囲む）は残し、用語の YAML を表の元として追加する
- 描いた用語集の表の列は、YAML の `name`（用語）・`aliases`（別名）・`avoid`（使用しない言い方）・`description`（意味）から作り、今の `docs/guide/用語集.mark.md` の表と同じ列を出す
- YAML から描いた用語も、今の表から入れた用語と同じく、本文の下線とツールチップ・参照の表（`collectReferences`）・点検（`checkIndex` の `avoided_term`）・本文の参照の取り出し（`collectMatches`）に入る
- `docs/guide/用語集.mark.md` の表を削除し、YAML を指すマーカーに置き換える。`docs/guide/用語集.yaml` の `items` の概要の「描く表は用語集.mark.md が持つ」も合わせて修正する

`未確定`: 用語の YAML を描く処理へ指定する経路（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `glossary` のマーカーの引数に YAML のパスを記載し、CLI（`export`・`build`・`check`）と利用側が YAML を読み込んで `mount`・`render` の引数で指定する | マーカーだけで表の元が分かる | YAML を読み込む経路を CLI・VS Code 拡張機能・dev-docs・mdmark-style のそれぞれに追加する |
| B | 設定の `aliases` の `alias_type: term` の行で既に読み込んでいるエイリアスから表を描き、マーカーの引数でその行を指す | 用語の YAML を読み込む経路が既にある（`export`・`build`・`check`・dev-docs が `aliases` を指定する）。追加するのはマーカーの引数と表を描く処理 | `aliases` を設定に記載していない利用側は描けない |

推奨: B

`docs/guide/用語集.yaml` は既に `project-index.yaml` の `alias_type: term` の行で配信されており、mdmark の設定の `aliases` からも同じ YAML を読み込める。読み込む経路を増やさずに済む。

### #532 書き出した HTML に元の Markdown を埋め込まない

- 書き出しの中身（`ExportPayload`）の `docs[].markdown` と取り込む文書の本文（`includes`）を埋め込まず、書き出すときに `render` で描いた HTML を埋め込む
- 開いたときは、埋め込んだ HTML を描く先の要素に入れ、`mount` と同じ読者の操作（ツールチップ・表の操作・目次・図の部品・コメント 等）を付ける
- 外部ライブラリと拡張のマーカーは、書き出すときに描けないため、マーカーの場所と引数を HTML に残し、開いたときにモジュールで描く
- 「Markdown でコピー」「Markdown でエクスポート」は、書き出すときに `toPureMarkdown` で作った純粋な Markdown を文書ごとに埋め込んで使用する
- まとめた HTML（`build`）の文書の行き来・リンクの書き換え・表示の状態の保存と復元は、今と同じに動く

`未確定`: 描いた HTML に操作を付ける起点（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `mount` に描いた HTML を受け取る引数を追加し、Markdown を描く処理を飛ばして操作だけを付ける | 1 文書・まとめた HTML とも `mount` の戻り値（`destroy`・`update`）をそのまま使用できる | `mount` の引数の組み合わせの検査が増える |
| B | 操作だけを付ける公開関数を新規作成する | `mount` の引数が変わらない | `mount` の後処理（拡張の読み込み・図の部品・目次）を新規の関数へ分ける作業が増える |

推奨: A

`mount` は描いた後の操作の付与を既に `interact.ts` にまとめており、描く処理を飛ばす分岐だけで足りる。
