# 要件

## 要望

記法のマーカーの引数を、次の表のとおりに扱う。

| 記載したもの | 例 | 扱い |
| --- | --- | --- |
| 知らないキー（`キー=値`） | 表の `size=`・コードブロックの `color=` | 書き方の警告を出さずに無視し、残りの指定で描く |
| 知らない機能（`+名前`・`-名前`） | 表の `+unknown` | 書き方の警告を出さずに無視し、残りの指定で描く |
| 知らない指定の単語 | 表の種類 `unknown`・タブの `fold`・節の `hidden` | 書き方の警告を出さずに無視し、残りの指定で描く |
| 知っているキーの誤った値 | 表に無い列名・読めない `highlight=` の番号・`open=` の読めない階層・page の `scheme=foo` | 今と同じ書き方の警告を出す |
| 組み合わせの誤り | `closed` と `open` の同時指定・`closed`・`open` の無い `title=`・`+columns` の無い表の `hide=` | 今と同じ書き方の警告を出す |

対象のマーカーは、表・コードブロック・ギャラリー・ステップ・タブ・ファイルツリー・ビュー・`wide`・`page`・`section`。
`features` のマーカーの知らない機能名を無視する今の振る舞いは変えない。

`title=` の値の空白の後ろの単語（`title=My App.ts` の `App.ts`）は、知らない指定の単語として無視せず、今と同じ書き方の警告を出す。
マーカーの引数は空白で区切るため、`title=` の直後の単語は、新しいバージョンの指定であることよりタイトルの続きであることが多い。

点検（`mdmark check` の `text`・`file` と MCP の `check`）は、描画が無視した知らないキー・機能・指定を、書き方の警告とも知らないマーカーとも別のずれの種類で返却する。
知らないマーカーは、描画では通知せずに取り除き、点検ではずれとして返却している。キー・機能・指定も同じ分け方にし、`widht=` のような書き誤りを書き込む前の点検で見つけられるようにする。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| コードの行のマーカーの知らない種類（`[!code blink]`）の警告 | マーカーの引数でなく、コードの行末に記載するマーカーで、知らないマーカーは記載した文字のままコードに残る。警告を外すと、残った文字の理由が分からなくなるため含めない | 予定なし |
| 画像・動画・音声の `{…}` の知らない属性の警告 | マーカーの引数でなく、画像の後ろに記載する属性の記法のため含めない | 予定なし |
| 拡張（`registerExtension`）のマーカーの引数が Schema に合わないときの警告 | 引数のスキーマは使う側が Schema で決め、mdmark が知らないキーを決めない | 予定なし |
| ai-monitor の規約『ドキュメント管理』の `### 表の種類`・`### タブとステップ`・`### 見出しの既定の開閉` の、知らない指定で警告が出る旨の記載 | 別のリポジトリの記載で、この変更が入った後に修正する | [shuhei1101/ai-monitor#3301](https://github.com/shuhei1101/ai-monitor/issues/3301) |
| `tests/unit/src/cli/markdown-check.test.ts` の `test_read_yaml_key_when_missing` が、負荷の高いときに未処理の拒否を出す | この PR が変えないテストの不具合（全件の実行で 1 回起き、単独では起きない） | [#388](https://github.com/shuhei1101/mdmark/issues/388) |
| `tests/integration/lib/mount.browser.test.ts` の `test_normal_when_range_scripts` が、負荷の高いときに読み込みの回数を 0 と数える | この PR が変えないテストの不安定さ（一緒に実行して 1 回起き、単独と実行し直しでは起きない） | [#389](https://github.com/shuhei1101/mdmark/issues/389) |
