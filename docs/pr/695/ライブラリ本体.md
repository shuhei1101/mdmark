## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| メンバーの型の `~T~` | `parseMember` で、メンバーの文字の `~…~` を `<…>` に置き換える（入れ子は内側から）。名前（`name`）は今のまま | 補足の `notes` のキー `{クラス名}.{メンバー名}` は変わらない |
| クラスの幅 | 補足の `{クラス名}.width` があればその幅、無ければ名前とメンバーの文字の長さから決めた幅（`MAP_CLASS.width` を下限、`map.node_fit` の最大幅を上限）にする | `classPartInputs` が `size` で幅を固定しない |
| メンバーの行の高さ | メンバーの行ごとに、決めた幅で折り返した行の数を見積もり、ノードの高さと区画の行の高さに入れる | `grid-auto-rows` の固定をやめ、行ごとの高さにする |
| 関係のラベル | 置き場所の候補（最も長い区間の中ほど → 他の区間）のうち、ノード・グループのタイトル・他のラベルと重ならない位置に置く。全て重なるときは線の脇へずらす | ER 図と同じ型の処理かは設計の段で確かめる（要件.yaml のスコープ外） |
| 図の幅 | クラスの幅・ラベルを含めて図の中身の大きさを決め、図の枠の中で切れない（横にスクロールできる）ことを確かめる | 原因（中身の大きさの計算か CSS の切り取りか）は設計の段で再現して決める |
| インターフェース定義 | 制約『map のクラス図』に、メンバーの型の `<T>`・幅・折り返した行の高さ・ラベルがノードに重ならないことを書き、長いメンバーとラベルを持つクラス図の結合テストのフローを追加する | - |
| 部品設計 | CMP-596-1 に、長いメンバーと補足の `width` を持つクラスの状態を追加する | - |
| モジュール構成 | MOD-596-1・MOD-472-133 の手順とテストのケースを修正する | - |
| 単体テスト | モジュール構成に追加したケースを作る | - |
| 結合テスト | インターフェース定義に追加したフローと、部品設計に追加した状態のテストを作る | - |
