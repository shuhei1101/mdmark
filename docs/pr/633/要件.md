# 要件

## 要望

develop で `node scripts/build.ts` が配布ファイルのサイズの検査で止まらずに終了コード 0 で終わり、`tests/integration/lib/build.test.ts` の 8 件が全 pass になる。
上限を変える場合は、非機能要件・インターフェース定義・モジュール構成・開発コマンドに記載した上限の値を、`scripts/build.ts` の `MAX_DIST_FILE_BYTES` と同じ値にそろえる。

作業ブランチの分岐点の develop（[6edae01e](https://github.com/shuhei1101/mdmark/commit/6edae01e)）で測った値は次のとおり。

| 時点 | `dist/index.js`（バイト） | 上限（688,128 バイト）との差 | `build.test.ts` |
| --- | --- | --- | --- |
| Issue を起票した develop（[f79ed7d7](https://github.com/shuhei1101/mdmark/commit/f79ed7d7)） | 701,585 | 13,457 超える | 5 pass・3 fail |
| 分岐点の develop（[6edae01e](https://github.com/shuhei1101/mdmark/commit/6edae01e)） | 687,125 | 1,003 残る | 8 pass |

分岐点の develop では fail は再現しない。
ER 図の部品の廃止（[#616](https://github.com/shuhei1101/mdmark/pull/616)）などのマージで `dist/index.js` が小さくなった。
上限まで 1,003 バイトしか残らないため、`src/` に機能を追加する次の作業 PR で同じ fail が起きる。

修正の方法: 案 A（インターフェース定義設計で決定）。上限を 688KB（704,512 バイト）に上げる。分岐点の develop の 687,125 バイトに、これまでの見直しと同じ 16KB 刻みで余地を持たせた値

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 設計の時点の develop の実測から上限を上げ、非機能要件の経緯の表に行を追加する | 非機能要件の根拠に記載した「超えるときは実測を添えて上げる」決まりのとおりで、変更が値だけで済む | 上限を上げるだけで、`dist/index.js` が大きくなる流れは変わらない |
| B | 利用する文書が限られる機能を、`dist/map.js` と同じく使用するときだけ読み込む配布ファイルへ分け、上限を変えずに余地を戻す | 利用側のページが開くたびに読み込む量が減る | 分ける機能の調査とモジュール構成・インターフェース定義の変更が要り、pt 2 を超えうる |
| C | 分岐点の develop で fail が再現しないため、変更せずに Issue を閉じる | 作業が要らない | 次の作業 PR が上限を超え、同じ fail がその作業 PR に移る |

推奨: A

非機能要件は、配布ファイルを分けて小さくする方針ではなく、機能を追加して超えるたびに実測で上限を上げる方針を決めている。
B は、その方針を変える判断を含むため、この Issue の範囲を超える。
