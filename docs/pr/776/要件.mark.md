# 要件

## 要望

Claude Code プラグインの MCP サーバーとスキルごとに、knowledge のテンプレートに沿った設計書を作成し、実装を設計書に合わせる。

| 対象 | 作成する設計書 | テンプレート |
| --- | --- | --- |
| MCP サーバー（`mdmark serve`） | MCP サーバーの定義 1 枚 | `template-mcp-server` |
| スキル `global-setup` | エージェントフロー（`type: skill`）1 枚 | `template-agent-flow` |
| スキル `setup` | エージェントフロー（`type: skill`）1 枚 | `template-agent-flow` |

- 設計書を作成する前に、配信元の設定 `project-index.yaml` の `documents[]` に種類の行を、shuhei1101/ai-monitor の `docs/pr/3744/反映作業/` の作業『配布先の配信元の設定への種類の行の追加』で追加する
- MCP サーバーの定義の `tools[].interface` は、ツールごとのインターフェース定義を指す。ツールのインターフェース定義が無いツールは、インターフェース定義を作成する
- スキルの SKILL.md は、エージェントフローの設計書から作った内容と一致させる
- 終了の条件: `project-index` の `describe(source)` の種類の一覧に `mcp_server`・`agent_flow` が並び、上の 3 枚の設計書が検査に合格し、MCP サーバーの登録するツール・instructions とスキルの SKILL.md が設計書と一致する

MCP サーバーの instructions とツールの description の本文は、knowledge の規約『プロンプトファイル』に沿ってプロンプトファイルに配置し、MCP サーバーはプロンプトファイルを読み込んで描画する。
本文の Jinja の描画には外部ライブラリ『@huggingface/jinja』を使用し、未定義の変数は描画の前の検査で弾く。
