# 要件

## 要望

1. mdmark の記法で記載する文書の拡張子を `.mark.md`（例: `hoge.mark.md`）にする。拡張子が `.md` で `.mark.md` でない文書を、純粋な Markdown（純粋な `.md`）と呼ぶ
2. 純粋な `.md` も、今と同じく描画・書き出し・まとめ・点検の対象のままにする。`build.include` の既定 `**/*.md` は `.mark.md` にも該当する
3. `mdmark check`（CLI・MCP の `check`）は、純粋な `.md` の文書が mdmark の記法を含むとき、その文書と最初の記法の行を指し、拡張子を `.mark.md` に変えるよう提案するずれを出す。記法を含まない純粋な `.md` と `.mark.md` には出さない
4. 文書のフォルダの設定で、3 の提案を止められる。止めたときは 3 のずれを出さない
5. Claude Code に、利用者の指示が無い限り純粋な `.md` に mdmark の記法を使用しないことが伝わる
6. Claude Code が `.mark.md` のファイルを Write・Edit するとき、記法のルールを MCP で参照するよう案内する
7. 利用者の発言が mdmark で記載するよう指示するとき、6 と同じ案内をする
8. 6・7 の案内は、1 つのセッションで 1 回だけ出す。案内済みかはプラグインのフックがセッションごとに記録し、rule-inject に依存しない。会話を圧縮したセッションでは、圧縮の後にもう一度案内する

判定と設定はインターフェース定義設計で次のとおりに決めた（[記法のルールの参照を案内する](../../interface/IF-472-43.ts.yaml)・[設定と索引を点検する](../../interface/IF-472-39.ts.yaml)）。

| 論点 | 決めた内容 | 理由 |
| --- | --- | --- |
| 3 の「mdmark の記法を含む」の判定の範囲 | 点検が知らないマーカーの点検で取得するマーカーのうち、知っているマーカー（`check.ignore` の名前を除く）が 1 つ以上ある。GFM の記法と `mermaid` のコードブロックは数えない。ずれの種類は `plain_md_with_marks` | 点検が既に持つ読み取りで判定でき、GFM と Mermaid だけの文書を誤って指さない |
| 4 の止める設定の持ち方 | `mdmark.config.yaml` の `check.suggestMarkExtension`（真偽値、省略時は `true`）。`false` で止める | 既存の文書の移行の時機はリポジトリごとに決めるため、フォルダ単位で止めれば足りる。点検の設定は既に `check` の下にある |
| 7 の「mdmark で記載するよう指示する」の判定 | 発言が大文字・小文字を区別せずに語 `mdmark` を含む | 1 セッションに 1 回だけの案内で、余分に出ても文脈の増え方が小さい。言い回しの揺れ（音声入力 等）で取りこぼさない |
| 8 の案内の記録 | 記録のフォルダ（`MDMARK_GUIDE_NOTICE_DIR`、省略時は `{os.tmpdir()}/mdmark-guide-notice`）に `session_id` の名前の空のファイルを作り、PreCompact のフックで消す | 一時フォルダに置けば片付けが要らない。PreToolUse と UserPromptSubmit で同じ記録を使用する。圧縮で案内が文脈から落ちるため、rule-inject と同じく圧縮の後にもう一度案内する |
