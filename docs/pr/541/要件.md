# 要件

## 要望

1. mdmark の記法で記載する文書の拡張子を `.mark.md`（例: `hoge.mark.md`）にする。拡張子が `.md` で `.mark.md` でない文書を、純粋な Markdown（純粋な `.md`）と呼ぶ
2. 純粋な `.md` も、今と同じく描画・書き出し・まとめ・点検の対象のままにする。`build.include` の既定 `**/*.md` は `.mark.md` にも該当する
3. `mdmark check`（CLI・MCP の `check`）は、純粋な `.md` の文書が mdmark の記法を含むとき、その文書と最初の記法の行を指し、拡張子を `.mark.md` に変えるよう提案するずれを出す。記法を含まない純粋な `.md` と `.mark.md` には出さない
4. 文書のフォルダの設定で、3 の提案を止められる。止めたときは 3 のずれを出さない
5. Claude Code に、利用者の指示が無い限り純粋な `.md` に mdmark の記法を使用しないことが伝わる
6. Claude Code が `.mark.md` のファイルを Write・Edit するとき、記法のルールを MCP で参照するよう案内する
7. 利用者の発言が mdmark で記載するよう指示するとき、6 と同じ案内をする
8. 6・7 の案内は、1 つのセッションで 1 回だけ出す。案内済みかはプラグインのフックがセッションごとに記録し、rule-inject に依存しない

`未確定`: 3 の「mdmark の記法を含む」の判定の範囲（決める段: インターフェース定義設計）

| 案 | 内容 |
| --- | --- |
| A | 点検が既に読み取っている mdmark のマーカー（記法のマーカー・拡張のマーカー）と、mdmark の図のコードブロックのどれかがある |
| B | A に加え、mdmark だけの記法（バッジ・色の名前 など）の 1 つでもある |

推奨: A

点検が既に持つ読み取りで判定でき、GFM と Mermaid だけの文書を誤って指さないため。

`未確定`: 4 の止める設定の持ち方（決める段: インターフェース定義設計）

| 案 | 内容 |
| --- | --- |
| A | `mdmark.config.yaml` に、提案を出すかの真偽値のキーを 1 つ追加する |
| B | `mdmark.config.yaml` に、提案を出さない文書の glob の並びのキーを追加する |

推奨: A

既存の文書の移行の時機はリポジトリごとに決めるため、フォルダ単位で止めれば足りる。

`未確定`: 7 の「mdmark で記載するよう指示する」の判定（決める段: インターフェース定義設計）

| 案 | 内容 |
| --- | --- |
| A | 発言が語 `mdmark` を含む |
| B | 発言が語 `mdmark` と、記載・作成を表す語の両方を含む |

推奨: A

1 セッションに 1 回だけの案内で、余分に出ても文脈の増え方が小さい。B は言い回しの揺れ（音声入力 等）で取りこぼす。
