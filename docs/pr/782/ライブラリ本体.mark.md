## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| ドラッグ中のスクロール（#779） | ノード・グループ（タイトルの行と縁）・線の区間を押してから離すまで、文書と図の表示する枠をスクロールさせない。グループの面と余白のドラッグで図の枠の中をスクロールする操作と、指の操作は今のまま | 再現する条件はマウス・ペンで、図が図の枠より広いとき（全画面・拡大を含む）。原因は、`src/map/flow-view.ts` がドラッグを始める範囲（ノード・グループのタイトルの行と縁・線の区間）が、図の移動のドラッグ（`src/shared/zoom.interact.ts`）を始めない範囲（`dragIgnore` の文字の要素・ボタン・リンク）に入っておらず、要素のドラッグと同時に図の枠の中のスクロールも始めること。`flow-view.ts` の `preventDefault` は親の `figure` で呼ぶため、子の viewport の図の移動を止めない。止め方: map の部品がドラッグを受け持つ要素に `data-drag-owner` を付け、`attachZoom` の `dragOwner` でその上では図の移動を始めない。`startDrag` はマウス・ペンで `setPointerCapture` と `preventDefault` を呼ぶ |
| ドラッグ後の経路（#778） | 線の端はどの操作でも接続先のノードの辺に付け、L 字の線の縦の区間を接続先のノードの端より外へ動かしたら、越えた側の辺へ回り込んでつなぐ。区間を動かした後は、動かした区間の位置だけを保ち、前後の区間はノードの辺までの直角の経路で計算し直す。動かした線がつながっていないノードの上を通るときは避けない | 利用者が案 A に決めた |
| 線の上の文字（#780 No 1） | 線より長い文字は、線から離して線の横（横の線は上、縦の線は右）に配置する。軸と格子の配置の図の線の文字にも同じ表示を適用する | 利用者が案 A に決めた。線の上の文字の表示は補足のキーを変えない |
| データの印の動き（#780 No 2） | 速さを線ごとに今の 0.9〜1.1 倍の範囲で変える。同じ図を描き直しても同じ線は同じ速さにする | 利用者の回答で決めた。速さの割り振り方（線の ID から決める等）は部品設計で決める |
| データの印の見た目（#780） | 今の 8 割の大きさにし、形状（丸・四角・ひし形・三角）と色（青・緑・橙・紫・赤）を線ごとに順に使う。色を指定したノードが 1 つでもある図では、色は出発点のノードの色（指定の無いノードからは灰色）にし、形状は線ごとに順に使う。印は線の文字とノードの下に描く | 塗り方（A〜E・ランダム。既定 C）と色合い（5 つ。既定は今のアクセントの文字の色）をオプションで選べるようにし、外側の輪郭・光を含めた印の大きさはどの塗り方も塗り方 E と同じにする（利用者の回答で決めた）。オプションは設定の `map.packets` で指定し、線ごとの塗り方は補足の `packet` の `fill` で上書きする。色の並びは配色ごとに CSS 変数で持ち、利用側のテーマで上書きできるようにする。補足の `packet` の指定はこれより優先する |
| 移行の手順 | 設定の Schema（`schemas/mdmark.config.schema.json` の `map`）に、省いてよい `packets`（`fill`・`palette`）を追加する。古い設定もそのまま新しい Schema に合うため、`migrations/no-steps.yaml` に `version: next` の行を置く | 補足の `packet` の `fill`・形状 `triangle` は `schemas/` に Schema を持たないため、移行の手順は要らない |
| 同じ線を使う図 | ER 図・状態遷移図・シーケンス図・クラス図・アーキテクチャ図・C4 図の線にも、構成図と同じ振る舞いを適用する | - |
| モック | `docs/mock/components/` に線のドラッグ後の経路・線の上の文字・データの印のモックを作り、配信して利用者と確認を重ねる | - |
| テスト | 単体: ドラッグ中にスクロールしないこと・動かした後の経路・同じ長さの線の印が同じ位置に並ばないこと。結合: ストーリーの状態で線の上の文字と線の向きが見えること | - |
