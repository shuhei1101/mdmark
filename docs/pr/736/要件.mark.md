# 要件

## 要望

文書の先頭の YAML のフロントマターに記載した値を、次の 3 つに使用する。

| 使用先 | 今の決まり方 | 変えた後 |
| --- | --- | --- |
| 索引の文書のメタデータ（関連文書の一覧・ツールチップ・参照の表・点検） | 索引の `docs[]` だけ | フロントマターの値も文書のメタデータとして参照する |
| まとめた HTML の文書の一覧と帯のタイトル | 索引の `title`、無ければ本文の最初の h1、無ければファイル名 | フロントマターの `title` を候補に加える |
| 書き出した HTML のページのタイトル（`mdmark export`・`export_html`・VS Code 拡張機能の HTML への書き出し） | CLI は上と同じ。VS Code 拡張機能はファイル名 | フロントマターの `title` を候補に加える |

フロントマターが無い文書・YAML として解析できないフロントマターを持つ文書は、今と同じ決まり方で描く。
索引のキー・公開関数の引数の互換は変えない。

`未確定`: フロントマターから参照するキー（決める工程: データ設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `title`・`tags` だけを参照する | 変更が小さい | `description`・`aliases` を記載しても使用されず、索引にも記載する必要が残る |
| B | 索引の文書のキーのうち `title`・`description`・`aliases`・`tags` を参照する（`id`・`path`・`related` は参照しない） | 索引の `docs[]` に記載せずにタイトル・概要・別名・タグを持てる | 点検と参照の表が参照するキーが増える |

推奨: B

要望の「など」は索引の文書のメタデータを指すと解釈でき、`id`・`path` はファイルの場所から、`related` は相手の `id` が要るため索引に残すのが分かりやすい。

`未確定`: 索引とフロントマターの両方に値があるときの優先と、コアコンセプト『索引と被参照』の「索引が正」を変えるか（決める工程: 単一ユースケース設計。ユーザーに確認する）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 索引の値を優先し、フロントマターは索引に無いキーと索引に無い文書を補う。「索引が正」は「索引を優先する」に書き換える | 今の索引を持つ利用側の描き方が変わらない | 両方に記載した値が食い違っても、フロントマターの値は通知なしに使用されない |
| B | フロントマターの値を優先する | 文書の中の値がそのまま出る | 今の索引を持つ利用側で、フロントマターを持つ文書のタイトルが変わる |
| C | A に加え、両方に違う値があるときに点検（`checkIndex`・`mdmark check`）がずれとして通知する | A の互換を保ち、食い違いに気づける | 点検のずれの種類が増える |

推奨: C

互換を変えずに、両方に記載して食い違った値を点検で修正できるため。
