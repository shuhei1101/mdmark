## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| フロントマターの解析 | `splitFrontmatter` が返却する中身を YAML として解析し、索引の文書のキーに該当する値を取り出す。最上位がマッピングでない・解析できない中身は、値を持たないものとして扱い、描画は止めない | 参照するキーは `title`・`description`・`aliases`・`tags`（[確認ログ](./確認ログ.yaml)） |
| 索引の文書のメタデータ | 索引とフロントマターの値を合わせた文書のメタデータを、参照の表・関連文書の一覧・ツールチップ・点検に使用する | 索引の値を優先し、フロントマターは索引に無いキーと索引に無い文書を補う（[確認ログ](./確認ログ.yaml)） |
| 文書のタイトル | `documentTitle` を、索引の `title`・フロントマターの `title`・本文の最初の h1・ファイル名の順の候補で決める | まとめた HTML の文書の一覧・帯のタイトル・ページのタイトルと、`mdmark export` のページのタイトルで有効になる |
| 点検 | 索引とフロントマターの両方に違う値があるずれを `checkIndex` に追加する | [確認ログ](./確認ログ.yaml) |
| 索引の Schema | `schemas/mdmark.index.schema.json` の `docs[]` の `required` から `title` を除き、同じ commit で `migrations/no-steps.yaml` に行を置く（必須を外すだけで、古い索引もそのまま新しい Schema に合う） | 実装の工程で行う。リポジトリの CLAUDE.md「設定・索引の Schema」 |
| 参照の表 | `collectReferences` のレスポンスに、フロントマターで補った文書の並び `docs` を加え、`mount`・`render` は被参照の一覧とツールチップの関連文書にそれを使用する | インターフェース定義『参照の表を作る』 |
| CLI・MCP | `mdmark build`・`mdmark export`・`build_site`・`export_html`・`mdmark check` は、ライブラリ本体の変更に従う | - |
| 既存機能への影響 | フロントマターを持たない文書の描き方とタイトルは変えない。索引のキーと公開関数の引数の互換は変えない | - |
| 配布物のサイズ | ブラウザの配布物（`dist/index.js`）に YAML の解析器を入れない。フロントマターの解析は呼ぶ側（CLI・VS Code 拡張機能・利用側のサーバー）が `yaml` で行い、`collectReferences`・`checkIndex`・`collectMatches` は解析済みの値を `input.frontmatter` で受け取る | 測った値: 上限 729088 バイト（712KB）、develop の `dist/index.js` 717032 バイト（残り 12056 バイト）、`yaml` 2.9.1 の `parse` だけを esbuild で minify してまとめた大きさ 97776 バイト。入れると上限を超えるため |
