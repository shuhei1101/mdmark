# 要件

## 要望

- map の範囲の Mermaid の 1 行目が `mindmap` のとき、コードブロックのまま表示せず、根を中央に置いて枝を外へ広げる木の配置で描く
- map の範囲の外の `mindmap` のコードブロックも、ほかの map が描ける種類と同じく、補足の無い map の図にする
- マーカー（`map`）・Mermaid のブロック・補足（`notes`・`layout`・巡回）の記載方法と、拡大と縮小・凡例・ツールチップ・巡回の操作は、flowchart・sequenceDiagram・erDiagram・stateDiagram-v2・classDiagram・architecture-beta・C4Context と同じにする。
  種類ごとに追加するのは、読み取り・木の配置・種類に固有の機能だけにする
- 項目の形（`[四角]`・`(角丸)`・`((円))`・`))バン((`・`)雲(`・`{{六角形}}`・形の指定なし）を、記載した形で描き分ける
- 枝（子を持つ項目）は開閉と、枝の中へ入る（その項目を根にして子孫だけを描く）ができる
- 項目を選ぶと、根からその項目までの道筋と、その項目の子孫だけを強調する
- 項目を補足の `notes` で説明できる
- 読めない行は、ほかの種類と同じく描画を止めずに書き方の警告にし、補足が指す無い項目は点検のずれにする
- 描けない種類の案内の文言（描ける種類の一覧）に mindmap を加える
- 既存の種類・ER 図の部品・map の範囲の外の mermaid のコードブロック（mindmap 以外）の記載方法と描画は変えない

`未確定`: ID を書かない項目を補足の `notes` のキーで指す方法（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | ID を書いた項目は ID、書かない項目は表示する文字をキーにする。同じ文字の項目が 2 つ以上あるときは点検のずれにし、ID を書くよう案内する | Mermaid の記載のまま読み手に分かるキーになる | 同じ文字の項目には ID が要る |
| B | 根からの道筋（`根/枝/項目`）をキーにする | 同じ文字の項目も ID なしで指せる | キーが長く、枝の文字を変えると子孫のキーが全て変わる |
| C | 記載順の `n{番号}` をキーにする | 文字に依らない | 行を足すと番号がずれ、キーから項目が分からない |

推奨: A

ほかの種類も ID か表示する名前をキーにしていて、同じ文字の項目だけを点検で知らせれば、作成者は ID を足して直せる。

`未確定`: 補足の `layout`（色・座標・並び順）とノードのドラッグを、木の配置でどこまで当てるか（決める段: 単一ユースケース設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 色と閉じた状態（`collapsed`）だけを当て、座標・並び順は当てずに書き方の警告にする。ドラッグはしない | 木の配置が崩れず、並び順は Mermaid の行の順で変えられる | 項目を任意の位置へ動かせない |
| B | 色・閉じた状態・兄弟の並び順を当て、座標は書き方の警告にする。ドラッグは兄弟の間の並べ替えだけにする | 図の上で並びを変えられる | 並び順を Mermaid の行の順と補足の 2 か所で持つ |
| C | 構成図と同じく、座標・並び順・ドラッグを全て当てる | ほかの種類と操作が揃う | 動かした項目と枝の線が木の形から外れる |

推奨: A

mindmap の並び順は Mermaid の行の順そのもので、補足で 2 か所目を持つと食い違う。座標を動かすと、根から外へ広げる配置の意味が崩れる。
