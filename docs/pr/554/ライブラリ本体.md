## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 名前の置き換え | 書き出しの最後に、HTML・CSS（配布物と利用側の `theme.css`）・まとめたスクリプト（拡張のモジュールを含む）・埋め込みの JSON の全体で、語の一部として出る `mdmark` を同じ別名へ置き換える。埋め込みの Markdown では、部品の要素名・CSS 変数・`mdmark-` のクラスの形だけを置き換え、地の文の語を残す | 成り立つかは PoC 検証で確かめる |
| コメントの削除 | 書き出した HTML の本文の HTML のコメントと、埋め込みの Markdown のマーカーでない HTML のコメントを削除する。開いた後の文書にコメントのノードを残さない。Lucide のライセンスの表記は、mdmark の名前を含まない形で残す | 埋め込みの Markdown のマーカーのコメントは描画に要るため残し、#532 で埋め込みと一緒に消える |
| バージョン・ライセンス | `--mdmark-version` を、書き出した HTML から削除する。まとめたスクリプトのライセンスの注釈は、第三者のライブラリと利用者の拡張のものだけで mdmark 自身のものは無いため、そのまま残す | `## PoC 結果` の「まとめたスクリプトのライセンスの注釈の実測」 |
| 既定と開発用の指定 | 既定で隠す。CLI の `export`・`build` に隠さない書き出しの引数を追加する | 引数の名前はインターフェース定義設計で決める |
| 既存機能への影響 | 隠した書き出しでも、表示・操作・利用側の CSS・拡張が隠さない書き出しと同じに動く | 書き出しの E2E を隠した書き出しで実行する |
| 保守性 | 終わりの条件（文字列 `mdmark` と `<!--` が残らない）を、書き出した HTML を検査する結合テストで確かめる | - |

結論: 成立。
出力全体の `mdmark` を大文字・小文字の形を保って 1 つの別名へ置き換えれば、クラス名を組み立てる箇所・単独の値・`window` の鍵・ログの文を含めて、名前ごとの対応表を持たずに揃う。
利用者が記載した値は、埋め込みの JSON の項目（`index`・`references`・`aliases`・`entry`・`docs` の `title`・`path`・`docId`・`includes` のキー）で分けられ、本文だけを形で置き換えれば足りる。

設計へ渡す点:

- 本文の置き換えは、`class` の属性の値に限る。`mdmark-[a-z]` で一律に置き換えると、本文のリンクの `./mdmark-intro.md` まで変わり、文書へ移れなくなる
- マーカーでない HTML のコメントは、PoC では「`<!-- 名前 -->`・`<!-- 名前: … -->`・`<!-- /名前 -->` の形でないもの」と判定した。`<!-- todo -->` のような 1 単語のコメントはマーカーと区別できないため、実装では描画の側のマーカーの名前の一覧で判定する
- Lucide のライセンスの表記の HTML のコメント（`assembleHtml` が置く）は、隠した書き出しでは HTML のコメントにせず、スクリプトの `/*! … */` へ移す（PoC の文書ではアイコンを使用せず、出なかった）
- 別名の値は PoC では `zq`。既存の名前と衝突しない値を設計で決める

最小再現コードの要点（[poc/hide.mjs](https://github.com/shuhei1101/mdmark/blob/b4c40105f08d7ff382a52cebc42794926a262c8c/poc/hide.mjs)）:

```js
export function replaceAll(text) {
  return text.replace(/mdmark/gi, (m) =>
    m === m.toUpperCase() ? ALIAS.toUpperCase() : m[0] === "M" ? ALIAS[0].toUpperCase() + ALIAS.slice(1) : ALIAS,
  );
}
export function replaceInMarkdown(md) {
  return md
    .replace(/(<\/?)mdmark-/gi, `$1${ALIAS}-`)
    .replace(/--mdmark-/g, `--${ALIAS}-`)
    .replace(/(\bclass\s*=\s*["'])([^"']*)/gi, (_, head, value) => head + value.replace(/\bmdmark-/g, `${ALIAS}-`))
    .replace(/\bmdmark-asset:/g, `${ALIAS}-asset:`);
}
// hide: payload の利用者が記載した値を除いて replaceAll、本文は replaceInMarkdown、
// 残りの HTML・CSS・スクリプトは :root{--mdmark-version:…} と <!-- … --> を削除してから replaceAll
```

### まとめたスクリプトのライセンスの注釈の実測

`createViewerEntry`（`view: true`、`/*! greet-ext (c) user - MIT */` を持つ拡張 1 つ）を `bundleViewer` でまとめ、戻り値の `/*! … */` を取り出した（今の `dist/`、commit 4fabd371）。

| 順 | 注釈 | 入口 |
| --- | --- | --- |
| 1 | `/*! greet-ext (c) user - MIT */` | 利用者の拡張（そのまま 1 つ） |
| 2 | `/*! Bundled license information: … */` | `is-plain-object/dist/is-plain-object.js`・`lucide/dist/esm/icons/*.mjs`・`lucide/dist/esm/lucide.mjs`・`markdown-it/dist/markdown-it.mjs`（`dist/viewer.js` の注釈） |
| 3 | `/*! Bundled license information: … */` | `lucide/dist/esm/lucide.mjs`（`dist/view.js` の注釈） |

- 入口のパスに `node_modules/` は付かない
- 配布物の注釈は入れ子にならず、配布物ごとに 1 つの注釈として並ぶ
- 3 つの注釈のどれにも `mdmark` が無く、mdmark 自身のファイルの入口も無い
