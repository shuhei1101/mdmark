# 要件

## 要望

HTML の書き出し（CLI の `export`・`build`、MCP の `export_html`・`build_site`）は、指定が無くても、書き出した HTML から mdmark を使用していることを読み取れなくする（D-453 No 1・7）。

| 対象 | 書き出した HTML での扱い | 出典 |
| --- | --- | --- |
| CSS のクラス名・CSS 変数の名前・スクリプトの関数名・要素の `id`・`data-` 属性に出る mdmark の名前 | 書き出しのときに短い別名へ置き換える | D-453 No 2 |
| HTML のコメントとマーカーのコメント | 全て削除する | D-453 No 3 |
| mdmark のバージョンの情報（`--mdmark-version` など）と mdmark 自身のライセンスの表記 | 削除する | D-453 No 4 |
| 同梱する第三者のライブラリ（Mermaid・Lucide など）のライセンスの表記 | 残す | D-453 No 4 |

- 終わりの条件: 既定で書き出した HTML（`export`・`build` の両方）の中に、文字列 `mdmark`（大文字・小文字を区別しない）が、残すと決めた第三者のライブラリのライセンスの表記と、利用者が書いた文書の本文の中を除いて現れない。HTML のコメントが `<!--` の形で現れない
- 書き出した HTML の表示と操作（目次・タブ・表の並べ替え・図・文書の行き来など）は、隠さない書き出しと同じに動く
- 利用側の `theme.css` と拡張のモジュールが参照する mdmark の名前も同じ別名へ置き換え、今の上書きと拡張がそのまま効く（破壊的変更にしない）
- 開発のときだけ、CLI の引数と MCP の引数で、隠さない書き出しを指定できる

`未確定`: 名前の置き換えの方法（決める段: PoC 検証）

| 案 | 内容 |
| --- | --- |
| A | 書き出しのときに、出力の CSS・スクリプト・HTML・埋め込みの JSON の全体で、`mdmark` を含む名前を 1 つの対応表で短い別名へ置き換える |
| B | 配布物のビルドで名前を置き換えた別の配布物を作り、書き出しはそれを埋め込む |

推奨: A

利用側の `theme.css`・拡張のモジュールも書き出しのときに同じ対応表で置き換えられ、配布物を 2 つ持たずに済むため。
