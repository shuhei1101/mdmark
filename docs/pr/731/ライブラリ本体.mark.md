### 設計書の行の alias_type の判定

`alias_type` は行の全ての文書の `name` と `aliases` を照合の単語にするため、登録しない名前を 1 つでも持つ行には付けない。

| 行 | 判定 | 判定表で該当した条件と例 |
| --- | --- | --- |
| data | 付ける | 名前が全て「データ: 」で始まり、重複も短い単語も無い |
| architecture | 付けない | ほかの文書の name に既にある: 「アーキテクチャ図」は knowledge・project-index・rule-inject などの配信元の文書の name として照合されている |
| config | 付ける | 名前が全て「設定: 」で始まる |
| er | 付ける | 名前が全て「ER 図: 」で始まる |
| test_procedure | 付けない | ほかの文書の name に既にある: 「テスト実行方法」は knowledge・project-index・rule-inject などの配信元の文書の name として照合されている |
| dev_command | 付けない | ほかの文書の name に既にある: 「開発コマンド」は knowledge・project-index・rule-inject などの配信元の文書の name として照合されている |
| nonfunctional | 付けない | ほかの文書の name に既にある: 「非機能要件」は knowledge・project-index・rule-inject などの配信元の文書の name として照合されている |
| scenario | 付けない | 一般語: 「図を描く」「文書を描く」「HTMLに書き出す」など、本文の一般の文に出る動詞句で、同じ名前のガイドとインターフェース定義もある |
| interface | 付けない | ほかの文書の name に既にある: 「複数の文書を1枚のHTMLにまとめる」「PDFに印刷する」など 14 件が scenario と同じ名前 |
| module | 付けない | ほかの文書の name に既にある: `ライブラリ本体 / ビューとコメント / spec.ts` など 3 件が同じ名前 |
| component | 付けない | 1〜2 文字・一般語: 「表」「キー」「タブ」「目次」「カード」「ビュー」 |
| screen | 付けない | 1〜2 文字: 「文書」 |
| external_api | 付けない | 一般語: 「GitHub」 |
| library | 付けない | 一般語: 「react」「yaml」「diff」「typescript」など、本文に道具の名前として出る |
| layout | 付けない | 一般語: 「mdmark」 |

AI slop の対応表にヒットするが、用語集の用語・部品の名前・キーの名前として使用しているため、置き換えずに判定フローチャート『用語の登録』で判定した単語。

| 単語 | 使用している箇所の例 | 判定 |
