# 要件

## 要望

`docs/` の設計書（`docs/*/*.yaml`）・ガイド（`docs/guide/`）・PR ドキュメント（`docs/pr/`）で、次の 2 つを実施する。

| 作業 | 終了の条件 |
| --- | --- |
| 文の削除と AI slop の修正 | 既出の言い直し・理由の説明・当たり前の注意を削除し、残す文が規約『文章の書き方』の確認表と AI slop の単語の対応表に当てはまらない |
| エイリアスと用語の登録 | 判定フローチャート『エイリアスの登録』『用語の登録』で登録すると判定した名前が、設計書の `aliases` と、`alias_type` を持つ用語集の行に入っている |

- 設計書の対象は `docs/` の種類のフォルダ（architecture・component・config・data・dev-command・er・external-api・interface・layout・library・module・nonfunctional・scenario・screen・test-procedure）の全ての YAML
- PR ドキュメントでは、規約『表し方の優先順位』の `hidden-content-04`（経緯・履歴の削除）を適用しない
- 文書の種類ごとにコミットとレビューを分けて進める
- 設計書の書き込みは `write_docs` で行い、Schema の検査に合格させる

用語集は、用語の YAML `docs/guide/用語集.yaml` を原本にし、`project-index.yaml` の `records: terms`・`alias_type: term` の行で配信する。`用語集.mark.md` の表は残す（確認ログ『用語集の持ち方』）。

AI slop の単語は、設計書・ガイドだけを文書ごとに判断して置き換え、PR ドキュメントには対応表を適用しない（文の削除だけにする。確認ログ『AI slop の単語の置き換えの範囲』）。
