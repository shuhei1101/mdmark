# 要件

## 要望

`docs/` の設計書（`docs/*/*.yaml`）・ガイド（`docs/guide/`）・PR ドキュメント（`docs/pr/`）で、次の 2 つを実施する。

| 作業 | 終了の条件 |
| --- | --- |
| 文の削除と AI slop の修正 | 既出の言い直し・理由の説明・当たり前の注意を削除し、残す文が規約『文章の書き方』の確認表と AI slop の単語の対応表に当てはまらない |
| エイリアスと用語の登録 | 判定フローチャート『エイリアスの登録』『用語の登録』で登録すると判定した名前が、設計書の `aliases` と、`alias_type` を持つ用語集の行に入っている |

- 設計書の対象は `docs/` の種類のフォルダ（architecture・component・config・data・dev-command・er・external-api・interface・layout・library・module・nonfunctional・scenario・screen・test-procedure）の全ての YAML
- PR ドキュメントでは、規約『表し方の優先順位』の `hidden-content-04`（経緯・履歴の削除）を適用しない
- 文書の種類ごとにコミットとレビューを分けて進める
- 設計書の書き込みは `write_docs` で行い、Schema の検査に合格させる

`未確定`: 用語集の持ち方（決める工程: ドキュメント修正）

`alias_type` の行は YAML のレコードを参照するため、Markdown の表の `docs/guide/用語集.mark.md` はそのままでは配信の用語集にできない。
mdmark は YAML から表を描けない（設定の `aliases` は YAML から下線とツールチップを作るだけ）。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 用語の YAML `docs/guide/用語集.yaml`（`terms[]` に用語・別名・意味）を新設し、`project-index.yaml` に `records: terms` の `alias_type` の行を追加する。`用語集.mark.md` の表は残す | このリポジトリの文書だけで終わる。knowledge の用語集（`docs/terms.yaml` を `alias_type: term` の行で配信）と同じ持ち方になる | 同じ用語を YAML と表の 2 か所で持つ |
| B | `用語集.mark.md` の表だけを持ち、`alias_type` の行を作らない | 用語を 1 か所で持つ | 要望の「用語集（`alias_type`）への登録」を満たさない |
| C | mdmark に YAML から用語集の表を描く機能を追加し、YAML だけを原本にする | 用語を 1 か所で持つ | コードの変更が要り、この PR の工程（文書だけ）を超える |

推奨: A

要望の終了の条件を満たせるのは A と C で、C はコードの設計と実装の工程が要る。
2 か所で持つずれは、C を別の Issue にして解消する。

`未確定`: AI slop の単語の置き換えの範囲（決める工程: ドキュメント修正）

knowledge の対応表 `word-list-ai-slop` のパターンにヒットする箇所は、設計書・ガイドで約 6,200 件、PR ドキュメントで約 16,600 件ある。
上位は「帯」（759 件）・「読む」（598 件）・「〜の枠」（530 件）・「直す」（479 件）・「書く」（462 件）で、「帯」「〜の枠」「地」は部品の名前（「案内の帯」「図の枠」）や配色の呼び名として使用している。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 設計書・ガイド・PR ドキュメントの全てで、ヒットした箇所を文書ごとに判断して OK の単語へ置き換える。部品の名前の単語は判定フローチャート『用語の登録』に回し、置き換えない | 要望の終了の条件どおり | 約 22,800 件を判断する。PR ドキュメントはマージ済みの作業の記録で、置き換えても読み手の判断が変わらない |
| B | 設計書・ガイド（約 6,200 件）だけを A と同じく置き換え、PR ドキュメントには対応表を適用しない（文の削除だけにする） | 今後参照される原本だけを修正する | 要望の「PR ドキュメントで AI slop を修正する」を除く |
| C | 動詞（直す・書く・読む・足す・外す など）だけを置き換え、名詞（帯・枠・地・印・段 など）は残す | 部品の名前を壊さずに機械的に進められる | 名詞の NG の単語が残り、対応表に当てはまらない状態にならない |

推奨: B

PR ドキュメントはマージ済みの作業の記録で、置き換えても今後の作業の判断は変わらない。
設計書・ガイドは今後の作業で参照される原本なので、A と同じく文書ごとに判断して置き換える。
