# 要件

## 要望

E2E で VS Code（1.141.0）を取得するのは、Playwright のワーカーがテストを流し始める前の 1 回だけにする。
ワーカーの中のテストは、取得済みの VS Code の実行ファイルの場所を使い、`downloadAndUnzipVSCode` を呼ばない。
取得はキャッシュの場所（`vscode/.vscode-test`）とバージョンを今と変えず、キャッシュが揃っていれば取り直さない。

テスト実行方法の E2E の説明と前提を、VS Code の取得がワーカーの前に 1 回だけ行われることに合わせる。
前提にある `npm --prefix vscode ci` の行は残す。

完了の基準は、`vscode/.vscode-test` を消した状態から、VS Code を起動する 8 つの spec（複合 1・単一 7）を Chromium のプロジェクトで並列のワーカーのまま流し、30 テストが全て pass すること。
流した後のキャッシュに、取得した VS Code が欠けずに揃っている（`icudtl.dat` がある）ことも確かめる。

| 対象箇所 | commit | 目的 | 変更回数 | 影響 |

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 直下の `npm ci` だけで `npm run typecheck` が通らない（`tests/e2e/vscode.ts` が `vscode/` の依存の型を引く） | 型検査の依存の不足で、VS Code の取得の競合とは別の事象 | [#91](https://github.com/shuhei1101/mdmark/issues/91) |
| 既に壊れて完了扱いになったキャッシュを見つけて取り直す | 取得を 1 回にすれば壊れた展開は生まれない。今回の E2E で壊れたキャッシュは tester が消して取り直している | 予定なし |
| VS Code 拡張機能の結合テスト（`vscode/tests/integration/run.ts` の `runTests`）の取得 | 1 つのプロセスで順に取得し、並列のワーカーから取りに行かない | 予定なし |
