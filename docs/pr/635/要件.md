### #581: VS Code 拡張機能のテスト

フォルダを移したら、テストのパスを記載した次の箇所を移した後のパスに合わせる。

- テストの設定: `vitest.config.ts`・`vscode/package.json` の `test:integration`・`vscode/scripts/build.ts` の結合テストのまとめ方・`vscode/tests/integration/run.ts` の import
- 管理用の YAML: `tests/files.yaml`・`vscode/files.yaml`
- 設計書: フォルダ構成（LAY-472-1）・テスト実行方法（TP-472-1）・テストのパスを記載したモジュール構成・部品設計・外部ライブラリの設計書

テストの中身は変えない。移した後も、移す前と同じテストが同じ件数で pass する。

`未確定`: VS Code の上で動かす拡張機能の結合テスト（`vscode/tests/integration/`）の置き場所（決める段: モジュール構成設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `tests/integration/vscode/` へ移し、Webview の部品のストーリーの結合テストと同じフォルダの下にまとめる。単体（`tests/unit/vscode/`）と結合（`tests/integration/vscode/`）の 2 か所は、ほかの対象と同じ層の分け方として残す | テストは `tests/` に置くというリポジトリの分け方にそろう | `vscode/scripts/build.ts` が `vscode/` の外のテストをまとめる。Vitest の `integration-node` の `include` から外す指定が要る |
| B | `vscode/tests/integration/` に残し、VS Code の上で mocha で動かすため `vscode/` の中に置く理由を LAY-472-1 に記載する | テストの設定とビルドを変えない | 置き場所は 3 か所のまま残る |

推奨: A

`vscode/tests/integration/run.ts` は既に `tests/integration/built-root.ts` を import しており、`tests/` の補助のコードに依存している。単体と結合の層の分け方は他の対象と同じで「同じ種類が散る」に当たらず、残る散らばりは VS Code の上で動かす結合テストだけになる。
