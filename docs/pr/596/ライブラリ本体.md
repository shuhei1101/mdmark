## 変更方針

<!-- table: {"kind": "data"} -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 種類の判定 | Mermaid の 1 行目の `classDiagram`・`architecture-beta`・`C4Context` を map の種類にする | マーカーは map のまま |
| 読み取り | 種類ごとに、項目・項目どうしのつながり・入れ子を、erDiagram・stateDiagram-v2 の読み取りと同じ戻り値の構造で読み取る。読めない行は項目にして返す | - |
| 共通の部分 | #531 で作った種類に依らない部分（補足の notes・layout・巡回、拡大と縮小・凡例・ツールチップ・中へ入る・開閉・選択の状態の保存）と構成図への差し込み `MapFlowExtension` を使用し、種類ごとの読み取り・配置・固有の機能だけを追加する | 共通の部分に足りないものは、モジュール構成設計で共通の側に追加する |
| 配置 | クラス図・アーキテクチャ図・C4 図は今の入れ子の自動配置で描き、補足の `layout` とドラッグも構成図と同じ規則で当てる。アーキテクチャ図の線の辺の指定と C4 図の `Rel_D` などの向きは配置の初期の指定にし、`layout` の指定があればそちらを優先する | - |
| 種類に固有の機能 | 項目を選ぶと関わる項目とつながりだけを強調し、2 つ選ぶとつなぐ最短の経路だけを残す。クラス図はメンバーを開閉する | - |
| 点検 | 補足が指す項目の ID（クラス名・`{クラス名}.{メンバー名}`・service と group の ID・要素と境界の別名・関係と線の記載順の `r{番号}`）の照合を、今の書き方の警告と点検のずれに加える | キーの構造は ER 図『map の補足』で決める |
| 既存機能への影響 | flowchart・sequenceDiagram・erDiagram・stateDiagram-v2・ER 図の部品・map の範囲外の mermaid のコードブロックの記載方法と描画を変えない | 破壊的変更は付けない |
| アクセシビリティ | 項目の選択を、今の map と同じキー操作で行う | - |
