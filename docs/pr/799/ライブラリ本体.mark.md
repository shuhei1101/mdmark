## 変更方針

<!-- table: {"kind": "data"} -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 対象の部品 | ビュー・コメント・グラフ・操作できる部品・map の図をカスタム要素にする | [要件](./要件.mark.md) の決定のとおり |
| 複合 UC | アプリの画面が配布物を `@0` で読み込み、部品のカスタム要素にアプリのデータを指定して描き、操作をイベントで受け取って保存する流れを新規の複合 UC にする | - |
| 単一 UC | 部品のカスタム要素でデータを描き、操作をイベントで受け取る単一 UC を 1 つ新規に作り、部品ごとにシナリオを分ける | - |
| データ | プロパティで指定する構造は、今の公開の型（`MdmarkViewOptions`・`MdmarkCommentStore`・`MdmarkChartDefinition`・`MdmarkParamDefinition` など）を使用し、新規の構造だけをデータの設計書に記載する | 同じ構造を 2 つ持たない |
| インターフェース | タグの名前・プロパティ・属性・イベントの名前と `detail`・誤りの通知を、部品ごとにインターフェース定義に新規で記載する | 文書の埋め込んだ HTML で使用している `<mdmark-chart>` などの名前と重ならないようにする |
| 描画の処理 | 今の `mountView`・`mountComments`・図の部品の描画の処理を再利用し、文書のマーカーで描いたものと同じ外観と操作にする | 同じ処理を 2 つ持たない |
| 部品設計 | 追加する要素から描いた状態とイベントを部品設計に追加し、Storybook のストーリーを追加する | - |
| 配布 | `src/elements.ts` の `ELEMENT_DEFINERS` に部品ごとの登録の関数を加え、`dist/index.js` を読み込むと登録する。ビュー・コメント・map の部品のモジュールは今と同じく使用したときにだけ読み込む | 配布ファイルを分けるかはモジュール構成設計で決める |
| 既存機能への影響 | `mount`・`render`・`mountView`・`mountComments`・`<mdmark-table>`・文書のマーカーと埋め込んだ HTML の部品の外観と操作を変えない | 単一 UC『部品をJavaScriptから使用する』『チャートを描く』『表をカスタム要素で描く』の E2E で確認する |
| セキュリティ | 指定した値は文字として出し、HTML として解釈しない | - |
| アクセシビリティ | 操作をキーボードで行える（今の部品と同じ） | - |
| ガイド | 使用方法のページを `docs/guide/` に新規で作り、リファレンスの API と用語集に追加する | 索引の行は [Claude Code プラグイン](./ClaudeCodeプラグイン.mark.md) |
