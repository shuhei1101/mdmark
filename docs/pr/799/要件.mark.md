# 要件

## 要望

アプリの画面が、mdmark の配布物を読み込んで部品のカスタム要素を配置し、データを JavaScript のプロパティで指定すると、文書のマーカーで描いたときと同じ外観と操作の部品が描かれる。

<!-- table: {"kind": "data"} -->

| 項目 | 要件 |
| --- | --- |
| 対象の部品 | ビュー・コメント・グラフ・操作できる部品・map の図をカスタム要素にする |
| 指定 | データは JavaScript のプロパティで指定する。プロパティを指定し直すと部品を描き直す。値は文字として出し、HTML として解釈しない |
| 操作の通知 | アプリの処理（保存する・詳細を開く・値を受け取る）に結び付く操作を、要素の `CustomEvent` で通知する。イベントは操作した対象を特定できる値を持つ。表示だけの操作（ビューの切り替え・並べ替え・絞り込み）は要素の中で完結する |
| 配布 | `<mdmark-table>` と同じ jsDelivr の URL から読み込み、`@0` で追従する。配布物を読み込むと `src/elements.ts` の登録の並びから登録する |
| 誤りの扱い | 指定に誤りがあると、例外を投げずに要素の中に通知を出し、ページのほかの要素は動く（`<mdmark-table>` と同じ） |
| 今の公開関数 | `mount`・`render`・`mountView`・`mountComments`・`<mdmark-table>` と、文書のマーカー・埋め込んだ HTML の部品の外観と操作を変えない |
| ガイド | エージェントが部品のカスタム要素の使用方法を、配信元 `mdmark` のタグ `topic:ガイド` のページ（`plugin/guide-index.yaml` の行）として参照できる |

<!-- /table -->

タグの名前・プロパティとイベントの名前は、インターフェース定義設計・部品設計で決定する。

| 項目 | 決定 |
| --- | --- |
| 対象の部品 | ビュー・コメント・グラフ・操作できる部品・map の図の全てをカスタム要素にする（要望が図を名指ししており、図の部品も部品の定義をデータとして指定すれば描けるため。複合ユースケース設計で決定） |
