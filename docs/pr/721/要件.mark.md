# 要件

## 要望

map の構成図・状態遷移図で、大きさの上書き（`overrides` の `size`）を持たないノードの大きさの見積もりを、描いたフォントの名前の幅と、形状ごとの左右の余白で見積もる。

- 描いたノードの名前の行の数が、見積もりの行の数と一致する（Chromium の「文書の Markdown」、Windows の Edge の「注文の明細を月ごとに集計する」を含む）
- 1 行に収まる名前のノードの幅は、描いた名前の幅に左右の余白と枠線を加えた幅（`MAP_LAYOUT.minWidth` から最大の幅まで）になる
- `pill` の形状のノードは、左の余白を `src/index.css` の 16px で見積もる。他の形状は今の左の余白（`LABEL_METRICS.padX`）のまま
- 描いたノードを測る処理（`src/map/flow-view.ts` の `measure`）を通らないストーリーでも、名前の最後の行の下に、下の余白より広い空きができない
- 半角を文字の大きさの 0.6 倍とみなす同じ型の見積もり（`src/map/class-diagram.ts` の `nameWidth` と、`textWidth`・`splitLines` を使用する `noteSize`）も同じ見積もりにする
- 名前の幅で見積もらない大きさの上書きを持つノード（ER 図のテーブル、C4 図の要素、状態遷移図の開始・終了・分岐、閉じたグループ）の大きさは変えない

`未確定`: 描いたフォントの名前の幅の求め方（決める段: モジュール構成設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | ブラウザで描くときは、ノードの名前と同じフォントで Canvas の `measureText` で名前の幅を測る。測れない環境では今の見積もりを使用する | フォントによらず描画と同じ幅になる | 配置の前に名前の幅を測るインターフェースが要る |
| B | 半角の倍率（0.6）を描画に近い値へ変える | 変更が値 1 つで済む | フォントごとの差は残り、Edge のように狭く描かれる環境では見積もりの行の数が多いまま |

推奨: A

フォントは利用側のテーマ（`--mdmark-font-body`）で変わるため、固定の倍率では描画と合わせられない。
