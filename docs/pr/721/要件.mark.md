# 要件

## 要望

map の構成図・状態遷移図で、大きさの上書き（`overrides` の `size`）を持たないノードの大きさの見積もりを、描いたフォントの名前の幅と、形状ごとの左右の余白で見積もる。

- 描いたノードの名前の行の数が、見積もりの行の数と一致する（Chromium の「文書の Markdown」、Windows の Edge の「注文の明細を月ごとに集計する」を含む）
- 1 行に収まる名前のノードの幅は、描いた名前の幅に左右の余白と枠線を加えた幅（`MAP_LAYOUT.minWidth` から最大の幅まで）になる
- `pill` の形状のノードは、左の余白を `src/index.css` の 16px で見積もる。他の形状は今の左の余白（`LABEL_METRICS.padX`）のまま
- 半角を文字の大きさの 0.6 倍とみなす同じ型の見積もり（`src/map/class-diagram.ts` の `nameWidth` と、`textWidth`・`splitLines` を使用する `noteSize`）も同じ見積もりにする。`nameWidth` を使用するクラスの幅が変わるのは `map.node_fit: width` のときだけで、既定の `height` ではクラスの幅は名前によらず `MAP_CLASS.width`（220px）のまま
- 名前の幅で見積もらない大きさの上書きを持つノード（ER 図のテーブル、C4 図の要素、状態遷移図の開始・終了・分岐、閉じたグループ）の大きさは変えない

名前の幅は、ブラウザで描くとき（`mount`）に、ノードの名前と同じフォントで canvas の `measureText` で測る。
DOM を持たない呼び出し（部品の描画のサーバー・単体テスト）は、今の見積もり（全角を文字の大きさ、半角を 0.6 倍）を明示して指定する（モジュール構成設計で、半角の倍率を変える案と比べて決定した。フォントは利用側のテーマ（`--mdmark-font-body`）で変わり、固定の倍率では描画と合わせられない）。

`未確定`: Storybook のストーリーの描画（決める段: モジュール構成設計のレビューの後のユーザーの確認）

ストーリーは部品の描画のサーバー（`scripts/storybook-render.ts`）が Node で配置して HTML を返すため、描くフォントを測れず、今の見積もりのまま配置する。
Issue の事象のうち、Windows の Edge で描画が見積もりより狭く、ストーリーで名前の下が空く事象は、この作業 PR の修正だけでは残る。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | ストーリーは今の見積もりのまま配置し、ストーリーの名前の下の空きはスコープ外にする | 部品の描画のサーバーの作りを変えない | ストーリーでは、フォントによって名前の下が空く・名前が見積もりより多く折り返す。部品設計の状態 MeasuredName のストーリーも今の見積もりで配置され、Chromium では「文書の Markdown」が 2 行に折り返して状態の記述どおりに描かれない（状態の定義を `mount` で描いたものに限り、再現の見本はストーリーでは直らないことの確認に変える） |
| B | ストーリーのページでも描いた後に名前の幅を測って配置し直す処理を読み込む | ストーリーも描画と同じ大きさになる | 部品の描画のサーバーが返す HTML に配置の処理を加える変更が増える |

推奨: A

利用者が読む文書は `mount` で描くため、修正の効果は利用者の画面に届く。ストーリーは部品の状態の確認に使用し、名前の下の空きは状態の確認を妨げない。
