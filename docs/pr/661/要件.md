# 要件

## 要望

[project-index.yaml](https://github.com/shuhei1101/mdmark/blob/4c455f92/project-index.yaml) に `nav` を記載し、dev-docs の画面の配信元 `mdmark` のタブとサイドバーを、knowledge の規約『開発ドキュメントのナビゲーション』（`dev-docs-navigation`）に合わせる。

| 基準 | 値 |
| --- | --- |
| タブの数 | 7 件以下 |
| タブの並び | はじめに・使い方・設計書・規約・コード・リファレンス・用語集の順。配信元に文書が無いタブは配置しない |
| 設計書 | タブ「設計書」1 つにまとめ、設計書の種類をサイドバーのグループにする |
| サイドバー | 各タブの文書をグループにまとめ、入れ子は 2 階層まで |
| グループの中の並び | 手順の順か重要さの順。名前の順は、名前を知っている文書を探す一覧（用語集など）だけ |
| 目次 | フォルダの目次（`kind: index`）をタブとサイドバーに並べない |
| `nav` の点検 | project-index の `check_project` が `nav` の警告・違反を返却しない |

公開ドキュメントの文書は `docs/guide/files.yml` の行の `category`（はじめに・使用方法・リファレンス）でタブに分ける。

`nav` を記載した後、dev-docs の画面をスクリーンショットで確認し、reviewer の確認を受ける（[shuhei1101/ai-monitor#3509](https://github.com/shuhei1101/ai-monitor/issues/3509)）。
撮る画面は次のとおり。

- タブの並びと数
- タブごとのサイドバーのグループ
- 目次と、参照する人が開かない内部のファイルが出ていないこと
- 文書をスクロールした状態

## 画面での確認

dev-docs は端末の設定の配信元 `mdmark` が指す develop の `project-index.yaml` から `nav` を参照するため、作業ブランチの `project-index.yaml` を指す仮の配信元 `mdmark-pr661`（`storage.type: disk`）を端末の設定に登録して撮った。

## テスト結果

関係する単体・結合テストは無い。変更は配信の設定・管理用の YAML の `name`・設計書の文で、mdmark のコードとテストが読むファイルを変えない。
