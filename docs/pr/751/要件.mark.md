| [#743](https://github.com/shuhei1101/mdmark/issues/743) | `docs/guide/files.yml` のガイドのページの名前ごとに、knowledge の判定フローチャート『エイリアスの登録』と判定表『エイリアスを登録しない条件』で登録するかを判定し、登録するページの行に `id`・`aliases` を記載する。`project-index.yaml` の `id: docs` の行に `alias_type: doc` を付ける | 判定フローチャート『エイリアスの登録』と判定表『エイリアスを登録しない条件』で登録すると判定したガイドのページの `docs/guide/files.yml` の行が `id`・`aliases` を持ち、`project-index.yaml` の `id: docs` の行が `alias_type` を持つ |

- #743 の行の書式は、`docs/guide/files.yml` が参照する knowledge の `design-schemas/v8.4.0` の `schemas/knowledge-files.schema.yaml` が既に持つ `id`・`aliases`・`inject_when` を使用し、スキーマは変えない
- ガイドのページには、シナリオ・インターフェース定義と同じ名前のページ（「文書を描く」「図を描く」など）と、一般語の名前のページ（「設定」「API」「CLI」「記法」「索引」など）がある。これらは判定表の「複数の文書や用語に当てはまる一般語」「ほかの文書・用語の name か aliases に既にある」の行で判定する
- 登録したガイドのページが、project-index の `list_match_words`（`source: mdmark`）の結果に `alias_type: doc` で出ることを確認する

登録しないと判定したページの行の扱いは、ドキュメント修正で次のとおり決めた（[ライブラリ本体](./ライブラリ本体.mark.md) の `## 変更方針`）。

- `alias_type` は行に付くため、`id` の無い行は project-index の点検でエイリアスのキーの違反になり、配信元の警告に残り続ける。全ての行に `id` を記載する
- 一般語・2 文字の名前・用語と同じ名前のページは、`inject_when` に本文が `mdmark` を含む条件を記載し、alias-inject がその文脈でだけ案内するようにする（判定表の注 n4「候補がタイトルなら、照合条件の記載で判定を終える」）
