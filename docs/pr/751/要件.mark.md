- #743 の行の書式は、`docs/guide/files.yml` が参照する knowledge の `design-schemas/v8.4.0` の `schemas/knowledge-files.schema.yaml` が既に持つ `id`・`aliases`・`inject_when` を使用し、スキーマは変えない
- ガイドのページには、シナリオ・インターフェース定義と同じ名前のページ（「文書を描く」「図を描く」など）と、一般語の名前のページ（「設定」「API」「CLI」「記法」「索引」など）がある。これらは判定表の「複数の文書や用語に当てはまる一般語」「ほかの文書・用語の name か aliases に既にある」の行で判定する
- 登録したガイドのページが、project-index の `list_match_words`（`source: mdmark`）の結果に `alias_type: doc` で出ることを確認する

`未確定`: 登録しないと判定したページの行の扱い（決める段: ドキュメント修正）

`alias_type` を付けた行の文書は、`name` と `aliases` の両方が照合の単語になる。
alias-inject は `id` が空の文書を照合の単語から除外し、除外した文書を読み込めない理由の一覧に挙げる。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 登録すると判定したページの行だけに `id` を記載し、他の行は `id` を持たない | 登録しないページの名前が照合に出ない | alias-inject・project-index が `id` の無い行を読み込めない理由に挙げるなら、警告が行の数だけ出る |
| B | 全ての行に `id` を記載し、一般語の名前のページには `inject_when` で照合する文脈を記載する | 警告が出ない | 一般語の名前のページの文脈を決めきれないと、関係ない入力にもガイドの文脈が入る |

推奨: A

終了の条件が「登録すると判定したページの行が `id`・`aliases` を持つ」で、判定表は一般語のタイトルを、特定の文脈でだけ指すときに限って照合条件で残す。
`id` の無い行を読み込めない理由に挙げるかは、ドキュメント修正で `list_match_words` と alias-inject の結果を参照して確認し、挙げるならその行に `inject_when` を記載する案 B へ切り替える。
