## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 開発コマンドの配布ファイルの上限 | `CMD-472-1.yaml` の「ビルド・生成」の `effects` の `688KB` を `712KB` に置き換える。文のほかの部分は変えない | - |
| `files.yml` の行の `id` | 全ての行に `guide-{分類}-{英語のスラッグ}` の `id` を記載する | `alias_type` は行に付くため、`id` の無い行は project-index の点検でエイリアスのキーの違反（`id` が無い）になる |
| `files.yml` の行の `aliases` | `### エイリアスの判定` で登録すると判定した別名を記載する | - |
| `files.yml` の行の `inject_when` | `### エイリアスの判定` で照合条件を記載すると判定したページに、本文が `mdmark` を含む条件（`field: text`・`op: contains`・`values: [mdmark]`）を記載する | - |
| `project-index.yaml` の `docs` の行 | `id: docs` の行に `alias_type: doc` を付ける | - |
| `project-index.yaml` の `nav` | ガイドのページの `page` を `docs/docs/guide/{パス}` から `docs/{id}` に書き換える | `page` は `{行の ID}/{文書の ID}` で、文書の ID が `id` の値に変わるため |
| 照合の確認 | project-index の `list_match_words`（`source: mdmark`・作業ブランチの worktree）で、全てのガイドのページの名前と別名が `docs` の行から出ることと、`describe` の配信元の警告が増えないことを確認する | 確認済み |

### エイリアスの判定

候補は、ページの名前と、master の公開ドキュメントの目次（AI Monitor のドキュメント索引に注入される名前）に残る改名前の名前。
判定表『エイリアスを登録しない条件』の行を上から適用した結果を並べる。

## テスト結果

コードを変えず、設計書の値・管理用の YAML のメタデータ・配信の設定だけを変えるため、規約『V字モデル』の対応表で関係する単体・結合テストは無い。
