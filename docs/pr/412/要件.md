# 要件

## 要望

Sprint v0.10.0 の E2E で fail した図の部品の 8 件を、ケースごとに実装とテストのどちらが設計書（シナリオ・部品設計『図の枠』『フロー図』『グラフ』『図のツールチップ』）と食い違うかを切り分け、食い違う側を修正する。
8 件が release ブランチの E2E で全て pass し、同じテストファイルの他のケースも fail しないことを終わりの条件にする。

<!-- table: data -->

| ケース | テスト | 終わりの条件 |
| --- | --- | --- |
| 単一ユースケース『図を拡大・縮小・移動する』 | `test_normal_when_drag_on_linked_node` | リンクを持つノードの上から始めたドラッグで図が動き、動いた量が 95 を超える |
| 同上 | `test_normal_when_drag_on_chart_item` | グラフの項目の上から始めたドラッグで図が動き、動いた量が 110 を超える |
| 同上 | `test_normal_when_group_titles_stuck` | 上端に留まったグループのタイトルが手前に出る |
| 同上 | `test_normal_when_mermaid` | 倍率の表示が 100%（全体が収まる倍率）で、図に掛けた `scale()` が 1 未満になる |
| 単一ユースケース『図を描く』 | `test_normal_when_flowchart` | 線が 1 種類だけの判定フローチャートの凡例に、線の種類（`処理の流れ`）が出ない |
| 単一ユースケース『図の要素のツールチップを見る』 | `test_normal_when_er_table` | テーブルの下に収まる位置では、ER 図のテーブルのツールチップがテーブルの下に出る |
| 複合ユースケース『固有の部品で図の文書を描いて確かめる』 | `test_normal` | 「分類」の箱の印にフォーカスすると、印の `aria-describedby` が指す入力・処理・出力のツールチップが箱の下に出る |
| 複合ユースケース『コードブロックのHTMLでチャートとヒントを読む』 | `test_normal_when_range_scripts` | `[data-node="mcp"] .mdmark-diagram-node-name` にポインターを重ねられ、時間切れにならない |

<!-- /table -->

テストの期待が設計書と食い違うケースは、テストを設計書に合わせて修正し、実装は変えない。
