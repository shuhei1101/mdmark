# 要件

## 要望

| No | 機能 | 終わりの条件 |
| --- | --- | --- |
| 1 | 変換 | 文書の `<!-- flow -->`・`<!-- sequence -->` の範囲の部品の定義（座標を記載した JSON）を、`<!-- map -->` の範囲（`mermaid` のブロック 1 つと補足 `<!-- map-data: {…} -->`）へ書き換える。フロー図はノード・グループ（システムの枠と層）・線とそのラベルを `flowchart` へ（判定フローチャートの開始・質問・アクション・結果のノードは Mermaid のノードの形へ）、箱の説明（`hint`・`io`）と線の詳細（`tip`）を補足の `notes` へ、リンク先をノードのリンクへ写す。シーケンス図は参加者・メッセージ・loop の範囲を `sequenceDiagram` へ写す。ノードの種類（`llm`・`dm` など）と線の種類（`read`・`write` など）は Mermaid のクラスと補足の `layout` の `line` で指し、種類の名前・アイコン・模様を設定の `map.kinds`・`map.lines` に作る。配置の値（座標・大きさ）は写さずに自動配置に任せ、報告にも挙げない。map に写す先の無い値（題の行の範囲・更新日、`stickyTitles`）は落として、文書・行・項目を変換の報告に挙げる。部品の定義を読めない範囲だけは書き換えずに、文書・行・理由を変換の報告に挙げる |
| 2 | 変換できる旨の警告 | `flow`・`sequence` の範囲は描かずに、map へ変換できる旨と変換の方法を書き方の警告で出す。点検（`mdmark check`）も同じ内容を通知する |
| 3 | 廃止 | `flow`・`sequence` の範囲を読んで描く処理・点検・部品・custom element（`<mdmark-flow>` など）と、それを説明する設計書・使い方集・テストを削除する。map が描く見た目に使っている部品（ノード・線の交差の飛び越え・ツールチップ・図の枠）と、グラフ・操作できる部品・ER 図は残す。判定フローチャートは `flow` の部品のため、No 1 で map へ変換して廃止する |
| 4 | このリポジトリの図の書き換え | 使い方集・見本・設計書・モックの `flow`・`sequence` の図を、No 1 の変換で map の範囲へ書き換え、変換の報告に挙がった値を手で直す |
| 5 | map のノードのリンク | map の `flowchart` の `click {ID} "{リンク先}"` を読み、ノードを押すとリンク先へ移る。リンク先を許可するかは今のフロー図のノードのリンク先と同じ決まりで判定し、許可しないリンク先は開かない。No 1 の変換は、フロー図のノードのリンク先をこの `click` の行へ写す |
| 6 | map のグループの説明 | 補足の `notes` のキーに `subgraph` の ID を記載すると、そのグループのタイトルの右にノードと同じマーカーを出し、マーカーにポインターを乗せるかフォーカスすると説明のツールチップを出す。No 1 の変換は、フロー図のシステムの枠と層の `hint` をこのグループの説明へ写す |
| 7 | map の範囲の用語の参照 | 本文の参照を取り出す処理（`collectMatches`）が、map の範囲の Mermaid のノードの名前を、描くときと同じ辞書の照合で用語の参照にする。文書の別名は、今の図の部品と同じく参照にしない |

変換は `migrations/` の移行の手順（次のバージョンの `steps.yaml` の `op: call` と、文書を書き換えるスクリプト）にし、`mdmark upgrade` で適用する（確認ログ）。
`flow`・`sequence` はこの PR のバージョンで描かなくし、範囲には map へ変換できる旨の警告だけを出す（確認ログ）。
