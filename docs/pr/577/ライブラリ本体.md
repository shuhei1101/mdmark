### 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 入れ子の解消 | 説明を持つノードで、フォーカスを受ける要素と説明のマーカーを入れ子にしない構造にする | `未確定`（決める工程: 部品設計） |
| キー操作 | Enter・Space での選択と Alt + 矢印キーでの移動を、フォーカスを受ける要素で今と同じに動かす | `nodeKeyTarget` の対象を構造に合わせる |
| ツールチップ | 説明のマーカーのフォーカス・押下で説明のツールチップを開閉する今の振る舞いを保つ | - |
| 説明を持たないノード | 入れ子が無いため今の構造のまま | - |
| テスト | 単体テストで構造とキー操作を確認し、結合テストで `parts-mapflow--default` に axe の `nested-interactive` が出ないことを確認する | - |

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 説明のマーカーをノードの `div` の外（ノードの兄弟の要素）に移し、ノードの右上に重ねて配置する。ノードの `div` は今の `tabindex="0"`・`role="button"` を保つ | ノードのフォーカスとキー操作の対象が変わらない | 説明のマーカーの位置をノードの位置に合わせて動かす処理（ドラッグ・配置の上書き）が要る |
| B | #534 のリンク先を持つノードと同じく、ノードの `div` はフォーカスを受けず、名前の要素をボタンにしてノードの代わりにフォーカスを受けさせ、説明のマーカーと並べる | #534 の構造と統一され、`nodeKeyTarget` の分岐を同じ構造で広げられる | 名前の文字の選択（文字の上ではカーソルを `text` にして選ばせる）と、ボタンの中の用語の下線（押せる要素の中に用語を入れ子にしない決まり）の扱いを合わせて変える必要がある |

推奨: A

ノードのフォーカスとキー操作の対象を変えずに入れ子を解消でき、名前の文字の選択と用語の下線の決まりに影響しないため。
