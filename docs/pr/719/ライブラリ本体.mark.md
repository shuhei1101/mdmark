## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| ノードの大きさの既定の見積もり | `sizeLeaf` で、名前の幅を左 `LABEL_METRICS.padX`・右 `MAP_NODE_PAD_RIGHT` の余白で見積もり、その余白を除いた幅で折り返した行の数が全て入る高さ（`leafHeight`）にする。大きさの上書き（`size`）を持つノードは変えない | 1 行に収まる名前のノードの幅は `未確定`（[要件](./要件.mark.md) の `## 要望`） |
| 余白の値の配置先 | `sizeLeaf` と `noteSize` が同じ右の余白を使用するよう、`MAP_NODE_PAD_RIGHT` を 1 か所に配置する | 配置先はモジュール構成設計で決める |
| 部品設計 | CMP-472-5 と CMP-531-2 に、名前を折り返すノードが名前の行を全て入る高さで、最後の行がノードの下の余白に食い込まないことを記載する | - |
| モジュール構成 | MOD-472-141 の `sizeLeaf` の説明を、右の余白を見積もる見積もりに修正する | - |
| インターフェース定義 | IF-472-35 の構成図・状態遷移図の結合テストのフローに、名前の幅が事象の範囲に入るノードで、名前の最後の行がノードの下の余白より上にある期待を追加する | - |
| 再現の見本 | `scripts/storybook-render.ts` に、名前の文字の幅が「ノードの幅 − 38px」から「ノードの幅 − 20px」の範囲に入るノードを持つ構成図・状態遷移図の見本を追加し、ブラウザで今の描画が下の余白に食い込むことを確認してから修正する | - |
| テスト | 単体テストで、右の余白を見積もった幅で折り返す名前のノードが行の数ぶん高くなることを確認する。結合テストで、ブラウザで描いた再現の見本のノードの名前の最後の行が、ノードの下の余白より上にあることを確認する | - |

ブラウザ（Chromium・描く先の幅 1200px・develop の [94d1c226](https://github.com/shuhei1101/mdmark/commit/94d1c226) の配布物）で確認した結果:

| ノード | 種類の行 | 大きさ | 名前の行の数 | 名前の最後の行の下端 / 下の余白の上端（ノードの上端から） |
| --- | --- | --- | --- | --- |
| 構成図「注文の明細を月ごとに集計する」（`:::step`） | あり（処理） | 幅 216px・高さ 66px | 2 | 62.9px / 59px（食い込む） |
| 構成図「注文の明細を月ごとに集計する」 | なし | 幅 216px・高さ 63px | 2 | 48.5px / 56px（収まる） |
| 状態遷移図「支払いの確認を待っている状態」（`map.kinds` の `state` なし） | なし | 幅 216px・高さ 63px | 2 | 48.5px / 56px（収まる） |
| 状態遷移図「支払いの確認を待っている状態」（`map.kinds` の `state` あり） | あり（状態） | 幅 216px・高さ 66px | 2 | 62.9px / 59px（食い込む） |

種類の行を持たないノードは名前をノードの上下の中央に配置するため、高さの見積もりに入っている種類の行の分だけ余り、食い込まない。
食い込むのは種類の行を持つノードで、インターフェース定義の結合テストのフローと再現の見本は種類の行を持つノードで組む。
