# 要件

## 要望

`mount` の `opts.resolveIdLink` を、構成図の上で描く種類（`FLOW_BASED`: `classDiagram`・`erDiagram`・`stateDiagram`・`architecture`・`C4*`）の図を付ける関数から `attachMapFlow` まで渡す。

| No | 要件 | 測り方 |
| --- | --- | --- |
| 1 | クラス図の `click {クラス} href "id:..."`・`link {クラス} "id:..."` の行のクラスを、`resolveIdLink` が返した URL の `a.mdmark-diagram-node-link` にし、クラスのノードに `has-link` を付ける | `id:SC-` だけを URL に変える `resolveIdLink` を指定して `mount` で描いたクラス図で、`id:SC-1` のクラスが URL の `href` のリンクを持つ |
| 2 | `resolveIdLink` が URL を返さない・例外を投げる `id:` のリンク先は、flowchart と同じくリンクにせず、図の枠の前の書き方の警告に並べる | 1 と同じ文書の `id:unknown` のクラスがリンクを持たず、図の枠の前の書き方の警告にクラスの ID と `id:unknown` がある |
| 3 | `resolveIdLink` を指定しないときは、今と同じく `id:` のリンク先をリンクにしない | `resolveIdLink` を指定せずに描いた 1 と同じ文書で、`id:` のクラスがリンクを持たない |
| 4 | `erDiagram`・`stateDiagram`・`architecture`・`C4*` を付ける関数も `resolveIdLink` を受け取って `attachMapFlow` へ渡し、図の種類によらず同じ引数で付ける | 4 つの種類の図を付ける関数が `resolveIdLink` を `attachMapFlow` に渡す（単体テスト） |

`erDiagram`・`stateDiagram`・`architecture`・`C4*` は、Mermaid に `click`・`link` の行が無く、読み取りがリンク先を作らない（`links` は常に空）。この 4 種類で観測できるリンクは増えない。
