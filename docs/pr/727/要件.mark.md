# 要件

## 要望

表の列の幅を決める処理（`measureColumns`・`attachAutoColumnWidths`）が、DOM の書き換えと幅の読み取りを交互に行わないようにし、表の多い文書を描いてもメインスレッドを長く止めないようにする。

- 終わりの条件 1: Issue の計測と同じ規模の文書（表 16 個・本文のセル 480 個）を描いたとき、`mount` を呼んでから全ての表の列の幅を決定するまでの時間が、非機能要件 NFR-13 の上限（1,000 ミリ秒）に収まる
- 終わりの条件 2: 描いた表の列の幅（`--mdmark-auto-width`・`--mdmark-auto-table-width`・`--mdmark-column-head-width`）が、今の測り方で決めた幅と変わらない（差は 1px 以内）
- 終わりの条件 3: 隠した列を後から測る・ピン止めのボタンの出し入れで見出しを測り直す・見える幅が変わったときに決め直す振る舞いが今のとおり動く

`未確定`: 測り方（決める段: モジュール構成設計）

| 案 | 内容 |
| --- | --- |
| A | 計測用の要素を全てのセルに足してから幅をまとめて読み、最後にまとめて消す。余白と罫線は列ごとに 1 回だけ読む |
| B | 文字の幅を Canvas の `measureText` で、セルの書体を 1 回読んで測る（DOM に触らない） |
| C | 画面に入っていない表の計測を、表示されるときまで遅らせる |

推奨: A

セルの中の書体・文字の大きさ・バッジなどの部品をそのまま使って測るため、今の幅と変わらないことを保ちやすい。B はセルの中の部品（バッジ・コード）の書体の違いを測り分けられず、C は表示したときに同じ重さの処理が残る。
