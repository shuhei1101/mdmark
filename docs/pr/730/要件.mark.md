# 要件

## 要望

表のピン止めした列のセルにある用語のツールチップを、開いたときに表の見出し行・集計の行・ピン止めした列のセルより手前に描き、全体を読めるようにする。

- 終わりの条件 1: 列をピン止めし、見出し行を留めた表で、ピン止めした列のセルの用語にポインターを乗せる・フォーカスすると、上に開いたツールチップの上端の位置で一番手前に描かれる要素（`document.elementFromPoint`）がツールチップの中の要素になる
- 終わりの条件 2: 下に開いたツールチップも、集計の行・ピン止めしていない後ろのセルに隠れない
- 終わりの条件 3: ピン止めしていない列のセル・表の外の本文の用語のツールチップの開閉・配置・キーボードとタッチの操作が今のとおり動く
- 終わりの条件 4: 同じ型の箇所として、ピン止めした列のセルの脚注の番号のツールチップ（`src/footnote/footnote.interact.ts` も開くと `position: fixed` にしてセルの中に残す）も、見出し行・ピン止めした列より手前に描く

ツールチップを手前に出す方法は、モジュール構成設計で案 C に決めた。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | ツールチップを開くときに Popover API（`popover="manual"`）でトップレイヤーへ出す | DOM の位置を動かさず、重なりのまとまりに関係なく一番手前に出る | 対応ブラウザの下限（非機能要件 NFR-2 の Chrome 99・Firefox 98・Safari 16.4）は Popover API（Chrome 114・Firefox 125・Safari 17）に対応せず、下限のブラウザでは直らない。トップレイヤーの既定のスタイル（余白・枠・背景）を打ち消す規則も要る |
| B | 開くときに要素を `document.body` の直下へ移し、閉じたら戻す | 対応ブラウザを問わない | Tab で中のリンクへ移る順・ホバーの判定・テーマの CSS 変数の継承が崩れ、修正する範囲が広い |
| C | 開いている間、ツールチップを持つ表のセルに `is-tip-open` を付け、`z-index` をツールチップと同じ `10` に上げる | 対応ブラウザを問わず、DOM の位置・フォーカスの順を変えない。class の付け外しと CSS の規則 1 つで済む | 開いたまま本文をスクロールすると、見出し行の下に潜ったそのセルが見出し行より手前に出る（閉じれば戻る） |

決定: C

画面で、ピン止めした列のセルの中で上に開いたツールチップの上端の位置の `document.elementFromPoint` が見出し行の並べ替えのボタンになり（ツールチップが見出し行の下）、セルの `z-index` を `10` にするとツールチップの中の要素になることを確認した（Chromium、文書を描いた後に先頭の列をピン止めした表）。
案 A でも手前に出ることを確認したが、対応ブラウザの下限では効かないため採らない。
