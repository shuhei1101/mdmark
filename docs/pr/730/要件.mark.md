# 要件

## 要望

表のピン止めした列のセルにある用語のツールチップを、開いたときに表の見出し行・集計の行・ピン止めした列のセルより手前に描き、全体を読めるようにする。

- 終わりの条件 1: 列をピン止めし、見出し行を留めた表で、ピン止めした列のセルの用語にポインターを乗せる・フォーカスすると、上に開いたツールチップの上端の位置で一番手前に描かれる要素（`document.elementFromPoint`）がツールチップの中の要素になる
- 終わりの条件 2: 下に開いたツールチップも、集計の行・ピン止めしていない後ろのセルに隠れない
- 終わりの条件 3: ピン止めしていない列のセル・表の外の本文の用語のツールチップの開閉・配置・キーボードとタッチの操作が今のとおり動く
- 終わりの条件 4: 同じ型の箇所として、ピン止めした列のセルの脚注の番号のツールチップ（`src/footnote/footnote.interact.ts` も開くと `position: fixed` にしてセルの中に残す）も、見出し行・ピン止めした列より手前に描く

`未確定`: ツールチップを手前に出す方法（決める段: モジュール構成設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | ツールチップを開くときに Popover API（`popover="manual"`）でトップレイヤーへ出す | DOM の位置を動かさず、重なりのまとまりに関係なく一番手前に出る。`aria-describedby` と Tab の順が今のまま | 開いている間の CSS のセレクターと、トップレイヤーの既定のスタイル（余白・枠）を合わせ直す |
| B | 開くときに要素を `document.body` の直下へ移し、閉じたら戻す | 対応するブラウザを問わない | Tab で中のリンクへ移る順・ホバーの判定・テーマの CSS 変数の継承が崩れ、修正する範囲が広い |
| C | 開いている間、ピン止めした列のセルの `z-index` を見出し行より上げる | CSS とクラスの付け外しだけで済む | 見出し行の下に潜ったセルが、スクロール中に見出し行より手前に出る |

推奨: A

DOM の位置とフォーカスの順を変えずに、sticky のセルが作る重なりのまとまりから抜け出せるため。
