## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 統合するか | 写す先の無い値の一覧と dev-docs への影響を添えて、ユーザーに確認する | `未確定`（要件.md） |
| 変換 | `er` の部品の定義を参照し、`<!-- map -->` の範囲（`erDiagram` の `mermaid` のブロックと補足）に書き換える。座標は写さず自動配置に任せる | 統合する場合。`migrations/next/` の移行の手順 |
| 写せない値の報告 | map に写す先の無い値は落として、文書・行・項目を変換の報告に挙げる。部品の定義を読めない範囲は書き換えずに報告に挙げる | 統合する場合 |
| 書き方の警告 | `er` の範囲は描かずに、map へ変換できる旨と変換の方法を出す | 統合する場合。flow・sequence の廃止の警告と同じ扱い |
| 点検 | `mdmark check` が `er` の範囲を、変換できる旨の通知にする。ER 図の定義の誤りの点検は削除する | 統合する場合 |
| 廃止 | `er` を参照する処理・描く処理・列の開閉・Schema・ストーリー・テストを削除する | 統合する場合。グラフ・操作できる部品・図の枠・ツールチップは残す |
| このリポジトリの図 | 使い方集・設計書の `er` の図を変換で書き換え、報告に挙がった値を手で修正する | 統合する場合。更新ドキュメント |
| 設定の Schema | 図の機能のキーの description から `er` を削除する | `migrations/next/steps.yaml` に移行の手順を配置するため、`no-steps.yaml` の行は要らない |
