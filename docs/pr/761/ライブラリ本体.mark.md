## 再現の確認

develop（`a30a0102`）の `layoutMap`（構成図）と `rewireMapEr`（ER 図）で、配置のパターンごとに線の端の辺とほかのノードの上を通る区間を調べた。

| パターン | 図 | 結果 |
| --- | --- | --- |
| 縦に並ぶ | 構成図 | 端は向いた辺につながる。ノードの上を通らない |
| 横に並ぶ | 構成図 | 端は向いた辺につながる。ノードの上を通らない |
| 斜め | 構成図 | 上の段のノードから下の段の左右のノードへの線が、上の段のノードの左右の辺から出て L 字に曲がる。下の段のノードへは上の辺から入る |
| 1 つのノードから下の段の 2 つのノードへ出る | 構成図 | 再現した。幅 120 のノードで、中心の差は縦 127・横 84 と縦が大きく、下の段のノードの上の辺が向いた辺になる。線は下の段のノードの左右の辺へ回り込んで入る |
| 多数の線が 1 つのノードに集まる | 構成図 | 上の段の斜めの位置のノードからの線（中心の差は横 336・縦 127 と横が大きい）は、向いた辺の左右の辺に入るが、同じ辺の中央の 1 点に重なって入る。向いた辺の定義では再現でない |
| グループをまたぐ | 構成図 | 間のノードを避けて下と上を回る。ノードの上を通らない |
| 関連が多いテーブル | ER 図 | 端は左右の辺につながる。ノードの上を通らないが、付け替えた端の近くで線が折り返す区間がある |
| 分類の中で上下に並ぶ 2 つのテーブル | ER 図 | A（y=84）と B（y=204）の横の中心の差は無く、線は A の右の辺の列の行の高さから出て、B の右の辺の FK の列の行の高さに入る。両端とも右の辺で、ER 図の近い側の辺の定義どおり |
| ER 図のモック（`docs/mock/refs/531/assets/samples.js` の `ER`・`ER_DATA`） | ER 図 | 再現した。分類「記録」の中の「注文」（中心 x=376）→「明細」（中心 x=200）の線が、「注文」の右の辺から出て「明細」の左の辺に入り（両端とも遠い側）、途中の縦の区間（x=522）が「支払い」の上を通る。「注文」→「支払い」の線も「支払い」の右の辺（遠い側）に入る。付け替えた端から引き直す経路が折り返しを重ねている |

構成図では、遠い側の辺につながる線が、端の出口が各辺の中央の 1 点だけで、経路探索が曲がる回数の少ない経路を選ぶときに再現した。ノードの上を通る線は構成図では再現せず、ER 図で、`rewireMapEr` が付け替えた端から経路を引き直すときに再現した。
