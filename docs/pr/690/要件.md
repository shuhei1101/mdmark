# 要件

## 要望

言語 `mermaid` のコードブロック（`data-map-plain` の範囲）と map の範囲の `classDiagram` で、`click {クラス} href "{URL}"`・`link {クラス} "{URL}"` の行のクラスが、`mapLinkProblems` が許したリンク先だけ `a.mdmark-diagram-node-link` を持つノードになることを、テストと設計書で保つ。
develop（27f48163）は既にこの振る舞いを持つため、実装は変えない（[確認事項](https://github.com/shuhei1101/mdmark/pull/690#discussion_r4624569102) で推奨案 B に決着）。

終わりの条件:

- IF-472-35 に、次の文書を `mount` で描いてクラスのリンクを押す結合テストのフローがあり、そのテスト `test_normal_when_plain_class_node_link_opened` が pass する

  ````markdown
  ```mermaid
  classDiagram
    class 受付
    click 受付 href "./doc-2"
  ```
  ````

- 許可しないリンク先（`javascript:` 等）のクラスはリンクを持たないことを、同じテストで確かめる
- モジュール構成 MOD-596-4 の手順 3 が `renderMapClassDiagram` に `links` を渡すことを記載し、MOD-596-4・MOD-472-133 にリンクを持つクラスの単体テストのケースがあり、pass する
- flowchart のノードのリンクの描き方は変えない

## 現状の確認

develop（27f48163）で確認した結果。

| 経路 | 結果 |
| --- | --- |
| `attachMapClass` を直接呼ぶ（`tests/unit/src/map/class-view.browser.test.ts` と同じ準備） | 受付のノードが `a.mdmark-diagram-node-link[href="./doc-2"]` を持つ。`renderMapClassDiagram` は `...args` で `links` を構成図の部品へ渡している |
| ストーリー `linked-class`（`tests/integration/lib/map-class.story.test.ts` の `test_linked_class`） | 部品の HTML ではリンクになる |
| `needsMermaidFallback`（`kind: classDiagram`、上の文書） | `false`（mermaid のライブラリへ切り戻さない） |
| ビルドした配布物の `mount` で、上の文書・メンバーを持つクラスの文書・flowchart の文書を描く（integration-browser） | 3 つとも map の図で、`a[href="./doc-2"]` が 1 件 |

Issue 本文が原因に挙げた「`renderMapClassDiagram` が `links` を参照しない」は、develop では当たらない。
Issue を書いた時点（730b1a5）の配布物は、テストのブラウザから読み込めず確かめていない。
