## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 原因 | ボタン（`button`）が `tr` の直下に入ると、ブラウザが表のセルでない子を無名のセルで包み、その無名のセルが列を 1 つ占める。`position: fixed` でも無名のセルは作られ、ボタンの後ろのセルが次の列へ押し出される | Chromium で `mount` の 2 列の表の 1 列目のセルを選んで確かめた。押し出された 2 列目のセルは 3 列目の位置（幅 0）へ移り、選んだセルの行の高さは 39px から 165px に変わった |
| ボタンの DOM の配置先 | 表のセル（`td`・`th`）の文字を選んだときは、ボタンをそのセルに最も近い表（`table`）の直後に配置する。他のブロックは今までどおりブロックの直後 | `mount` の文書では表を包む横スクロールの領域の中、表の直後に入る。`mountComments` の `el` が表の中の要素で表が `el` の外にあっても、表の直後に配置する（`detach` でボタンを削除するため、`el` の外に残らない） |
| 設計書の食い違い | IF-472-27・IF-472-35・SCR-472-4・CMP-472-14・MOD-472-157 のボタンの配置先の記述を、決めた配置先に揃える | - |
| キーボード操作 | 選んだ後の Tab でボタンに届くことを、決めた配置先でも保つ | 部品設計で扱う |
| 単体テスト | 表のセルの文字を選んだときに、ボタンが `tr` の直下に入らず、出る位置が今までどおりであることを確かめる | - |
| 結合テスト | 表のセルの文字を選んでボタンを出す前後で、セルと表の幅が変わらないことを実際のブラウザで確かめる | - |
