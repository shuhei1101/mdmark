## 変更方針

<!-- table: {"kind": "data"} -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 閲覧機能（並び） | `.mdmark-tablist` を折り返さない 1 行にし、収まらない分は並びの中で横にスクロールさせる。タブのボタンは縮めず、タブ名を省略しない | 選んだタブの下線（中身の地とつなぐ下の罫線）が横スクロールの領域で切れないようにする |
| 閲覧機能（選んだタブ） | タブを選んだとき（押す・矢印・Home・End・描いた直後・同じ組の切り替え・URL の `#ID`）、選んだタブのボタンが並びの見える範囲からはみ出していれば、並びの横のスクロール位置だけを動かして全体が入るようにする | 縦のスクロール位置を動かす `scrollIntoView` は使わない。`choose` のボタンの位置を戻す処理と干渉させない。押す・キー・同じ組の切り替え・残したタブ名は単一 UC『タブを切り替える』の E2E で、URL の `#ID` で選ぶ経路は『文書を描く』の結合テスト（`tests/integration/lib/mount.browser.test.ts`）で確かめる |
| アクセシビリティ | キーボードで選んだタブにフォーカスを移したときも、そのタブが並びの見える範囲に入る | WAI-ARIA のタブの作法は今のまま |
| 記法（折り返しの指定） | タブのマーカーに `wrap`（真偽値。既定 `false`）を追加し、`true` のタブ群はタブ名の並びを今までどおり折り返して並べる（横スクロールと端のボタンを付けない） | 指定の読み取りと記載の警告はデータ設計・インターフェース定義で決める |
| 既存機能への影響 | 横幅に収まるタブ群・入れ子のタブ・折り畳みに入れたタブ・印刷の見え方は今のまま | 配置の無い時点（取り付ける前・`display: none`・閉じた折り畳み）で選んだタブは、並びの見える幅が 0 から変わったときに見える範囲へ入れる（インターフェース定義『文書を描く』の制約「タブの操作」） |
