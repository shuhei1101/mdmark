# 要件

## 要望

配信元の設定 `project-index.yaml` に `direct_commit` を追加し、dev-docs のメタデータの画面から直コミットできる種類を決める。

| 対象 | 内容 |
| --- | --- |
| `$schema` | `direct_commit` を持つ project-index のスキーマ（develop のブランチ）を指す |
| `direct_commit.branch` | `develop` |
| `direct_commit.kinds`（本文も書き換えてよい種類） | 設計書の YAML の種類（`data`・`architecture`・`scenario`・`interface`・`module`・`component`・`screen`・`config`・`er`・`external_api`・`library`・`test_procedure`・`dev_command`・`nonfunctional`・`layout`・`agent`・`mcp_server`・`launch`・`agent_flow`・`llm_call`・`evaluation`・`eval_criterion`・`eval_case`）と用語集 `terms` |
| `direct_commit.kinds`（`body: false`） | 管理用の YAML の行で配信する種類（`files_top`・`mock`・`docs`・`src`・`tests`・`scripts`・`init_templates`・`schemas`・`migrations`・`vscode`・`plugin`・`storybook`・`workflows`） |

shuhei1101/dev-docs#317 の `project-index.yaml` と同じく、設計書の種類はそのまま許可し、管理用の YAML の行は本文のファイルを書き換えない `body: false` で許可する。

マージの後に、端末の設定の配信元 `mdmark` の行の `sources[].direct_commit.write_api_kinds` へ、許可した全ての種類を登録する（`反映作業/index.yaml`）。
