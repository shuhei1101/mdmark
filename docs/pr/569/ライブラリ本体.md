## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| `ignores` | Webview の外を除外する指定をやめ、`node_modules/`・`dist/`・JavaScript（`*.{js,mjs,cjs}`）を除外する | 引数なしの `lint:eslint` が `src/`・`scripts/`・`vscode/src/`・`plugin/` の `*.ts` と Webview を検査する |
| 複雑さの規則 | 4 規則を Webview の設定から別の設定のまとまりへ移し、`files` を `src/**/*.ts`・`scripts/**/*.ts`・`vscode/src/**/*.{ts,tsx}`・`plugin/**/*.ts` にする | 閾値は変えない。Webview も同じまとまりで検査する |
| 型の情報 | 複雑さだけを適用するまとまりは typescript-eslint のパーサーだけを使用し、`projectService` を使用しない | 4 規則は型の情報を使用しない |
| Webview だけの規則 | React・アクセシビリティ・import の向き・Tailwind・記載方法・型の情報を使用する規則は、今の `files`（`vscode/src/webview/**/*.{ts,tsx}`）のまま | - |
| 違反の修正 | 違反した関数を、規約『設計原則』の SLAP と cognitive complexity で、1 つの抽象度の処理を持つ関数に分ける。引数が 4 つ以上の関数は、引数をオブジェクトにまとめる | `eslint-disable` のコメントで除外しない。`src/index.ts` から export する公開関数のシグネチャは変えない（変える必要が出たら、インターフェース定義設計を `todo` に戻す） |
| 分けた関数の配置 | 分けた関数は元の関数と同じファイルに配置し、export しない | - |
| 設計書 | 分けた関数（export しない）はモジュール構成の設計書に追加しない。設計書に記載した関数のうち、引数が 4 つ以上の関数は引数をオブジェクトにまとめた形に設計書を書き換える（`bundleModule`・`renderFlow`・`renderEr`・`pushWarning`・`attachMapFlow`・`attachMapSequence`・`layoutMap`。VS Code 拡張機能の `libraryOrigins` も同じ）。markdown-it のルールなど外部が引数を決める関数は、残余引数で受け、設計書の引数の表は変えない（`readAnnotationDefinition`・`readFootnoteDefinition`） | 設計書と実装で二重管理にしない（規約『設計書を作成する目的』） |
| 回帰の確認 | 既存の単体テスト・結合テストを全て回し、全 pass を確認する。lint は `npm run check` で回す | 挙動を変えないため、新しいテストは分けた関数に分岐が残るときだけ追加する |
