### #711 はみ出す表の既定のピン止め

- ピン止めを持つ表（既定の種類と `data`）が幅からはみ出すとき、設定を記載しない既定では、描いた直後にどの列も留めない
- 設定で、今の動き（描いた直後に `columns.{列名}.pinned` の `true` の列、無ければ行見出しの列、行見出しも無ければ先頭の列を留める）を選べる
- 既定がピン止めなしのときも、`columns.{列名}.pinned` の `true` の列は描いた直後に留める
- 列のピン止めのボタン・`table.pin`（`each` / `through`）・`-pin` は今のまま使用できる
- 設定の JSON Schema を変えるため、移行の手順か `migrations/no-steps.yaml` の行を配置する

`未確定`: 既定で留めるかを選ぶ設定の持ち方（決める工程: データ設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `table` に、既定で留めるかの真偽値のキーを追加する（既定 `false`） | 留める動き（`each` / `through`）と既定で留めるかを別々に選べる | `mount`・`interact` の受け渡しに値が 1 つ増える |
| B | `table.pin` に、既定で留めない値を追加する | キーが増えない | 留める動きと既定で留めるかの組み合わせ（4 通り）を 1 つの値で表すことになり、値が増える |

推奨: A

留める動きと既定で留めるかは独立した選択で、1 つの値にまとめると `each` / `through` のそれぞれに既定のオン・オフの値が要る。

### #462 差分のブロックのフロントマターの変更

- 比較元の Markdown と今の Markdown で、文書の先頭のフロントマターが追加・変更・削除されたとき、描いた文書の上の差分のブロックでその変更を示す
- フロントマターに変更が無いときは、今と同じ表示にする
- Markdown の行の差分は今のまま変えない

- 機能 `frontmatter` がオフ（既定）のときは、変更・削除したフロントマターだけを本文の先頭に差分のブロックとして差し込む（変更は後のリビジョン、削除は前のリビジョンのフロントマター）
- 機能 `frontmatter` がオンのときは、本文の先頭のフロントマターの表示を差分のブロックの色で示す（削除はオフと同じく前のリビジョンのフロントマターを差し込む）
- 書き換えたフロントマターの読み上げの名前は、本文のブロックと同じ「追加:」、削除は「削除:」
