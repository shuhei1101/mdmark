## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 今の書き方の変換 | `src/render/legacy-marks.ts` と単体テストを削除し、`src/files.yaml`・`tests/files.yaml` の行を削除する | 移行の手順は `migrations/v0.11.0/legacy-marks.js` を使用する |
| 描く処理 | 記法・機能・ページのマーカーの今の書き方の引数を適用せず、記載の警告で JSON のオブジェクトでの記載と `mdmark upgrade` を案内する | 拡張・`libraries` のマーカーは今までどおり描かずに記載の警告を出す |
| 点検 | 今の書き方の引数を `legacy_mark` のまま 1 件のずれにし、内容で JSON のオブジェクトでの記載と `mdmark upgrade` を案内する | 移行の後の点検の除外（`legacy_mark`）はそのまま使用する |
| ビルド | `buildLegacyMarks` はソースが無いと出力しない今の決まりのまま、`src/render/legacy-marks.ts` を指すビルドの処理を残すか削除するかを設計で決める | - |
| 設計書・ガイド | 今の書き方を描く記述を、描かずに案内する記述へ変え、ER 図の今の引数との対応の表は移行の手順が使用する対応として扱う | 用語集の「今の書き方」の説明も変える |
| 既存機能への影響 | 移行の前の文書を描くと、今の書き方のマーカーの表・範囲の指定が適用されず記載の警告が出る（破壊的変更） | 変更履歴は release で記載する |
