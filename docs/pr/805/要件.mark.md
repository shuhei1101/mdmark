### #802 develop の配布物の再作成

終了の条件: develop の配布物の再作成が失敗したら放置されずに対応される。配布ファイルの上限を超える変更は develop へマージする前に分かる。再作成したら `@develop` を読み込む側に待たずに最新のファイルが返る。失敗を修正した後に次のマージを待たずに再作成できる。

- `develop-dist` が失敗したら、失敗した実行の URL と commit を持つ Issue を `確認:task-planner` を付けて起票する。同じ失敗の Issue が open なら起票しない
- 配布ファイル 1 つの上限（非機能要件 NFR-1 の 1024KB）を超える変更は、作業 PR のテストで失敗する。今の結合テストのビルド（`tests/integration/built-root.ts`）は上限を jsDelivr の 20MB にしてビルドしており、NFR-1 の上限を超えても失敗しない
- `develop-dist` が `dist/` などを commit して push した後、変わったファイルの jsDelivr の `@develop` のキャッシュを削除する。削除した後に `@develop` の URL が commit したファイルを返す
- `develop-dist` を手動で起動できる（`workflow_dispatch`）
- GitHub Actions を実行できないときに、手元でビルドして commit し、キャッシュを削除する代わりの経路を開発コマンドに記載する

`未確定`: 失敗の Issue の「同じ失敗」の見分け方（決める段: インターフェース定義設計）

| 案 | 内容 |
| --- | --- |
| A | workflow 名を持つ固定のタイトルの open の Issue があれば、起票せずにその Issue へ失敗した実行の URL をコメントする |
| B | 失敗した step の名前ごとに Issue を分け、同じ step の open の Issue があれば起票しない |

推奨: A

どの step で失敗しても対応する人は同じで、修正するまで develop の配布物が古いことも同じため。

### #803 埋め込んだ動画のリサイズハンドル

終了の条件: 閲覧する人が埋め込んだ動画の大きさを画面で変えられ、大きさを変えても縦横の比率は変わらず全体が縮小・拡大する。

- 段落の動画（再生バーを持つ図）に、閲覧する人が大きさを変える操作を付ける
- 大きさを変えても、動画の縦横の比率は変わらず、全体が縮小・拡大する。本文の幅を超えない
- 記載する人の `{width=…}` の指定と、今の設定・文書の描き方は変えない（操作を付けない状態の HTML と見た目を変えない）
- マージの前に、#803 の本文の必読の MindStella のワークスペースの記録と実装・文書を突き合わせ、ずれが無いかを確認する。実装中に設計を変更した箇所は除き、機能を落としていないかを確認する
- リサイズハンドルは再生バーを持つ段落の動画だけに付け、画像・音声・再生のボタン（表のセルの中・`modal`・`thumbnail`）には付けない。画像は押すとライトボックスで拡大でき、閲覧する人が大きさを変える手段を既に持つ
- 大きさは動画ごとに変え、1 つ変えても同じ文書のほかの動画の大きさは変えない。図の枠のリサイズハンドルが表示する枠ごとに高さを保ち、記載する人も `{width=…}` を動画ごとに指定する

`未確定`: 操作の見た目と振る舞い（決める段: モック作成）

| 案 | 内容 |
| --- | --- |
| A | 図の枠のリサイズハンドルと同じ見た目のハンドル（押せる範囲は 28×24）を、動画の下端の外側の右端に配置し、常に出す。ドラッグと上下キーで比率を保って幅と高さを変える。ハンドルを押す（動かさずに離す）か Enter で「小さくする」「大きくする」「元の大きさに戻す」のメニューを開き、ドラッグの代わりにタップ・クリックだけで変えて戻せる。ダブルクリックでも元の大きさに戻し、変えた大きさは同じタブの中で再読み込みしても保つ |
| B | 同じハンドルを動画の右上に重ね、ポインターを乗せたときかフォーカスしたときだけ出す。操作は A と同じ |

推奨: A

再生バーの右下には全画面のボタンがあり、動画の上に重ねると隠すか誤って押す。A は動画と重ならず、図の枠のリサイズハンドルと同じく常に出るので、タッチの端末でも見つけられる。

`未確定`: 設定で操作を削除できるようにするか（決める段: インターフェース定義設計）

| 案 | 内容 |
| --- | --- |
| A | 機能を追加し、既定でオンにする（`features.diagram-resize` と同じ考え方。Schema と移行の手順の扱いも合わせる） |
| B | `features.diagram-resize` で図の枠と動画の両方を切り替える |
| C | 機能を追加せず、常に出す |

推奨: A

図と動画で使う場面が違い、片方だけを削除したい利用側があるため。
