# 要件

## 要望

- VS Code 拡張機能の設定の読み取り（`pickPreviewConfig`）で、重ねた設定の `tooltips`・`syntax` がマップのときだけ取り出し、プレビューの `render` の `config` と書き出す HTML の `config` に入れる
- `tooltips.placement`・`tooltips.diagramPlacement` は、記載した値のまま `mount` に指定する。プレビュー・HTML に書き出す・ブラウザで開く・PDF に印刷のどれでも、ツールチップがその位置に出る
- `syntax.url` の `http:`・`https:` の URL はそのまま指定し、その origin をプレビューの CSP の `script-src` に入れる（`syntax.url` を記載しないときは既定の jsDelivr の origin）
- 相対パスの `syntax.url` は、`libraries`・`html-scripts.url`・`mermaid.url` と同じく、値を記載した設定ファイルのフォルダから解決する。プレビューでは Webview で読み込める URL にし、末尾の `/` を残す
- 書き出す HTML では、相対パスの `syntax.url` のとき、文書が使用する言語があれば色分けのライブラリの本体とその言語のモジュールを HTML に埋め、file:// で開いても色分けして描く。まとめられないモジュールは埋めず、出力チャネルに警告を記録して書き出しを続ける
- `tooltips`・`syntax` がマップでないとき・記載しないときは指定せず、mdmark の既定で描く

`未確定`: 書き出す HTML に相対パスの `syntax.url` の本体と言語のモジュールを埋める方法（決める段: インターフェース定義設計）

| 案 | 内容 |
| --- | --- |
| A | 本体と文書が使用する言語のモジュールを 1 つずつまとめて `data:` の URL にし、HTML の import map で `{syntax.url}core.min.js`・`{syntax.url}languages/{言語}.min.js` をその URL に割り当てる |
| B | CLI の書き出しが起動の処理で呼ぶ `setEmbeddedSyntax` を公開 API にし、拡張機能が埋めた本体と言語のモジュールをそれで指定する（CLI と同じ指定の仕方）。公開 API の追加と、拡張機能が読み込む配布物をその版以上にすることが要る |

推奨: A

`syntax.url` は本体と言語のモジュールを引くフォルダの URL で、1 つの `data:` の URL では表せない。A はライブラリ本体を変えずに済み、拡張機能が読み込む jsDelivr の配布物の版によらず効く。
