### ガイドの索引の移し先

`guide/index.yaml` を `plugin/guide-index.yaml` へ移し、`guide/files.yaml` の行を `plugin/files.yaml` へ移して、直下の `guide/` を削除する。

| 案 | 内容 | 判定 |
| --- | --- | --- |
| A | `plugin/guide-index.yaml` へ移す | 採用 |
| B | `docs/guide/` の下へ移す | 不採用。`docs/guide/files.yml` は公開ドキュメントの行で、タグ `topic:ガイド` の行がガイドの一覧になる（SC-472-15）。索引の行が入ると一覧に混ざる |
| C | `scripts/` の下へ移す | 不採用。`scripts/` は開発のスクリプトのフォルダで、手で記載するプラグインの定義の置き場所でない |

索引は Claude Code プラグインが案内するガイドの一覧で、手で記載するプラグインの定義（`plugin.json`・`.mcp.json`・スキル）と同じ `claude_plugin` の中身になる。
`plugin/` を git から入れると索引も一緒に入るが、プラグインは索引を読まない（ビルドが構造と指すページを検査するだけ）。
dev-docs の配信元の `id: guide` の行は、`plugin/files.yaml` を配信する `id: plugin` の行に含まれるため削除する。

### ガイドのページの GitHub 上の URL

改名したガイドのページの旧パスは残さない（旧 URL は 404 になる）。リポジトリの中のリンクは全て改名後のパスへ合わせる（[確認ログ](./確認ログ.yaml)）。
