## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 組み直すか | 機能ごとのフォルダへ組み直す（[要件](./要件.md) の推奨 A） | `未確定`（決める段: モジュール構成設計） |
| 機能のフォルダの切り方 | 記法の単位（表・ファイルツリー・コードブロック・図・脚注 など）で 1 フォルダにし、その記法の変換・操作・部品・DOM を使用しない計算・ストーリーを入れる。中身が 1 つだけになる記法は、近い記法のフォルダにまとめる | 規約『フォルダ構成の切り方とレビュー』の「切りすぎない」 |
| 複数の機能が使用するもの | `escape.ts`・`icons.ts`・`colors.ts` など複数の機能の部品が使用するものと、`src/render/` の直下の変換の流れは、使用する側の共通の親の `shared/` か今の `render/` に配置する | 規約の「共通のもの」。置き場所はモジュール構成設計で決める |
| 既に機能で分かれているフォルダ | `src/map/`・`src/cli/` などの中は分け方を変えず、import のパスだけを修正する | - |
| ファイルの移動 | `git mv` で移し、中身は import のパスの修正だけにする | 履歴を追えるようにする |
| 公開関数・配布物の起点 | `src/index.ts` の export と、`dist/` の起点のファイル名は変えない | 型定義のパスの扱いはインターフェース定義設計で決める |
| 設計書 | モジュール構成の分類（記法・操作・部品）を機能の分類にし、モジュール構成・部品設計・インターフェース定義・外部ライブラリ・フォルダ構成のパスを移した先に合わせる | パスの書き換えは `write_docs` の `replace_text` でする |
| 単体テスト | `tests/unit/src/` の置き場所を移した先の `src/` の並びに合わせ、import を修正する | テストの中身は変えない |
| 結合テスト | import を修正する | テストの中身は変えない |
| 確認 | lint・型検査・ビルド・単体テストを全件で実行して合格させる。ビルドした `dist/index.js`・`dist/view.js`・`dist/comments.js`・`dist/map.js` が、組み直す前と同じ公開関数を export していることを確認する | 結合テストの実行範囲は、実行の前に計画書の表にしてレビューで確認する |
