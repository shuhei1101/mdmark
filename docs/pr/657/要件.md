# 要件

## 要望

`src/` のうち層で分かれているフォルダ（`src/render/syntax/`・`src/interact/`・`src/parts/`）と直下の `table-logic.ts`・`tree-logic.ts`・`code-fold-logic.ts` を、機能ごとのフォルダへ組み直すかを決める。

機能ごとのフォルダへ組み直す（モジュール構成設計で決定）。

- 1 つの機能（例: 表・ファイルツリー・コードブロック）の記法の変換・読者の操作・部品・DOM を使用しない計算を、その機能のフォルダ（`src/{機能}/`）に配置する
- 機能のフォルダのファイル名の後ろに中身の役割（`.syntax.ts`・`.part.ts`・`.part.stories.ts`・`.interact.ts`・`.logic.ts`）を付ける
- 持ち主の機能が無い助けは `src/shared/` に配置し、ある機能の記法・部品・操作を別の機能が組み込むときは持ち主の機能のフォルダに置いたまま import する
- 移したファイルを参照する `src/`・`scripts/`・`.storybook/`・`tests/`・`vscode/` の import と、設計書（モジュール構成・部品設計・インターフェース定義・外部ライブラリ・フォルダ構成）と `files.yaml` のパスを、移した先に合わせる
- 単体テスト（`tests/unit/src/`）の置き場所を、移した先の `src/` の並びに合わせる
- 描く結果・公開関数・配布物の起点のファイル（`dist/index.js`・`dist/view.js`・`dist/comments.js`・`dist/map.js`・`dist/cli.js`・`dist/viewer.js`）のファイル名は変えない
- 配布物の型定義のうち、`src/` の並びに合わせて出力する `dist/` の下のフォルダの型定義（`dist/render/`・`dist/interact/`・`dist/parts/` など）は、移した先のパスに変わるままにする。インターフェース定義が記載する型定義（`dist/index.d.ts`・`dist/mount.d.ts` など `src/` の直下のもの）は変わらない
- 全ての機能を、この作業 PR で移す
- lint・型検査・ビルド・単体テストが通る

型定義の扱いは、`package.json` に `exports` が無く、利用側が参照する起点は `dist/index.js` とその型定義で、`dist/` の下のフォルダの型定義はインターフェース定義に無いため、再 export のファイルを配置しない。
全ての機能をこの作業 PR で移すのは、移す作業がファイルの移動と import のパスの修正で、並列不可の期間を 1 回に収めるため。
