## 要望

[A-5](/mnt/c/Users/shuhe/repo/tmp/何でも会話/.mindstella/docs/A-5.md) の手順で、`docs/` の文書（設計書・公開ドキュメント・PR ドキュメント）を mdmark の書き方と表し方の優先順位に移行する。

| No | 工程 | 終わりの条件 |
| --- | --- | --- |
| 1 | 棚卸し | dev-docs の `search_docs` で、Mermaid・接頭辞の無いタグ・空の description・本文に生の文字で記載した ID と Issue 番号とパス・避ける単語を含む文書の一覧を作る |
| 2 | 図の置き換え | 文書の Mermaid の図（```mermaid で囲まれていないシナリオの flow を含む）を、map のマーカーで囲み補足を付けて描く。図の中のラベルに内部の ID を出さない |
| 3 | 文を表へ | 同じ属性を持つ項目が 2 件以上ある文・箇条書きを表にし、`**キー**: 値` が 3 つ以上並ぶものを「項目 / 値」の表にする |
| 4 | 文を削り、AI slop を修正する | 既出の言い直し・理由の説明・当たり前の注意を削り、残す文を規約『文章の書き方』で点検する。[#289](https://github.com/shuhei1101/mdmark/issues/289) の後に残った文だけを扱う |
| 5 | メタデータの付け直し | タグを `action:`・`topic:`・`tool:` の接頭辞と `main` 1 つで付け、エイリアス・用語・description（「何を定め、どんなときに読むか」の 1 文）・関連を今の規約で付ける |
| 6 | 本文に出さないものの移動 | 検討事項の ID を関連のキーへ、Issue 番号・文書のパスをタイトル付きのリンクへ移す |
| 7 | 検査 | dev-docs の `write_docs` で書き込み、mdmark の `check` を通し、画面で描いて図が重ならず読めることを確認する |

あわせて次を行う。

| 改善 | 内容 |
| --- | --- |
| タグの付け直し | 付ける前に `group_by: tags` で既存のタグを再利用する |
| エイリアスと用語 | 判定フローチャート『エイリアスの登録』『用語の登録』で判定し、`aliases` と用語集（`alias_type`）へ登録する |
| description の書き方 | 規約『タグと用語の登録』の description の点検の表で点検する |
| 設計書とコードの関連 | `src/`・`tests/`・`vscode/`・`plugin/` の `files.yaml` のコード・テストの行に、設計書への `related`（`implements`・`tests`）を張る |
| 設計書の Schema の参照への移行 | [#587](https://github.com/shuhei1101/mdmark/issues/587) の反映作業『各プロジェクトのスキーマの参照への移行』のうち、ER 図を除く設計書の種類の分を引き取る。`dev-docs.yaml` の設計書の行の `schema` を knowledge の `schemas/design/{種類}.schema.yaml`（`design-schemas/v8.4.0`）へ切り替え、参照しなくなった `schemas/` のコピーを削除し、設計書を knowledge の Schema の検査に合格させる。ER 図・管理用の YAML の Schema・`index.schema.yaml`・データの設計書・フォルダ構成の設計書の `schemas/` のエントリは #587 に残す |
