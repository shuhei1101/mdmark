## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| ノートのノードの大きさ | `classPartInputs` で、ノートのノードの幅を文の幅に左右の余白（左 `LABEL_METRICS.padX`・右 `MAP_NODE_PAD_RIGHT`）を加えた幅（`MAP_LAYOUT.minWidth` から `maxWidth` まで）にし、左右の余白を引いた幅で折り返した行の数が全て入る高さの `size` を `overrides` に入れる。1 行に収まるノートの大きさは今と同じにする | 案 A で決定 |
| 部品設計 | CMP-596-1 の状態 `LongMembers`（折り返すノートを既に持つ）と引数 `layout` に、ノートのノードが折り返した文の行が全て入る高さで、最後の行がノードの下端で切れないことを記載する | - |
| モジュール構成 | MOD-596-1 の `classPartInputs` の説明に、ノートのノードの大きさの上書きを追加する。MOD-472-141 に、`sizeLeaf` と `classPartInputs` が共通に使用する `textWidth`・`splitLines`（公開にする）と `leafHeight`（新規）を追加する | - |
| CSS | `src/index.css` の map のノードの `padding-right: 28px` に、`MAP_NODE_PAD_RIGHT` と同じ値である旨のコメントを追加する | - |
| インターフェース定義 | IF-472-35 のクラス図の結合テストのフローに、折り返したノートの文の矩形がノードの矩形に収まる期待を追加する | - |
| テスト | 単体テストで、折り返すノートのノードの `overrides` の高さが行の数ぶん高くなり、1 行のノートは今の高さのままであることを確認する。結合テストで、ブラウザで描いた `MAP_LONG_CLASS` のノートの文の最後の行の矩形が、ノートのノードの矩形の中にあることを確認する | - |

ノートのノードの高さの見積もり方（モジュール構成設計で決定）

ブラウザ（Chromium・幅 1200px）で `LONG_CLASS` を描いて確認した結果:

| 項目 | 値 |
| --- | --- |
| ノートのノードの大きさ | 幅 216px・高さ 66px（構成図の既定の見積もりのまま） |
| ノートの左右の余白 | 左 10px・右 28px（`src/index.css` の map のノードの `padding-right: 28px`） |
| 文の行の数 | 見積もりは 1 行（左右の余白を 10px ずつとした幅 196px に文の幅 196px が収まる）、描画は 2 行（左右の余白を引いた幅 178px で折り返す） |
| 2 行目の下端 | ノードの下の枠線の 3px 上で、下の余白 6px に食い込む |

既定の見積もりは右上の i と開閉の山形の分の右の余白を見積もらないため、文の幅が見積もりより狭く、折り返した行が高さに入らない。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | ノートの文を描く文字の大きさと幅で折り返した行の数から、`classPartInputs` で高さを見積もって `overrides` に入れる | クラスのノードと同じ場所で大きさを決め、構成図の既定の見積もりを変えない | ノートの文の描き方を変えると、見積もりも合わせて変える必要がある |
| B | 構成図の既定の見積もり（`sizeLeaf`）を、ノートの文の描き方に合わせて変える | 上書きを追加しない | 構成図・状態遷移図のノードの大きさも変わる |

決定: A（レビューで合意した推奨のとおり）

Issue の範囲はクラス図のノートで、構成図・状態遷移図のノードの大きさを変えずに済むため。
