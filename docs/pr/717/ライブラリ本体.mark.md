## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| ノートのノードの大きさ | `classPartInputs` で、ノートのノードにも、ノードの幅で折り返した文の行の数が全て入る高さの `size` を `overrides` に入れる。1 行に収まるノートの大きさは今と同じにする | 未確定 |
| 部品設計 | CMP-596-1 の状態 `LongMembers`（折り返すノートを既に持つ）と引数 `layout` に、ノートのノードが折り返した文の行が全て入る高さで、最後の行がノードの下端で切れないことを記載する | - |
| モジュール構成 | MOD-596-1 の `classPartInputs` の説明に、ノートのノードの大きさの上書きを追加する | - |
| インターフェース定義 | IF-472-35 のクラス図の結合テストのフローに、折り返したノートの文の矩形がノードの矩形に収まる期待を追加する | - |
| テスト | 単体テストで、折り返すノートのノードの `overrides` の高さが行の数ぶん高くなり、1 行のノートは今の高さのままであることを確認する。結合テストで、ブラウザで描いた `MAP_LONG_CLASS` のノートの文の最後の行の矩形が、ノートのノードの矩形の中にあることを確認する | - |

`未確定`: ノートのノードの高さの見積もり方（決める段: モジュール構成設計）

構成図の既定の見積もり（`src/map/layout.ts` の `sizeLeaf`）は、上書きの無いノードでも名前の文字の大きさで折り返した行の数を高さに入れる。
既定の見積もりが文の行を入れきれない理由（ノートの文の描画の文字の大きさ・幅が見積もりと違うか）を、ブラウザで描いたストーリー `LongMembers` で確認してから見積もり方を決める。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | ノートの文を描く文字の大きさと幅で折り返した行の数から、`classPartInputs` で高さを見積もって `overrides` に入れる | クラスのノードと同じ場所で大きさを決め、構成図の既定の見積もりを変えない | ノートの文の描き方を変えると、見積もりも合わせて変える必要がある |
| B | 構成図の既定の見積もり（`sizeLeaf`）を、ノートの文の描き方に合わせて変える | 上書きを追加しない | 構成図・状態遷移図のノードの大きさも変わる |

推奨: A

Issue の範囲はクラス図のノートで、構成図・状態遷移図のノードの大きさを変えずに済むため。
