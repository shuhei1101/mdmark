# 要件

## 要望

アプリの画面が、mdmark の配布物を読み込んで `<mdmark-table>` を配置し、列の定義と行のデータを JavaScript のプロパティで指定すると、Markdown の表を囲んだときと同じ外観と操作の表が描かれる。

<!-- table: {"kind": "data"} -->

| 項目 | 要件 |
| --- | --- |
| 表の機能 | 並べ替え・絞り込み・ピン止め・列の表示・列の並べ替え・列の幅の変更・長い文字の省略を、Markdown の表の部品（CMP-472-61）と同じ操作で使用できる。長い文字は列の幅を超えて隣の列に重ならない |
| 指定 | 列の定義と行のデータは JavaScript のプロパティで指定する。プロパティを指定し直すと表を描き直す。値は文字として出し、HTML として解釈しない |
| 操作の通知 | 行を押した・セルを編集した・行を追加した操作を、`<mdmark-table>` の `CustomEvent` でアプリへ通知する。イベントは操作した行（とセル）を特定できる値を持つ |
| セルの中身の差し替え | アプリがセルの中身を差し替えられる（スロットか描画の関数。方式は設計で決定する） |
| 配布 | 今の配布物と同じ jsDelivr の URL から読み込む。アプリは `@0` の指定で読み込むと、mdmark のバージョンを上げたときに依存の更新とビルドをせずに追従する。固定のバージョンを指定して読み込む方法も残す |
| 破壊的変更 | 0.x の間も `@0` で追従し、`<mdmark-table>` に破壊的変更を出すときは使用する側のアプリも同時に合わせる（利用者の回答。[案 C](https://github.com/shuhei1101/mdmark/issues/793#issuecomment-7079910656)） |
| 今の公開関数 | `mount`・`render`・`mountView`・`mountComments` と Markdown の表の部品の外観と操作を変えない |
| ほかの部品 | 表のほかの部品（今 mdmark が持つもの）も、同じ方式のカスタム要素で後から追加できる構造にする |
| ガイド | エージェントが部品の使用方法を、配信元 `mdmark` のタグ `topic:ガイド` のページ（`plugin/guide-index.yaml` の行）として参照できる |

<!-- /table -->

タグの名前・プロパティとイベントの名前・セルの中身の差し替え方は、インターフェース定義設計・部品設計で決定する。

`未確定`: セルの編集・行の追加の UI（決める工程: モック作成）

| 案 | 内容 |
| --- | --- |
| A | 表の部品がセルの編集の入力欄と行の追加のボタンを描き、確定した値をイベントで通知する |
| B | 表の部品は操作のイベントだけを通知し、入力欄はアプリがセルの中身の差し替えで描く |

推奨: A

Issue の要望は「決めた書き方をするだけで使用できる」ことで、入力欄をアプリごとに作ると、表をアプリごとに作っている今の問題が編集で残る。
