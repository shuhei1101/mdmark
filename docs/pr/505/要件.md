#458 の列の幅は、次を満たす。

- 判定の順は [#458 の本文](https://github.com/shuhei1101/mdmark/issues/458) の判定フローチャートに [ユーザーの修正](https://github.com/shuhei1101/mdmark/issues/458#issuecomment-6768376588)（Q2 は `width.mode` が `nowrap` か。`width.min`・`width.max` は em の数で、折り返す列の最小の幅・最大の幅を置き換える）を適用したものを起点にし、設計で値と測り方を決める
- 読者がつまみで幅を変えた列は、読者が変えた幅を優先する
- 絞り込み・並べ替え・列の表示の切り替えでは幅を変えず、表の見える幅が変わったときだけ計算し直す
- 「表が常に最大の幅を取る」事象は、再現する文書を単一ユースケース設計の最初に確認する

#458 の自動の列の幅を持つ表は、狭い幅でも最終列を行の詳細へ畳まず、最小の幅で描いて横にスクロールする（[ユーザーの回答](https://github.com/shuhei1101/mdmark/pull/505#discussion_r4555812978)の案 A）。今の「狭い幅で最終列を畳む」描き方は削除する。

#459 の既定は `depth` を省いたとき `"all"` と同じ描き方にし、閉じて始める文書は `depth` に階層の数を記載する。

#501 は、右側の目次の項目を押したときと URL の `#ID` が見出しを指すときに、見出しを囲む閉じたセクションに加えて見出し自身の閉じたセクションも開く。
表の行へのリンクとコメントのマーカーへの移動は、指す先が見出しでないため今の開き方のまま。
目次の項目を押すと URL の末尾が見出しの `#ID` になり、URL の `#ID` で移るときと同じ処理を呼ぶため、2 つの開き方を統一する。

#458 の列の幅は、ユーザーの[追加の指示](https://github.com/shuhei1101/mdmark/pull/505#discussion_r4554479222)のとおりに決める。

- 改行で分けた 1 行が決めた文字数以上のセルを持つ列を長文の列にし、長文の列だけを折り返す。ほかの列は折り返さず、最も長い行の幅にする
- 長文の列は、表の幅を制限せず本文の幅いっぱいまで広げて、なるべく横幅を使う。折り返さずに収まるなら、本文の幅まで広げずその幅で止める
- 全ての列に最小の幅を持たせる（長文の列は決めた最小の幅、ほかの列は最も長い行の幅）。最小の幅の合計が見える幅を超えたら、最小の幅で描いて表を横にスクロールする
- 長文の列とみなす文字数と、長文の列の最小の幅は部品設計『表』で決める（モックは 20 文字と 30em。最も長い行の幅の方が短ければその幅）。列ごとの例外は `width.min`・`width.max` で記載できる

#458 の「表が常に最大の幅を取る」は、[#168](https://github.com/shuhei1101/mdmark/issues/168) で入れた、表を本文の幅いっぱいに広げて列を本文の幅まで広げる描き方で起きる（単一ユースケース『表を操作する』の「表を本文の幅に広げる」）。
列の幅の合計が本文の幅に収まる表は、本文の幅まで広げず列の幅の合計で描き、収まらない表だけ本文の幅で横にスクロールする。

#460 は、帯の背景を本文と同じ色にして（[ユーザーの回答](https://github.com/shuhei1101/mdmark/pull/505#discussion_r4554582525)の案 B）、言語のラベルを帯の上端に付けた、枠線を持たない塗りのタブにする。ライトとダークの配色で同じにする。
