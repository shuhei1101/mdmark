# 要件

## 要望

HTML コメントのマーカーの設定を、名前の後ろの JSON のオブジェクトで記載できるようにする（`<!-- details: {"title": "補足の手順", "open": true} -->`）。
キーの構成・型・既定・選べる値は資料 A-128（`/mnt/c/Users/shuhe/repo/tmp/何でも会話/.mindstella/docs/A-128.md`）を正とし、マーカーごとの設定の設計書と JSON Schema に写す。

| No | 機能 | 終わりの条件 |
| --- | --- | --- |
| 1 | JSON の記載 | `<!-- 名前: {JSON のオブジェクト} -->` を、最上位の波括弧を含めて 1 つの JSON のオブジェクトとして参照する（複数行にまたがる記載を含む）。引数の無いマーカーは `<!-- 名前 -->` のまま描く。JSON として読めない記載は、その場所に記載の警告を出し、その設定を適用しない |
| 2 | マーカーごとのキー | A-128 の表・タブ・ステップ・ファイルツリー・コードブロックの飾り・セクション・details・wide・行の詳細・図と表の番号・ギャラリー・取り込み・ページの設定・機能のオン・オフ・用語集の表・ビューのキーを、A-128 の型と既定のとおりに描画へ適用する。後から引数が付きうる値はオブジェクト（`total[].calc`・`format.type`・`highlight.color`・`lines.start`）、行の範囲は `{"from": 2, "to": 4}`、列を指す値は `{"column": "列の見出しの文字"}`、折り畳みは共通のオブジェクト `collapse`（`open`・`title`）にする |
| 3 | 表の列の設定と機能 | 表の `columns.{列名}` の `filter`・`hidden`・`pinned`・`total` を記載すると、その機能が付く。`features.{機能}` はキーを記載すると機能を追加し、`enabled` の `false` で削除する。`false` にした機能の列の設定は適用せず、点検が通知する |
| 4 | 検証 | マーカーごとの JSON Schema で値を検証する。型の誤りは、その場所に記載の警告を出してその設定を適用しない。知らないキーは描くのを止めずに無視し、点検（`mdmark check`）が通知する。表に無い列名（`columns.{列名}`）と列に無い値（`board.values.{値}`）は、今と同じくその場所に記載の警告を出す。値に `-->` を記載できないため、`>` を `>` にする書き方を点検が案内する |
| 5 | 設定の設計書 | マーカーごとに設定の設計書を持つ。キーの表（キー・型・必須・説明・例。オブジェクトの中のキーは `.`、配列の要素は `[]` でつなぐ）と見本のコードブロックを持ち、マーカーの JSON Schema はこの設計書と同じ内容にする。共通の決まり・共通のオブジェクト・今の引数との対応も設計書に持つ |
| 6 | 今の書き方 | 拡張でないマーカーの今の書き方（`キー=値`・`+機能`・位置の値）は、この PR を入れるマイナーバージョンの間だけ今のとおり描き、点検が JSON の記載への移行を通知する |
| 7 | 拡張と `libraries` のマーカー | `registerExtension` の拡張の `schema` と `draw` は、マーカーの JSON のオブジェクトを `options` に、範囲の中の定義を `definition` に受け取る（`args`・`keys` は無くす）。設定の `libraries` のマーカーは `draw(slot, options)` に JSON のオブジェクトを受け取る。どちらも今の書き方の記載は描かずに記載の警告を出し、移行（`mdmark upgrade`）を案内する |
| 8 | 移行 | `migrations/` の移行の手順（`files: [documents]`）で、文書のマーカーの今の書き方を A-128 の「今の引数との対応」のとおり JSON のオブジェクトへ書き換える。今の実装が適用している設定だけを書き出し、適用されていない記載（`+total` の無い `total=` など）と読み込めない記載は書き出さずに移行の報告に挙げる。拡張・`libraries` のマーカーは、引数をキーへ移す対応を持たないため書き換えずに移行の報告に挙げる |
| 9 | 使い方集と雛形 | 使い方集（`docs/guide/`・`guide/index.yaml`）の記載例と説明、雛形（`templates/`）の拡張を JSON の記載と `options`・`definition` に合わせる。`docs/guide/` の各ページの本文のマーカーは、No 8 の移行の手順を適用して書き換える |

`map`・`map-data` のマーカーは既に A-128 の構成の JSON のオブジェクトで、No 4 の検証の仕組みと設計書（No 5）に合わせる。

マーカーごとの設定の設計書は、既にある種類の ER 図（利用側が記載し mdmark が読み込むデータの構造）に、共通の決まりの 1 ファイルとマーカーごとに 1 ファイルずつ作る（テンプレートは新しく作らない）。

`未確定`: 描くときの JSON Schema の検証の処理（決める工程: モジュール構成設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | CLI が使用している ajv を配布物にも含め、描くときと点検で同じ JSON Schema を検証する | 描くときと点検の結果が一致する | 配布物が大きくなる |
| B | 描くときは型だけを手で検査し、JSON Schema の検証は点検（CLI）だけで行う | 配布物が大きくならない | 描くときと点検で同じ検証を 2 つ持つ |

推奨: A

描くときと点検の検証を 1 つの JSON Schema にそろえ、設計書と食い違わないようにするため（大きさは設計で配布物の非機能要件と照らす）。
