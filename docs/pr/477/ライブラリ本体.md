## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| マーカーの読み取り | 名前の後ろが `{` で始まる引数は、`-->` の前までを `JSON.parse` で 1 つのオブジェクトとして参照する。`{` で始まらない引数は今の書き方として今の読み取りで参照し、今の書き方であることを記録する | 読めない JSON・オブジェクトでない値は、その場所に記載の警告を出して設定を適用しない |
| 設定の設計書と JSON Schema | マーカーごとに A-128 のキーの表と見本を設計書へ写し、同じ内容の JSON Schema を `schemas/` に配置する。共通のオブジェクト（`collapse`・行の範囲・列を指す値）は共通の定義にして各マーカーから参照する | ER 図『マーカーの設定の共通の決まり』とマーカーごとの ER 図（`docs/er/ER-477-*`） |
| 検証 | 描くときと点検で同じ JSON Schema を使用する。型の誤り・表に無い列名・列に無い値は描くときに記載の警告を出し、知らないキーと今の書き方は点検だけが通知する | `未確定`: 描くときの検証の処理（要件.md） |
| 各マーカーの記法 | `keys`・`args` を参照している各マーカーの処理を、検証を通したオブジェクトの値を参照する処理に置き換える。今の書き方は、今の読み取りの結果を A-128 の対応表で同じオブジェクトへ変換してから渡し、描く処理を 1 つにする | 表は列の設定を記載した機能を付ける（要件.md の No 3） |
| 拡張と `libraries` | `MdmarkMarkArgs` を `options`・`definition` に変え、`libraries` の `draw` に `options` を渡す。今の書き方の拡張・`libraries` のマーカーは描かずに記載の警告を出す | 公開の型の互換が壊れる破壊的変更。変更履歴に移行の方法を記載する |
| 点検 | `mdmark check` と Markdown の点検に、知らないキー・型の誤り・今の書き方・値の `--` の通知を追加する | 今の書き方の通知は、移行のコマンドを案内する |
| 移行 | 今の書き方の読み取りと A-128 の対応表で、文書のマーカーを JSON のオブジェクトへ書き換える移行のスクリプトを、`files: [documents]` の `call` の手順で追加する。適用されていない記載・読み込めない記載・拡張と `libraries` のマーカーは書き換えずに移行の報告に挙げる | 書き換えた結果を描いた HTML が、書き換える前と同じになることをテストで確かめる |
| 使い方集と雛形 | 記法のページのキーの説明を JSON の記載とマーカーごとの設計書へのリンクにし、記載例を書き換える。`docs/guide/` の各ページの本文のマーカーは移行のスクリプトを適用して書き換える | 要件.yaml の更新ドキュメント |
